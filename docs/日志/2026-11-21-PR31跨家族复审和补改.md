# 2026-11-21 PR #31 跨家族复审和补改

## 要做什么

作者原话：「这个项目下面应该又有了不少改动，你查看并处理一下。」另外交代 Codex 现在用不了，「以后的复审都调用agy中的gemini 4」。

## 做了什么

上次收工（11-19，main 停在 `5d569dd`）以后多出来的只有 PR #31（分支 `cursor/user-feedback-eight-0dab`）：Cursor 里的 Grok 4.7 写了八条用户反馈的初版，agy 里的 Gemini 4 Carbon 审改过一轮，经过见 `2026-11-21-八条用户反馈` 和 `2026-11-21-PR31审核`。main 本身没有新提交，本机也没有别的会话在动它。

PR 的两轮作者都不是 Claude，所以这次由 Claude 做跨家族复审：主会话自己逐行读了删文件那一块（卸载便携 Java、清理没建完的文件夹、写和去掉创建记号），另派两个只读的 Claude 审查代理分头看下载校验与报错脱敏、接管识别与界面文案。三方都没有查出挡合并的问题，查实的几条在这个分支上补改，按主题分了三个提交，另有两个小提交是照 Gemini 的可选意见改的：

`7fca240` 改下载。便携 Java 走清华镜像时要向 Adoptium 的接口要官方 SHA-256，原写法对每个候选文件名各问两次、每次是默认的两轮三十秒，国内连不上 api.adoptium.net 时最坏要白等约四分钟才落到 Mojang 运行时，期间安装锁一直占着。现在一共问两个地址、各最多十秒，两个都没要到就报「连不上 Adoptium 的接口」，`Ensure` 看到这个就不再走同一个接口的 Adoptium 官方源。校验原则没变：清华的压缩包仍只认 Adoptium 给的同名文件的校验值。同一个提交里，清华压缩包挑最新时把版本段和构建号分开比（原来会把 17.0.21.1_2 判得比 17.0.21_9 旧）；NeoForge 拿到官方 SHA-1 以后加进来的 forgecdn 不再排第一，放在 BMCLAPI 后面（「仅官方」时本来就不加它），因为它在国内的连通性没人实测过，排第一的话连不上或很慢时每次都先在它上面耗；net/http 解析不了跳转地址时会把原文写进报错，里面可能有账号和签名，换成一句固定的话。

`2997af6` 改接管识别。PR 为了不拿 Velocity 的版本号和 Minecraft 版本比大小，把同分的候选按核心分组、只在同一种核心里比版本，结果认不出核心的新旧两个 jar（比如 Arclight 升级后旧 jar 没删）和换过核心的旧 jar（paper-1.20.4 加 purpur-1.21.1）都退回按文件名挑，比 main 差。现在所有游戏服（含认不出核心的）算一组照旧按 Minecraft 版本挑新的，每种代理端各算一组；缺版本号的排最后，1.20 和 1.20.0 这种数值相同的接着比构建号，不同核心的构建号不互相比。这样排序真的是严格弱序了，PR 原来的注释和审核日志说「保证严格弱序」其实不成立，审查代理构造出了反例。同一个提交把报错和工具箱提示里剩下的「Mohist / Banner」改成「Mohist / Taiyitist（原 Banner）」，正版 UUID 设计文档里「接管时读端口」改准成「服务器列表里显示 velocity.toml 写的端口」。

`9b89150` 照 Gemini 4 Argon 的可选意见，Java 压缩包名切出来的构建号不是纯数字时整段当版本号，免得不带 `hotspot_` 的名字被切在前缀的字母 b 上。

`5e33f05` 改「没装上的文件」的界面。后端对站点不在允许列表、又没有校验值的项也给「信任站点并下载」，真下载时才拒掉；「全选可下载项」以前照样选上，还会把用户已经选好的「用本地文件代替」改掉，和旁边的提示说的不一样。现在全选只动还没选处理方式、带校验值的行，提示照实写。分批提交时某一批出错，那一批可能已经在后端处理了一部分（连接途中断开），以前按上一批的旧响应重画，已经装好的文件还显示在清单里；现在先重新要一次清单再画。仿真后端补上了真后端的「没有校验值不下载」，原有用例里信任下载的数据补上校验值，新加了没有校验值、已经选了本地文件、回应丢了三种情况。

`b52b9b4` 照 Gemini 4 Argon 第二轮的可选意见，重新要清单的那段时间里离开了页面，不再在新页面上弹旧页面的错。

另外把 Codex 不可用、以后复审改调 agy 里的 Gemini 4 这件事记进了主会话的记忆和委派手册的状态表（都在仓库外）。

PR #31 还没有合并：合不合进 main、什么时候发版，等作者点头。

补改之前先在 PR 原来的头 `596667c` 上跑了一遍：gofmt、`go vet ./...` 干净，`go test -count=1 ./...` 44 个包全过；界面全量 268/268，原型自检 162/162。

补改过程中每个提交都跑了改过的包和相关的界面用例。跳转地址脱敏做了反向验证：去掉修复后新用例确实报出泄露的账号，恢复后通过。接管识别用审查代理留下的十七组目录探针，分别对 main 和补改后的代码跑了一遍对照：两个回归回到 main 的结果，其余差异都是有意的（有 velocity.toml 时 Velocity 优先、不再拿 Velocity 版本号和游戏版本比、三个候选里缺版本号或版本写法不同时 main 挑旧的、现在挑新的）。

补改之后（`5e33f05` 上）又跑了一遍全量：gofmt、`go vet ./...` 干净，`go test -count=1 ./...` 44 个包全过，界面全量 268/268（新的断言加在原有用例里，条数没变），原型自检 162/162。`b52b9b4` 只加了一行，改完以后把和「没装上的文件」、PR #31 相关的 18 条界面用例重跑了一遍，都过。「全选」靠的是真后端 GET import-pending 的每一项里带着 `sha1`，仿真数据是手工补的，照不到真后端；读代码核实了清单原样带出这个字段，又加了一条 Go 用例 `TestPendingViewCarriesSHA1ForSelectAll` 把这个约定锁住（有校验值的带、没有的不带），提交在日志后面。

## 没做完或没验证的

- 国内家庭网络到 api.adoptium.net、neoforged.forgecdn.net、清华镜像的连通性还是没人实测，forgecdn 排第几、校验值查询给十秒够不够，都是按「连不上时别让人白等」定的。
- 清华镜像目录本身也连不上、同时 Adoptium 接口也连不上时，Adoptium 官方源那一步仍按默认时限等（Gemini 记的已知问题，这次的改动之前就这样）。Mojang 运行时那条路的文件校验值来自 BMCLAPI 给的清单，等于镜像自证，也是老样子；PR 正文「一律向 Adoptium 官方核对」只说的是清华和 Adoptium 两条路。
- 两个审查代理记的、这次没改的：卸载便携 Java 的同时另一处把某台服切到这套 Java，那台服下次开服会找不到 Java（不丢数据）；一次提交 500 项时整批做完才返回，界面上只有一个置灰的按钮；离开页面后剩下的批次不再提交；Paper 旁边放着原版 server.jar 时会弹「不止一种服务端」；仿真后端在删除半成品的返回结构、几句报错原话、Java 卸载的「正在创建」那条 409 上和真后端不一样（界面不依赖这些）；界面用例里「501 项拒绝」测的是仿真后端自己，局域网下不显示半成品横幅、删除被 409 拒绝时的提示、按钮防连点没有断言。
- 创建记号写进新目录以后、还没记住这个新根目录时程序崩了，重启后扫不到那里的半成品；列出半成品的接口会顺手去掉已登记服务器里残留的记号，读接口带了一点写（Gemini 4 Carbon 那轮记的，没改）。
- 符号链接那两处子断言在作者电脑上没开开发者模式，照旧跳过。
