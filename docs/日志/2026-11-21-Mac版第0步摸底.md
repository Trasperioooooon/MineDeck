# 2026-11-21 Mac 版第 0 步摸底

## 要做什么

作者换了一台 Apple 芯片的 Mac，想知道能不能做 Mac 版。方向已经定了：不另写原生应用，同一套代码按平台分文件（`_windows.go` / `_darwin.go`），同时出 Windows 和 Mac 两个版本。主会话派下来的第 0 步（任务原文概括）：

> 在 macOS arm64 上把 MineDeck 后端编译并跑起来，先不要原生窗口，在浏览器里打开界面，然后列出哪些功能在 Mac 上已经能用、哪些还要补。

具体三件：建一个 darwin 能编译的入口；把共用文件里的 Windows API 调用拆成按平台的文件，Mac 这边做最小可用的实现，做不了的返回明确的错误、不假装成功；实际建一台服务器、开服、看控制台、关服，记下各个主要功能在 Mac 上的状态。约束：Windows 版不能受影响（`GOOS=windows go vet ./...`、`GOOS=windows go build ./cmd/minedeck` 保持干净，原有行为不变）；Mac 上 `go test ./...` 能跑的包要比原来多（原来 22 个通过、24 个编不过）；原生窗口、钥匙串、打包签名这些后面阶段的事不做，只列出来；作者在 Windows 和 Mac 两台电脑上交替开发，Windows 那边可能有没推的改动，改动要小、要集中；只在自己的分支上提交，不推送、不合进 main。

## 做了什么

分支 `claude/recursing-thompson-92e476`（从 `5d569dd` 拉出），代码一个提交 `5e1311b`，加上这份日志和现状、待办各一条。没推送，没合进 main。

入口：没另建 `cmd/minedeck-mac`，在原来的 `cmd/minedeck` 里分文件，侵入更小、命令行参数和启动流程只有一份。WebView2 窗口那段（`openWebView`）从 `main.go` 原样挪进 `webview_windows.go`；`host_darwin.go` 里的 `openWebView` 用 `open` 打开默认浏览器，然后等退出信号，`setDPIAware`、`bridgeIdle` 在 Mac 上什么都不做。`main.go` 里只剩挪走代码和去掉 import 的改动。

共用文件里的 Windows API 按平台拆开。Windows 那一半都是原样挪进 `_windows.go`，外面只包了一层函数名（逐行对过：新文件里多出来的只有包装函数的签名和注释）；Mac 那一半是新写的：

| 地方 | Windows（原样挪过去） | Mac（新写） |
|---|---|---|
| `app`：剩余空间、内存、系统版本 | `sys_windows.go` | `sys_darwin.go`：statfs、sysctl `hw.memsize`；可用内存用 `kern.memorystatus_level` 估算 |
| `diskguard`：剩余空间、按卷排队 | `volume_windows.go` | `volume_unix.go`：statfs、`st_dev` |
| `procutil`：Job Object、隐藏窗口 | `procutil_windows.go` | `procutil_unix.go`：子进程放进自己的进程组（终端里 Ctrl-C 只打到 MineDeck，关服仍由它发 stop）；没有 Job Object 的对应做法，见下面「没做完」 |
| `java`：扫描、程序名 | `scan_windows.go`（注册表、Program Files、启动器运行时） | `scan_darwin.go`：系统和用户的 JVM 目录、Homebrew、SDKMAN、`.jdks`、官方启动器的运行时；`/usr/bin/java` 是系统转发程序，不扫；便携 Java 不自动下载，缺了说怎么自己装 |
| `inst`：开服前试绑端口 | `portcheck_windows.go`（SO_EXCLUSIVEADDRUSE） | `portcheck_unix.go`：按系统默认试绑，认 EADDRINUSE、EACCES |
| `inst`：真实路径 | `realpath_windows.go` 没动 | `realpath_darwin.go`：`fcntl(F_GETPATH)` 按打开以后的文件问路径，和 Windows 按句柄问是同一个思路 |
| `worldimport`：目录身份、改名、错误码 | `identity_windows.go`、`txn_windows.go` | `identity_darwin.go`（设备号、inode、创建时间）、`txn_darwin.go`（`renamex_np` 的 `RENAME_EXCL`，改完给上级目录刷盘） |
| `worldimport`：session.lock 有没有人锁着 | `lock_windows.go` 没动 | `lock_unix.go`：`fcntl(F_GETLK)` |
| `ops/catalog`：端口被谁占着 | `port_windows.go` 没动 | `port_darwin.go`：系统自带的 `lsof`，程序名从 `kern.procargs2` 取 |
| `update`：换程序 | `run_windows.go` 没动 | `run_other.go`：不支持；`Apply` 在校验和检查之后、下载之前拦下 |

共用代码里另外改的几处：`java.Exe`、扫描和接管认 Java 程序名改走平台函数（`java.IsExeName`）；两处 `explorer.exe` 换成 `procutil.OpenFolder`（Mac 上是 `open`，访达）；OpenFrp 和自建 frp 的 frpc 下载前加一道判断，Mac 上直接报「Mac 版还不能下载 frpc」，不白下一个 Windows 的 exe。Java 自动下载和 frpc 下载的这两道拦截是包里的变量，Mac 上跑测试时打开，下载、解压、校验这几步照样测得到。

顺带修了一处只在 Mac 上出错的：接管时查「这个文件夹正在新建或接管中」，登记用的是小写的键，比的时候拿的却是原样大小写的路径。Windows 的 `filepath.Rel` 不分大小写所以没事，Mac 上就漏判了，同一个文件夹能同时接管两次。现在两边都按小写比，Windows 上行为不变（`inst/adopt.go`）。

测试：五个测试文件直接用了 x/sys/windows（独占打开文件、8.3 短名、符号链接权限）。这些辅助函数挪进 `_windows_test.go`，Mac 上用权限清零加 `chflags uchg`（改不了、换不掉、删不掉，同一文件夹里别的照常）模拟占用。`props_atomic_test.go` 里原来内联的三行独占打开换成调同一个辅助函数，Windows 上打开方式一样。

## 验证了什么

都在作者的 Mac（Apple 芯片）上做。

- `GOOS=windows go vet ./...`：干净。`GOOS=windows go build ./cmd/minedeck`：干净，带发版参数（`-trimpath -ldflags="-s -w -H windowsgui"`）也编得过。
- Mac 上 `go vet ./...`（含测试）：干净。`go build ./...`：干净。
- Mac 上 `go test ./...`：原来 22 个包通过、24 个编不过；现在 33 个通过、0 个编不过、6 个有失败用例（另有 12 个包在 Mac 上没有测试文件，比如 `cmd/minedeck` 的测试都是 `_windows_test.go`）。`worldimport` 全过。失败的原因只有两类（数的是顶层用例）：
  - 加密存储（`internal/secret`，DPAPI）没有 Mac 版：`web` 44 条全是、`tunnel` 56 条里 54 条、`app` 2 条、`ops/catalog` 1 条。测试一开头存凭据或令牌就失败。
  - 测试夹具是 Windows 的东西：`inst` 16 条（假的 `java.exe` 7 条，反斜杠、盘符路径 6 条，`\Device\…` 设备路径，`cmd /c` 跑 run.bat，127.0.0.2 在 Mac 上默认没有）、`tunnel` 2 条（拿 Windows 的 frpc.exe 测试替身）、`transfer` 1 条（`..\..\outside.jar`、`C:/Windows`）、`ops/catalog` 1 条（假的 `java.exe`）。Mac 上反斜杠是文件名里的普通字符，这些输入在 Mac 上不越界。
- 实测：编出 Mac 版程序，放进会话临时目录里的 `macrun` 文件夹（数据就在程序旁边），`-nogui` 起后端，在内置浏览器里打开界面。第一次运行的协议框和建服时的 Minecraft EULA 是子会话勾的，只落在这个测试文件夹里。用完停掉了进程，没留下后台的 java 和 MineDeck。逐项结果见下面的表。

| 功能 | Mac 上的状态 | 怎么验的 |
|---|---|---|
| 界面 | 能用 | 默认浏览器打开，各页正常显示；没有宿主函数时标题栏、外链按网页的方式处理 |
| 建服 | 能用（要本机已经装了对应的 Java） | 界面向导建 Paper 1.21.11，接口建 Fabric 1.21.11；都用上了扫描到的本机 Java 21。接口建 Paper 26.3（要 Java 25，本机没有）时报「Mac 版还不能自动下载 Java 25」并说怎么装 |
| 开关服 | 能用；MineDeck 被强退时 java 会留下 | 开服到「运行中」、停服「已正常关闭」、没有残留进程；Ctrl-C（SIGINT）退出 MineDeck 时先把开着的服关掉；`kill -9` MineDeck 后 java 还在（Windows 上 Job Object 会连带结束） |
| 控制台 | 能用 | 实时输出，发 `say`、`list` 有回应 |
| 备份 | 能用 | 运行中备份；停服还原，还原前自动备一份 |
| 模组、插件 | Modrinth 能用；CurseForge 不能用 | Modrinth 浏览、待装清单装插件；Fabric 服开关正常。CurseForge 要 Key，Key 存不了（加密存储）。Forge、NeoForge 的安装器没试 |
| 地图导入 | 能用，有一处兜底比 Windows 弱 | 文件夹扫描、预检（空间、模组差异）、导入、换回来都成；开着服时 F_GETLK 认得出 Java 锁着 session.lock（进程号对得上）。1.16 以前的版本不锁这个文件，Windows 靠「文件开着不让改名」兜底，Mac 上没有这道 |
| 隧道 | 不能用 | frpc 只有 Windows 的包，下载前就拦下；平台账户的凭据也存不了 |
| AI | 不能用 | 保存 Key 报「DPAPI 只在 Windows 上可用」；AI 助手、游戏内 AI、伙伴都要 Key |
| 音乐共享 | 不能用 | 报「音频采集仅支持 Windows」（WASAPI） |
| 远程管理 | 能用 | 设访问密码、开局域网访问，重启后监听所有网卡；不带凭据访问接口回 401；用本机局域网地址密码登录后能列服务器 |
| 其他 | 见右 | 查端口被谁占着能用（认出是哪台服务器的 java）；内存、剩余空间显示正确。MCP 接口不能用（令牌存在加密存储里，看代码推断，`TestMCPRoutes` 失败也印证）；选文件夹对话框不能用（只能手填路径）；开机自启、程序内更新明确报不支持；「打开文件夹」接上了 `open`，没点过 |

## 没做完或没验证的

- Windows 上的测试没跑：这台是 Mac，只做了 Windows 的 vet 和编译。推到 GitHub 以后由 CI（windows-latest）跑。
- 没做（任务说留给后面阶段）：原生窗口和菜单栏图标、钥匙串、Mac 版 Java 和 frpc 的下载、开机自启、程序内更新、打包签名公证、音乐共享。
- 进程管理：MineDeck 被强退、崩溃时 java、frpc 会留下，Mac 上还没有对应 Job Object 的做法。只接了 Ctrl-C（SIGINT），SIGTERM 没接（不想改 Windows 也会走到的 `main.go`）。
- 数据文件夹还在程序旁边（`app.Init` 用程序所在的文件夹）。打成 .app 以后程序包里不能写，要挪到用户的「应用程序支持」文件夹。
- Mac 上还会生成 `run.bat`（没用，应当生成 `run.sh`）；接管、导入时认启动脚本的逻辑按 Windows 写。
- 界面里的 Windows 痕迹：建服时预览的路径用反斜杠拼（`servers\Paper`）；Java 路径的示例是 `C:\Program Files\…`；「资源管理器」「Windows 安全中心」这些说法。
- `fatal` 启动失败时用 `mshta` 弹窗，Mac 上弹不出来（日志照写、照常退出）。
- 没试的：接管已有服务器、Forge 和 NeoForge 的安装器、交接包导出导入、整合包导入、真客户端进服。

## 留给下一位的

- 后面各阶段大概的工作量（一个人加 AI，粗估，不含等 Apple 开发者账号）：
  - WKWebView 窗口和菜单栏图标：3–5 天。go-webview2 只管 Windows，Mac 要换 cgo 写的 WKWebView 宿主（或 webview/webview_go），把 11 个宿主函数接上；Mac 习惯用系统的红绿灯按钮，界面的自绘标题栏要跟着改；关窗进菜单栏、Cmd-Q 退出前先停服。选文件夹对话框（NSOpenPanel）顺带做。
  - 钥匙串：1–2 天。在钥匙串里放一把随机主密钥，`secret` 的 protect / unprotect 用它加解密，`secrets.json` 的格式加一个 Mac 的前缀。做完 AI、CurseForge、隧道凭据、MCP 令牌就都能存了，上面失败的测试里一百来条会过。
  - Mac 版 Java 和 frpc 下载：2–3 天。Adoptium 和清华镜像的 Mac 包是 `.tar.gz`，要补一套和 zip 同样设防（路径越界、磁盘余量、「还没装完」记号）的解压，还要补可执行权限；JDK 装在 `Contents/Home` 下面。Mojang 的运行时清单换 `mac-os-arm64`，按清单的 executable 标记补权限。frp 官方有 `darwin_arm64` 的包要另配校验和；OpenFrp、樱花要查各自有没有 Mac 版。frpc 的文件名规则（`.exe` 结尾）和坏 exe 的检查（认 PE 头）要按平台分。
  - 进程管理：1–2 天。被强退时不留 java：上次留下的进程按记下的进程号认出来、提示或代为关掉，或者另起看门进程用 kqueue 盯住 MineDeck；停服超时强杀时连进程组一起杀；接上 SIGTERM；生成 `run.sh`。
  - 开机自启和更新：开机自启用 LaunchAgent 或 SMAppService（后者要签过名的 .app），约 1 天；程序内更新要下 .app 的压缩包、核对校验和与签名、退出后替换整个 .app，约 2–3 天。
  - .app 打包和签名公证：2–3 天。程序包结构、Info.plist、图标、数据挪到「应用程序支持」文件夹、Developer ID 签名、notarytool 公证、DMG，CI 加 macOS 的打包任务。要先有 Apple 开发者账号（年费 99 美元）。
  - 音乐共享改用 ScreenCaptureKit：4–6 天，最没底的一块。macOS 13 起能按应用录声音（对应 Windows 的按进程录），要「屏幕录制」权限，得有 .app 才好测；接进现在的 `Capability` / `ListSources` / `Start` 接口，重采样到现在的格式。
  - 合起来三到四周。建议先做钥匙串（最省事、解开的功能最多），再做窗口和打包。
- 建议在 CI 里加一个 macos-latest 的任务，只跑 `go vet ./...` 和 `go build ./cmd/minedeck`，免得 Windows 上的改动又让 Mac 编不过。
- 新写平台相关的代码时：Windows 那一半放 `_windows.go`；Mac 能和 Linux 共用的放 `_unix.go`（`//go:build !windows`），只有 Mac 有的放 `_darwin.go`。Linux 原来就编不过几个包，这次没管。
- 替作者定的，都可以否决：入口不另建 `cmd/minedeck-mac`；Mac 上缺 Java 直接报错、不去试 Windows 的下载源；隧道、程序内更新在 Mac 上下载之前拦下；子进程放进自己的进程组；测试里用 `chflags uchg` 模拟占用、拿包里的变量在测试时打开下载；第一次运行的协议框和测试服的 Minecraft EULA 由子会话在测试文件夹里勾了。
