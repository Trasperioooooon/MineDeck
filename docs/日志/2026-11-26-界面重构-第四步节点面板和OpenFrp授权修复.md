# 界面重构：第四步改成节点面板，顺手修了 OpenFrp 授权连不上

接着 `2026-11-26-界面重构-穿透账户能做到哪一步.md`。改了草图 `design-system/redesign/wizard.html`、计划书和现状；另外修了一处程序（`internal/tunnel` 里 OpenFrp 授权的轮询），这是作者转来的用户反馈，作者选了在这个会话里做。活都是主会话自己做的，复审交给了 agy 里的 Gemini 4 Argon。

## 作者这次说了什么

上一次主会话把穿透账户能做到哪一步查清楚了，留了四处等作者定。作者的回答：节点不自动挑，要做一个像官网那样的节点面板，第四步的布局要好好重新设计；OpenFrp 的公网端口照主会话的建议由 MineDeck 替人挑；删除隧道也要加上，默认在 MineDeck 里删了，平台上那条一起删。作者还问樱花的访问密钥能不能加密存在本机：v3.2.9 每次加隧道都要粘一遍，想让用户第一次填了以后选要不要保存，设置页的隧道账户管理里也放一个全局的入口。最后转来一条用户反馈：OpenFrp 授权时官网显示成功，MineDeck 却报「穿透平台返回 HTTP 400: request_uuid参数不能为空」。

## OpenFrp 授权连不上

原因是 OpenFrp 11-24 改写了 API 文档，轮询登录结果那一步的 `request_uuid` 从 GET 请求的请求体挪到了网址后面的查询参数，平台已经照新规矩办了，MineDeck 还照旧文档放在请求体里，平台读不到，就回了那句报错。改成放在查询参数里、GET 不再带请求体。测试里的假平台也照新文档改成只认查询参数，改代码之前 4 个 OpenFrp 登录的测试正好以用户看到的那句报错失败，改完全过，`internal/tunnel` 整包测试也过了，全部代码编得过。

改完交给 agy 里的 Gemini 4 Argon（请求的是 `gemini-4-argon-high`，实际模型 agy 不报，未确认；它自己说是 Gemini 4 Argon High）只读复审，把改动、发请求的代码和新旧两版文档贴给它，不让它调工具。它说修复正确，没有要改的；建议测试里判断请求体的条件从「长度大于 0」改成「不等于 0」，照改了。新文档里建隧道的 `local_port` 写的是整数，MineDeck 一直按旧文档发字符串，它和主会话都认为没有真实账号实测之前先不动，记在了计划书里。改动已提交推送（134d8ce），没有发版。

## 樱花访问密钥能不能记住

本来就能。在穿透页最下面「平台账户」里连樱花时，访问密钥就用 Windows 的 DPAPI 加密存在本机，绑当前 Windows 用户。作者每次都要粘，是因为用的是页面顶上手填的「添加隧道」表单，那个表单不读账户里存的密钥。重构以后手填表单只留给自己的 frps，樱花一律走账户。第四步樱花没连时粘一次密钥，「记住密钥」默认开；不记住的话这条隧道照样能用，下次建服务器要再粘。设置页里放樱花访问密钥的换和删。Mac 上这套加密现在一律失败，Mac 版要换成钥匙串，也记进了计划书。

## 第四步第二稿

面板从 420 加到 500 高，1280×800 下不滚动，右边「谁能进」不变。左栏最上面一排四张卡：局域网、OpenFrp、樱花穿透、自己的 frps，第一稿「只在局域网 / 开内网穿透」再挑平台的两层并成了一层。选 OpenFrp 或连上了的樱花，下面就是节点面板：「新建隧道 / 用已有的」、搜索框、筛选（全部、公开游戏、支持 UDP）、樱花的「公开招人」开关，下面按地区分组的节点卡片，三列，在栏里自己滚，卡片上有公开游戏、无 UDP、满载这些小标签。不替人挑，没选节点点「创建服务器」会拦下。开了「公开招人」只有公开游戏节点能点。「用已有的」只有本地端口对得上的 TCP 隧道能选。樱花没连时是粘访问密钥加「记住密钥」开关，下面一块虚线框占着节点面板的位置。自己的 frps 是四个框。

在 1280×800 下用真鼠标点过：四张卡来回换；没选节点时被拦下、出「先选一个节点」；选节点、筛选「支持 UDP」、切「用已有的」；樱花空着密钥点「连接」被拦、填了按回车转圈后换成节点面板；「公开招人」打开后只剩五个公开游戏节点能点，原来选的普通节点取消了；自己的 frps 没填地址被拦；代理端三个穿透选项灰着。浅色主题看过。没有报错。
