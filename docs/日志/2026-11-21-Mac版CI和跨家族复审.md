改了的四处，都只动只在 Mac 上编进去的文件，在提交 `cfce04c`：

- `InsideReal` 给空的根时，Mac 版先去掉末尾斜杠再判断，空串被当成了根目录 `/`，什么路径都算在里面；Windows 版给空根返回假。现在的调用方传进来的根都出自 `RealPathStrict`，查不清会报错，实际碰不上，改成和 Windows 一样是防以后的调用方。补了一个 Mac 上的测试 `realpath_darwin_test.go`：共用的 `TestInsideRealIsExact` 用的是 Windows 的设备路径，在 Mac 上本来就是已知失败的那批之一。
- 查真实路径时的 `open` 和 `fcntl(F_GETPATH)` 遇到 EINTR 就重做。Go 自己的 `os.Open` 也这么做：网络盘上 open 会被运行时的抢占信号打断。原来碰上了会把在的文件当成打不开，`RealPathStrict` 报「查不清」、拒绝操作，是往安全的方向错，但会莫名其妙地拒绝。
- 地图导入改名的 `moveFile`：文件系统不认 `RENAME_EXCL` 时的退路，原来用 `exists` 看目标在不在，看不清（没权限、盘出错）会当成不在、接着去普通改名，有可能盖掉目标；现在改用 `present`，看不清就停下，和 `txn.go` 里「决定搬不搬东西的地方都用 present」的规矩一致。调用方 `doStep` 进来之前已经用 `present` 看过一次，原写法只有两次查看之间出状况才会出事，这次是让 Mac 版自己也守住。要覆盖（只有记录文件）时直接用 `rename`，原来是 `renamex_np` 不带标志，行为一样，只是更直白。
- 「打开文件夹」和 Mac 版启动时打开浏览器，原来只 `Start` 不等，每次留下一个 `open` 的僵尸进程，一直到 MineDeck 退出。现在 `Start` 之后起一个 goroutine 等它退出。Gemini 建议改成 `Run`，没照做：`open` 万一卡住，请求会一直挂着。

没改、写进 PR 等作者定的三条（应修一档）：

- 接管已有服务器时「不能选整个磁盘」在 Mac 上只拦得住 `/`，拦不住外置盘的根（`/Volumes/某个 U 盘`）；Windows 上整个盘的根目录（只有盘符的那种）是拦下的。接管进来以后要是「连文件夹一起删除」，整个盘就清空了。建议加一个按平台的判断，用 statfs 取挂载点，路径就是挂载点时拦下。没改：牵涉删服安全，要在 Mac 上实测外置盘和 `/System/Volumes/Data` 那种挂载点。
- 换地图前查 session.lock：查不清（打开失败，比如那台服是别的账号或 sudo 起的）时调用方当成没人用、照常往下走。Windows 上后面整目录改名时会被开着的文件挡住，Mac 上挡不住，session.lock 是唯一的一道。改法有两种：调用方（`service.go`，Windows 也编）在出错时也中止换图，这会让 Windows 上「打不开 session.lock」从放行改成拒绝；或者只在 `lock_unix.go` 里把打开失败当成有人占着。选哪种要作者定。
- 没接 SIGTERM 和 SIGHUP：在活动监视器里点退出、注销关机、`kill`、关掉启动它的终端窗口，MineDeck 都会当场退出，不停服，java 留在后台接着跑（服务器本身还在跑、世界照常保存，不会立刻丢数据，但 MineDeck 再起来管不到它）。摸底时有意没改共用的 `main.go`。只在 `host_darwin.go` 里加只管得到开浏览器那条路，`-nogui` 那条要改 `main.go`；而 Windows 上 Go 会把注销、关机这类控制台事件当成 SIGTERM 送来，改之前要先核对对窗口程序有没有影响。建议在进程管理那一阶段第一件做，或者作者同意的话现在就改。

存疑、要在 Mac 上实测才能定的三条：

- 默认不分大小写的 APFS 上，F_GETPATH 返回的是不是磁盘上的大小写。共用代码里判断文件夹有没有叠在一起的 `within`、`sameDir` 用 `filepath.Rel`，在 Mac 上分大小写。Gemini 把这条列成应修；主会话对过调用方，接管时选的文件夹一定存在，只要已有的几级都解成磁盘上的大小写就不会漏判，所以放在存疑。实测办法：建一个 `Foo`，用 `foo` 去问，看回来的是不是 `Foo`。
- firmlink：同一个文件夹从 `/System/Volumes/Data/Users/…` 进来和从 `/Users/…` 进来，F_GETPATH 给的是不是同一种写法。不是的话两种写法会被当成两个不相干的文件夹。
- 名字以 `.app` 结尾的服务器文件夹，`open` 会把它当成程序启动，而不是在访达里打开。Gemini 建议 `open -a Finder`，这样到底是打开文件夹还是照样启动它，没把握；`open -R`（在访达里选中它）也是个办法。

可选、可以留到后面对应阶段的：

- `OpenFileInside` 打开文件时不带 `O_NONBLOCK`，碰上命名管道会卡住。两个调用方（工具箱导出整合包、读配置备份）之前都确认过是普通文件，只有在中间被人换成管道时才碰得上，后果是那一个请求卡住。session.lock 是同名管道时扫描导入来源也会卡住，同理。
- 端口：Mac 上通配地址和 `127.0.0.1` 能被两个程序同时监听。开服前的试绑和 Java 自己绑的结果一致（都绑得上），但本机用 `127.0.0.1` 进服会连到那个别的程序；Windows 上 Java 会直接报端口被占。要不要在 server-ip 留空时多试绑一次 `127.0.0.1`，是取舍。
- 关服超时强杀时连进程组一起杀（子进程已经放进了自己的进程组）：进程管理阶段。
- 测试辅助按路径撤销 `chflags`，上层目录被改了名就撤不掉，临时文件夹删不掉。现在 Mac 上 worldimport 的测试全过，没碰上；改成按文件描述符撤销要在 Mac 上验证。
- `update.Apply` 里拦 Mac 的那一句排在「没附带 exe」「拿不到校验和」后面，Mac 上可能先看到这两句；挪到最前面只改提示，文件是共用的。
- F_GETPATH 的路径上限是 1024 字节，比 Windows 短；超长时 `realPath` 往上退一级，`RealPathStrict` 报查不清，往安全的方向错。
- 区分大小写的 APFS 卷上，共用代码按小写去重会把 `Foo` 和 `foo` 两台服务器当成一台；Windows 上打开了「区分大小写」的文件夹也是这样，是原有的取舍。
