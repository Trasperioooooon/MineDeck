# 2026-11-23 阶段 06 待装清单（第 1 轮返工）

## 要做什么

作者要求照公共规则与阶段 06 第 1 轮返工意见，把上一轮复审指出的三处阻断问题、一处被占空目录收尾问题、上一轮因文件范围未放开而留下的草稿清单跨核心与切页提示（A31），以及离开确认和几处可维护性细节一并补齐。

具体包括：

1. **A29 查前置期间改动清单的竞态**：点「全部安装」触发装前检查期间，左侧搜索结果或可选前置仍可点加入清单；检查返回后若不与最新清单重比签名，新加项目的必装前置不会在确认框里列出就被一并装上。
2. **A121 云同步文件夹误判与空文件夹被占收尾**：
   - Go 1.23 起 Windows 上 OneDrive 按需文件这类非名称代理重解析点会报 `ModeDir|ModeIrregular`，顶层若把 `ModeIrregular` 当链接直接 `os.Remove`，非空云同步实例文件夹会删不掉。
   - 实例文件夹里的内容和 `instance.json` 都已经删掉、只剩最后一步删空文件夹因别的进程把它当工作目录而失败时，`Delete` 若报错保留实例，下次再删会卡在「找不到 instance.json」。
3. **删除重试间隔复用与可维护性收敛**：在 `internal/atomicfile` 导出删除专用的短暂占用重试函数，去掉 `internal/inst` 里重复的间隔表与跨平台魔法错误码；合并 `internal/modcart` 两处打开文件算 SHA-1 的重复代码；把 `log4j` 非官方配置冲突文案改成拆出标题和正文共用，不再靠截取前缀和句号切分；修正并发删除测试里未验证过的内核句柄注释。
4. **A31 草稿清单记录核心版本与目标服务器**：往草稿清单加项目时逐项记下核心和 MC 版本，向导回头换核心或版本时离线提示「清空草稿清单」或「留着」；发出建服请求时把新服务器名字记到草稿清单上，若等建服期间切走，目标服务器详情页显示「新建时挑的 N 项还没装」（给「一起装上」和「不要了」），先离线标出核心不匹配项，再带 `includeDraft=true` 查依赖标出 `unresolved` 项。
5. **A33 分批提交离开确认补完**：把单一 `leaveCheck` 改为 `Set` 登记表并返回注销函数，避免两处面板同时分批时先结束的一处抹掉另一处的确认；离开确认不再压过未保存修改的 `dirtyCheck`，两样都在时依次确认；措辞写明在途那批会照常做完；抽出分批提交函数缩短 `pendingPanel`，并修正叠层离场动画期间 `gone()` 的判定。

## 做了什么

工作在分支 `claude/clear-backlog-1122` 上，开工基准为上一轮提交 `cc63012`，按功能拆为三次提交推进：

- **实例删除、重试间隔复用与可维护性整理（A121、A32）**：
  - 在 `internal/atomicfile/replace_windows.go`（及 `replace_other.go`）导出 `RetryRemove(op func() error) error`，复用包内已有的 `retryDelays` 退避表，仅对 `windows.ERROR_SHARING_VIOLATION` 与 `windows.ERROR_DIR_NOT_EMPTY` 重试，不重试 `ERROR_ACCESS_DENIED`（权限不足或只读拒绝访问等半秒也不会恢复）。`internal/inst/inst.go` 删掉自建的间隔表与错误码判断，统一改调 `atomicfile.RetryRemove`。
  - 在 `internal/inst/inst.go` 抽出纯函数 `walkInstanceDir(mode fs.FileMode) bool`，只按 `mode.IsDir()` 决定往里逐项删还是只删自身：Go 1.23 起符号链接与目录联接均不带 `ModeDir`，而带 `ModeDir|ModeIrregular` 的云同步真文件夹照常往里删。
  - `removeInstanceDirMarkerLast` 区分「子项或 `instance.json` 删除失败」与「`instance.json` 已删掉、仅最后 `os.Remove(dir)` 删空文件夹失败」：后者由 `safeRemoveInstanceDir` 记录包含目录路径的日志后返回 `nil`，让 `Manager.Delete` 照常把实例移出列表并忘掉独立登记；头部三项核对原封不动。
  - 在 `internal/modcart/download.go` 抽出给已打开文件算 SHA-1 的 `hashOpenedSHA1`，供 `fileSHA1` 与 `sha1cache.go` 共用；在 `internal/inst/log4j_migrate.go` 新增 `log4jXMLConflictParts` 直接返回标题和正文，`log4jXMLConflictNote` 与 `install.go` 的 `customLog4jConflictParts` 各自拼接，保持用户可见文案一字不变；`internal/inst/stage05_test.go` 第 318 行注释改为陈述重试用意的说明。
- **装前查前置竞态修复与分批离开确认完善（A29、A33）**：
  - `internal/web/ui/modcart.js` 把装前检查拆成 `ensureFreshDeps`：若装前检查被本地文件增删触发的新检查顶掉则顺延等待在途检查；检查返回后再次比对 `depSig !== cartSig()`，变动过就自动补查（最多 3 轮，仍对不上则恢复按钮并提示再点一次），并返回与该次检查严格对应的 `expect` / `expectLocal` 快照传给安装接口。
  - `internal/web/ui/app.js` 把 `leaveCheck` 改为 `leaveChecks`（`Set`）与 `registerLeaveCheck`，`confirmBeforeLeave` 收集全部在途离开提示并同时检查 `dirtyCheck`，两样都在时依次弹窗确认；提示语更新为「还有 N 项还没提交，离开后不会继续；正在处理的这一批会照常做完」；把分批循环、批次进度与登记注销抽成独立函数 `submitPendingBatches`，并补上 `box.closest("[data-leaving]")` 防止叠层点关闭进入离场动画期间继续发出后续批次。
- **草稿清单记核心版本与目标服务器、详情页衔接（A31）**：
  - `internal/modcart` 在 `Item` 上增加 `PickedCore`、`PickedMC`（`omitempty`，仅 `inst == Draft` 时由 `AddFor` 记录，实例和工具箱清单不记），在 `cartFile` 上增加 `DraftInst`（`omitempty`），旧版 `cart.json` 无这些字段照常加载，草稿清单一旦清空或装空自动清掉 `DraftInst`。
  - `internal/ops/catalog/modcart.go` 的 `modcart.add` 接收可选的 `core`、`mc` 与 `draftInst`，`modcart.list` 查看草稿清单时一并带出 `draftInst`，同步更新操作参数描述与 `docs/设计与参考/API.md`；`internal/web/modcart.go` 的 `GET /api/modcart/deps` 把查询串里的布尔值 `includeDraft` 转给 `modcart.deps`。
  - `internal/web/ui/app.js` 在向导建服请求成功后（非原版且未跳过选模组步）将新服务器名记入草稿清单（失败不挡建服）；`internal/web/ui/modcart.js` 在向导步按记录的核心版本与本地文件加载器离线提示不匹配项（给「清空草稿清单」和「留着」），在目标服务器详情页显示「新建时挑的 N 项还没装」（给「一起装上」和「不要了」），先离线标出核心对不上的项，再异步带 `includeDraft=true` 查前置标出 `unresolved` 项，别的服务器详情页不显示。仿真后端 `tools/ui-dev/server.js` 同步对齐。
