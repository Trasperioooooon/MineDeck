**PR #32 在 Windows 上的核对。** 交给一个 Claude 子代理，在两个临时工作树里分别放 PR 的头和它的基线 `586f2ef`，逐项比：

## 验证了什么

都在作者的 Windows 电脑上。

- **全量**（`fae3be0`，和发版代码只差发布说明和几份文档；脚本是仓库外 `MineDeck-r324` 里的 gate.sh，照 r323 那份改的）：gofmt、Windows 编译、vet 都干净；`go test ./... -count=1` 44 个有测试的包全过；界面交互用例 268/268（含 Mac 改过的两条「外部链接」）；原型自检 162/162。用时约 20 分钟。
- **便携 Java 真下载**：用这一版的 `java.Ensure` 写了个临时的检查程序（没进仓库），在空文件夹里把 Java 8、11、17、21、25 各下一遍。五个都走「按 Adoptium 公布的 SHA-256 从清华镜像下载」，10 到 35 秒，解出来的 `java -version` 都对（8u512、11.0.33、17.0.21、21.0.13、25.0.5）。这是在日本的网络上，没在国内网络上试。
- **新接口的真程序实测**（发版参数编的 3.2.4，`-nogui`，只连本机；脚本在 `MineDeck-r324`）：
  - 卸载 Java：被服务器配着的 17 回 409，报错点名那台服务器；`confirm=false` 回 400；没人用的 21 删掉了；只有「没装完」记号的 11 先列在 `incomplete` 里，卸载以后文件夹和记号都没了。
  - 没建完的文件夹：带记号、含 world 的文件夹列出来，`hasWorld` 为 true；登记过的只去掉记号、不列；没记号的不列；`confirm=false` 回 400；删掉以后再删回 400「找不到这个文件夹」，再列是空的。
- **发出后核对**（`verify-release324.ps1`）：发布页不是预发布也不是草稿，Latest 是 v3.2.4，正文就是标签里的发布说明、没有占位字样；exe 和两个伙伴模组对得上 SHA256SUMS，模组对得上标签里的清单；exe 是窗口程序，在空文件夹里用 `-nogui` 起来报 3.2.4。查更新：3.2.4 自己查不到；v3.2.3（没选渠道、选「最新版」）、v3.2.0-beta.5（没选渠道、选「稳定版」）、v3.1.2 都查到了 v3.2.4。PR #27 的只读文件保存在发出的 exe 上照常。
- **应用内更新**（`update324.ps1`，从 PowerShell 起，各用独立的副本）：从 v3.2.3 和 v3.1.2 各点一次「更新」。旧进程两秒内退出，自己重启开了窗口，脚本随后关掉；没留下 `MineDeck.new.exe` 和 `update.bat`；换上的 exe 和附件哈希一致；再起来报 3.2.4，服务器、隧道和存着的凭据都在，没有进程留下。
- **合 PR #32 以后的全量**（`ad353ee`，同一个 gate.sh）：gofmt、Windows 编译、vet 都干净；Go 44 个有测试的包全过；界面交互用例 268/268；原型自检 162/162。用时约 20 分钟。另外在 Windows 上交叉编译 `GOOS=darwin GOARCH=arm64` 的 build 和 vet，都干净。
