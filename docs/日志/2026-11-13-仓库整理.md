## 2026-11-13 仓库整理：补忽略规则，清本机的分支和工作树（Claude 写）

作者觉得这几天提交和分支太多，仓库越来越大，GitHub 首页一打开就是一长串文件，问要不要精简、要不要重配忽略规则。盘点下来是三句话：GitHub 上的仓库只有 30 MB 左右，不用瘦身；首页那一长串是程序入口的源码，忽略规则管不了；忽略规则有几处缺口，本机攒了一批可以删的分支和工作树。作者让先做本机这一部分。

这一节插在宣传片那节前面，没有接在文件末尾：PR #16 也在末尾加了一节，两边都接在末尾会再撞一次。

体积的来历记一笔，免得以后再查。仓库里六首配乐占 18 MB，两张封面底图 2.5 MB，代码和文档加起来不到 10 MB。主仓库这个文件夹在本机有 2 GB，是三支片子的输出（`tools/promo/` 下各自的 `out/`，合计约 1.7 GB）和工作树，都是早就忽略的东西，没有上 GitHub。重写历史最多省不到 20 MB，标签、开着的 PR、工作树和这份文档里引用的提交号都会作废，所以不做。以后会让仓库明显变大的只有宣传片素材，下次做片子时再定要不要进仓库。

`.gitignore` 补了两处。一处是 `/data/`：程序用到 AI 助手、音乐共享、待装清单时会在 exe 旁边建这个文件夹，`data/ai/sessions` 里是对话记录；作者平时就在仓库根目录跑 exe，仓库又是公开的。现在根目录还没有这个文件夹；查过全部历史（所有分支、远端和标签），`data/`、这几个 AI 工具的文件夹，还有 `config.json`、`secrets.json` 这些运行时文件，从来没有进过任何提交。另一处是 AI 工具留在本机的 `.claude/`、`.agents/`、`.review/`、`.mimocode/`、`.mimocode-project-id`：前两样原来没忽略，每次 `git status` 都挂着；`.review/`、`.mimocode-project-id` 和 `.claude/worktrees/` 原来只写在本机的 `.git/info/exclude` 里，独立克隆吃不到。`exclude` 里那几行没删，还没拿到新 `.gitignore` 的分支，工作树靠它。改完核对过，没有哪条分支上入库的文件落进这些规则里。

提交以后作者说「.gitignore好了之后提交并推送」，Claude 理解成再过一遍、补完整再推，于是对着程序和工具的代码又过了一遍，补了四样。这四样是 Claude 挑的，推之前作者没有逐条看过，推完以后才逐条列给作者，哪条不合适都可以改。`secrets.json` 保存时先写 `secrets.json.tmp` 再改名（`internal/secret/secret.go`），程序在这中间被杀掉，带密钥的临时文件就留在 exe 旁边；所以 `/config.json`、`/secrets.json`、`/tunnels.json` 三条都改成带 `*` 的写法，临时文件和手工备份（`config.json.bak` 之类）一起盖住。`tools/handover-test` 的脚本互相导入会生成 `__pycache__/`，加了 `__pycache__/` 和 `*.pyc`。两份 README 让在仓库根目录用 `go build -o testsend`、`-o testctl` 编测试小工具，Linux 上编出来没有 `.exe` 后缀，原来的 `*.exe` 盖不住，加了 `/testsend`、`/testctl`；这两条只管根目录，`bridge/voicechat/testsend/` 和 `companion/testctl/` 两个源码目录不受影响。还有给 Codex 复审临时放 diff 的 `.codex-review/`。3.1.1 的新更新脚本写的还是 exe 旁边的 `update.bat`，原来那条够用。这一遍同样核对过，没有哪条分支上入库的文件落进新规则里。

本机分支删了六条，删之前逐条核对过内容在别处有。`release-v3.1.0`（`1e44a4b`）和 `v310-fixes`（`556a7e8`）已经在 main 里。`codex/v3.1.0-preflight`（`613771c`）有用的三个提交内容都在 main 里，剩下的 `ea20e53` 是个空提交。三条 `worktree-agent-*`（`116aa38`、`3d9929c`、`cf3a05d`）都在 `v311-fixes` 和 `origin/v311-fixes` 里。括号里是删掉时的位置，要找回来用 `git branch 名字 提交号`。三个子代理的工作树 `.claude/worktrees/agent-*` 也移除了：里面没有没提交的东西；v3.1.1 那一节提醒的 `node_modules` 目录联接和工作树的锁，动手时都已经不在了，逐个查过才删的，主仓库的 `tools/ui-dev/node_modules` 没受影响。联接是 3.1.1 那个会话和它的子代理做完以后自己拆的。锁最可能是 Claude Code 自己解的：子代理工作树的锁上写着加锁进程的进程号，那个进程退出以后，别的 Claude Code 进程做例行清理时会把这种没主人的锁解掉。这个机制是在本机装的 2.1.321 的程序里查到的；这一次具体是哪个进程解的没有直接看到，是按时间推断的（锁在 02:10 到 02:19 之间消失，那段时间 MineDeck 的其他会话都没有动静）。所以锁自己没了不等于有别的会话在动仓库。根目录那个没有后缀的 `minedeck` 文件也删了，是 11 月 1 日 Codex 后台脚本的一段日志误写到这里的。v3.1.1 那一节「要清理的」头两条（子代理的工作树和分支、`v310-fixes` 等三条分支）就是这次办的，不用再做。

现在本机剩十条分支、九个工作树。留着的有：`v311-fixes`（PR #16，工作树目录名还是 `.claude/worktrees/v310-fixes`，里面有一个指向主仓库 `node_modules` 的目录联接）、`website-a`（PR #10）、vibe 的五个工作区、`claude/eager-cerf-07d023`（在线体验，4 个提交）和 `claude/compassionate-bell-d63e72`（局域网连接地址，1 个提交）。最后这两条没合并，也没推到 GitHub，只有这台电脑上有。

清理做完以后，作者让把 `.gitignore` 的改动和这一节提交并推到 main，又自己在 GitHub 仓库设置里打开了「合并后自动删除分支」。这个设置原来是关的，所以合完的分支才会留在上面；用接口查过，现在是开的。以后 PR 合完，GitHub 上的分支会自己删掉，本机的那条还要手动删。这个设置只管以后合并的 PR，所以 PR #15 合完留下的 `v310-fixes` 是作者另外让删的；删之前确认过它整条都在 main 里，没有开着的 PR 用它。现在 GitHub 上只有 `main`、`v311-fixes`、`website-a` 三条分支。
