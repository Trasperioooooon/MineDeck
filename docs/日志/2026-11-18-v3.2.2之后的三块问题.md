### 第一块：`4baa21c`，log4shell 收尾

**先查清了 A。** 在测试文件夹 `MineDeck-l4j` 里用 Java 8 便携版，把上一轮留下的五个服务端之外又下了几个来比：PaperMC 官方接口上还拿得到的 Paper 1.8.8 的 443、444，1.11.2 的 1104、1106，1.12.2 的 1618、1620（都按接口给的 SHA-256 核过）；Spigot 的 1.8.8、1.12.2、1.16.5 是从 getbukkit 的下载站直接拿的现成 jar，不是自己用 BuildTools 编的，来源不是官方，没有可核对的校验值，只在本机绑着 127.0.0.1 跑。每个都看了三样。

第一样，jar 里打包的 log4j。Paper 用的是 paperclip：`server.jar` 只是启动器和补丁，第一次启动时把原版服务端打上补丁，生成 `cache` 里的服务端 jar 再运行，log4j 在生成出来的那个 jar 里。2021 年 12 月以后的构建（1.8.8-445、1.11.2-1106、1.12.2-1620、1.16.5-794）里 Maven 留下的版本记录都是 log4j-core 2.17.0。更早的构建不一样：1.8.8-443（2016 年）和 1.11.2-1104（2017 年）没有版本记录，1.12.2-1618（2019 年）是 2.8.1。1.8.8-444 是 2.8.1，而且它在 Windows 上一启动就报 jansi 的类初始化错误，根本起不来，套不套配置都一样。Spigot 修 log4shell 的办法不是换成修过的 log4j：1.8.8 那个 jar 里是 2.8.1，靠的是它自带的 `log4j2.xml` 里每条格式都写了 `%msg{nolookups}`；1.12.2 和 1.16.5 没有版本记录，自带配置也是这个写法。原版服务端和 Forge 的启动 jar 都没有版本记录。

第二样，套上 Mojang 的配置时控制台和「Done」那一行。Paper 1.8.8-443、445，1.11.2-1104、1106，Spigot 1.8.8（套 17-111），以及 Spigot 1.12.2、1.16.5（套 112-116）都一样：标准输出在「Loading libraries」之后就没了（最多再有几行 log4j 自己报的 ERROR），服务器其实起来了，`logs/latest.log` 里有 Done，往标准输入发命令也照常执行。Paper 1.12.2 的两个构建和 1.16.5-794 套上 112-116 一切正常。也就是说，A 的范围比任务单写的大：不只是 1.7–1.11.2 的 Paper，接管进来的 Spigot 从 1.8 到 1.16.5 都这样。

第三样，不套 Mojang 配置、只带 noLookups 时 jndi 连不连得出去。2.17.0 的四个 Paper 构建都是 0 次；1.8.8-443、1.11.2-1104、1.12.2-1618 各连出去 2 次；三个 Spigot 都是 0 次。

上一轮表里 Paper 1.8.8 套配置那两行的「0 次」其实没测到：那时的脚本 `probe.ps1` 要在标准输出里看到 Done 才发那句 `say`，控制台没输出时根本没发。这次另写了 `probe2.ps1`，两处都看（标准输出和 `logs/latest.log`），看到一处就发，再数连接。重测的结果还是 0 次，结论没变，只是这次是真发了。

**原因。** CraftBukkit 系的控制台不走 Mojang 配置里的那个 Console 输出端，走的是一个名叫 TerminalConsole 的队列：Spigot 三个 jar 自带的 `log4j2.xml` 里都有这个队列，服务端自己起线程从队列里取日志往控制台写。它启动时还会把 Console 类型的输出端摘掉，这一步是我对 CraftBukkit 源码的记忆，这次没有反编译核对。Mojang 的两份配置是照原版服务端写的，里面没有这个队列，控制台就哑了。试过的 Paper 1.12.2（两个构建）和 1.16.5 换了控制台的实现（jar 里带着 TerminalConsoleAppender），不受影响。为了证实，在官方 17-111 上只多加一个 TerminalConsole 队列做了一份试验配置（`tc-17-111.xml`，只在测试文件夹里，不是官方文件）：Paper 1.11.2-1104（没修过的）、Spigot 1.8.8、Paper 1.8.8-445 套上它，控制台和 Done 都回来了，jndi 那句也是 0 次连接。

**定的做法（替作者定的，可以否决）。** 照任务单的参考方向：读得出实际运行的那个 jar 里 log4j-core 是修过的版本，就不套 Mojang 的配置；读得出没修过的、读不出来的，照旧套。

- 怎么读（`internal/inst/log4j_bundled.go`）：只认 jar 里 Maven 留下的版本记录（`META-INF/maven/org.apache.logging.log4j/log4j-core/pom.properties`），不猜。启动的 jar 是 paperclip 时，看它在 `cache` 里生成的服务端 jar，而且要和 paperclip 自己记的 SHA-256 对得上（对不上说明换过 `server.jar` 还没启动过，现在那个不是下次要运行的）；文件夹里有 `paperclip.properties` 的不看，它能改掉补丁说明。用参数文件启动的（1.17 起的 Forge）不看。
- 哪些版本算修过：2.16.0 起，以及给 Java 7、Java 6 的回补版 2.12.2、2.3.1 起，这些版本把「消息里的 `${…}` 展开」整个去掉了。2.15.0 只是默认关掉、还能用配置打开，不算。带后缀的（2.0-beta9、-SNAPSHOT）不算。任务单举的例子是「2.17.1 及以上，或者实测证明这个构建自己挡得住」；Paper 给老版本的最后一个构建都停在 2.17.0，线划在 2.17.1 的话正好把要解决的 445 划在外面，所以按「消息展开去掉了没有」来划。实测过的只有 2.17.0。
- 入口：新建、接管、导入现成服务端、交接包都经过 `addLog4jFlags`，在那里判断；保存 JVM 参数时强制保留的那几条（`log4jFlags`）用同一个判断，不会出现这边不加、保存时又补回去。noLookups 照旧带着。
- 已经建好、已经套着配置、按新做法不该套的：把引用摘掉，不只是提示。理由是这些服务器的控制台现在是哑的，只提示的话人看到了也改不了（配置在的时候保存参数会被补回去，现在不补了，但要人自己去删一条参数才好，没必要）。只摘 MineDeck 自己加的那两条引用，别的参数一条不动，配置文件留在服务器文件夹里不删，`instance.json` 和 `run.bat` 跟着改。这条不分版本段：1.12–1.16.5 里修过的 Paper（比如 1.16.5-794）现在套着 112-116 也没有毛病，一样会被摘掉，为的是一条规矩到底。
- 什么时候摘：程序启动后那一遍（`MigrateLog4j`）；启动服务器时再看一眼，该摘的当场摘、这一次启动就生效。后一处是为了 paperclip：程序启动那一遍时它可能还没生成过服务端（判断不了），开过一次以后才看得出来。
- B（`internal/inst/log4j_migrate.go`）：1.7–1.16.5 的游戏服，启动参数里没有任何 `-Dlog4j.configurationFile=` 的，按版本下载对应的官方配置，`fetchLog4jXML` 核对过 SHA-1 再把引用加在参数末尾。下载不成什么都不动，控制台说清楚；启动这台服务器时再说一声、后台再试，不等下载。用户自己引用了别的日志配置的不动；按新做法不该套的（自带的 log4j 修过了）不套。下载期间只占着「更新 log4shell 防护」的使用登记，不挡开服。
- 判断不了、照旧套着配置的 CraftBukkit 系：带着配置启动时、以及 B 给它补上配置的那一刻，在控制台里说明为什么没有输出、输出去哪看、怎么办（换成修过的构建，MineDeck 会自动摘掉配置）。这类服务端是从 jar 上认的：主类是 `org.bukkit.craftbukkit.*`、又不带 TerminalConsoleAppender；对照过的九个 jar（Paper 六个、Spigot 三个）里，按这条认出来的和实际没有输出的对得上。接管、导入时任务日志里也说一句。

`docs/设计与参考/API.md` 里保存设置和接管那两处的说法跟着改了。

### 第二块：`ecc91bf`，frpc 收尾

认坏 exe 选的是只看 PE 文件的结构（`internal/tunnel/frpcexe.go` 的 `inspectExe`）：开头是不是 MZ、PE 头在不在、节表列出的每一节的数据是不是都在文件里。不运行它，读几百个字节，每次启动隧道都查也不费事。v3.2.2 以前留下的半截 exe 是「文件名对、内容只有前面一段」，后面的节一定缺数据。这条规矩和 Windows 加载程序时的要求是一回事：用例里把测试程序自己截掉一截再真的去启动，只少最后 1 KB 系统也拒绝加载（错误码 193），所以完整能跑的程序不会被误伤。

没有选「跑一次 `frpc -v`」：杀毒软件常拦 frpc（2026-11-12 作者电脑上就被隔离过），启动被拦、被拖慢时分不清是它坏了还是被拦了，容易把好的删掉，每次启动隧道还要多等。没有选「比大小」：OpenFrp 的 frpc 没有可对的大小和哈希，樱花的是用户自己放的。这样认不出来的是大小没变、中间内容坏了的，那要哈希才行。

认出来以后怎么办，按这个 frpc 归谁管分：

- OpenFrp、自定义 frps 的 frpc 是 MineDeck 自己下载、解压的：半截的（含空文件）、不是 Windows 程序的（网页、压缩包）都删掉，接着走原来的下载、解压。只删 frpc 文件夹这一层里文件名像 frpc 的那个 exe，别的文件不碰。删不掉（被占着）就报错说清是哪个文件、在哪，不往下走。文件夹里另有一份好的 frpc 时用好的那份。
- 樱花的 frpc 是用户手动放的，MineDeck 没法替他重新下载：只有半截的才删（文件的开头是个程序、后面缺了，这样的确实没用了），删完照旧提示手动放置；不是 Windows 程序的东西拿不准是什么（可能是下载成了网页、压缩包没解开，也可能是有意放的别的东西），不删，报错里说是哪个文件、怎么回事；读不了的（被占着、被杀毒软件拦着）判断不了，和以前一样交给启动那一步。

OpenFrp 查版本：`internal/dl/dl.go` 加了 `FetchJSONHTTPS`，按当时的 `dl.Client` 抄一份、只把跳转换成 `dl.HTTPSRedirect`，别处的 `FetchJSON` 不受影响。只宣告 TLS 1.3 的 `openfrpHTTPClient` 没动，也没拿它去连接口（那个设置是为了过下载站 CDN 的闸）。自定义 frps 的下载跳转没改：zip 要对上官方 SHA-256，国内镜像可能跳到 http 的地址，限了反而下不下来，注释里写明了。

**已有用例的改动，逐条：** `internal/tunnel/starting_test.go`、`guardport_test.go`、`blocked_test.go` 各改了一行夹具。这三条用例拿随手写的几个字（"fake"、"不会真的运行"）当「一个放好了的 frpc」，现在这样的文件会被当成坏的（前两条是自定义 frps，会被删掉再去下载；后一条是樱花，会报「不能运行」），换成了结构完整的假 exe（新测试文件里的 `fakeFrpcExe`）。断言一个字没动。

### 第三块：c1007f1 复审遗留，五个提交

逐条核实的结果，改了的五条：

- **强退后留下的临时文件没人清**（`95ca321`）。属实：下载、拷本地模组、保存文件、解压 frpc 用的都是随机名的临时文件，正常结束时当场删，被结束、断电时留下，全仓库没有别处清。新包 `internal/tmpsweep`，程序启动后在后台清一遍。往保守里定：只认那几种名字，而且随机的那一段必须全是数字；只清一小时以上没动过的普通文件；不进链接和目录联接；删不掉的（还开着）跳过。范围是程序文件夹这一层、`data`、`cache`、`runtimes` 这几棵树，和每台服务器文件夹的根上及 `mods`、`plugins`、`config` 这几层。用最终代码编的程序在测试文件夹里试过：摆一个两天前的、一个刚写的、一个别人的 `.part`，起一下程序，只有两天前那个被清掉，程序日志里有一句「清掉了 1 个以前没写完留下的临时文件」。
- **替换文件前为刷盘重新打开临时文件，这一下不在重试里**（`dc31c6e`）。属实，用例证实了：临时文件被别的程序打开着、又不许别人写时，重新打开当场报共享冲突，整次保存就不成了，而紧接着的改名遇到同一种占用是会等的。改成遇到共享冲突按改名用的同一张间隔表再试（约半秒）。
- **几处出错路径把带本机完整路径的系统错误原样返回**（`31cc4f6`）。属实：装本地模组的三处（排队拿磁盘名额、建临时文件、打开暂存文件）、地图导入的三处（检测上传的文件时拿不到文件、检测失败后删不掉、单个 NBT 文件打不开）。这些话会进任务日志、提醒和检测结果，局域网里登录的人和 AI 助手都看得到。改成一句说明加原因，原因还包在错误里，`errors.Is` 照旧认得出。原清单同一条的后半句（装伙伴模组改名失败少一句提示）v3.2.2 已经修了。
- **排队等整盘独占名额时取消不了**（`5e037af`，只改了解 Java 这一处）。属实：带 `context.Background()` 的有解 Java、解 frpc、拷本地模组两处、备份和还原四处；原清单说的「装伙伴模组的一条路」现在已经带着 ctx。解 Java 改成跟着任务的 ctx 走，排队时、解压途中取消都会停下，要排队时往任务日志里写一句在等什么、可以取消。
- **同一格时钟里的两次备份同名**（`648e8bb`）。属实，影响很小（要世界极小、标签一样、又落在时钟的同一跳里，而且两份内容本来就差不多）。取名字时这个名字已经有文件了就等一毫秒重取，最多等半秒，时钟一直不走就报错，不盖已有的备份。名字的格式没变。

没改的，按轻重排：

- **排队取消不了的另外几处，和界面上「在排队」的提示。** 解 frpc：启动隧道本身没有取消的入口，要先给 `Provider.EnsureFrpc` 加 ctx，`extractZipFlat` 的两个参数的写法已有用例在用。拷本地模组：要改 modcart 的接口和操作层，另一位执行者这一轮正在改那一带。备份和还原：`CreateBackup`、`RestoreBackup` 现在都不带 ctx。建议下一轮一起做：给这几处接上 ctx，`diskguard.Options.OnWait` 已经有了，往任务日志或控制台里写一句就是提示；界面上要不要另外显示「在排队」等作者定。

- **换地图卡住留下封锁时改不了内存、Java 和定时任务。** 读代码属实：保存启动设置、保存实例设置都先调 `UseWorldInstance`，有封锁时它直接返回封锁的原因。这是有意加的登记，放不放开是取舍，等作者定。如果放开，这几样只写 `instance.json` 和 `run.bat`，不碰世界目录，技术上可以另走一条不查封锁的登记。

- 清临时文件没覆盖到的：备份文件夹里的 `.backup-*.tmp`（不是 `.minedeck-` 开头的名字，没敢动）；整合包导入时下到更深的子文件夹里没写完的。

**Go。** 最后在分支头上跑的：`gofmt -l ./internal ./cmd` 没有输出；`go build ./...`、`go vet ./...` 通过；`go test -count=1` 跑了 inst、tunnel、dl、tmpsweep、atomicfile、modcart、worldimport、java、web、ops、ops/catalog、transfer、companion、musicshare 和 cmd/minedeck，十五个包都是 ok。没有跑全量 `go test ./...`，界面用例没跑（这一轮没有改界面）。

**第一块的实测**（测试文件夹 `MineDeck-l4j`；服务端的 `server.properties` 都写 `server-ip=127.0.0.1`、`online-mode=false`；本机监听只绑 127.0.0.1:38389；发的是 `say ${jndi:ldap://127.0.0.1:38389/x}`，没有向外发任何 jndi 请求）。各构建单独起服的对照见上面「先查清了 A」，原始记录在测试文件夹的 `probe2-summary.log`。

用真程序走的那一遍：照旧版的写法手摆了五台服（`setup-a2.ps1`），两台 Paper 1.8.8-445（一台照 v3.2.2 带着 17-111，一台照 v3.2.0 带着 112-116），一台只带 noLookups 的原版 1.8.9，一台只带 noLookups 的原版 1.12.2，一台只带 noLookups 的 Paper 1.11.2-1104（没修过的老构建）。先用 v3.2.2 编的程序跑一遍当对照，再用这条分支编的程序跑不联网和联网两遍（`e2e-a2.ps1`，从网页接口启停、发命令、读控制台）。

- v3.2.2：两台 Paper 1.8.8 的状态一直停在 starting（控制台只有一行服务器输出，`logs/latest.log` 里有 Done），0 次连接；1.8.9 和 1.12.2 状态 running，各连出去 3 次；Paper 1.11.2-1104 running，2 次。
- 这条分支，不联网（把这个进程的代理指到不通的本机端口）：两台 Paper 1.8.8 在程序启动后就摘掉了引用（不用下载），起服后状态 running、控制台 180 多行、Done 认出来了，0 次连接，`instance.json` 和 `run.bat` 里都没有引用了，配置文件还在。另外三台什么都没改，照样能开、状态 running，控制台里说了「没有套上 Mojang 的日志配置，等于没防；这次……也没下载成……服务器照样能开」，连接数和 v3.2.2 一样（3、3、2）。

**反向验证**，每处都是把产品代码改回去（或去掉关键的一步），确认新用例失败，再改回来，改回以后按文件哈希核对过和改之前一样：

## 没做完或没验证的

- **A 只解决了一半。** 自带的 log4j 换成了修过的版本的（2021 年 12 月以后的 Paper 构建）解决了。Spigot 从 jar 上认不出修没修过（log4j 还是 2.8.1，靠的是它自带的配置），没修过的老 Paper 构建更不能不套，这两类照旧套着 Mojang 的配置，控制台照旧没有输出、MineDeck 认不出启动完成，只是多了一段说明。而且范围比以前知道的大：Spigot 的 1.12–1.16.5 也这样。
- **B 有一个副作用。** 给当初没套上配置的服务器补配置时，如果它是上面说的那两类，补上以后控制台就哑了（实测的 Paper 1.11.2-1104 就是）。没修过的服务器本来能被远程利用，补上是对的；但修过的 Spigot 补上以后只有坏处。从 jar 上分不出这两种，照任务单「判断不了的保守处理」办了。
- paperclip 的服务端一次都没启动过时（刚导入的包）判断不了，照旧套配置；1.7–1.11.2 的第一次启动控制台没有输出，停掉再启动时才会摘掉。新建不受影响（新建的版本列表从 1.12.2 起，试过的 Paper 1.12.2、1.16.5 套着配置也正常）。
- 修过的版本那条线里，实测过的只有 2.17.0；2.16.0 和两个回补版是按 log4j 的发布说明划的。Paper 的 1.9.4、1.10.2 没试，混合端（Mohist 这类）没看。只在 Windows、Java 8 上试过。
- 实测的旧服是手摆的 `instance.json`，没有走接管、导入的界面；各入口加什么参数只有用例。没有在真窗口里看过。
- Spigot 的三个 jar 来自第三方下载站，不是自己编的，不保证和 BuildTools 现在编出来的一样。
- 第二块：这台电脑上没有现成的 frpc，没拿真的 OpenFrp、樱花、frp 的 frpc 试过结构检查（没有为这个去下载：以前在这台电脑上 OpenFrp 的 frpc 一解压就被安全中心隔离）；用的是测试程序自己和几个系统自带的程序。没有真的连过 OpenFrp 的接口。
- 第三块：刷盘重试没有在真的杀毒软件、同步盘底下试；装本地模组的三处报错里，建临时文件失败、排队拿名额失败这两处造不出来，没有用例；没改的几条见上面。
- 没有跨家复审。
