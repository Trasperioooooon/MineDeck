# 阶段 22 返工 1：Mac 上挂的 9 条测试（A93）

## 要做什么

清账阶段 22 交上来以后，主会话借 GitHub 的 macOS 机器（`macos-latest`，Apple 芯片）在 `07dd1dd` 上跑了一次全量 Go 测试：44 个包里 41 个过，`internal/inst` 5 条、`internal/tunnel` 3 条、`internal/update` 1 条还挂着。主会话的返工单要求只改测试、产品代码不动，让这 9 条在 Mac 上测到它们本来要测的东西，而不是在 Mac 上一跳了事；都改好以后，CI 的 `go-macos` 作业在 `go build` 后面加一步 `go test ./... -count=1`。

## 做了什么

一共五处，全是测试和 CI，产品代码一行没动。

**只读文件挡不住替换。** `TestAdoptRollsBackOnFailure` 和 `TestAdoptLeftoverClearsMarkerAndRestoresOnFailure` 要让接管在写 run.bat 那一步失败，看前面动过的文件能不能全部恢复。原来的造法是把 run.bat 设成只读：Windows 上带保护的原子写（`atomicfile.WriteProtected`）看到只读就不替换；Mac 上改名替换根本不看文件自己的权限位，`chmod 0444` 挡不住，接管照常成功，测试就挂了。返工单提的两个办法都会让失败来得太早：把 run.bat 换成文件夹的话，接管一开始给要动的文件拍快照（`snapshotFiles`）就拒绝了，什么都还没动；把所在文件夹设成只读的话，去掉创建记号、备份、建临时文件都会先失败，而且 Windows 上文件夹的只读属性不挡写入。这两种情况下面的「恢复原样」检查不测什么也会过。

所以改成按平台各用各的「用户把文件保护起来」：新加的 `makeUnreplaceable` 在 Windows 上照旧设只读（`unreplaceable_windows_test.go`，和原来一字不差），在 Mac 上给文件加「不可更改」标记（`chflags uchg`，Finder 简介里勾「已锁定」就是它，`unreplaceable_darwin_test.go`），只加标记、不动权限位，快照和备份照样读得出来。Mac 上改名盖掉带这个标记的文件会被系统拒绝，这一点有现成的证据：`props_atomic_test.go` 里原文件被占着的那一段，Mac 上的 `lockExclusive` 就是靠这个标记让保存失败，那条在 Mac 的 CI 上是过的。两条用例另加了一句检查：任务日志里要有「原来的 run.bat 另存为」，也就是失败确实发生在备份之后，以后谁的改动让失败提前了，测试会红，不会悄悄空过。

**Windows 路径写法。** `TestCheckAdoptDir` 里「整个磁盘」和「结尾带分隔符」两项原来写死反斜杠，在 Mac 上一个成了相对路径、一个成了名字里带反斜杠的不存在的文件夹。改成按本机分隔符拼：Windows 上还是 `C:\` 和 `…\`，Mac 上是 `/` 和 `…/`，`/` 在产品代码里走的正是「不能选整个磁盘」那一支。`TestAdoptNeoForge` 断言生成的 run.bat 里参数文件写成反斜杠；产品代码（`launchArgs`）用 `filepath.FromSlash`，Mac 上生成的也是 run.bat（还没有 run.sh），里面是正斜杠，期望值改成同样按 `filepath.FromSlash` 拼。

`TestRealPathOfMissingDir` 里有两处 Windows 才有的形状。一处是「一级都打不开时原样返回」用的 `Q:\no\such\drive`：Mac 上这是个相对路径，会被接到当前目录后面。Mac 上没有盘符，根目录 `/` 总打得开，绝对路径碰不到「一级都打不开」，最上一级就不在的路径会原样接在 `/` 后面，结果也是原样，Mac 上改测 `/minedeck-no-such-dir/no/such`。另一处是 8.3 短名：Mac 上没有短名，同一个位置的另一种写法是经符号链接绕进来，于是把「上层换了写法」抽成 `otherSpelling`，Windows 上照旧取短名（盘上没开短名就跳过），Mac 上在临时目录里建一个指向它的符号链接，后面「不存在的目录按真实路径比」「列表里的服务器目录用另一种写法、已经不在了，选上层照样认得出」两项检查两边共用。

**DPAPI。** `tunnel` 三条（`TestLoadWrongShapeIsCorrupt`、`TestLoadMissingTunnelsKey`、`TestNoDuplicatesThenSaveLeavesNoBackup`）在 Mac 上报的是「凭据：加密失败」。返工单建议把阶段 12 的包内变量 `sealSecret` 换成假的加密，但这条路不通：`sealSecret` 只在读 tunnels.json 时给旧版明文凭据加密（`load`），这三条的出错点是新增、修改自己调的 `secret.Seal`（`Add`、`UpdateOpt`、`PatchOpt`），它们在查「读没读成」之前先加密凭据，Mac 上一加密就失败，走不到要测的那一步；`secret` 包里也没有给测试换掉加密的口子。要在 Mac 上测「带凭据的新增」就得在产品代码里开一个口子，这一轮不做。改法是只在测试里绕开：新加 `anyTunnel`，Windows 上就是原来的 `openfrpTunnel`，Mac 上换成不带凭据的自定义 frps（空凭据不加密）。这三条测的是「没读成时新增、修改报 LoadError」和「没撞号时保存不留备份」，凭据不是要测的东西。

**Mac 不能在程序里更新。** `TestLatestChannelStillNeedsChecksums` 在 Mac 上，`Apply` 一进来就拦下「Mac 版还不能在程序里自动更新」，走不到「没有校验和要拒绝」。前半段「查得到、没有校验和」两边照旧测；后半段在 Mac 上改成断言拦下的就是 `errNoSelfUpdate`，Windows 上照旧断言 SHA256SUMS 那句。

**CI。** `go-macos` 作业在 `go build` 后面加了 `go test ./... -count=1`；作业上面那两行注释原来写着「不跑 go test，Mac 上已知有 6 个包会失败」，加了这一步以后就不对了，跟着改成现在的说法。

## 验证了什么

都在 Windows 上：改过的文件 `gofmt -l` 没有输出；`go vet ./...` 和 `GOOS=darwin GOARCH=arm64 go vet ./...` 都没有提醒；按 darwin/arm64 把 `inst`、`tunnel`、`update` 三个包的测试编出来（只编不跑）都成功；`go test ./internal/inst/ ./internal/tunnel/ ./internal/update/ -count=1` 三个包都过，9 条用例单独加 `-v` 跑都是 PASS，`TestRealPathOfMissingDir` 在这台机器上没有跳过（盘上开着 8.3 短名，短名那一半真的跑了）。本阶段没有要求反向验证的条目。

## 留给下一位的

- Mac 上的 `atomicfile.WriteProtected` 其实不保护只读文件：非 Windows 的替换直接 `os.Rename`，文件的只读权限位不起作用（`replace_other.go`），和它注释里「目标只读时当场拒绝」对不上。Mac 用户把 run.bat 设成只读，MineDeck 照样会盖掉它。要不要管、怎么管，等作者定。
- Mac 上生成的仍是给 cmd 用的 run.bat，接管时选了相对路径报的「请填完整的路径」，括号里举的例子也是带盘符的 Windows 写法。属于 Mac 版后面的阶段。
- `TestCheckAdoptDir` 里「路径全改成大写也认得出已经在列表里」那一项在 Mac 上能过，靠的是 Mac 默认的文件系统不分大小写；放在区分大小写的卷上会失败。CI 的机器是默认卷，眼下不影响。
- 要在 Mac 上测「带凭据的新增、修改」，得等钥匙串（D01）做好，或者在产品代码里给 `secret.Seal` 开一个只给测试用的口子。
