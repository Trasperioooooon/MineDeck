- **启动迁移在官方日志配置已在盘上时直接跳过下载**：上一轮 `internal/inst/log4j_migrate.go` 的 `fetchAndPublishLog4jXML` 总是建空临时目录去调 `fetchLog4jXML`，绕开了目标文件已在盘上且校验通过时的免下载分支，导致离线机器上缺引用（补引用）或引用错版本（换引用）的服务器就算文件夹里已有官方配置也修不上。现改为在 `fetchAndPublishLog4jXML` 开头先用 `log4jXMLOnDisk` 看一眼实例目录，已经是官方那份就直接返回；同时把原函数拆成「下载到临时目录」的 `stageLog4jXML` 和「拿着路径锁不覆盖落盘」的 `publishLog4jXMLIfAbsent` 两个短函数。在 `internal/inst/log4j_test.go` 新增 `TestMigrateLog4jSkipsDownloadWhenOfficialOnDisk`，保留真 `fetchLog4jXML`、把下载前缀指到计数且恒回 404 的 `httptest.Server`，确认补引用和换引用两条路都以 0 次网络请求完成迁移。
- **同一真实文件夹既经联接登记又在存放根下时采用根下路径（做法由审核方选定）**：A08 把 `app.InstanceDirs()` 挪到 `app.InstanceRoots()` 前面后，若真实文件夹本就在 `ServersDir` 等存放根下、同时又经目录联接登记在 `InstanceDirs` 里，`i.Dir` 会记成联接路径；「连同文件删除」调 `os.RemoveAll(i.Dir)` 只拆掉联接而留下存放根里的真文件夹，下次启动又被扫回来。按审核方选定的方案修改 `internal/inst/inst.go` 的 `NewManager`：「登记的优先」只管两个不同文件夹撞名的情形；当存放根扫描遇到已经由 `InstanceDirs` 加载过的同一个真实文件夹时，把 `i.Dir`（及指向它的 `KeptDir`）改成存放根下的真实目录。`internal/inst/adopt_registered_test.go` 的 `TestForgetRegisteredAlias` 恢复断言 `i.Dir == real`，并新增 `TestDeleteRemovesRootDirWhenRegisteredViaJunction` 验证连同文件删除后真目录消失、新建 `Manager` 重载不再复活。
