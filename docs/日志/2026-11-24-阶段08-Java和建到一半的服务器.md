## 做了什么

**阶段 07 的尾巴（`90087ef`、`863317e`，A30）。**

复审方把三处保护数据的分支改坏，现有用例全绿，这次各补了一条用例：补清删服记录时 `cart.json` 存不进去，什么都不删（暂存的文件、删服记录、`cart.json` 都原样）；已有的删服记录读不出来时，读不出来 `cart.json` 那段时间再删一台要报错，不能拿只有这一台的新记录把它盖掉；读得出来时删服或点「清空」，`cart.json` 存不进去，暂存的文件不能先删。让 `cart.json` 存不进去的办法是在它的临时文件的位置上放一个文件夹，参考了复审方仓库外的探针，没有原样搬，按功能起名放进了 `forget_test.go`。

草稿清单的目标记号原来没有时间，补清是按「记号还是这个名字就清」做的。补清被推迟、或者补清成了删服记录却删不掉的时候，同名新建的那台刚记上的目标会被清掉，那台的详情页就不出「新建时挑的 N 项还没装」。现在 `cart.json` 里多一个 `draftInstAt`（`omitzero`，老文件没有，读进来是零值，按删服之前算），补清时和清单条目一样按时间比，只清删服之前记的。有一个容易漏的地方：原来 `SetDraftInst` 遇到已经是这个名字就直接返回，补清推迟期间旧记号正好是同一个名字，新记的就根本没写进去。现在同一个名字也重记时间。内存里的记号和时间合成一个小结构 `draftTarget`，`writeLocked` 收它；`clearAllLocked` 原来要调用方算好记号再传进来，改成传「要不要清指着这台的记号」，判断挪了进去；`staged.go` 的 `without` 和 `modcart.go` 的 `withEntry` 做的是同一件事，并成了 `withEntry`。`retryLoadLocked` 的注释改准了：补清删不掉记录时会在锁里重试一会儿（Windows 上最多约半秒）。

删服务器的接口清不掉这台的待装清单时返回 `{note}`，界面原来不看返回值。现在删服照常算成功，另给一条带「详情」的提示，正文是一句短话，「详情」里是后端的原话。仿真后端加了 `modCart.forgetFail` 开关。新建向导在读草稿清单偶发失败时原来不记目标，现在 `draft === null` 时也记：不知道是不是空车，后端在草稿清单真是空的时本来就不记，漏记的代价是那台详情页没有横幅。`API.md` 删服务器那一行写明待装清单跟着清、读不出来时记下来以后再清、清不掉时 `data` 是 `{note}`；待装清单那一段提了 `cart-pending-removals.json`。

**A34 卸载和换 Java 互斥（`98fa995`）。**

`RemovePortable` 拿着安装锁 `ensureMu`，查完有没有服务器用着这套 Java 再删，查和删之间另一个页面能把服务器换成它。任务单让复用 `remove.go` 里「正在卸载」的标记和 `ErrBusy`、别另起一把锁。读下来，文件里现成的「正在卸载」只有盘上的 `.incomplete` 记号，它在查完以后才写，而且也表示「装到一半」；把它挪到查之前，卸载被拒时就得把它删回去，删不掉的话这套 Java 就变成「没装好」。所以没有用它，而是在内存里记：`removing` 是正在卸载的大版本，`switching` 按大版本记有几台服务器正在换成它，两边都是原子量。卸载先记上自己再看有没有人在换，换 Java 先记上自己再看是不是正在卸载，原子操作有统一的先后，两边不会都没看到对方。换 Java 这边没有去等 `ensureMu`：那把锁在下载别的大版本的那几分钟里一直占着，等它的话连换一套现成的 Java 都得干等。

java 包加了 `UsePortable(major, set)`，操作层 `instance.java.set` 的两处 `SetJava`（现成的直接换、下载完再换）都经新的 `setJava`：要换上的是便携 Java 时用 `UsePortable` 包住，正在卸载回 409「这套 Java 正在卸载」；换的途中卸载报 `ErrBusy`，它的说法加上了「有服务器正在换成这套 Java」，仿真后端同步。本机装的 Java 不经 MineDeck 卸载，换它不受影响。

**A36 下载还没完时再保存（同在 `98fa995`）。**

下载便携 Java 再换上的任务按服务器和大版本记在 `javaDownloads` 里，同一台、同一个版本的还在跑时再保存一次，返回已有任务的编号。任务单写的是「同一个大版本」，这里多加了「同一台服务器」：别的服务器要同一个版本，下好了要换上的是它自己，借用别人的任务它就永远换不上了；它照样建自己的任务，安装锁保证文件不会重复下。任务结束前先从表里去掉，任务一显示结束，再保存就是新的一次。界面本来就是拿返回的编号跳任务页，不用改。下载和换上拆成了 `downloadAndSetJava`，`java.Ensure` 经包内变量 `ensureJava` 调，测试里换成不联网、能停住的函数。

**A35 Adoptium 连不上（`966c132`）。**

原来清华镜像目录连不上时，根本没问过 Adoptium，于是 Adoptium 官方源那一步按默认时限问 jre、再问 jdk，各两轮三十秒，最坏两分钟才改用 Mojang 运行时；下载源选「官方」时也一样。现在加了 `adoptiumDown`：连接被拒、DNS 解析失败、超时这类网络错误才算「连不上」，回了话的（404、5xx、回的不是 JSON）不算。官方源那条路问接口也用 `adoptiumIndexWait` 的短时限（和问校验值清单共用 `fetchAdoptiumJSON`，清单都很小），jre 那一问连不上就不问 jdk，直接报连不上；问校验值的两问里第一问连不上也不问第二问。`Ensure` 的前两条路拆成 `fromAdoptiumBuilds`，看到连不上就在任务日志里写「Adoptium 的接口连不上，直接改用 Mojang 官方运行时」。顺带一个行为变化：原来校验值的两问只要都没要到（包括 404）就当成连不上、跳过官方源，现在只有网络错误才跳过，接口回了话就照常试官方源。

**A37 Paper 旁边的原版 jar（`1c418d3`）。**

`mixedServerNote` 原来对 Fabric、Forge 这些加载器旁边的原版 jar 不提示，Paper 系不在里面。现在 Paper、Purpur、Folia、Leaves 预填在前、旁边只多一个原版 jar 时，提示换成「旁边的 server.jar 是原版，没有用它。」（文件名按实际的写）。原版 jar 有两个、或者和别的核心放在一起（Paper 加 Fabric）照旧提示不止一种。启动脚本点名用原版 jar 的，预填的就是原版，也照旧提示。

**A38 没建完的文件夹（`bce7852`）。**

第 1 点先核实，属实：新建、导入现成服务端、导入交接包三条路都是先写创建记号，建完（`completeCreate`、`FinalizeCreate`）才 `RememberRoot`。三条路写记号都经 `WriteCreatingMarker`，现在由它先把所在的存放位置记进配置再写记号，建完时那两处 `RememberRoot` 去掉了。建不成时这个位置也留在配置里，下次启动多看一个文件夹而已。

第 2 点：`CreatingLeftovers` 遇到有 `instance.json`（或移出列表留下的 `.bak`）的文件夹会去掉残留的记号。原来的意图是已登记的服务器不该留着记号，不然以后它的 `instance.json` 没了，会被当成半成品列出来、能被删掉。现在列表只读，这件事挪到启动时做（`NewManager` 末尾调 `clearStaleCreatingMarkers`），点删的时候照旧顺手去掉。两处共用同一段扫描（`scanCreatingLeftovers`，已登记的交给回调），文件里那几处链接判断原样没动，也没新写。原来有一条用例断言「列表时去掉记号」，按新行为改成断言「列表不动记号」，启动时去掉另起一条用例。`API.md` 和 `instance.creating.list` 的说明跟着改。

## 留给下一位的

- `app.addRoot` 是在 `c.Roots` 上原地 `append`，而 `RememberInstanceDir` 特意避开了这种写法（`GetConfig` 给出去的副本和配置共用底层数组）。现在 `RememberRoot` 在建服开头就调，碰上的机会多了一点，没改，记在这里。
- 卸载报忙（`ErrBusy`）现在一句话同时说「正在安装或卸载」和「有服务器正在换成这套」，分不出是哪一种；要分开得另起一个错误。
