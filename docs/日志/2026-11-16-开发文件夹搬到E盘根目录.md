## 做了什么

先把这台电脑上记着旧路径的地方摸了一遍。会跟着路径走、搬了不改就会坏的有这些：git 的工作树互相指向（主检出里 `.git\worktrees\*\gitdir` 和每个工作树的 `.git` 文件都是绝对路径，十个工作树里五个在 `.claude\worktrees` 下跟着搬，五个是 `~\.vibe\worktrees` 下 Vibe 的长期工作树不动）；Claude Code 按工作目录起名的项目文件夹（`~\.claude\projects\E--Archive-files-MineDeck`，记忆和会话记录都在里面，另有五个 `…--claude-worktrees-*`）；`~\.claude.json` 里按路径记的项目条目；Claude 桌面应用数据目录（`%LOCALAPPDATA%\Claude-Data\claude_pzs8sxrjxfjjc`）里每个会话的记录、「MineDeck」预设、预览服务器偏好、工作树清单；仓库里被忽略的 `.claude\launch.json`；`D:\MineDeck-ux\rig` 下从仓库复制过去的两个走查脚本。计划任务、环境变量、快捷方式、Windows Terminal、防火墙规则里都没有旧路径。

这个会话自己的工作目录就在要搬的文件夹里，桌面应用开着时又会随时改写它自己的那几个文件，所以搬家不能在会话里做。写成了一个脚本，作者完全退出 Claude 以后双击运行：

- `E:\Archive_files\minedeck-move.ps1`，由同目录的 `MineDeck搬家.bat` 启动（pwsh 7），`MineDeck搬家-撤销.bat` 带 `-Undo` 反方向搬回，`-DryRun` 只检查不改。脚本放在要搬的文件夹外面，没进仓库。
- 顺序是：先检查（旧文件夹在、新位置不存在、没有 claude 进程、目标项目文件夹不存在、要改的配置里还没有新路径的键），把要改的文件复制到 `~\.claude\backups\<时间>-minedeck-move\`，然后同盘改名。改名失败就停下、删掉刚建的备份，什么都没动；改名成功后再修 git、改 Claude 项目文件夹的名字、改配置里的路径，每一步出错都记下来接着做，最后统一报告。
- git 用的是在新主检出里跑 `git worktree repair <搬进去的五个工作树的新路径>`，它同时把外面五个工作树的 `.git` 文件改指到新主检出。搬前搬后对比每个工作树的 HEAD、分支、`git status --porcelain` 的哈希和 stash 条数。
- 配置里的路径用一个正则换：只认完整的 `E:<分隔符>Archive_files<分隔符>MineDeck`，分隔符可以是 `\`、JSON 里转义的 `\\` 或 `/`，大小写不限，后面不能紧跟字母数字、点、横线（`E:\Archive_files` 本身、`MineDeck-old` 这类不碰）；原文全小写的（桌面应用记的规范化键）换成全小写。按原来的编码和 BOM 写回，先写临时文件再覆盖；JSON 文件改前能解析的，改后解析不了就不写。撤销用同一套逻辑反方向换，所以搬完以后新增的内容也能一起换回去，不用拿备份硬盖。

仓库里改了五行，都是给测试和走查用的、写死了旧路径的地方：`tools/ux-walkthrough/drive.js` 和 `consolewatch.js` 里 playwright 的路径，`tools/ux-walkthrough/共同规则.md`、`tools/handover-test/任务说明.md`、`tools/handover-test/给测试AI的提示词.txt` 里「不许碰真仓库」那条的路径（不改的话搬完以后这道防线就形同虚设）。`docs/日志`、`docs/评审-*`、`docs/research` 和 `.claude/archive` 里的旧路径是当时的记录，没改。

Claude 的记忆里改了三处还在当作操作说明用的旧路径（`minedeck-project`、`ui-dev-tests-in-worktree`、`vibe-worktree-layout`），新加一条 `minedeck-moved-to-e-root` 记这次搬家。记忆文件夹本身靠脚本改名跟着走。

故意没改的：以前会话 .jsonl 的内容（几百兆的历史，Claude 按文件夹名找会话，不靠里面的 cwd 字段）；Codex（`~\.codex\config.toml`、`.codex-global-state.json` 的 MineDeck 工作区）、Grok、Vibe 的信任目录，这是信任决定，第一次在新位置用时它们会问；`~\.claude\settings.json` autoMode 环境描述里写死的 `compassionate-bell-d63e72` 工作树旧路径，那是作者的权限配置；`~\.claude\history.jsonl` 里一条以旧路径为项目的输入历史。

提交：仓库里那五行、`docs/现状.md` 和这份日志在同一个提交里，推到了 main。脚本本身在仓库外面，最终版的 SHA256 是 `4F30CF11…0EF5FE`（`E:\Archive_files\minedeck-move.ps1`）。

## 谁做的

主会话：Claude 桌面应用，Opus 5.5（`claude-opus-5-5`），写脚本、搭演练、改仓库和记忆。中途请顾问（advisor）看过一次方案，它建议不改以前的会话记录内容、不动信任目录和 settings.json、改仓库里那几道防线，都照做了。

跨家族只读复审：Codex CLI，两轮，都是把脚本、演练脚本和真实机器上的只检查输出复制到临时目录、用只读沙箱审（`codex exec -s read-only --disable multi_agent`，任务单从 stdin 给），两轮退出码 0、stderr 空，审完核对过临时目录里的文件哈希没变。客户端记录的模型都是 `gpt-6-astra`；第一轮没传思考档，沿用了 `~\.codex\config.toml` 现在的默认 `xhigh`（作者 11-14 指定的是 max，配置里的默认后来变成了 xhigh，这里没去改配置）；第二轮用 `-c model_reasoning_effort="max"` 单次指定，记录是 `max`。服务端实际型号未确认，Codex 自己报的是「GPT-6，具体变体未提供」。两轮它都说一开始列文件时工具默认目录不对、看到了临时目录外的文件名，后面的读取都限定在指定目录。

第一轮提了九条。主会话核对真实数据后，下面这些都加了防护：只差大小写的几种旧写法换完会撞成同一个 JSON 键（检查阶段比对，撞了就中止）；检查和写入之间别的程序改了文件（确认后再查一次 claude 进程；检查时记下读到的字节的哈希，备份后不一致就在改名前中止；写回前对同一份字节再比一次，不一致就不改那个文件）；路径右边界会误伤「MineDeck 副本」「MineDeck备份」这类同级名字（改成后面只能是分隔符、引号、反引号或结尾）；同时开两个窗口（加了互斥量）；git 核验不查退出码、stash 只比条数、`git status` 会刷新索引（都改了）；看着像但没匹配上的 Claude 项目文件夹给出提示。没改的：撤销仍是反方向替换而不是拿备份覆盖，因为搬完以后新增的会话和配置也要一起换回去，拿备份硬盖会丢掉它们，备份留作最后手段；混合分隔符、JSON 的 `\/` 写法、非 UTF-8 文件，真实文件里都没有。第二轮对这些改动的结论是「各项改动基本按意图生效，没发现新问题」，只说并发窗口没有完全消除；主会话随后把哈希比对挪到了上面说的位置（检查时的字节对备份、写回时的同一份字节对备份），这一步没有再送审。

## 验证了什么

在临时目录搭了演练环境（`reh-setup.ps1`）：一个假仓库，带两个搬进去的工作树（一个有未提交改动、一个分离头）、一个外部工作树、一条 stash、一个中文文件名；假的 Claude 主目录（要改名的三个项目文件夹，加上父目录和 `MineDeck-old` 两个不该动的）；各种写法的假配置（正斜杠键、JSON 转义、全小写键、带 BOM、CRLF、`MineDeck-old` 诱饵）。在这上面跑了：

- `-DryRun`：每个文件的命中数和手算的一致，诱饵都没命中。
- 正式搬：`git worktree list` 四个都在，外部工作树的 `.git` 改指到新位置，未提交改动和 stash 都在，三个项目文件夹改了名，父目录和 `MineDeck-old` 没动，配置都换成新路径。
- `-Undo`：搬回后八个配置文件和原件逐字节一致（含 BOM 文件和 CRLF 文件），工作树和项目文件夹都回到原名。
- 按复审改完以后，用和 .bat 一样的方式（独立的 pwsh 进程）把正搬、撤销、锁文件重跑了一遍，结果同上；另外试了大小写变体（检查阶段中止）、第二个窗口（直接退出），都是退出码 2、什么都没改。备份后发现文件被改过那条路径没能在演练里触发，只读过代码。
- 锁住仓库里一个文件再跑：停在改名那一步，退出码 3，文件夹和配置原样，刚建的备份删掉了。
- 目标已存在：一开始就拒绝，退出码 2。

在真实机器上跑了 `-DryRun`（只读）：工作树主检出 1 个、跟着搬 5 个、外部 5 个，全部干净；要改名的 Claude 项目文件夹 6 个；要改的文件 48 个，命中数和之前手查的对得上（`.claude.json` 8 处，即 6 个 MineDeck 项目键加 2 个仓库路径值，父目录 `E:/Archive_files` 那条不动；`git-worktrees.json` 37 处；桌面会话记录 41 个、418 处，另外 2 个工作目录是 `E:\Archive_files` 本身的没碰）。收紧右边界以后，又拿一个不设右边界的宽松写法在七个非会话文件上数了一遍，两边的个数完全一样，说明收紧没有漏掉要换的地方；会话记录里比收紧前少换的那 1 处，是某段正文里的提及（后面跟的不是分隔符或引号），具体是哪个字符没去查。
