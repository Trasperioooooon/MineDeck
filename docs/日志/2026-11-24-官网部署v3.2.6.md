# 2026-11-24 官网部署 v3.2.6（Claude 写）

## 要做什么

v3.2.6 发出以后，作者说 minedeck.cn 也更新一下，并且想把这件事交给 agy 里的 Gemini 4 Neon（xhigh）去做，看它做得怎么样，做得好以后就都交给它。

## 交给 Neon 没成

主会话在仓库外的部署文件夹里写了任务单（只跑一次发布脚本、不先干跑，失败就停下汇报，最多跑一次只读的 `-VerifyOnly`，不手动登服务器、不切版本、不删旧目录，不改部署脚本，在仓库里不提交），准备用 `agy -p … --model gemini-4-neon-xhigh --dangerously-skip-permissions` 起它。这一步被 Claude Code 自动模式的安全分类器拦了，理由是「削弱监督」：带免确认参数起一个外部代理往生产服务器发布。agy 的无头模式不带这个参数连读文件都会被拒，所以没有更窄的做法。主会话没有绕，把启动命令写成部署文件夹里一个能双击的脚本，交作者定；作者选了让主会话直接跑。任务单和双击脚本留在部署文件夹里，以后想试 Neon 时可以直接用。

## 做了什么

照惯例跑仓库外的发布脚本（`publish.ps1`，不带参数，没有先干跑），官网源码取本机 main 检出，当时在 `78379cb`。一次过：

1. 从 GitHub 拉版本数据，写进 `website/data/`（四个文件随这份日志提交）。
2. 构建、检查产物：145 个页面、11262 处内部引用没有失效的；镜像链接和 Release 文件各 100 个，一一对得上；占位字样都是 0 处。
3. 镜像同步：100 个文件里 96 个已有且对得上，下了 v3.2.6 的 4 个（17.7 MB，3 秒）。
4. 上传新镜像文件和官网包（189 个文件、3.37 MB），服务器按清单把镜像全量核对一遍，从 `20261123-153716` 切到 `20261124-141032`。
5. 线上核对：从本机取回全站 188 个文件、约 68 秒，没有问题；首页页脚是「© 2026 MineDeck 贡献者 · AGPL-3.0」，备案号照旧；100 个镜像链接状态和大小都对；服务器经自己的 Nginx 把 v3.2.6 的 4 个文件完整下载一遍，SHA-256 都对。

主会话另外从外面只读核对：`https://minedeck.cn/data/latest.json` 的稳定版是 v3.2.6，SHA-256 和大小和 GitHub 附件一致；首页写的是 v3.2.6；`dl.minedeck.cn` 上 v3.2.6 的 `MineDeck.exe` 回 200、大小 18,354,688 字节。
