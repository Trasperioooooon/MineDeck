## 清账：Gemini 第二批的审核

审核记录、返工单和执行者汇报在清账工作树和 Gemini 工作树的 `.claude/tasks/` 下，不进仓库，这里只写结论。

阶段 14、16、17、19（v3.2.8）前一天晚上到今天凌晨就审完了：14 和 17 各返工一轮，16、19 一次过。17 的复审交给 agy 里的 Gemini 4 Carbon，第 6 部分撞了它的额度，作者说放着，额度回来以后续上，补出来的三条也进了返工单。

第二批里，**阶段 23**（文档中心补齐 27 篇英文）主会话抽查四篇的 frontmatter、一篇的锚点和一篇前三节的正文，对得上，过了；A95 的旧截图照作者的安排没动。**阶段 M**（可维护性收拾，H01–H15）主会话挑会改行为的几处读了：测试文件改名是纯改名，抽出来的 `atomicfile.WriteNew` 刷盘、临时文件名、清理都和原来一样，设置预览改走操作层以后照旧只给人用，合并后的便携 Java 路径判断比原来两份都严；分支最新的提交上全量过了，过关。

**阶段 22**（Mac 能在 Windows 上做的部分）代码读着没问题，但主会话借 GitHub 的 macOS 机器在分支上跑了一次 `go test ./...`，44 个包里有 3 个包 9 条挂了：Windows 的只读属性在 Mac 上挡不住改名替换、测试里写死了盘符和反斜杠、Mac 上没有加密存储、Mac 版不能在程序里更新。返工交给 Opus 子代理：它没照返工单建议的两种造法（那样失败来得太早，后面的回滚检查不测什么也会过），Mac 上改用「已锁定」标记让文件换不掉，并加了一道「失败要发生在备份之后」的检查；加密那三条在 Mac 上改用不带凭据的隧道；CI 的 Mac 作业加了 `go test`。主会话把它推上 GitHub 跑，三个作业都绿，Mac 上的 56 个包和上次一样、没有失败，过关。

**阶段 21**（主窗口导航拦截、选文件夹对话框挪到 UI 线程）交给 Fable 复审员，它用真的 WebView2 窗口和真的系统对话框写了探针，找出四件要改的：同源地址里带反斜杠或零散的 `%` 时被当成外部链接交给默认浏览器；对话框开着时宿主的派发回调全被模态循环压住，关掉以后也不执行；回调里出错会悄悄放行；注释和日志说「偶尔才发一笔请求」「能拦拖拽」，实测是每次都发、拖拽没验证。返工由 Opus 子代理做，同源只看协议、主机、端口，同源的绝不外交；对话框关掉后补派发一次，派发后唤醒丢了每 200 毫秒补发一次；出错时取消导航并记日志；四处都做了反向验证。同一个复审员再审：在真窗口里试了 16 种怪地址，没有一例判成放行却落到别的主机，对话框关掉 87 毫秒后被压住的回调就执行了（上一轮 1.5 秒后仍不执行），结论过。主会话顺手改了它提的三处小问题（补一条钉住「在反斜杠处截断」的用例，两处注释改准）。阶段 21 排在 v3.3.0-beta.1，合进来以前主会话还要在真程序里走一遍。

**阶段 20**（硬链接原地写、云同步文件夹被当链接）第一轮 Fable 复审要返工：盘点只做了一个包，音乐共享写 `.bak` 的那处还开着；多加了一道「符号链接文件一律拒」，改变了白名单等十几处原地写的行为（几台服务器共用一份 `whitelist.json` 的符号链接是常见做法）；还原时的链接检查从目标本身查起，云同步的文件会让整次还原被拒；几个包装函数没有用例；汇报里有好几个仓库里不存在的名字。返工由 Opus 子代理做：全仓的写入点过了一遍，改了三处（音乐共享的 `.bak`、配置备份、换地图记录的临时文件），撤掉那一道，还原从上一级查起，补了用例，七组反向验证。它自己还发现一处：先删再建的写法在 Windows 上删只读文件时会先去掉只读属性，硬链接两端共用属性，外面那份会被改成可写，于是改成先查硬链接数再删。写这份日志时另一个 Fable 复审员还在审。

主会话还发现一件第二批共有的事：Gemini 的分支是一条线，20、M、22 后面接着 23 和 21，按原来的安排 v3.2.9 只放 20、M、22，23 和 21 要到 v3.3.0-beta.1。到时候是把整条分支一起合进去（v3.2.9 多带 21 的窗口拦截和 23 的英文文档），还是挑着合，要问作者。
