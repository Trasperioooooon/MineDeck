# 2026-11-25 阶段 M：可维护性收拾（H01–H15）

## 背景与目标

前序几个阶段补齐核心功能和安全边界后，代码库里陆续攒下一些只影响可读性与长期维护的债：有的测试文件还沿用开发阶段或评审轮次起名，评论与用例标题里混着只在本机有意义的编号；Windows 端口监听查询、新文件原子写入、便携 Java 路径校验、测试假服务器进程这些逻辑在多个包里各写了一套；个别启动检查、日志迁移与前端渲染函数偏长；少量只服务测试的辅助方法留在正式文件里，个别路线还绕开操作层直接调实例方法或临时改写全局 HTTP `DefaultTransport`。

这一轮以结构整理与代码清洁为目标，严格对照可维护性清单推进 **H01–H15**（清单第 8 节到 H15 结束），要求行为与现有测试断言完全不变，每一小步独立提交并单独回归，最后再做全套构建、测试与端到端 UI 复核。

## 做了什么

按先测试命名前置对齐、再跨包去重与职责归位、最后细节收口的顺序，拆成 12 个小步提交逐步落地：

先理顺测试与命名（H01–H02）。用只改文件名、零内容变动的重命名提交，把 5 个包里按阶段或评审轮次起名的 23 个测试文件全部改回按功能命名；随后把 Go 源码、前端脚本与 UI 测试脚本里残余的本机阶段、返工编号注释和用例名替换成业务语义，并核对 Go 测试函数名均已不带阶段或轮次字样。

再合并跨包重复逻辑并隔离测试钩子（H03–H07、H09、H11）。把实例端口冲突检查与操作层端口建议里重复的 Windows TCP 监听表查询以及 macOS 进程名反查收拢到新的内部包 `internal/portprobe`；将 `startInstance` 中带临时解锁的端口前置检查拆为独立方法 `(m *Manager) checkStartPort`，用 `withUnlocked` 保证异常路径也能成对加回锁；把跨包端口探测测试钩子移入 `internal/inst/testhooks.go`，并清理掉仅剩测试直接调用的 `log4jFlags` 和 `UpdateSettings`；在 `internal/atomicfile` 抽出通用的 `WriteNew` 来合并日志配置迁移和隧道备份里的新建文件原子发布逻辑，补上 `TestWriteNew` 单元测试；同时把分散在实例测试与 Web 测试里的假服务器子进程入口收拢到 `internal/fakeserver`，把便携 Java 目录归属判断合并为 `inst.JavaPathInside`。

最后梳理分层边界、函数粒度与收尾细节（H08、H10、H12–H15）。拆分过长的 Log4j 迁移、实例接管以及前端实例列表与 JVM 预览相关函数；为配置预览在操作层注册 `instance.settings.preview`（`HumanOnly` 且 `NoLog`），让 `handlePreviewSettings` 统一走 `s.do` 分发；补齐构建残留与导入排除规则注释；让隧道测试共用 `junction` 联接帮手；并为 `tunnel.Accounts` 增加 `SetHTTPClientForTest` 测试钩子，使 Web 隧道创建路由测试注入独立客户端，不再改写全局 `http.DefaultTransport`。

- **公共能力包与原子写入**：新增 `internal/portprobe` 包（含 Windows/Unix 监听表实现与 macOS 进程名查询）、新增 `internal/fakeserver` 包；扩展 `internal/atomicfile/atomicfile.go` 提供 `WriteNew` 及对应 `internal/atomicfile/writenew_test.go`，`internal/inst/log4j_migrate.go` 与 `internal/tunnel/tunnel.go` 改调该接口。
- **实例管理、操作层与 Web 接口**：`internal/inst/proc.go` 拆分 `checkStartPort`；新增 `internal/inst/testhooks.go` 收纳跨包探测钩子；`internal/inst/inst.go`、`install.go`、`adopt.go`、`creating_leftover.go` 完成死代码清理、函数拆分、导出 `JavaPathInside` 及补注释；操作层 `internal/ops/catalog/instances.go` 与 `mc.go` 及 Web 层 `internal/web/instances.go` 对齐分层调用；`internal/transfer/import.go` 补齐排除说明；`internal/tunnel/testhooks.go`、`internal/tunnel/frpcexe_windows_test.go`、`internal/web/routes_test.go` 与 `internal/web/tunnelcreate_test.go` 收口测试注入与注释。

## 怎么验证的

重构前先保留基线测试清单与全量测试结果作为对照。12 个提交期间每做完一项都跑 `gofmt`、跨平台 `go vet` / `go build` 及对应包测试；拆出 `checkStartPort` 后单独对并发端口窗口与锁持有测试以及整个 `internal/inst` 跑了 `-count=20`（全部通过，无一次并发偶发失败）。

全部代码落盘后执行收尾总检：`gofmt -l .` 无待格式化文件；Windows 端 `go vet ./...` 与 `GOOS=darwin GOARCH=arm64` 下 `go vet ./...`、`go build ./...` 全部通过；用 `go test -list . ./...` 比对 `Test*` / `Benchmark*` / `Example*` 清单，除 H07 新增 `TestWriteNew` 外由 1358 个增至 1359 个、原有测试函数零丢失零改名；Windows 全量 `go test ./... -count=1` 全部通过（46 个含测试包全部 `ok`，10 个无测试包为 `[no test files]`，与基线相比仅多出新建的 `portprobe` 与 `fakeserver` 两个辅助包）；`tools/ui-dev` 针对本次涉及改名的 6 项及页面无报错共 7 条 UI 端到端用例在 Playwright 实测中 `7/7 passed`。

## 遇到的问题与取舍

做 H07 时核查了所有新建文件原子发布点：`log4j_migrate.go` 与 `tunnel.go` 都是生成较小内容，直接切换为基于字节切片的 `atomicfile.WriteNew` 最简洁；而 `internal/inst/backup.go` 的 `zipDirsExclusive` 需要把整份世界或实例归档流式写进临时压缩包，再独占落盘。为了不在创建大备份时把整个压缩包先缓存在内存里，没有强行让它改走字节切片版 `WriteNew`，保留其流式写入接 `atomicfile.PublishNew` 的结构。

做 H03 与 H09 时各保留了一个有意区别的设计点：操作层端口建议原有的测试允许替换 `listenPorts` 包变量来模拟监听表，因此将原有 `tcpListeners` 收拢为调用 `portprobe.ListenPorts` 的薄包装而非强改整套端口建议测试；操作层 `gamechat_test.go` 用到的 `MINEDECK_FAKE_STDIN` 模拟的是标准输入交互行为而非完整假服务器生命周期，所以没有硬塞进 `internal/fakeserver`。做 H11 时注意到选定 Java 文件尚未存在时，`RealPathStrict` 会失败，因此 `JavaPathInside` 先严格解析再用 `InsideReal` 判断，落空时回退到解析已有父目录后的相对路径局部性检查，从而继续拦截目录联接逃逸。
