### 更新脚本

v3.1.0 及以前的 `update.bat` 有四个毛病，都实测复现过。一是脚本按 UTF-8 写盘，cmd 却按系统代码页（936、932）读，中文路径走样，`cd /d` 失败。二是开机自启的 MineDeck 当前目录是 `C:\Windows\System32`，脚本里的 `move`、`start` 用的是相对名字，找不到文件；`start` 找不到时弹的对话框被 HideWindow 藏起来了，cmd 就一直挂着，MineDeck 再也不会打开。三是文件夹名字里的 `%` 会被 cmd 吃掉。四是 PATH 里 GNU 的 `find` 排在 System32 前面时，等旧进程退出那一步直接跳过，`move` 失败，又把旧版打开。

新脚本在 `internal/update/run_windows.go`。脚本本身只有 ASCII，路径、进程号这些都放在环境变量 `MD_UPDATE_*` 里传进去，cmd 只展开一次，中文、`%`、`!`、`^`、`&` 都不走样。`tasklist`、`find`、`ping` 写系统目录下的全路径。cmd 用 `/d /e:on /v:off /s /c` 起，只带 CREATE_NO_WINDOW，不再设 HideWindow，万一弹框也看得见。等旧进程最多等 120 次，`move` 失败最多再试 60 次；实在换不成，旧进程还在就什么都不开，旧进程已经退了就把旧版打开，不会两样都没有，也不会开出第二个。测试在 `internal/update/swap_windows_test.go`：放在名字是 `我的世界 100% A&B (开服) !x! ^y a=b;c,d'e` 的文件夹里，PATH 前面放着冒名的 `find`、`tasklist`、`ping`、`cmd`，用一个窗口小程序（`testdata/swapmarker`）扮演新旧两版，正常换、旧进程不退、exe 一直被占着三种情况都测了。

端到端也跑过：用这版代码编了一个「3.0.9」，放进带中文和 `%` 的文件夹，从 System32 起（和开机自启一样），PATH 前面放着 Git 的 `find`，点更新，换成了线上的 v3.1.0 并自己打开；代码页切到 936 也换得成。

要记住：换程序的是旧版本写的脚本。从 3.1.0 升到 3.1.1 跑的还是旧脚本，这条路只能发版以后测，而且旧版要从 PowerShell 或资源管理器里起，别从 Git Bash 里起。

### 其余几处，怎么分的工

`run.bat` 开头加了 `setlocal DisableDelayedExpansion`，Claude 自己改的，测试照 `/v:on` 再跑一遍。别的交给三个 Claude 子代理，各在自己的工作树里做：A 做外部链接，B 做端口检查和清除凭据，C 做四处加固。Claude 逐行看过再合进来（`aca68d7`、`9d1992a`、`ac9e871`），合并时自己又改了两处：整合包覆盖目录里只差大小写的文件照旧以后写的为准，只是记进日志（`82cdd37`）；交接包里名字不能用和路径样子不对分开说（`17615b6`）。

外部链接：前端 `app.js` 的 `initExternalLinks` 在捕获阶段拦下指向别的网站的点击、中键和 `window.open`，交给宿主函数 `hostOpenURL`；宿主在 `openurl_windows.go` 里只认 http、https 的绝对地址，再用 ShellExecuteEx 交给默认浏览器。宿主函数对页面里任何脚本都开放，所以把关全在 `checkExternalURL`。ShellExecuteEx 带了 SEE_MASK_NOASYNC 和 SEE_MASK_FLAG_NO_UI：在后台线程上调、调完就撤掉 COM，不等的话浏览器可能没打开却报成功。x/sys 里没有它，结构体是照 C 的定义手写的，有一条测试真调它打开一个不存在的文件，报「找不到文件」就说明结构体对得上。

端口：`internal/inst/portcheck.go` 照 Java 绑端口的办法（独占、双栈通配）试绑一次，被占着直接报错，不起 Java。崩溃重启、定时重启和「重启」碰上端口还没放开，先等最多 5 秒。和 Java 17 实际绑端口的结果对照过六种占法。v2.9.0-beta.2 那一节说的 `inst.CheckPort` 已经没有了，由它取代。担心过一件事：停服时服务端先关玩家的连接，连接会在 TIME_WAIT 里停一两分钟，要是这挡住了独占的绑定，定时重启就会在 5 秒以后放弃（3.1.0 是照样起 Java、失败了再靠崩溃重启重试）。实测不会：服务端先关、连接停在 TIME_WAIT 时，带 SO_EXCLUSIVEADDRUSE 照样能马上绑上。`server-ip` 写的是域名时，试绑之前要解析，给了 3 秒的时限，因为 Start 调它时拿着这台服务器的锁。

清除凭据：隧道卡片上的「清除凭据」，只给存过凭据的自定义 frps 隧道；OpenFrp 和樱花启动必须带凭据，不给清。

四处加固：B-9 读写配置先用 `RealPathStrict`（`internal/inst/realpath_windows.go`）查真实落点，查不清就拒绝。比较用的是系统的设备路径（`\Device\HarddiskVolumeN\…`），不是盘符形式：ImDisk 这类没在挂载管理里登记的盘，查盘符形式会失败，查不清就拒绝的话，放在这种盘上的服务器一个配置都读写不了。B-10 换 AI 服务商时设置和 Key 一起存好才换内存，失败就退回（`commitLocked`），要发请求的 Client、Test 用和设置一起取到的那个 Key 判断配没配好。B-2 局域网读设置时 Webhook 地址只给开头，原样传回算没改；保存前再用 url.Parse 查一道，要带主机名。C-2e 新加 `internal/winname`，导入时一律从严查 Windows 文件名，各条导入路径怎么处理只差大小写的文件，功能清单里写了；导出交接包时这类名字留在包外，写进剔除清单。

最后加了一处不在作者勾的范围里、但同一类的：窗口版里把文件或链接拖到没地方接的位置，以前 WebView2 会另开一个自带的小窗把它打开，和外部链接以前弹的是同一种窗口。现在 `app.js` 的 `guardDrops` 把这种拖放接下来、标成不能放；待装清单的拖放区和输入框照旧。这一条是准备手测清单时查出来的，作者可以否决。

写这一条的时候以为旧行为更糟：整个窗口被换成那个文件或网页，窗口版没有返回键，只能退出重开。那是照印象推的，没有看过，所以发布说明里那句当时标了（待补）。11 月 13 日拿正式版 3.1.0 在真窗口里对照，主窗口并不动，只是另开小窗（见下面「真窗口里走了一遍」）。发布说明已经照实改了。`app.js` 里 `guardDrops` 上面的注释和 `tools/ui-dev/tests.js` 里那条测试的名字还是旧说法，发版前不再动要打进程序的文件，留到发版以后改。

### 复审

请 Gemini 4 Argon（medium）只读复审了五份：更新脚本、B-9/B-10/B-2、C-2e、外部链接，最后补了端口检查（它每次开服都要过，误报的话谁的服务器都开不了）。清除凭据没有送去，是 Claude 自己逐行审的。认下并改了的：ImDisk 盘的设备路径；ShellExecuteEx 带 NOASYNC 和 NO_UI；B-10 用同一个 Key 判断；Webhook 地址查主机名；导出时只差大小写的另一个文件写进日志、名字不能用的不记两遍；链接拦截只接左键、认得 SVG 里的链接（都在 `8c8fe6e`）。驳回的有备用数据流绕过（`configPath` 本来就拒绝 `:`）、`ß` 转大写、主机名里的反斜杠、盘根上的 `start /D`，理由都对过代码。

端口检查那一份认下并改了的：JVM 参数里打开了 `java.net.preferIPv4Stack` 时 Java 只用 IPv4，改成按 IPv4 查（不然别的程序只在 IPv6 上占着同一个端口会被说成被占）；`server-ip` 写成带方括号的 IPv6 先去掉括号；`server-port=0` 的不查；重启前等端口的时候，用户已经把服务器启动了就不再等；重启时端口一直被占着，控制台说清楚不再自动重试。没改的：崩溃自动重启碰上端口一直被占，只等 5 秒就停，不像 3.1.0 那样起了 Java、失败了再按崩溃重启的间隔试两次。旧进程退出时端口就放开了，TIME_WAIT 也不挡，5 秒后还占着基本是别的程序一直占着，所以没加重试。`server-ip` 写 `localhost` 这类多地址的名字时，Go 和 Java 都先取 IPv4，结论一致。解析域名时 Start 拿着锁最多 3 秒，只在 `server-ip` 写了解析很慢的域名时才会碰上。

认了但这次不改的，记在这里：硬链接能指到服务器文件夹外面（查真实落点查不出硬链接）；查完落点和真正写入之间被换掉（以后可以考虑 Go 的 os.Root）；备份目录下的子路径；整合包清单和覆盖目录之间只差大小写的冲突；主窗口自己跳到别的网站没有拦（B-13 的后续，要在宿主里接 WebView2 的 NavigationStarting，go-webview2 没有现成的口子）。
