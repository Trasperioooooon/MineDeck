# 2026-11-25 阶段 21：主窗口导航拦截和选文件夹对话框（A89）

## 背景与目标

桌面版主窗口基于 `github.com/jchv/go-webview2` 承载本地管理界面，前期遗留两处窗口宿主边界隐患：第一，页面侧虽然通过 `hostOpenURL` 接管常规外部链接点击与 `window.open`，但若遇拖拽文件或页面内脚本直接改写 `location.href` 等绕开前端事件的路径，WebView2 主窗口本身并未在原生导航层拦下，可能直接在特权本地窗口内跳往外部站点或 `file://`；第二，追溯过往评审与开发日志确认，`hostdlg.PickFolder` 会在 HTTP 请求处理协程中以主窗口句柄作为属主调用 `IFileOpenDialog::Show(hwndOwner)`，与持有主窗口消息循环的 WebView2 UI 线程形成跨线程模态所有权，存在卡死或失焦风险。

本阶段在不改动 `go.mod` / `go.sum`、不引入第三方依赖且不复制大段上游库代码的前提下，完成 WebView2 顶层导航拦截与系统选文件夹对话框 UI 线程派发改造，并通过单元与真实 WebView2 隐藏窗口测试验证。

## 做了什么

**第一件：WebView2 主窗口 `NavigationStarting` 导航拦截。**
调研 `go-webview2` 的 `pkg/edge/corewebview2.go` 确认 `iCoreWebView2Vtbl` 已按虚函数表顺序声明 `AddNavigationStarting` 与 `RemoveNavigationStarting`，只是未暴露导出方法。实现中沿用已有 `disableWebViewStatusBar` 的分层反射方案（带 `recover()` 防御结构变更退回），通过 `reflect.TypeFor[*edge.Chromium]()` 与 `reflect.TypeFor[*edge.ICoreWebView2]()` 拿到 `vtbl.AddNavigationStarting` / `RemoveNavigationStarting`（`edge.ComProc`）并用其 `Call` 方法完成注册与注销。

在事件生命周期与内存安全方面，全局只通过 `edge.NewComProc` 创建一次 4 个 COM 回调跳板（`QueryInterface` 匹配 `IUnknown` 与 `IID_ICoreWebView2NavigationStartingEventHandler`、`AddRef`、`Release` 及带 `recover()` 保护的 `Invoke`），由函数表拷贝 `vtblCopy` 与实例对象 `handler` 通过 `runtime.Pinner` 固定在内存，回调表内只存 `uintptr` 索引避免 Go 堆指针跨 C 边界；清理函数使用 `sync.OnceFunc` 先调 `RemoveNavigationStarting(token)` 再从回调表移除并 `Unpin()`。导航裁决函数 `classifyMainFrameNavigation` 对与本机服务地址严格同源（相同 `scheme`/`host`/`port` 且不含 `userinfo`）的请求直接放行；对同源携带 `userinfo` 的请求以及一切非 `http`/`https` 协议（`file://`、`javascript:`、`about:blank`、`data:`、`blob:` 等）直接取消导航且不对外打开；对合法外部 `http`/`https` 链接先写 `put_Cancel(1)` 拦截再异步交给 `openExternalURL` 用系统默认浏览器打开。

**第二件：`hostdlg.PickFolder` 切回主窗口 UI 线程派发。**
新增 `hostdlg.SetDispatcher(uiThreadID, dispatch)` 供 `openWebView` 在锁定 OS 线程后注入 UI 线程 ID 与 `w.Dispatch`，窗口退出时借助 `defer` 栈依次先取消导航拦截、再调用 `clear()` 解除派发器并唤醒潜在等待者、接着重置 `SetOwner(0)`，最后销毁窗口。非 UI 线程调用 `PickFolder` 时，`callNativePicker` 将 `nativePicker`（`pickFolderNative`）派发回 UI 线程执行并以 `doneCh` 等待结果；若派发等待期间主窗口已关闭触发 `clear()`，则由 `stopped` 通道立即解锁并返回 `ErrUnavailable`（不再意外弹出游离的 PowerShell 后备框）；若原生对话框在 UI 线程报系统错误，则由原调用协程在 UI 线程之外运行 PowerShell 后备以免阻塞消息循环；而当调用方自身已处于 `uiThreadID` 时直接原地调用 `nativePicker`，杜绝“UI 线程等待 `Dispatch` 队列中的自己”造成死锁。

## 改了哪些地方

- **主窗口导航拦截与接线**：新增 `cmd/minedeck/webviewnav_windows.go`（导航分类、`edge` COM 反射桥接与 `Pinner` 托管、`installWebViewNavGuard`）与 `cmd/minedeck/webviewnav_windows_test.go`（纯分类单测及真实隐藏 WebView2 测试）；`cmd/minedeck/webview_windows.go` 在启动阶段注册 `hostdlg.SetDispatcher`、`defer` 清理顺序及 `installWebViewNavGuard`。
- **选文件夹对话框派发**：修改 `internal/hostdlg/hostdlg.go`（新增 `SetDispatcher`、`callNativePicker` 自调直通与 `stopped` 取消唤醒），在 `internal/hostdlg/dispatch_windows.go` 与 `internal/hostdlg/hostdlg_other.go` 提供跨平台 `currentThreadID()`，并新增 `internal/hostdlg/dispatch_windows_test.go` 覆盖跨线程切回、UI 线程防自锁、原生失败回退线程隔离及 `clear()` 唤醒四类场景。

## 怎么验证的

1. **格式、静态检查与跨平台编译**：`gofmt -l .` 无输出；Windows 下 `go vet ./...` 与 `go build ./...` 全部通过；`GOOS=darwin GOARCH=arm64` 下 `go vet ./...` 与 `go build ./...` 全部通过。
2. **完整包测试**：`go test -v -count=1 ./internal/hostdlg/ ./cmd/minedeck/` 全部通过（`internal/hostdlg` 4 条新增派发测试全部 `PASS`，5 条依赖 `MINEDECK_LIVE_DIALOG=1` 的真弹窗交互测试按默认规则显式 `SKIP`；`cmd/minedeck` 全部用例包含 `TestWebViewNavInterceptorLive` 与 `TestWebViewStatusBarDisabled` 均 `PASS`）。
3. **反向对比验证**：分别临时注释 `cancelNav(args)` 与 `currentThreadID() == d.uiThreadID` 分支后重跑对应测试：`TestWebViewNavInterceptorLive` 立刻检出主窗口跳到外部服务页面并失败退出，`TestPickFolderSelfCallOnUIThreadDoesNotDeadlock` 在 `0.50s` 超时捕获自锁并报错退出；恢复代码后两项复跑全过。
4. **仓外可执行构建核对**：将主程序单独编至系统临时目录下的隔离输出路径并确认生成可运行文件，随后立即删除临时构建产物；遵循任务边界，未运行整包 `main()`，避免 `autostart.RemoveLegacy()` 修改当前系统用户的开机启动注册表或拉起真实桌面浏览器。

## 遇到的问题与取舍

在真实 WebView2（Edge `158.0.0.0`）环境运行 `TestWebViewNavInterceptorLive` 时观察到一个底层机制特性：当页面内脚本执行 `location.href` 跳往本机另一测试服务端口时，宿主回调读取并写回 `PutCancel(1)`（紧接着用 `GetCancel` 读回确认为 `1`）能够可靠取消页面提交——主窗口始终停留在原地址与原标题上，且后续同源脚本跳转照常工作；但在多进程 IPC 异步切过边界的一瞬，渲染进程仍有可能向本机回环外部端口先发出一笔初始 HTTP `GET`，随后因 `Cancel=1` 被浏览器丢弃响应而不发生页面切换。综合评估需求（阻止主窗口切出本地界面而不加新依赖或额外拦截 `WebResourceRequested`），保持聚焦简洁的 `NavigationStarting` 拦截，并在真窗口测试中以“拦截期间 `location.href` / `document.title` 未偏移、`EXT_PAGE` 从未提交及随后同源导航正常”以及反向对比测试作为确凿依据。

另外，由于仓库 `tools/ux-walkthrough` 的脚手架路径写死在单独调试目录、且整程序运行会改写注册表并打开外部默认浏览器，本阶段真窗口实测选在隔离的 `webview2.NewWithOptions` 隐藏窗（独立临时 `DataPath` + 双本地 `httptest.Server` + 替换 `launchURL`）中执行，效果等同真实 WebView2 进程且零本机环境污染。

## 后续留意

- `go-webview2` 未来如升级版本导致未导出字段 `*edge.Chromium.webview` 或 `vtbl.AddNavigationStarting` 变更，启动时会优雅降级记日志而不影响主窗口打开，同时 `TestExtractCoreWebView2RejectsMalformed` 与 `TestWebViewNavInterceptorLive` 会第一时间在测试中报警。
- 默认构建的带参数真弹窗测试（`internal/hostdlg` 下需 `MINEDECK_LIVE_DIALOG=1` 的用例）会在桌面真实闪现系统文件框，仍留在人工/交互桌面测试环节按需触发。
