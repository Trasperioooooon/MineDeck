# 2026-11-16 公开仓库去掉本机路径

## 要做什么

作者先问：「怎么连搬家也要记录，那是不是github公开仓库上面别人也能看到我本机项目的位置变化了呢？」听了说明后定下：「从仓库删掉，评审记录里那一百多条本机链接和现状里的 D 盘路径换成相对路径」。

## 做了什么

这个仓库是公开的。之前按「每次工作写一份日志」的规矩，把只跟作者电脑有关的两份日志也提交了，里面写了作者电脑上的文件夹位置和本机工具的配置位置。仓库里更早也零散写着本机路径：两份评审记录里一百多条指向本机工作树的链接，几份日志里的用户目录，现状里仓库外测试目录的完整路径。

这次做了四件事：

一是删掉那两份只跟本机环境有关的日志（`git rm`）。它们在提交 `76e5f21`、`5bf60a7` 的历史里还能翻到；作者没要求改写历史，这里也没改。

二是把 `docs/测试与评审/` 下两份评审记录（PR13 平台账户控制台、合并后复审 2026-11-14）里的本机路径去掉。指向当时本机工作树里源码的链接，改成从文档所在位置出发的相对链接，行号从 `:917` 这种写法改成 GitHub 认的 `#L917`；合并后复审里原来按仓库根目录写、本来就打不开的 `internal/...` 链接也一起改成了相对链接。一共 168 条。行号是评审当时那个分支的，现在的代码可能已经挪了几行，看的时候以评审里的原文描述为准。指向本机 Go 标准库源码的 3 条改成了不带链接的包路径（如 `archive/zip/reader.go:131`）；1 条指向当时评审工作材料（从来没进过仓库）的链接改成了纯文字。正文里的本机路径：gcc 的位置改成「Strawberry Perl 自带的 gcc.exe」，测试目录和临时文件夹只留文件夹名，工作树写成仓库里的相对路径 `.claude/worktrees/…`。CI 日志里 GitHub runner 的路径不是作者电脑上的，留着。

三是 `docs/现状.md`「待清理」里仓库外测试目录那条，去掉盘符，只写文件夹名，注明都在作者电脑上、仓库外面。

四是在 `docs/日志/README.md` 的规矩里加了一段：只跟作者电脑有关的事不写日志、不进现状和待办；仓库文档不写本机绝对路径和用户名；提交前搜一遍盘符路径。这条规矩写进 README 而不只是 Claude 的记忆，是因为别家 AI 接手时也读这份 README。

没动的：其他旧日志里的本机路径（日志写完不改，作者这次只点了上面几处）；`tools/` 下走查和交接测试脚本里写死的路径，那些是脚本运行要用的配置，不是记录。

## 谁做的

主会话：Claude 桌面应用，Opus 5.5（`claude-opus-5-5`）。没有委派，作者说过这类整理不用 Codex 复审。

- 两份评审记录里再搜盘符路径、用户名和旧文件夹名：除了 CI runner 的两处，一处不剩。`现状.md`、`待办.md`、`功能清单.md` 里盘符路径为 0。
