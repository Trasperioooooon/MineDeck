# 2026-11-28 界面重构：作者审完服务器详情页

## 要做什么

Gemini 文案复审收尾以后（见 `2026-11-28-界面重构-Gemini改草图文案的复审和修正`），作者说「好的，那我来审草图」，从服务器详情页开始一页一页看，边看边提要改的地方。最小窗口那件另有日志（`2026-11-28-界面重构-最小窗口改成基准窗口`），这份记的是之后详情页各标签上作者提的改动。最后作者说：「那到这里，服务器详情页就算是过完了，我没提到的几个页面就是通过的了。」

作者逐条提的，原话摘要：

- 玩家页：「从左往右的顺序改为『在线玩家』、『管理员 OP』、『封禁名单』、『白名单』」。
- 设置 · 常用：「白名单怎么这么长？可以缩短」；服务器简介「怎么只给选中的文字进行添加下划线、删除线、斜体等这种操作？现在貌似只能将插入的『§o』这些符号后面的所有文字应用对应的效果」；「这个介绍的输入框和预览框，能不能多占几行」。问到向导里的简介，作者说「向导保持一行」。
- Java：「切换 java 版本，后面的构建没有改变，这正确吗？此外，现在是不是还没有加我在上一个会话中提到的，修复 java 运行时的功能？」主会话问画哪几处，作者说「两件都画」。
- 全部配置：「像这类，应该只有 false 或者 true 吧？就不能改成二选一的吗？万一拼错了还可能报错。java 那个修复，要不也先在草图里呈现出来，到时候程序真代码去适配。」
- 扩展 · 游戏内 AI：「总开关都关了，那下面的内容应该整体变灰且不可更改」。主会话先画成淡掉再去色，作者说「我想要的不是这样的灰色，是那种被蒙上了一层，变暗的效果」。识别测试里的设置要不要一起盖，作者说「保持能用」。

## 做了什么

全是草图（`design-system/redesign/`）和计划文档，程序一行没动。

玩家页四栏换成作者给的顺序（`feea962`）。

设置 · 常用（`46946a4`）。「谁能进」两块不再铺满一行，按字的宽度排在左边。服务器简介的输入框和预览改成两行的框：游戏的服务器列表最多显示两行，所以回车最多换一次行，粘贴进来多的只留前两行。调色板改成选中一段字时只改这一段：前面插新码，后面补回原来生效的颜色和样式，改完仍选中，可以接着叠；没选中时照旧插在光标处。调色板浮层改从整个框的下沿弹出，免得挡住第二行。待审文档里写了改程序时的一个坑：真换行存进 server.properties 要写成 `\n`，程序现在只做 `\uXXXX` 转义。向导第三步封面上的简介照作者说的保持一行（`ca83c9f` 只改了文档）。

Java（`9f8445f`）。构建是同一游戏版本服务端的几次更新，和 Java 无关，换 Java 时构建不变是对的。但下拉把低于游戏版本要求的 Java 也列成能选，选了起不来，程序也不拦；改成灰掉、悬停写要求，要求照程序的规则取。修复入口画了三处，做法照 `docs/计划/2026-11-27-v3.3.0-beta.1-下载与更新整改.md` 第四节，那份文档第四节也补了一句「界面上的入口已画进草图」：
- 全局设置 Java 页：打开时自动检查，坏了的标「无法启动」，MineDeck 下载的每一套都能重新下载，左栏右上角有「重新检查」。
- 详情页「启动与内存」的 Java 下拉：坏了的那一项标红，右边一颗「重新下载」。
- 控制台报错横幅：多一种「Java 无法启动」，直接给「重新下载 Java 17」。

几处草图参数是 `&java=bad`、`diag=java`。顺带把下拉菜单里的悬停提示改成弹在菜单旁边（共用的 `kit.js`），规范第七节同步改了。

全部配置（`145e4ac`）。只能是 true / false 的换成「true | false」两段；游戏难度、默认游戏模式、世界类型、区块压缩换成下拉，菜单里是原文，后面淡淡的中文名。文件里写的不是这几个值时，两段都不选中、框标黄，悬停说服务端会怎么当。

扩展（`174b5d2`、`0c0325e`、`77f60f4`，文档 `8f25ec6`）。游戏内 AI 的总开关关着时，「设置」那一段：
- 先画成淡到 0.7 再去色；作者说要的是蒙上一层、变暗，最后改成面板上盖一层暗色，浅色是阴影色 20%，深色是黑 42%，圆角同栏，盖住栏间的缝。
- 按钮、输入框设 `inert`，点击和回车的处理也先看是不是在盖住的面板里。列表照样能滚，标题照样能悬停，空白处悬停说「游戏内 AI 未开启，开启后方可修改」。
- 「问答记录」「识别测试」照常能用，作者定识别测试里的高级识别设置也保持能用。
- 作者说的是游戏内 AI 这一页，主会话把 AI 伙伴的「设置」也照着改了（作者没有另说）；「伙伴」「安装」照常能用，因为开关要等模组装好才能开。音乐共享没有总开关。
- 规范第六节记下了这条做法。

最后作者说详情页审完、没提到的算通过。待审文档的详情页各节标题后面标了「11-28 审完」；开头加了一段，写明各节「要你敲定的」作者没单独说的，都按草图现在的画法算定了，并列出其中改变程序现有做法、或要后端补的几条。

## 验证了什么

每一处改完都用无头浏览器截图脚本（主会话自己写的，放在不进 git 的目录里）在 1280×800 下截深浅两色，看页面不滚、没有报错、字没被截断；交互用脚本在页面里点：
- 简介：选中一段再点调色板，选区和前后的码对得上；第三行进不去。
- Java：低版本灰掉；重新下载的状态依次走完。
- 全部配置：两段点了选中块对齐、算进未保存，「放弃修改」能还原；下拉能选。
- 扩展：总开关关着时，点模板开关、步进器、伙伴页的删除键和禁挖区域那一行都没反应；换分段再换回来仍盖着；打开后全部恢复。最后一版又在桌面版右侧的浏览器里真用滚轮滚了命令模板列表（滚得动），真悬停了灰掉的行和栏标题，提示都对。

没有跑程序的测试，因为程序没改。
