# 2026-11-21 官网发布脚本的回退判定（Claude 写）

## 要做什么

接着 `2026-11-21-官网部署v3.2.4`：那次两个旧版本的镜像链接从本机偶发连不上，整次发布被判失败，切回又因为 SSH 被断开没切成。主会话问要不要改发布脚本，作者答：「改，先给我看改法」。看过改法和本机试的结果以后，作者说：「就这样改脚本，没法测试的那一项就不测了吧，仅作记录。」

## 做了什么

改的是仓库外的发布脚本和它调用的镜像链接核对脚本，改之前两个文件和部署说明都留了原样备份。

- **镜像链接核对**：第一轮照旧，6 个并发，每个链接最多试三次、隔两秒。新加第二轮：第一轮连不上的，等 30 秒后一个一个再试，每个最多三次、隔十秒。两轮都连不上时，旧版本的链接只记警告、不算失败，因为这些文件切换前服务器已经按清单全量核对过；这次发布的最新稳定版的链接照旧算失败，因为新页面上的下载按钮指着它。404、大小不对，不管哪个版本都照旧算失败，因为那说明页面上的链接本身错了。
- **切回上一版**：最多试三次，中间等 20 秒、40 秒。切回脚本只是把站点指回切换前记下的上一版，多跑一次没有副作用。不管切没切成，最后都经 HTTPS 读线上的 `data/latest.json`，比对构建时间，直接报出线上现在是新版还是旧版；三次都没切成时提示照部署说明里的回滚命令手动切。
- 部署说明补了这两处改动的来由和用法。

## 谁做的

- **主会话**：Claude Code 桌面应用，claude-opus-5-5（系统提示），思考档未确认。改法、本机试、换上新脚本、核对、这份日志。
- 没有委派别的执行者。

## 验证了什么

都在作者的 Windows 电脑上，换上新脚本以前先在草稿上试：

- 新的发布脚本用 Windows PowerShell 5.1 解析没有语法错误，仍然只有 ASCII 字符。
- 镜像链接核对五种情况：真实构建 92 个链接全对、通过；造一个连不上的旧版本链接，两轮以后记成警告、通过；造一个连不上的最新版链接，失败；造一个回 404 的旧版本链接，失败；不带新参数时和以前一样算失败。
- 判断线上是哪一版：对着线上的构建报「是新版」，对着别的构建时间报「不是」，站点连不上时报「读不出」。
- 切回的重试用假的 SSH 试了两种：三次都失败时等两次、最后报「切回失败了三次，线上是新版」；第一次失败、第二次成功时报「已切回，线上不是新版」。
- 换上新脚本以后，用只读的核对模式对线上跑了一遍：全站 184 个文件、92 个镜像链接、服务器上 v3.2.4 四个文件的完整下载，全过。

## 没做完或没验证的

- 切回时 SSH 真被服务器断开、重试能不能连上，本机造不出来，照作者说的不测，只记在这里和部署说明里。
- 11-21 晚那次 SSH 为什么被断开，还是没查。

## 留给下一位的

- 以后核对输出里出现「警告（不算失败）」时，是旧版本的镜像链接从本机连不上，发布照常算成功；想确认可以过一会儿再用只读的核对模式跑一遍。
