## 做了什么

都在分支 `claude/clear-backlog-1122` 上，代码六个提交，这份日志另一个提交。

**拿到 2xx 以后的不确定按已建成（A57，`5700815`、`fbd5784`）。** 关键是让「HTTP 是否已经回了成功」能从请求函数里分出来，又不动别的调用方。OpenFrp 那边，`openFrpPostAt` 变成一个薄壳，里面调新的 `openFrpDo`，后者多交回一个 `applied`：HTTP 回了 2xx、响应里也没明说失败（`flag` 不是 false）。返工单提过把「存换发的授权」挪到看完 `flag` 之后，我没挪：现在任何 2xx 都会存换发的授权，包括 `flag:false` 的，挪了就改了所有调用方的行为。做法是先解析响应体、算出 `applied`，再照原来的先后（存授权出错、响应体看不懂、`flag` 为 false）交回错误，老调用方拿到的错误一字不差，只有创建多拿一个状态。存换发授权那几行顺手拆成了 `keepRotatedAuth`，免得 `openFrpDo` 越写越长。樱花那边，`sakuraRequest` 也成了薄壳，里面是新的 `sakuraDo`，同样交回 `applied`；`sakuraRequestJSON` 只有创建一个调用方，直接改成多交回这个状态。「明说没做」只认 `flag` 明确写着 false：响应体是合法 JSON 却没写 `flag` 的，一开始被我算成了没建成（`flag` 解析成 bool 时缺了就是 false），交回前问 advisor 时被指出来，补了一条用例、把 `flag` 改成指针，单独一个提交 `fbd5784`。樱花在 2xx 的响应体里写着 `code≥400` 的（原来就有这一支判断），和 OpenFrp 的 `flag:false` 一样当成平台明说没做。另外，响应头已经回了 2xx、读响应体时连接断了的，`request()` 原来把状态码丢成 0，现在照样交回去，这种也算已建成；请求发出去以后完全没回音的（超时、断网）没有扩进来，还是算没建成。

两个创建函数拿到「`applied` 为真却报错」时，把错误包一层新的 `unconfirmedError`，交回「已建成」。`createdNotImportedError` 认出它以后换第三种说法：原文是「平台回了成功，但……。请到平台隧道列表里看一下有没有建好，有就导入它，不要再创建一次」，给人看的那句是「平台回了成功，但没能确认隧道建好。请到平台隧道列表里看一下，有就导入它，不要再创建」，没有套「已经建好」的口气，因为这几种确实只是多半建好。新的那句也放进了检查提示长度和格式的用例里。

**樱花没有 frpc 密钥时先别建（A57，同一个提交）。** `createSakuraTunnel` 拿到 `/user/info` 以后立刻查密钥，空的直接报「SakuraFrp 账户没有可用于 frpc 的访问密钥，没有创建隧道」，不带已建成；原来 `POST` 之后那一句删掉。

**「这是公开服务器」跟着锁（A57，`c804496`）。** `createPlatTunnel` 里置 `busy` 的那一刻把开关也禁用；平台上没建成、按钮恢复可点时一起放开；已建成时保持禁用。

**frpc 的几处小问题（A56，`ab21d87`）。** `alsoDropZip` 改成两个都用 `%w`。「一直在变」那句话抽成 `noteFrpcChanging`，已经放着的（`usableFrpc`）和刚解压出来的（`dropBadExtracted`）都调它；为此 `openfrpFetchExtract`、`dropBadExtracted` 多收一个控制台参数，由持有控制台的 `openfrpInstall` 传进去。用例那句断言改成查「重新下载」。

**用例。** 后端几处出口的用例放在 `accounts_create_test.go`：OpenFrp 新加一张表，按 `newProxy` 怎么回分七种（回了成功但响应体不是 JSON、读响应体时断了、响应体里没有 `flag`、换发的授权存不进去，这四种算多半建好；`flag:false`、`flag:false` 且授权也存不进去、HTTP 500，这三种算没建成）。为此假平台的 `newProxy` 加了一个只管它怎么回的钩子（原来它不走 `failNext`、`rotateTo`，一进来就算建好）。「授权存不进去」是在 `secrets.json.tmp` 的位置建一个文件夹造出来的（`secret.Store.Set` 先写这个临时文件再改名），用例里先确认一次 `Set` 真的失败，免得以后 Store 换了写法时空过。樱花那张表补了「回了成功、响应体不是 JSON」「2xx 里写着错误码」两种，「账户没有 frpc 密钥」改成没建、而且断言一次 `POST` 都没发。`errors.Is(err, errAccountChanged)` 那条见下面「留给下一位的」。

frpc 的用例：`TestOpenfrpUnusableZipCannotBeDeleted`（Windows）造了缓存的压缩包本身坏了、里面没有 frpc 两种，压缩包又被别的句柄占着删不掉，断言报错前后两段都在、`errors.Is` 认得出 `zip.ErrFormat` 和系统的「被占用」、没有去下载；`TestExtractedFrpcKeepsChangingIsNoted` 照已有的「一直在变」用例的写法，让刚解压出来的 frpc 每查一次就变一下，断言照常交回去、隧道日志里有那一句。

**隧道 ID 的边界用例（A60，`e96034c`）。** `00`、`99999999999999999999`、全角的「１２３」都拒；自定义 frps 的隧道（隧道 ID 填的「随便」）改成樱花时要过检查，被拒后存着的不动。这几条加上就是过的，产品代码没动。

**走真路由的 `created`（A57，`ce56fdf`）。** `internal/web` 里没有现成的办法把平台账户指到假平台：几个平台地址是常量，`Accounts` 里存地址的字段不导出。不过平台账户的 `http.Client` 没设 `Transport`，用的是 `http.DefaultTransport`，所以新文件 `tunnelcreate_test.go` 里那一条用例临时把它换成一个只认 `api.natfrp.com`、改写到本机假平台的传输层（别的地址一律报「测试里不许联网」，用完换回），没加导出的测试钩子，也没改 `newFullEnv`。用例经真路由先连上樱花，再 `POST /api/tunnel-accounts/natfrp/tunnels`，假平台回 201 却不给编号，断言响应 JSON 带 `created: true` 和去导入的那句提示、`POST` 只发了一次。

## 留给下一位的

- 返工单说用「取完密钥账户被断开」那条钉住 `errors.Is(err, errAccountChanged)`，先跑了一下是失败的：那一条走到的是 `addLocalTunnel` 自己报的「操作途中账户被断开或换了，没有写进 MineDeck……」，不是 `errAccountChanged`，两句开头一样，原来的字符串断言分不出来。`addLocalTunnel` 导入也在用，不在这轮范围里，所以没改它，把断言放到哨兵真会流过的出口：新加一种「刷新列表时账户被断开」，下一步取密钥时 `openFrpPostAt` 交回 `errAccountChanged`，经 `%w` 和 `createdNotImportedError.Unwrap()` 传上来，`errors.Is` 认得出。原来那一条加了一句注释说明为什么不带哨兵。
- 请求途中那条界面用例原来是「切一下开关，按钮还是禁用」，现在开关本身禁用了，改成断言开关和按钮都锁着、硬点开关不会切过去。它不再钉住 `paintNodes` 里的 `busy ||`（开关点不动，走不到那里）；那一处留着当第二道保险，没有用例单独守着。
- `docs/设计与参考/API.md` 平台创建那一行说 `created` 是「平台上已建好」，现在的意思放宽成了「已建好或多半已建好」，这轮范围不含 API.md，没改。
- 走真路由那条用例靠的是平台账户的 `http.Client` 没设 `Transport`。以后要是给它配了自己的传输层，这条用例换掉的 `http.DefaultTransport` 就拦不住了，得改成别的办法（比如加一个 `…ForTest` 的地址钩子）。
