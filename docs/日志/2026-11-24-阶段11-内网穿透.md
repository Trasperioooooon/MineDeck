# 2026-11-24 阶段 11 内网穿透

## 要做什么

清账阶段 11，没有作者的原话，是主会话照清账计划派下来的一张任务单，六条：OpenFrp 的 frpc 坏了会循环重下、检查和删除之间有时间窗、解压后又挑中刚判坏的（A56，要反向验证）；在平台上创建隧道写不进磁盘时对话框还开着、按钮能再点（A57）；跟随服务器启动时读不出 `tunnels.json` 只记程序日志（A59）；后端编辑隧道没有「只许改名称、绑定、跟随」的校验，先核实（A60）；编辑隧道时没有短凭据的提醒（A61）；「跟随服务器启动」默认是开的（A62，规格是主会话替作者定的，可否决）。

## 做了什么

都在分支 `claude/clear-backlog-1122` 上，基准是 `66dbe23`，代码五个提交，这份日志另一个提交。

**A56 的删前确认和「判坏的不再挑中」（`630d57e`）。** 查出 frpc 坏了、到删掉它之间，文件可能已经被换成好的，比如用户刚好放进来一份。现在 `inspectExe` 顺带交回查的那个文件当时的样子，取自它打开着的句柄；删之前 `removeIfUnchanged` 再 `Lstat` 一次，核对三样：是不是同一个文件（`os.SameFile`，挡住改名换进来的），大小和修改时间有没有变（挡住原地改写的）。变了就不删、重新查，前后最多查三次；一直在变说明有程序正往里写，按「判断不了」交回去，和读不了的文件一样由启动那一步去报。剩下的空隙是最后那次 `Lstat` 到 `os.Remove` 之间，只隔一两个系统调用，没有用句柄删除（那要按平台分开写，frpc 目前只在 Windows 上用，收益不大）。`usableFrpc` 的判断逻辑没变，只是换成经 `checkFrpc` 走这一套，并把 OpenFrp、自定义 frps 文件夹里判坏了、因为不是标准名而没删的那几个带出来；解压完挑 frpc 时（`findExe` 现在按 `frpcCandidates` 的先后挑，`frpcAfterExtract` 多了一个 skip 参数）跳过它们。以前解压出来的那份被杀毒软件删了，会挑中这个坏的、交给启动去报一句看不懂的错，现在照实报「frpc 不见了」。

**A56 的解压后检查（`d4008fe`）。** 循环的根子在解压以后只看文件名、不查结构：OpenFrp 的 zip 没有哈希可对，缓存里那份能解压、里面的 frpc 却是坏的时，每次启动都是删掉 frpc、再从同一个缓存 zip 解出同样坏的一份。现在 `openfrpProvider.EnsureFrpc` 把下载以后的几步拆成 `openfrpInstall` 和 `openfrpFetchExtract`：解压出来的 frpc 先过一遍 `inspectExe`，坏的删掉（是这次刚放进去的，删前同样确认没被换掉），缓存的 zip 也删掉，从下载那一步重来一次；第二次还是坏的就停下，报「下载到的 frpc 是坏的」，后面接上原来那句手动放 frpc 的办法和文件夹。只改了 OpenFrp：自定义 frps 的 zip 要对上官方的 SHA-256，里面的 frpc 不会是坏的。解压出来的文件是这一次放进去的，所以 frpc 文件夹是目录联接时也照样删，和 `extractZipFlat` 失败回滚时的做法一致。

三条旧用例跟着改了夹具，没改断言：`TestOpenfrpBadZipIsDroppedAndRedownloaded`、`TestOpenfrpNewVersionDoesNotReuseOldZip`、`TestOpenfrpRefusesRedirectToHTTP` 里的假 frpc 原来是「MZ 旧版」这种几十个字节的字，现在解压后要过结构检查，会被当成半截的，换成 `fakeFrpcExe()` 后面接一段区分用的字（结构检查允许程序后面跟着别的数据）。

**A59（`842b744`）。** 服务器启动时 `tunnels.json` 还是没读成，跟着它的隧道一条也拉不起来，以前只记一行程序日志。现在 `StartBound` 交给 `noteFollowLoadErr`：照跟随启停的写法记一条 `tunnel.start` 的操作记录（来源 schedule、做的人是「跟随服务器」、参数只有实例名，因为不知道是哪几条隧道，错误里写「隧道配置读不出来，这次没有拉起跟随启动的隧道」再接读不出来的原因），再在服务器的控制台里说一句。隧道层够不着服务器，所以加了 `SetInstanceConsole`，由操作层在 `catalog.New` 里和 `SetAutoHook` 一起接上。`TestStartBoundRetriesLoad` 原来断言没读成时什么记录都没有，这正是要改的行为，改成要收到这一条、控制台里也要有那句，后面「读成以后照常去拉」那一半没动。

**A57（`57bd748`）。** 先核实了后端：`Manager.Add` 写不进磁盘时把内存里的列表和编号都退回去（`TestAddFailsAndRollsBackWhenSaveFails`、`TestAccountImportAndCreateReportSaveFailure` 守着），界面刷新不会看到一条其实没存的隧道，这一半不用改。再看界面：「在平台上创建并导入」的对话框其实已经是请求途中按钮禁用、失败后按钮恢复、成功后关掉并刷新概览，缺的是两样，失败原因只弹一下提示、不在对话框里，失败后也不刷新概览，平台上已经建好的那条要收起概览再展开才看得到。现在原因写在对话框的报错位置（`errInline`，正文接后端给的那句人话，原文在复制键里），失败后后面的概览重新拉一次；等的时候对话框已经被关掉的，照旧弹提示。手动「添加隧道」的按钮原来完全没有防连点，连点两下会加出两条，现在请求途中禁用。写不进磁盘那条老界面用例原来断言的是提示，跟着改成断言对话框里的原因和复制键里的原文。

这里有一处照任务单做、但我拿不准的：平台上已经建好、只是本机存不上时，任务单要按钮恢复可点，可再点一次就会在平台上再建一条。后端给的那句话里写了「不要再创建」，界面没从按钮上拦。要拦的话可以让后端在这种报错里多给一个记号，界面认它锁住按钮，交主会话和作者定。

**A62（`509a5e5`）。** 添加表单、导入对话框、平台上创建的对话框三处的「跟随服务器启动」都改成默认不勾。编辑对话框照存着的值，没动。后端新建隧道（`tunnel.add`、`tunnel.account.import`、`tunnel.account.create`）没传这一项时本来就是不跟随（布尔零值），AI 和 MCP 不能新建隧道。音乐共享页那几句「勾上『跟随服务器启动』」在默认不勾以后正好成立，没改。「减少动态」那条导入用例原来靠默认勾着拿到 `autoStart: true`，改成在用例里勾上，它要验的「弹窗立刻移除时也带得出勾选的值」不变。

**A60，核实后不改。** 现在能改隧道的入口和各自能改什么：

界面上的「编辑」只发改了的名称、绑定、跟随启动三项；「清除凭据」只发 `clearCredential`。后端 `PUT /api/tunnels/{id}` 走操作 `tunnel.update`，它是「仅人工」、不是「仅本机」，能改 `Patch` 里的全部字段（服务商、名称、凭据、隧道 ID、frps 地址和端口、公网端口、本地端口、绑定、跟随、用途、协议）外加 `clearCredential`。谁能调：本机界面、本机别的程序带着令牌调开放接口、局域网里登录了的设备都能；应用内 AI 助手、MCP、游戏内 AI、AI 伙伴、定时任务都被 `ops.allow` 按「仅人工」拒掉，它们手里只有读列表（不含凭据）和启停隧道（要人确认的提案）。平台账户那一组（创建、导入、连接）是「仅本机」，局域网碰不到。

要不要拦局域网改凭据、改服务商：局域网本来就能用 `tunnel.add` 新建一条任意服务商、任意凭据、任意 frps 的隧道，也能删，所以单拦修改堵不住什么。修改里真正危险的是「借着沿用存着的凭据，把它送到别的服务器去」，这一条 `replaceLocked` 早就挡着：换了服务商、或者自定义 frps 换了地址或端口，凭据留空一律回 400，要重填。我又逐个看了凭据沿用时还能改的几项：OpenFrp、樱花的隧道 ID 是作为单独的一个参数交给服务商自己的 frpc，连的还是服务商的服务器；自定义 frps 的本地端口、公网端口、协议改了，令牌去的还是同一台 frps；地址还要过 `checkServerAddr`，本地端口不能是 MineDeck 的网页端口。没找到「不该能改却能改」的入口，按任务单不改。清账计划书里那句「后端只许编辑改名称、绑定、跟随」和阶段文件不一致，以阶段文件为准；真那样收紧，会断掉 `API.md` 写明的修改接口、现有的 PUT 用例和「清除凭据」按钮。

**A61，核实后不适用、没做。** 编辑对话框里没有凭据输入框，上面还写着「服务商、地址、端口和凭据不在这里改」，编辑时根本改不了凭据，也就没有提醒的位置。11-17 发 v3.2.0 时复审已经指出「编辑时也提醒」的说法不对，发布说明改成了「添加隧道时提醒」。要做这条得先定编辑里能不能改凭据，那是新功能，方向也和 A60 相反，没自己加。

## 验证了什么
