# 2026-11-22 至 11-23 清账阶段 01 到 05 的审核（Claude 写）

## 要做什么

作者 11-22 定的分工：清账的活都交给 Gemini 4 Carbon（作者自己在 Antigravity 里交），Claude 只负责每个阶段的审核，代码问题写成返工单交回去。复审由作者点名派 Claude 的 `reviewer` 子代理，模型和思考档由作者指定。

这份日志记阶段 01 到 05 审核这一侧的经过：复审结论、主会话替作者定的事，以及对执行者日志的更正。各阶段改了什么，看执行者自己写的日志（`2026-11-22-阶段01-…` 到 `2026-11-23-阶段05-…-返工1`）。

阶段文件、返工单、审核记录都在本机工作树的 `.claude/tasks/` 下，不进仓库。下面提到的「R1」「R2」是返工单里的条目编号，读仓库的人查不到。为了能对上号，这里照实写出它们各指什么。

## 做了什么

每个阶段的流程都一样：
1. 执行者交回提交和汇报以后，主会话先查范围：改动的文件在不在允许范围里、提交说明有没有署名行、入库内容有没有本机路径。
2. 派复审，复审方回来以后，主会话亲自读它点名的代码再下结论。
3. 过了就在待修清单上勾掉、推分支；不过就写返工单。
4. 留下的小问题不值得再返工一轮时，并进下一阶段提示词的开头，单独一个提交。

五个阶段都返工了一轮，第二轮都过了。

**阶段 01（测试本身的毛病）**：
- 第一轮 Fable max，第二轮 Fable xhigh。
- 第一轮挡过关的是 diskguard 那条测试拿被测函数自己当裁判，测不出它坏掉。
- 复审方顺手查到 11 处建目录联接失败就无条件跳过的测试，记成 B07，一起改了。
- 定下的规矩：`CI` 环境变量有值时，建不了符号链接或联接要失败，不许跳过。这样 GitHub 的 Windows 机器上这些测试真跑到了（推分支以后 CI 绿，证明建得了）。

**阶段 02（文件写入、锁和重试）**：
- 第一轮 Fable max，第二轮 Fable xhigh。
- 第一轮挡过关的是备份「先建 0 字节占位、再换上去」。占位文件被杀毒、索引之类开着超过半秒，备份就白做，还可能留下 0 字节的 `.zip`。复审方在仓库外复现了。返工改成 Windows 上用不覆盖的改名一步发布。
- 单实例检查原定等 10 秒。主会话读了换 exe 的脚本：新进程只在旧进程退出以后才被拉起，用不着等那么久，就改成 3 秒；带 `-nogui`、`-minimized` 时不弹框，以退出码 1 退出。这是主会话改了自己替作者定的规格。

**阶段 03（清临时文件的规则）**：
- 第一轮 Fable max，第二轮 Fable xhigh。
- 第一轮要返工的三条，都在决定「到哪里删、删什么名字」：
  - 清理自己去读配置文件找备份文件夹，和程序认的不一致。
  - 名字校验、备份根是联接这两处保护没有测试守着。
  - 随机段放宽到 24 位，`CreateTemp` 实际最多 10 位。
- 主会话放开了 `cmd/minedeck/main.go` 的 `sweepStaleTemps`，让程序把备份文件夹和服务器名传进去。
- 第二轮过关以后，复审又查到带前导零、或大于 4294967295 的数字名也会被清。并进阶段 04 开头修掉了；A21 等那段审过才勾。

**阶段 04（开服和服务器设置）**：
- 第一轮 Fable max，第二轮 Fable xhigh。
- 第一轮挡过关的两条，都出在新加的「系统保留端口」判断上：
  - 把 netsh 里带 `*` 的「管理的端口排除」也当成了保留段，绑得上的端口起不了服。复审方在本机复现了：改动前照常起服，改动后报「被系统保留」。
  - netsh 在实例锁里跑，最多 6 秒。
- 返工改成开服以试绑为准，只有试绑报权限错误时才查 netsh；放锁查完再重拿锁。
- 第一版运行中拨游戏规则开关发出去的规则名不对。是执行者自己在汇报里提出来的，返工按版本改了。

**阶段 05（接管和 log4j 的边角）**：
- 第一轮按作者要求派 Opus max，这一轮起复审单列「可维护性」一项；第二轮 Fable xhigh。
- 第一轮挡过关的是两处新带进来的回归，新旧两版对照确认：
  - 官方日志配置已经在盘上，程序启动时那一遍整理也要联网。
  - 经目录联接登记、真实文件夹又在存放根下的服务器，删除只删掉联接，重开又回来。
- 第二轮过关以后，接着合进 main 发了 v3.2.5，见 `2026-11-23-v3.2.5正式版和改许可证`。

**主会话替作者定的，都可以否决，计划书「替作者定的」一节都有**：
- 单实例等 3 秒，`-nogui`、`-minimized` 不弹框。
- 新建、导入提交时，被自家另一台服务器占着端口一律只提示、不拦（第一版对开着的那台回 409，复审时改回走查 R08 的规矩）。

- 接管时不摘 `.bak` 里的旧日志配置引用。
- 阶段 05 返工 R2：同一个真实文件夹用存放根下的路径。

**可维护性**：11-23 作者说「你以后可是要长期和我维护这个仓库，你自己注意可维护性」。主会话查了前四个阶段入库的代码，查到这几处：
