## 做了什么

代码已提交于 `7888f91`（分支 `gemini/v328-stages`）。

**A84（严格 SemVer 比较）**：在 `internal/update/update.go` 的 `parseVer` 中去掉 `strings.ToLower(pre)`，直接保留原始大小写拆分预发布段，与 `tools/ui-dev/server.js` 的 `parseVer` 和 `docs/设计与参考/API.md` 的文档说明保持一致。`internal/update/update_test.go` 里原有的一条 `{"3.2.0-Beta.2", "3.2.0-beta.1", 1}`（当时注释为「大小写不算」）按严格 SemVer ASCII 序（`'B' < 'b'`）改为 `-1`，另加大小写对比以及 SemVer 2.0 规范示例链（`alpha` 到 `1.0.0`）和 `docs/releases/` 全部 22 个现有发布标签（`v2.9.0-beta.1` 到 `v3.2.6`）的两两矩阵测试。

**A80（稳定渠道跳过误标 Latest 的预发布）**：在 `internal/update/update.go` 抽出 `isStableRelease`（非草稿、非 `Prerelease`、标签符合版本号格式且 `!isPre(TagName)`）与只拉第一页 `per_page=30` 的 `fetchReleasesPage`。当稳定渠道调 `/releases/latest` 拿到的发布不满足 `isStableRelease` 时，退回 `fetchReleasesPage` 在第一页列表里挑版本号最大的 `isStableRelease`；如果这一页全都是预发布或草稿、一个正式版也找不到，直接返回 `&Release{Channel: app.UpdateStable}, false, nil`（当作没有更新，不报错）。同步修正了 `internal/ops/catalog/appops.go` 的 `checkResult` 中 `"ahead": rel.Tag != "" && update.Newer(current, rel.Tag)`（否则回退找不到正式版、空 `Tag` 会使 `compare(current, "") > 0` 把 `ahead` 误算成 `true`），并在 `tools/ui-dev/server.js` 的 `updateCheck` 和 `internal/web/ui/app.js` 的 `updateResultText` 里补齐没有正式版时的提示分支。

**A79（允许切回「跟随当前版本」）**：核实了 `internal/app/app.go` 的 `UpdateChannelFor(choice, version)`：传入 `""`（没选过）时每次按当前运行版本动态定渠道（测试版跟随 `latest`，正式版跟随 `stable`，以后从测试版升回正式版还会自动跟回 `stable`），而选了 `stable` 或 `latest` 就会固定落盘。以前 `internal/ops/catalog/appops.go` 的 `app.config.set` 用 `.OneOf(app.UpdateStable, app.UpdateLatest)` 拒收空串。本次放开 `.OneOf("", app.UpdateStable, app.UpdateLatest)`，传 `""` 时清空 `UpdateChannel` 且因 `omitempty` 不在 `config.json` 落盘；在 `app.js` 的 `setAbout` 增加第一项单选 `跟随当前版本（默认）`（`data-ch="auto"`，点选时发送 `{ updateChannel: "" }`），同步更新 `tools/ui-dev/server.js`、`docs/设计与参考/API.md`、`internal/ops/catalog/update_channel_test.go`、新增 `internal/web/update_channel_http_test.go` 与 `tools/ui-dev/tests.js`。

**A78（启动后台更新检查日志写渠道与界面不打扰提示）**：在 `internal/update/update.go` 新增 `StartupNotice`、`StartupUpdate()`、`ClearStartupUpdate()`、`ChannelLabel` 与 `RunStartupCheck`。`cmd/minedeck/main.go` 启动检查 goroutine 改调 `update.RunStartupCheck`，按配置渠道记下「稳定版渠道：已是最新 v...」「测试版渠道：有新版本 v...（当前 v...）」或带渠道的失败日志；查到新版本时将摘要存进内存，待切换渠道、手动 `检查更新`（或无更新结果）、开始更新时自动清除。为不打扰且不破坏 `internal/web/routes_test.go` 对 62 个 HTTP 路由数的校验，直接复用已有 `GET /api/app` 返回可选字段 `startupUpdate`；前端 `index.html`、`app.css`、`app.js` 在侧栏「设置」按钮（改用 `<i class="nav-dot">` 避开 `app.css` 窄窗下 `.nav-item span { display: none }` 隐藏文本规则）与设置二级导航「更新与关于」加上小圆点，「更新与关于」页内显示「启动时查到新版本 X」与「查看」按钮（无弹窗），点「查看」后收起通知与圆点并在 `#up-result` 展开版本与更新按钮。
