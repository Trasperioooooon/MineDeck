## 左栏分类按重要程度排

作者的意思是十个分类按重要程度排，内网穿透往上放，不分组也不收起。主会话排成：内网穿透、下载与网络、Java 运行时、存储位置、AI（可选）、手机远程管理、通知与集成、启动与托盘、外观、更新与关于。前四个关系到朋友能不能连进来、服务器能不能建起来和跑起来；中间三个是可选的功能；最后是窗口行为、外观和版本信息。打开设置时停在第一个分类。这个先后是主会话定的，作者可以否决。

## 背景图

作者问选了背景图以后程序会变成什么样，又说选完肯定要立刻生效。程序现在的做法是从程序文件夹的 bg 里随机挑一张铺满窗口，上面盖 88% 的底色，卡片照旧是实底，所以壁纸几乎看不出来。草图照这个思路画了出来：整页底下铺图，铺满、居中、不跟着滚；上面盖一层页面底色，深色盖 72%、浅色盖 64%，看得出是一张图，又不和面板抢；面板、底部胶囊、弹窗都是实底，字始终落在实色面上，所以只有版心两边、顶上和胶囊那一排透出图来。外观页点「选择背景图…」整页马上铺上，点 × 马上撤掉。共用件 `kit.js` 加了 `KIT.setBg`，任何一页地址加 `bg=1` 都能看，铺着时点去别的草图页会自动带上。示例壁纸是主会话画的一张方块风景（`design-system/redesign/img/bg-sample.svg`），只用来演示。

只选一张、不再从文件夹里随机，是主会话照「选完立刻生效」定的，可否决。另提了一个可以加的「背景浓淡」，留给作者定。

## 下载与网络

作者嫌这一页太空，问模组下载源、Forge 这类核心的下载源、音乐共享的下载源、MineDeck 的更新下载源能不能都挪到这里。主会话查了程序：真正能设的线路只有一项（`config.source`），管服务端核心和 Java；模组和插件只从 Modrinth 官方下，AI 伙伴模组和音乐共享要装的 Simple Voice Chat 也是从 Modrinth 下，都没有选项；软件更新只走 GitHub，界面上是「更新与关于」页的「更新仓库」框。另外有两样现成的东西没有界面：导入整合包时逐个确认过的下载站点（清单 A81，想要一个取消的地方），以及计划里说要加的下载缓存清理。

所以这一页重画成六项，交给一个子代理画（Claude 子代理 fable-high，环境声明的模型是 Fable 5.2，独立工作树），主会话审过以后合进来。第一排是「服务端核心与 Java」和「模组与插件」，第二排是「软件更新」和「CurseForge API Key（选填）」，三条线路都是三段分段，点了马上生效，覆盖哪些下载写在名字的悬停里。模组与插件的国内镜像用 MCIM（社区维护的 Modrinth 镜像），伙伴模组、Simple Voice Chat、整合包里的 Modrinth 文件都跟着这一项走。软件更新是「自动 / 仅官网 / 仅 GitHub」，照 11-27 已经定了的更新改法：官网和 GitHub 都查、取较新的，校验值以 GitHub 为准。一道细线下面是「信任的下载站点」和「下载缓存」：站点一行一个，点 × 马上移除，下次遇到会重新问；缓存显示总占用和分项，清理前用共用确认框问一句。「更新与关于」拿掉了「更新仓库」框，更新渠道和启动时检查更新留在原处。

这四样程序都还没有，改程序时要补后端：模组的镜像线路和设置、软件更新的线路选择、信任站点的列表和删除接口（数据已经有）、缓存按核心、Java、模组分项统计和清理。MCIM 动手前要先核实能不能用、使用条款怎么写。加信任站点和下载缓存、拿掉「更新仓库」框（给自己编译分支的人改配置文件里的 updateRepo）都是主会话替作者定的，可否决。

主会话审的时候补了两处：「仅国内镜像」那一段的悬停原来只写了 Paper、Purpur 没有国内镜像，和名字悬停里列的四个不一致，补成 Paper、Purpur、Leaves、Mohist（第一次打开的引导页里同一句也改了）；「更新与关于」页自己的那套确认框换成了全站共用的 `KIT.confirm`，规范第九节说改到哪页顺手换。
