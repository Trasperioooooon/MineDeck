## 2026-11-15 开发文件夹里不再放能运行的程序（Claude 写）

作者的意思是：开发文件夹只放源码，测试用的程序和它跑出来的数据，以后一律放到开发文件夹外面。

数据为什么会落进仓库：`internal/app/app.go` 的 `Init` 拿 exe 所在的文件夹当数据目录，用 `go run` 跑的时候退回当前目录。所以在仓库根目录编个 exe 跑一下，或者在根目录 `go run ./cmd/minedeck`，仓库里就会长出 `servers`、`backups`、`runtimes`、`cache` 和 `config.json`。`.gitignore` 挡着它们不入库，但它们会一直堆在源码旁边。README「参与和构建」里的调试构建命令，也是编在当前目录。

这次清掉的东西都移进了回收站，没有永久删除：根目录的 `AutoMCHUB.exe`（7 月的 2.6.1）、`MineDeck-beta2-fix.exe` 和 `minedeck.exe`（都是 11 月 2 日编的）；`cache` 文件夹，里面只有 `javas.json` 和一张 `vision_probe.png`；还有三个空文件夹 `runtimes`、`servers`、`backups`。动手之前查过，没有进程在跑这几个 exe，注册表的开机启动项、桌面和开始菜单的快捷方式、各家 AI 工具的 MCP 配置、`tools/` 和 D 盘几个测试文件夹里的脚本，也都没有指向它们的。

根目录的 `config.json` 先留着问了作者，作者说删，随后也移进了回收站。它是 7 月作者在仓库里实际用 MineDeck 时生成的：打开了局域网访问，设了访问密码，更新源还写着旧名 AutoMCHUB，已经没有程序在用它。以前的记录说清理时不能删它，那是因为当时作者真的在仓库根目录用这份程序，这条现在作废了。仓库根目录现在只剩入库的源码，加上 `.claude` 这类 AI 工具目录。

以后照这样做。要跑起来看的程序，用 `go build -o` 编到仓库外面的文件夹，在那边运行；不在仓库根目录运行任何 exe，也不在根目录 `go run ./cmd/minedeck`。工具要数据目录的，参数指到外面（`tools/worldimport-realtest` 本来就要求 `-base` 指一个专门的测试文件夹）。子代理和别家 AI 编出来的测试程序放在会话的草稿目录或 D 盘的测试文件夹里，用完删掉。现在放在外面的有这几处：`D:\MineDeck` 是作者自己从头试用的那一份；`D:\MineDeck-v310-test`、`D:\MineDeck-wi-test`、`D:\MineDeck-ux` 是前几轮测试用的，脚本和程序都在那边。新的测试照这个样子，在 D 盘另开一个文件夹。

这一节没有改代码，也没有改 README。README 里那两条构建命令仍然编在当前目录，对一般贡献者来说没问题；要不要改成编到外面，要不要加一个双击就把当前源码编到外面并启动的脚本，等作者说。

同一天看到、但不属于测试环境所以没动的：`tools/promo/` 下三个 `out` 文件夹合计约 1.7 GB，是宣传片和演示视频的渲染输出（v3.1 那支还没发布）；`.claude/worktrees` 里的四个工作树；`.agents`、`.review`、`.mimocode`；`tools/ui-dev/node_modules`（工作树跑界面测试时要借用它）。
