## 2026-11-14 「仅本机」要带令牌，隧道不许指向网页端口，操作记录脱敏补漏（Claude 写）

这两处是 11 月 14 日用 Codex（gpt-6-astra，max）复审外部贡献 PR #13（OpenFrp、樱花的平台账户）时发现的，问题都在 main 原有的公共代码里，不是 PR #13 带进来的，所以单独开了分支 `claude/local-needs-token-redact-fix` 来修。PR #13 那边已经做了局部的缓解（平台账户创建和导入时拒绝指向网页端口的隧道，概览改成仅本机），这里修的是根子。

### 第一处：经隧道转发能冒充本机

以前判断「是不是本机」只看连接地址是不是回环（`callerOf` 里的 `isLoopbackReq`），而开了局域网访问以后，接口又认局域网的会话 Cookie。两样放在一起就有个口子：局域网登录的人可以用普通的隧道接口建一条自定义 frps 隧道，把公网端口转到 MineDeck 自己的网页端口上，启动以后带着 Cookie 从隧道进来。frpc 跑在主机上，它转进来的连接地址就是 127.0.0.1，于是打开目录、选文件夹、AI 设置、复制 MCP 配置（里面有 MCP 令牌）这些「仅本机」的操作全都放行了。

现在算本机要两样都有：连接来自本机，并且请求带着这次启动的网页令牌（请求头 `X-Token` 或查询串 `?token=`，比较用定长比较）。令牌只出现在本机窗口打开的启动地址里，局域网登录拿不到它，这个会话也查过没有接口会把它下发出去（只在启动时写进进程的标准错误，正式版是窗口程序，没有控制台也没有日志文件）。只带 Cookie 的本机请求按局域网算，操作记录里记作 `lan`、地址 127.0.0.1。本机窗口和用启动地址打开的浏览器一直带着令牌，不受影响。

有一处用法会变：在本机的浏览器里不带令牌打开 MineDeck、用访问密码登录，以前算本机，现在只有局域网会话的权限，选文件夹、改 AI 设置这类操作会被拒。要本机权限就从窗口里打开，或者用带 `?token=` 的启动地址。

另外在隧道层加了一道：自定义 frps 隧道的本地端口如果等于 MineDeck 这次的网页端口，新增、修改、启动都拒绝，跟随实例启动也走同一个检查（`tunnel.Manager.SetGuardPort`，由 `catalog` 的 `tunnelOps` 按 `Env.Port` 设好）。启动时再查一遍，是为了兜住以前存下的隧道，以及默认端口被占用、这次换了随机端口的情况。樱花和 OpenFrp 的本地端口填在服务商后台，MineDeck 看不到，这一道拦不住它们；真正堵住口子的是上面的令牌规则，这一道只是不让人把管理界面随手摆到公网上。

### 第二处：操作记录的脱敏漏了同层字段

`redact` 认出一个对象是 `{"key":…, "value":…}` 这种键值对以后，就只按 `key` 判断 `value` 要不要遮，同一层别的字段不再按名字查，所以 `{"key":"motd","value":"x","token":"…"}` 里的 token 会原样写进操作记录（交给 AI 的工具结果也用同一个函数）。现在两条规则各管各的：键值对的 `value` 按 `key` 判断，其余字段照常按自己的名字判断。顺带把 `authorization` 加进了密钥名单。

Codex 复审时还指出一处 main 原有的歧义，这次一并修了：键值对是按「有 key 又有 value」认的，而 AI 设置（`ai.provider.set`）的 API Key 恰好就叫 `key`，参数说明又不拒绝多余的字段。本机的程序调接口时多带一个 `value`，API Key 就被当成键名原样记进操作记录，局域网会话是能看操作记录的。没有哪个操作的参数本身就是一组键值对（server.properties 的键值对都放在 `pairs` 数组里），所以操作记录现在对参数最外层的 `key` 一律遮住（`oplog.go` 的 `redactArgs`），里面嵌着的键值对照旧保留键名。交给 AI 的工具结果用的 `ops.Redact` 没动。

### 复审

代码提交 `8de04b2` 请 Codex 只读复审了两轮，由发起这个任务的会话来跑，请求的模型是 gpt-6-astra，思考档 max。客户端的会话记录里写的也是这个模型，但 Codex 自己只说「基于 GPT-6」，服务器那边实际跑的是哪个模型，算「未确认」。第一轮正常跑完，结论是两处都修好了，没有必须改的，和 PR #13 也没有语义上的冲突。它提了四条建议：上面那处 `key` 的歧义（已修）；API.md 写清楚本机的两个条件和用密码登录的本机浏览器会怎样（这次的文档已经写了）；补几条集成测试（已补：带 `?token=` 的 SSE、非默认端口、键值对里再嵌键值对；PR #13 账户接口只带 Cookie 被拒的测试要等它合进来再加）；平台隧道启动时不再查端口（这条不会让本机绕过重新出现，见下面「还留着的事」）。第二轮专门查局域网会话能不能拿到网页令牌，跑到一半被 OpenAI 的内容过滤打断（报的是「可能有网络安全风险」），没有出最终报告。发起会话没有换说法重试，也没有去申请放宽，这要作者来定。它没跑完的几处，由发起会话对着代码自己核过了。复审以后补的那个提交（`29bb16c`：最外层 `key` 的修法、补的测试和文档）又请 Codex 只读看了一轮短的，模型设置同上，实际模型同样未确认。结论是可以合并，没有必须改的，也没有建议改的；它单独查了一遍，带最外层 `key` 的只有 `ai.provider.set` 和 `ai.models.list`（后者不写操作记录），两处都是 API Key，不会多遮。它提了一条可选的：给最外层 `key` 是 null、真假值、数字、对象，参数为空，以及拒绝带 `key` 的提案这几种情况补测试，代码本身它判断是对的，这次没有补。原始输出放在会话之间共享的笔记文件夹里，不在仓库中。

### 访问密码就是对这台电脑的信任

第二轮在被打断前找到、发起会话又核实了的一条，比这次修的口子更根本：知道访问密码的局域网用户，能上传任意 jar 当模组（`modcart.local.add` 不限本机）、改 JVM 参数（`instance.settings.set`）、再开服，这就是以当前 Windows 用户在主机上运行代码，想读网页令牌也好、做别的也好都拦不住。所以对一个存心作恶、又知道访问密码的人，「仅本机」不是硬边界，访问密码本身就等于对这台电脑的信任。这次修掉的是不用运行代码就能绕过去的那条路，仍然值得修。API.md 和功能清单里加了一句「访问密码只给愿意让他用这台电脑的人」。要不要收紧局域网用户能做的事（比如上传模组、改启动参数改成仅本机），是产品上的决定，留给作者。

### 验证

回归测试都放在新文件里，免得和 PR #13 改的测试文件冲突。`internal/web/localtoken_test.go` 从本机地址真的登录一次拿到 Cookie，再试只带 Cookie、Cookie 加上界面的请求头、加上隧道的 Host、加上错的令牌，都不算本机；带令牌的、只带 `?token=` 的算本机；外部 AI 的提案事件流（SSE）只带 Cookie 连不上，带 `?token=` 连得上；网页接口新增、修改指向网页端口的隧道被拒。`internal/tunnel/guardport_test.go` 试新增、修改、手动启动以前存下的隧道和跟随实例启动，都拿假的 frpc 跑，不会联网，也不会真起进程。`internal/ops/catalog/guardport_test.go` 让网页端口是 41234，确认守的是这次实际的端口，不是写死的 27333。`internal/ops/oplog_redact_test.go` 管脱敏的两处。每个测试都反着试过：把对应的那处检查去掉（隧道那组是新增、修改、启动三处分别去掉），测试都会失败。

最终的工作树上，`GOOS=windows go build ./...`、`GOOS=windows go vet ./...` 和 `go test ./...`（34 个包）都过了，gofmt 干净。`tools/ui-dev` 的 `npm test` 131 条全过，借用的是主检出里装好的 Playwright 1.63.0（`NODE_PATH` 指过去），这个工作树没有另装依赖。真窗口里没有试过。
