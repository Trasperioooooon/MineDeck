# 2026-11-21 官网重新部署

## 要做什么

作者问「官网更新部署了吗？」，主会话查过没有（minedeck.cn 还是 11-18 晚上那一版，显示 v3.2.2，文档中心是 404），作者说「Deploy it」。第二次发布被自动切回以后，作者说「Switch it, and skip the download step in the future—let the server perform the verification itself.」

## 做了什么

照 `2026-11-18-官网重新部署` 的做法，用仓库外的发布脚本按 main 上的 `website/`（`28fba8f`）构建发布。这一版带上了 v3.2.3 的版本号和下载、11-19 合进来的文档中心、Java 那篇 log4shell 的改正，以及 PR #31 在功能页上把 Banner 改叫 Taiyitist（原 Banner）。

第一次在上传之前就停了：发布脚本自带的产物检查把「localhost」当成开发时的残留，而文档中心的正文要写到它（Ollama 默认的 `localhost:11434`、MCP 只收本机请求），一共六处，都是该写的。这条检查是 11-18 写的，那时还没有文档中心。主会话把它改窄：页面里的链接和资源指向本机地址才拦，正文里提到不拦；拿一份塞进本机链接的产物试过，确实拦得住。

第二次上传、切换都成了，从本机经公网把全站 182 个文件取回比对没有问题，88 个镜像链接的状态和大小都对，服务器上按 GitHub 给的 SHA-256 全量核对镜像也通过；只有最后一步「从本机把最新版的 MineDeck.exe 完整下载一遍」在十分钟上限上超时，脚本按设计把站点切回了 11-18 那一版。和 11-18 那次是同一个原因：这台电脑在日本，到国内这台服务器只有约 30 KB/s（同一个文件从 GitHub 下约 1 MB/s），18 MB 的程序要十分钟上下。

作者同意以后，主会话把站点手动指到刚传上去的新版本目录，上一版的回退记录照旧指着 11-18 那一版。然后照作者说的改发布脚本：最新版镜像文件的完整下载不再从本机做，改由服务器经自己的 Nginx（真域名、真证书，解析到本机回环地址）把每个文件下一遍，逐个对 GitHub 给的 SHA-256，几秒钟就完；本机这头仍查全站文件和每个镜像链接的状态、大小。另加了一个只核对、什么都不改的跑法，手动切过版本以后可以拿它再查一遍。切换以后从本机取全站时又碰上一次连接超时（一张图片），所以本机这头取全站文件和查镜像链接时，连不上、超时会隔两秒再试，最多三次；状态码不对、内容不一致照旧算失败，不重试。这些改动都在仓库外的部署目录里，改之前留了备份。

拉下来的版本数据（`website/data/` 的四个文件：多了 v3.2.3，星标数、活动统计跟着更新）照 `website/README.md` 说的随这份日志提交。

## 谁做的

主会话：Claude Code 桌面端，Claude Opus 5.5。没有委派。

## 验证了什么

- 构建：139 个页面，站内引用 10620 处、失效 0 处，镜像链接 88 个和 Release 的文件一一对应，占位字样 0。
- 服务器上的新版本目录 183 个文件；v3.2.3 的 MineDeck.exe 在服务器上算出来的 SHA-256 和 GitHub 公布的一致。
- 新的服务器端下载核对：v3.2.3 的四个文件经 Nginx 下载、校验通过，约 4 秒；故意给错校验值、请求一个不存在的文件，都会失败退出。
- 发布脚本改完以后在 Windows PowerShell 5.1 和 7 下都解析通过，仍是纯 ASCII。
- 手动切换以后：先从本机取回全站，182 个文件里 181 个对上，一张图片连接超时，单独重取一次和构建产物一模一样。然后用改过的发布脚本「只核对」跑了两遍（第二遍已带上重试）：两遍都是全站 182 个文件 0 问题，88 个镜像链接状态和大小都对，服务器端把 v3.2.3 的四个文件经 Nginx 下载核对通过。
- 重试的反向检查：把站点地址指向一个拒绝连接的端口，每个文件试三次（约 4 秒）以后照样报失败、退出码 1。

## 没做完或没验证的

- 本机到镜像的慢只量了一次（30 KB/s），国内用户实际从镜像下载的速度没人实测过。
- 服务器端核对走的是本机回环，查的是文件、Nginx 配置和证书；国内公网到这台服务器的连通性它管不了，本机这头的 HEAD 只证明从日本连得上。
- 英文文档还有 27 篇是回退页（构建时的提醒），反馈页的「直接提交」通道还没开，和 11-19 时一样。

## 留给下一位的

- 以后发版后更新官网照旧跑发布脚本；它不会再因为本机下载慢把好好的新版本切回去。手动切过版本，就用只核对的跑法再查一遍。
- 旧的版本目录不会自动删，服务器上现在有四份，每份几 MB。
