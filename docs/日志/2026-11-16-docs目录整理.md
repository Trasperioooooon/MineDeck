# 2026-11-16 docs 目录整理

## 要做什么

作者原话（本机路径换成了仓库里的相对路径）：「现在来整理一下仓库的 docs 的文件，现在这个根目录下面有很多单独的，这个 docs 目录下面能不能只留下三份最重要的，其他过时的都收入文件夹？」

## 做了什么

`docs/` 根目录原来散着 30 份文件。现在根目录只留三份：`现状.md`（接手的人第一个读的）、`待办.md`、`功能清单.md`（README 链着它，是产品功能的全貌）。其余的按用途收进文件夹，全部用 `git mv`，`git log --follow` 能看到以前的历史。

- `设计与参考/`：API.md、frp-account-api-notes.md、MC自动化开服技术实现方案与版本映射表.md、地图导入-设计.md、AI与音乐共享功能设计.md。这几份代码注释和 README 还在引用，不算过时，只是不该摆在根目录。
- `使用指南/`：接收者上手指南.md、好友测试指南.md、地图导入-使用说明.md。
- `测试与评审/`：测试计划.md、四份测试报告、v3.1.0-发版清单.md、四份评审、评估-核对路径以后被换成联接的竞态.md，还有可用性走查-2026-11-14.md 和它的证据文件夹（两样放在一起，报告里指向证据的相对链接不用改）。
- `调研/`：原来的 `research/` 整个并进来（world-import-compat.md、dataversions.json、os-root-实验），加上 Frp服务可行性调研.md、UI与体验改进调研报告.md、工具箱-调研.md、竞品分析与产品路线图.md、推广计划.md。
- `归档/`：交接说明.md（11-16 起只剩一页指路）、TODO.md（v2.1.0 时期的施工清单，只有末节「地图导入的后续」还被待办引用）。
- `日志/`、`releases/`、`images/`、`文案重写/` 原样不动。`releases/` 和 `images/` 是 CI 发版和官网部署读的固定位置，不能挪。

## 验证了什么

- 根目录只剩三份 md 和九个文件夹。
- 链接：扫了 README 和 docs 下除日志、发布说明以外所有 md 里的相对链接。整理前就有 173 条打不开（两份评审记录里指向本机工作树的绝对路径，和一份评审里按仓库根目录写的 `internal/...` 链接）；整理新弄断的 6 条已经补上 `../` 或文件夹名，再扫一遍，除了那些整理前就打不开的，没有别的断链。
- 已发布的东西：旧版本发布说明里的文档链接都钉在标签上（`blob/v3.1.0/docs/...`），指向那个版本的旧位置，照旧能打开。只有 v3.2.0-beta.1 的发布说明链的是 `blob/main/docs/地图导入-使用说明.md`，GitHub 上那个版本页面里的这条链接会打不开；仓库里的发布说明文件没改，GitHub 上的发布页面也没去改。官网两条链接改到了新位置，推到 main 会触发官网重新部署。
- 代码：改动的 Go 和 JS 文件 `git diff` 逐行看过，全是注释；`go build ./...`、改到的七个 Go 包的 `go vet`、四个 JS 文件的 `node --check` 都通过。界面测试和 Go 测试没跑，只改了注释。
