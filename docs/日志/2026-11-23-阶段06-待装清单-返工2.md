# 2026-11-23 阶段 06 待装清单（第 2 轮返工）

清账阶段 06 第 2 轮返工。第 1 轮返工的功能复审都过了，挡住过关的是可维护性：给草稿清单加的那条安装路径（详情页横幅上的「一起装上」），把「全部安装」的查前置、装前核对、弹确认框发安装三段几乎逐行抄了一份，而且这份重复已经出了一个 bug。同一轮一起改的还有：草稿清单的目标记号混在「加项目」的读操作里，AI 能随手记、删服不清、核心原样存；删服务器到最后放行时的日志说法太绝对；A31 的界面用例是一条大用例；几处测试帮手和注释的小毛病。

这一轮起执行者从 Gemini 换成了 Claude 子代理，由主会话派活、另一个 Claude 子代理复审。

## 做了什么

都在分支 `claude/clear-backlog-1122` 上，基准是 `14b40a0`。

**草稿清单那条安装路径不再另抄一份（A29、A31）。** `internal/web/ui/modcart.js` 里原来有两套前置检查：只查这台清单的一套，连同草稿清单一起查（`includeDraft=true`）的一套，各有自己的结果、签名、序号和在途请求，装前核对和安装也各写了一遍。现在把「一路前置检查」做成一个小工厂 `depChecker`，两路各建一个，差别只剩查询串、签名和回来以后画哪儿；装前核对 `ensureFresh` 和发安装 `installFrom` 两条路径共用，「全部安装」和「一起装上」只是传的参数不同（哪一路检查、取哪份快照、提示里说再点哪个按钮、要不要带 `includeDraft`）。快照也收成了 `cartSnapshot` / `withDraftSnapshot` 两个函数，签名从快照算，原来手写的两份签名就不要了。

那个 bug 是这样的：详情页有「新建时挑的 N 项还没装」横幅、这台自己的清单里又有带必装前置的模组时，点「全部安装」，在确认框里点「先不装」，横幅上的「一起装上」「不要了」一直停在禁用。原因是查前置回来重画横幅时按「正在安装」把按钮画成了禁用，而「全部安装」那条路恢复时只恢复它自己那个按钮。现在「正在安装」只有一个 `installing`，只在 `installFrom` 里改，恢复时统一调 `paintActions()`，横幅上的按钮也不再自己写 `disabled`，能不能点全由 `paintActions` 定。

顺带的几处：核心的叫法改用 `app.js` 现成的 `coreName()`（取自 `/api/cores`），删掉了另起的那张表，向导里说的「给 Taiyitist（原 Banner）挑的」和核心卡片对得上了，从 jar 里读出来的加载器那张表留着；横幅拆成画一行项目、画一行本地文件、「不要了」三个小函数；拼查询串统一用 `targetQuery`，给它加了一个参数，同名的项可以盖掉（读草稿清单时传 `inst: ""` 就是不带实例名），搜索那一处也一起换了。`buildPanel` 从 703 行降到 605 行（从函数头数到配对的右括号）。

**草稿清单的目标记号拆成单独的仅人工操作（A31）。** 新加操作 `modcart.draft.target`（仅人工，不限本机）和接口 `POST /api/modcart/draft/target`，参数只有 `inst`，只做「记下草稿清单是给哪台新服务器挑的」；它不查这台在不在，因为向导调它的时候服务器多半还在建。`modcart.add` 去掉了 `draftInst`，`projectIds` 恢复成必填，向导改调新接口。AI 助手和 MCP 调不了新操作，往 `modcart.add` 里夹带 `draftInst` 也不算数了。删服务器时（`instance.delete`），草稿清单记的目标正是这台，就用新加的 `modcart.Service.ForgetDraftInst` 把记号清掉，草稿清单本身留着，删别的服务器不动记号；理由和旁边清这台清单的那段注释一样，不清的话以后同名新建、接管或导入一台，就会冒出那条横幅。`modcart.add` 收到的 `core` 在操作层归一成小写、去掉首尾空白，用 `mcsrc.ValidCore` 认，认不出来的核心连同版本都不记（只有版本没有核心，界面用不上），不报错。`catalog_test.go` 的操作登记表只加了这一个名字。AI 工具说明、文件头的风险说明、`docs/设计与参考/API.md` 跟着改了，仿真后端加了新路由，`POST /api/modcart` 照后端去掉了 `draftInst`、同样归一核心，删服时同样清记号。

**删服务器到最后放行时，日志按实际情况说（A121）。** 只剩删文件夹本身失败时照旧放行、移出列表，但放行前再读一次目录：空的照原来说「留了一个空文件夹」；不空的写清还剩几项、头几项叫什么、文件夹在哪，说明可能是删的同时有程序写了文件或者还开着里面的文件；读不出来的也照实说。抽成了 `logLeftInstanceDir`，空和不空各有一条用例。

**界面用例拆开、补齐（A31）。** 原来覆盖好几个场景的一条大用例拆成按功能命名的十二条：向导换核心后「清空草稿清单」「留着」各一条（「留着」那条也验了再回来不重复提示），只换游戏版本也提示，从电脑添加的 Fabric 文件换成 Paper 也提示，点了「跳过这一步」不记目标不装，换成原版不提示不装不记，建服请求发出后切走记下目标、只有那台的详情页有横幅，建服请求还没回来就切走照样记上，记目标的请求失败建服照常装，横幅先离线标对不上的、查完前置标装不上的（本地文件按这台的核心提醒），「一起装上」带 `includeDraft` 和两份清单的并集，「不要了」只清草稿清单、这台自己清单里的项还在。另外为那个按钮 bug 加了两条：横幅在场时「全部安装」点「先不装」、横幅上「一起装上」点「先不装」，三个按钮都要恢复可点。没装上的文件那条用例里原来断言浏览器后退到 `#/tunnels`，把历史栈的老毛病（拦下后退、点取消以后下一次后退会多跳一页）写死了，改成只断言离开了设置页，那个毛病这一轮不修。

**可维护性的小处。** `modcart.go` 里只剩测试在用的 `write()` 删了，测试照加锁的规矩直接调 `writeLocked`，`writeLocked` 的注释补了一句调用方持有锁。`atomicfile/replace_windows.go` 里 `beforeRetry` 的注释改准了，现在 `RetryRemove` 也调它。`delete_windows_test.go` 不再另起一套子进程帮手，改用 `proc_test.go` 现成的 `fakeServerEnv`（测试程序自己扮演服务器进程），设 `cmd.Dir` 占住工作目录，读到第一行就算就绪，关掉标准输入就放开；名不副实的 `atomicRemoveEmpty` 换成直接调 `atomicfile.RetryRemove`。

第 1 轮返工在 `app.js` 的 `navigate()` 开头加了一句：切页时关掉处理面板（没装上的文件）的叠层。那一轮的汇报和日志都没提。复审方查过所有调用处，无害；这里补记一笔。
