# 2026-11-21 界面测试在 Mac 上跑通

## 要做什么

作者换了一台 Mac，在上面跑 `tools/ui-dev` 的全部界面测试时，265 条里有两条「外部链接」的测试只在 Mac 上失败。问作者要不要改成 Mac 上也能过，作者说：「好，改一下」。Windows 那边的提交推上来以后，作者说：「提交并推送吧」。

## 做了什么

只改了 `tools/ui-dev/tests.js` 里的这两条，程序代码没动，和这份日志在同一个提交里，直接推到 main。

- 「外部链接：原生窗口里左键、Ctrl / Shift 点……」：Ctrl 点改用 Playwright 的 `ControlOrMeta`。Mac 上 Ctrl 点是右键，Chromium 只发 `contextmenu` 不发 `click`，所以交给宿主的少了一次，测试数出来 4 个而不是 5 个。Mac 上和 Windows 的 Ctrl 点对应的是 Cmd 点；`ControlOrMeta` 在 Windows 上就是 Ctrl，行为不变。
- 「外部链接：局域网浏览器里……」：原来左键、中键各开一个新窗口，都等新窗口加载完再核对地址。中键开的是后台标签页，在 Mac 上 Playwright 自带的无头 Chromium（headless shell 153）里，这个标签页一直停在空地址，渲染进程随后崩掉（Target crashed），等到 30 秒超时。换成完整版 Chromium 能开出来，但这个标签页的主页面请求不经过 `route`，真的连到了 openfrp.net。所以改成：左键开的照旧等加载、核对地址；中键只确认开出了新标签页，不等它加载；另外在 window 上记下这两次点击，确认都没被页面 `preventDefault`，主窗口也没跳走。

## 谁做的

Claude Code 桌面版（Code 标签页）的主会话，模型 Claude Opus 5.5（`claude-opus-5-5`），思考档未确认。没有委派。

## 验证了什么

都在作者的 Mac（Apple 芯片）上做的。

- 改之前：全部 265 条里过了 263 条，失败的就是这两条，单独重跑能复现。
- 找原因：在 Mac 上用 Playwright 单独试，Ctrl 点只发 `contextmenu`，Cmd 点和 Shift 点都发 `click`；中键开出来的后台标签页在无头 Chromium 里停在空地址，切到前台时报 Target crashed。
- 反向验证：把新加的记录点击那段放到原生窗口模式（有 `hostOpenURL`）里跑，记下的是「click（被拦）」「auxclick（被拦）」，说明页面拦了链接时新断言会失败。
- 改之后：在 PR #31 合进来以后的 main（`28fba8f`）加上这次的改动跑全部，268/268 通过。

## 没做完或没验证的

- 改过的这两条没在 Windows 上跑过。`ControlOrMeta` 在 Windows 上等同于 Ctrl；局域网那条在 Windows 上只是不再等中键开出来的标签页加载，其余断言比原来严。CI 不跑界面测试，下次在 Windows 上跑全量时顺带看一眼（已记进待办）。
- 完整版 Chromium 里中键标签页绕过 `route` 的原因没深究。现在测试不等这个标签页加载，也就不靠它。

## 留给下一位的

- 作者从这天起在 Windows 和 Mac 两台电脑上换着开发。在 Mac 上：界面测试能跑全量；`GOOS=windows go vet ./...` 和交叉编译 Windows 版 exe 都能做；Go 测试只有不依赖 Windows 的包能跑（main 上 22 个包能过，另有 24 个包引用了 `golang.org/x/sys/windows`，在 Mac 上编不过），Windows 那部分靠 CI。真窗口和系统相关的实测仍要在 Windows 上做。
- 在 Mac 上写界面测试要注意：Ctrl 点写成 `ControlOrMeta`；不要等中键开出来的标签页加载。
