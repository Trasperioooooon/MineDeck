# 2026-11-27 下载和更新问题调查

## 要做什么

作者原话：「关于软件更新，现在应该还是走github的，但是其实可以走minedeck官网。此外，我记得加了neoforge、forge等中国大陆的镜像源，但是处在那边的用户还是反馈下载总是连接中断，要重试好多次。还有，对于下载了一半彻底失败的，现在的软件还不能实现重新下载部署，好像也没有清理的按钮，这肯定是个产品设计bug吧？」

主会话给出调查结果和推荐以后，作者又说：「需要定的几个点都按照你的推荐来……至于中国大陆镜像源我们这里不好测的问题，你可以写一个最小化的验证脚本，我分享给中国大陆的用户让他们去运行拿结果（只拿结果，不获取他们的IP地址、设备信息等隐私信息）。哦对了，还有，有时候会遇到java错误的问题，我们可以下载java但是不能修复或者重新下载，这个也可以增加功能。我的建议是不开工，这些都只做记录，等我们UI彻底好了，在v3.3.0beta.1版中一次性去修复这些问题。」

同一轮里作者还说 #36 界面部分的收尾复审不用再做了。

## 做了什么

程序一行没改，只做了调查、记录和一个测试脚本。

调查读了更新（`internal/update/`）、下载（`internal/dl/dl.go`）、各家核心的来源（`internal/mcsrc/`）、建服和安装器（`internal/inst/install.go`、`creating_leftover.go`）、Java（`internal/java/`）、失败页（`internal/web/ui/app.js` 的任务页）和官网构建（`website/build.mjs`、`website/lib/data.mjs`）。结论和改法都写在 `docs/计划/2026-11-27-v3.3.0-beta.1-下载与更新整改.md`，作者认了的取舍也记在那里。最要紧的发现有两条。一条是大陆用户的软件更新，卡在检查版本、取校验值这两步直连 GitHub，exe 的加速站根本用不上。另一条是创建失败会把 Forge、NeoForge 安装器已经下好的依赖库连同服务器文件夹一起删掉，每次重试都从零拉一百多个文件，失败页上那句「再试一次很快」对它们不成立。

为了拿到真实的依赖库清单，从 NeoForge 官方 maven 下了一个 21.1.77 安装器（约 6.8MB，放在临时目录，没运行），读了里面的 install_profile.json 和 version.json：135 个依赖库，约 41MB，96 个在 maven.neoforged.net，39 个在 libraries.minecraft.net；它找原版服务端的路径是 `libraries/net/minecraft/server/<版本>/server-<版本>.jar`。

新加了 `tools/cn-net-test/`：`MineDeck下载测试.bat` 给大陆用户双击运行，README 是给作者的说明。脚本只用 Windows 自带的 curl 和 PowerShell，连软件更新、版本列表、各家核心、Java 的那些地址，再从 BMCLAPI 和官方各拉 20 个依赖库、下几个大文件、看断点续传。每次请求记结果、耗时、速度、跳转次数和最后分到的下载服务器名，不记 IP、电脑名、用户名和系统版本，不读用户的文件，下载的数据直接丢掉。

从日本跑的时候顺带看到：BMCLAPI 会把请求分到志愿者节点（bmclapi*.sakura.sld.tw）、高校镜像（mirrors.qlu.edu.cn、mirrors.cernet.edu.cn），原版服务端有时直接跳回 Mojang 官方。小文件从 BMCLAPI 拿，首字节 1.3 到 5.4 秒；从官方拿，只要 0.3 到 0.5 秒。测到的节点都支持断点续传。这些只是日本这条线路上的样子，不代表大陆。

## 谁做的

主会话（Claude Code，Opus 5.5）自己做的，没有委派。脚本没有交别家复审：它不进程序，只读网络、不写用户文件；隐私这一条由主会话核对了结果文件。

## 验证了什么

- 脚本里的地址在日本逐个请求过，都是 200；20 个依赖库从 BMCLAPI 取到的大小和清单里写的一致。
- 在本机用省流量模式（`MD_NETTEST_QUICK=1`）把整个脚本从 PowerShell 跑了两遍，35 项全部成功，汇总、明细都对。结果文件带 BOM、能用记事本打开，里面搜不到用户名、本机路径、IP 地址和电脑名。
- 脚本文件确认是 CRLF 换行、不带 BOM。

## 没做完或没验证的

- 脚本没在大陆跑过，也没在 Windows 10 的老版本上跑过：系统自带的 curl 从 Windows 10 1803 起才有，再老的会提示测不了。
- 脚本的完整模式（下约 90MB）没在本机跑：日本到 dl.minedeck.cn 只有几十 KB/秒，省流量模式已经把每一段都走到了。
- Forge 1.17 以后提前放原版服务端能不能被安装器认，只是读 NeoForge 安装器推出来的，没拿 Forge 的安装器实测。
- 整改计划里的各项都没开工，按作者说的等界面重构做完。
