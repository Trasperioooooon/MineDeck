# 待修清单（2026-11-22）

这份清单是 2026-11-22 Claude 把 `docs/现状.md`、`docs/待办.md`、v3.2.0 到 v3.2.4 发布说明里的「已知情况」，以及现状里只写了「见某某日志」的十几份日志展开对过一遍以后列出来的。作者看完说今天尽量全解决掉，怎么解决见同目录的 `2026-11-22-清账计划书.md`。

每条有一个固定编号，计划书、给执行者的提示词和审核记录都用这个编号。括号里写这一条今天归哪个阶段，或者为什么今天不动：

- 「阶段 NN」：今天交给执行者做，NN 是计划书里的阶段号。
- 「阶段 Q」：提示词写好了，等作者一句话再发（这几条在上一份清单里算「等作者定排进哪一版」）。
- 「放着」：作者 11-22 说，要他拍板的先放着不动。
- 「不排」：没有稳妥的改法、要新装软件，或者其实是新功能，今天不做，后面写了原因。
- 「不在今天」：要真账号、真客户端、国内网络或真 Mac，执行者在这台电脑上做不了。

标「核实过」的是 11-22 那次在代码里亲眼看过、确认还没修的；其余照日志转述，意思是「没看到哪份日志写已修」。做完一条就把方框勾上，后面补一句是哪个提交。
