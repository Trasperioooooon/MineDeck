2026-11-12。检查的是 main 的 `c7e7a03`，程序里的版本号还是 3.1.0-beta.4。检查放在一个独立的测试目录 `D:\MineDeck-v310-test` 里做：源码是一份推送不出去的克隆；测试用的 MineDeck 都放在那里面，用 `-nogui` 起。作者自己在用的那份 MineDeck 和真实数据没有碰。

大部分工作是 Codex 做的：自动测试和构建、安全审查、真机测试的 C、D 两组，还有发版清单。它的额度在收尾阶段用完了，后面由 Claude 接手：对着源码复核了几条要紧的发现，补查了 CI 用的 Go 版本，在分支上把全部测试重跑了一遍，写了这份定稿和交接说明。

逐项的过程记录在测试目录的 `results\报告.md`，D 组的汇总在 `results\runtime\D-management\summary.md`。截图、接口回包、任务日志这些证据都在 `results\` 下面。发版要改的地方、发布说明要点、发版后的核对，在 `docs/v3.1.0-发版清单.md`。

## 结论

功能上可以发。下面这些都在真程序上走通了，没有发现让正式版用不了的功能问题：
- Paper、Fabric、Forge、NeoForge、原版五种核心，共 8 台服务器新建开服；
- 四类导入：Modrinth 整合包、不填 Key 的 CurseForge 整合包、现成服务端压缩包、交接包；
- 接管已有服务器、换 Java、待装清单、备份还原、报错诊断；
- 局域网访问、AI 测试连接、MCP；
- 从 v3.0.0 和 beta.4 换成新程序以后，原来的服务器和设置都还在。

但发之前有两件事要先办，下一节细说。一件是正式版会用停止维护的 Go 编出来，拿不到安全补丁；另一件是最常见的那种真 Server Pack 导进来，报的是一句内部错误，和刚改过的发布说明对不上。

安全审查另外坐实了几处问题，危害都有前提：要么作者打开了局域网访问，要么用户自己导入了别人做的恶意整合包，要么有人手动双击了 `run.bat`。其中四处改起来很小，建议和那两件一起修了再发；其余的可以放到以后。

## 发版前要先办的两件事

### 正式版会用停止维护的 Go 编

两个工作流 `.github/workflows/release.yml` 和 `test.yml` 写的都是 `go-version: "1.25"`。2026-11-12 查 go.dev，还在维护的只剩 go1.27.4 和 go1.26.11，1.25 已经不出补丁了。

Codex 用本机的 Go 1.27.1 跑 govulncheck，标准库有 12 条代码实际会走到的已知漏洞。其中两条直接对着程序的 HTTP 服务：
- 大量小区间的 Range 请求会耗 CPU；
- multipart 头解析的内存上限能被绕过。

govulncheck 列出的修复版本最高是 1.27.4，用 1.27.4 编就都修了；停留在 1.25 的话，以后也等不到补丁。

改法很小：两个工作流的 `go-version` 都改成 `"1.27"`。本机的全部测试本来就是在 Go 1.27 上跑的，都通过；改了以后，推到 main 那次 CI 会在 Windows 上再跑一遍。

### ServerPackCreator 打的 Server Pack 报内部错误

作者放进来的三份真包都是 ServerPackCreator 打的：BMC4（Forge 1.20.1）、BMC5 Neo（NeoForge 1.21.1）、Prominence II（Fabric 1.20.1，外面又套了一层 zip，解开里层再试的）。它们的最外层都有一份 ServerPackCreator 自己的 `manifest.json`。

程序只看文件名，就把它当成 CurseForge 整合包的清单去解析，回的是这样一句，没有人话提示：

```
解析 manifest.json 失败: json: cannot unmarshal string into ...
```

这三份包都只带启动脚本，没有装好的加载器，被拒绝本身是对的。问题在说法：beta.4 的发布说明刚写了「这种包会被拒绝，提示『看着像现成服务端，但没认出核心和版本』」，对最常见的这种包并不成立。

出问题的地方是 `internal/modpack/format.go` 的 `indexKind`：只要文件名是 `manifest.json` 就算 CurseForge。然后 `internal/modpack/modpack.go` 的 `Parse` 直接交给 `parseCurseForge`，不再往下按服务端去认。

建议发版前改识别。CurseForge 整合包的清单里有 `"manifestType": "minecraftModpack"`；ServerPackCreator 的没有这一项，有 `serverPackCreatorVersion`，`files` 是一串字符串。认出不是整合包清单，就接着按服务端去认，这样会落到已经写好的那句提示上，详情里也有 Codex 这次改好的下一步说明。

## 建议发版前顺手修的

这四处改动都不大，各自的前提写在里面。

### 局域网登录不限请求大小（B-1）

没登录的人发一个几 MB 的 JSON，程序会整份读进来才回 401。Codex 用 8 MiB 的请求实测过。失败后的等待，只是每个请求各睡 0.7 秒，同时发很多个请求不受限制。

前提：作者打开了局域网访问，发请求的人在同一个网络里。

改法：`internal/web/auth.go` 的 `handleLogin` 先用 `http.MaxBytesReader` 把请求限到几 KB，密码长度设个上限，失败次数按来源限速。

### 服务器名字里的换行、JVM 参数里的双引号能改写 run.bat（B-7）

- `internal/inst/inst.go` 的 `validateName` 不拦控制字符；`title` 那一行的转义（`batEscapeTitle`）管不住换行。
- `internal/inst/install.go` 的 `batQuoteArg` 给每个参数加了引号，但参数里自带的引号会把它提前关掉。

Codex 用无害的 `echo` 实测过，两种都能让 cmd 多执行一行。只影响手动双击 `run.bat` 的时候：MineDeck 自己开服是直接起 java，不经过它。

改法：名字里拒绝控制字符；JVM 参数里有 `"` 就拒绝，或者换成 cmd 认的转义。

### 整合包的 overrides 解压没有总量上限（B-4）

现成服务端压缩包有「解开后 8 GB、20 万个文件」的上限；Modrinth 和 CurseForge 整合包的 overrides 文件夹没有。Codex 造了一个 8 MB 的整合包，overrides 里解出来是 8 GB。实测时输出直接丢掉了，没有真的写盘。用户导入一个恶意整合包，就能把磁盘写满。

改法：`internal/modpack/modpack.go` 的 `ExtractOverrides` 照服务端压缩包那样，先按申报的大小和个数卡一遍，解压时再按实际写出的字节累计。这一条的改动比另外三条大一点。

### 自定义 frps 的地址会被当成模板解释（B-5）

隧道地址原样进了 frpc 配置的模板。地址里填模板写法，就能把这条隧道的 frps 令牌拼进主机名，frpc 一解析这个域名，令牌就带出去了。Codex 只在内存里渲染过配置，没有真起 frpc、没有真发 DNS 查询。

前提：要有人能改隧道设置。新增、修改隧道是「要人点」的操作，但没有限定只许本机（`internal/ops/catalog/tunnels.go`），所以登录了局域网访问的人也能改。这些人本来读不到令牌，借这一条就能拿到。

改法：`internal/tunnel/providers.go` 的 customProvider 里，地址只认字面的主机名或 IP。

## 可以放到以后的

- **配置写入会顺着目录联接写出去（B-9）。** 服务器文件夹里已经有一个目录联接的话，写配置能顺着它写到服务器文件夹外面。代码在 `internal/ops/catalog/files.go`：检查真实落点的那一步出错时，没有拦，照常写了。前提是联接已经在那儿，导入的包造不出联接。
- **写盘失败时 Key 和地址会对不上（B-10）。** 切换 AI 服务商时，如果写盘失败，后面的请求会把旧 Key 发到新地址（`internal/ai/service.go`）。前提是写盘失败。
- **局域网能读到完整的 Webhook 地址（B-2）。** 登录了局域网访问的人能读到完整的 Webhook 地址，地址里带着令牌的话会露出来（`internal/ops/catalog/appops.go`）。
- **几种 Windows 文件名照收（C-2e）。** 现成服务端压缩包里的这几种名字被收下了：`CON.txt`、`COM1.txt`，结尾带点或空格的，只差大小写的两个同名文件。它们都落在服务器文件夹里，没有越界，Windows 11 上落成普通文件；大小写重名时，后一个盖掉前一个。别的 12 种恶意写法都按预期拒绝或跳过了。
- **端口被占着时提示来得晚（D-5）。** 「启动」接口照样回成功，要等服务器自己报 BindException 才提示。最后的诊断和横幅是对的。代码在 `internal/inst/proc.go`。
- **OpenFrp 的 frpc（D-6）。** 下载不校验哈希、不限定 https、缓存文件名是固定的，这三点交接说明里早就记过。这次真机下载、解压都成功，几分钟后 Windows 安全中心把它当作木马隔离了；作者给的保护历史截图证实了这一点。隧道卡片上那段中文说明，这次没有在界面上看到。
- **字体生成物和仓库里的对不上（A-6）。** 重新生成的中文字体比仓库里的多一个减号（U+2212），西文字体本来就有它，界面不缺字。下次换字体时一起重新生成。
- **宿主函数没有来源检查（B-13）。** WebView2 宿主开给页面的函数不查来源。Claude 补看了代码：开出去的只有拖动、最小化、最大化、关闭、藏到托盘这类窗口函数（`main.go` 里 `w.Bind` 那一段），没有读写文件或执行命令的；界面里的外部链接也都带 `target="_blank"`。影响很小。
- **安全扫描插件没出报告。** Codex 起过一次，但它的正式报告受客户端的显示限制没生成完。不要当成「插件扫描通过」。

## 要作者定的

- **局域网能改哪些设置。** 现在除了主机路径、AI 和 MCP，普通设置局域网都能改，`docs/API.md` 里写明了，其中也包括更新源。所以登录了局域网的人，能把更新源指到自己的仓库再触发更新，等于能在这台电脑上跑程序。不过他们本来就能给服务器装模组和插件，效果一样。要收紧，就得定哪些设置只许本机改。
- **交接说明里挂着的那几件。** 交接包 8 GiB 的上限、导入客户端整合包时要不要提醒、文案收尾时替作者拿的主意、导入现成服务端时沿用包里的正版验证。每件的建议写在 `docs/v3.1.0-发版清单.md` 的「要作者拿主意的事项」里。
