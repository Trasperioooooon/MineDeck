这是 MineDeck v3.2.3，一个小版本，没有新功能。主要是 v3.2.2 里 log4shell 防护和 frpc 两件事的收尾，另外修了 v3.2.2 已知情况里的几条和五个小问题。

**用 Paper 开 1.8 到 1.11.2 服务器的，升级以后控制台可能会回来。** 2021 年 12 月以后发的 Paper 构建（比如 1.8.8 的 build 445）自带的 log4j 已经修过 log4shell，用不着 Mojang 的那份日志配置；可 1.11.2 及以前的 Paper 套上那份配置以后，控制台在「Loading libraries」之后就没有输出，MineDeck 认不出启动完成，一直显示启动中。3.2.3 认得出自带的 log4j 修过了的服务端，会把那份配置的引用摘掉。

## 怎么升级

用着 v3.2.2、v3.2.1 或 v3.2.0 的，打开「设置 → 更新与关于」，点「检查更新」，查到新版本以后点更新就能升到 3.2.3。服务器、Java、设置、隧道和 AI Key 都会接着用。更新前先停掉正在运行的服务器。

用着 v3.1.1、v3.1.2 或者 3.2.0 测试版的，也能在程序里直接升到 3.2.3：3.2.0 的 beta.3 到 beta.5 不管更新渠道选的是哪个都查得到，beta.1、beta.2 和 3.1.x 只看正式版，3.2.3 就是正式版，也查得到。

从 v3.1.0 及更早的版本升级时，换程序的是旧版本自己带的更新脚本，它有两种情况换不成，新版本这时已经下载好、放在旁边。处理办法见 [v3.2.0 的发布说明](https://github.com/Trasperioooooon/MineDeck/blob/v3.2.0/docs/releases/v3.2.0.md)「已知情况 → 升级和更新」的第一条。

从 v2.6.1 及更早的版本升级（那时的程序叫 `AutoMCHUB.exe`），自动更新找不到改名后的文件，请手动下载 `MineDeck.exe` 放进原来的文件夹。旧的开机自启项会被删掉，需要的话在「设置 → 启动与托盘」里重新打开。

## 修了什么

### log4shell 防护

MineDeck 现在会看服务端 jar 里自带的是哪一版 log4j，按它来决定套不套 Mojang 的日志配置。只认 jar 里打包工具留下的版本记录，而且 log4j 本身得真在这个 jar 里；Paper 1.17 以前那种启动时才生成服务端的（paperclip），看它生成的那一个，生成过、核对得上才算。看不出来的，照旧按以前的做法办。

- **自带的 log4j 已经修过的，不再套 Mojang 的配置。** 修过的指 2.16.0 及以后，2.12.x 从 2.12.2 起，2.3.x 从 2.3.1 起（后两个是给老版本 Java 的）；2.15.0、2.13.x 这些不算。新建、接管、导入、导入交接包时都按这个判断。已经套上的，打开 MineDeck 以后和每次从 MineDeck 里启动这台服务器之前，会把启动参数里引用这两份官方配置的那条摘掉（自己手动加的同样写法也算），服务器设置里别的参数一条不动，配置文件留在服务器文件夹里；启动前摘的，这一次启动就生效。`run.bat` 是 MineDeck 生成的，会跟着整份重写，自己在里面改过东西的，升级前另存一份。保存启动参数时也不会再把这条补回去。
- **当初防护配置没下载成的 1.7 到 1.16.5 服务器，现在会补上。** 启动参数里一条日志配置引用都没有的（多半是建的时候没联网），打开 MineDeck 以后会在后台下载对应版本的官方配置，核对过 Mojang 给的校验值再补上引用，下次从 MineDeck 里启动时生效；服务器文件夹里已经有一份官方的，从 MineDeck 里启动这台服务器时当场补上，这一次就生效。下载不成时什么都不改，控制台里会说，之后每次从 MineDeck 里启动这台服务器都会在后台再试。和以前一样，这些都要 MineDeck 认得出这台服务器的 Minecraft 版本（本机存着的版本清单里有它）；认不出时什么都不做，联网在「新建服务器」里打开一次原版的版本列表，这份清单就会更新。
  - **Spigot 和 1.11.2 及以前的 Paper 不补。** 这两类服务端的控制台用的是老写法，套上 Mojang 的配置以后控制台同样没有输出，MineDeck 会一直显示启动中，热备份、定时命令和定时重启也跟着不做。所以这一版不替它们补，启动时控制台里会提醒。之前试过的三个 Spigot 构建（1.8.8、1.12.2、1.16.5）靠自带的日志配置防住了，可 MineDeck 不核对你那一份 Spigot 的配置；这几个版本 2021 年 12 月以前的 Paper 构建防不住，请换成这个版本最新的 Paper 构建（换了以后 MineDeck 会按上一条处理）。确认之前只让信得过的人进服。试过的 1.12.2、1.16.5 的 Paper 构建控制台用的是新写法，这样的 Paper 就算 log4j 没修过也照样会补上，补上以后控制台正常。用 paperclip 启动、它生成的服务端还核对不上的（比如还没开过），也先不补，等核对得上再看。
- **服务器文件夹里已经有同名、内容和官方不一样的配置文件时，打开 MineDeck 后和从 MineDeck 里开服前的这次整理不再覆盖它。** 补配置、把 1.7 到 1.11.2 的旧配置换成新配置的时候，都不覆盖、也不改启动参数，控制台里会说清楚。想用官方的，把那个文件改名或挪走，再重开 MineDeck。v3.2.2 的发布说明里写的是会被换成官方那份，这一步的做法改了；接管、保存启动参数时的做法没变，见已知情况。
- **套着 Mojang 的配置、控制台又会没有输出的服务器**（Spigot、1.11.2 及以前的 Paper），启动时控制台里先说明为什么没有输出、服务器自己的日志在 `logs\latest.log`。

### frpc

- **以前的版本解压失败留下的半截 frpc，现在认得出来。** 启动隧道时，文件夹里已经有的 frpc 会先看一眼程序头和节表（只读几百个字节，不运行它），认出空文件、明显截短的和不是 Windows 程序的；读不了的照旧交给启动那一步。刚从压缩包里解出来的，这一次只按文件名选。OpenFrp 和自定义 frps 的 frpc 是 MineDeck 自己下载的，`frpc.exe`、`frpc_windows_amd64.exe` 这两个名字的要是坏的，会删掉重新准备；别的名字的不碰。樱花的 frpc 是你自己放的，只删半截的，删完会请你重新放一份；不是程序的不删，报错里会说是哪个文件。frpc 所在的文件夹本身是链接或目录联接的，检查出来的坏 exe 一个都不删。
- **OpenFrp 查版本的那一步，跳转也只跟 https 的了。** 下载那一步在 v3.2.2 就是这样。

### v3.2.2 已知情况里的另外两条

- **待装清单读不出来的那段时间，工具箱「导出 Modrinth 整合包」选「自己挑模组」时**，以前说清单是空的，现在照实说清单文件读不出来，并提示怎么修。修好文件以后直接再点预览就行，不用先去打开一次待装清单。
- **从电脑添加模组时查不到那个盘还剩多少空间**，待装清单的位置不再显示「无法显示待装清单」，清单照常列着，失败的原因写在那个文件旁边。

### 五个小问题

- MineDeck 被强行结束、断电或者蓝屏时，正在下载、复制、保存的临时文件会留在原地，以前没人清。现在程序打开以后在后台清一遍：只清 MineDeck 自己起的那几种临时文件名，只清一小时以上没动过的，按名字和修改时间认。范围是程序文件夹、`data`、下载缓存、便携运行时，以及每台服务器文件夹的根上和 `mods`、`plugins`、`config` 这几层；这些文件夹本身是链接或目录联接的跳过，往下翻的时候也不进链接和联接。上层文件夹是联接的不管（比如整台服务器的文件夹是联接，它下面普通的 `mods` 照样清）。
- 保存设置等文件时，临时文件正被杀毒软件这类程序短暂占着，以前有一步不等就直接失败，现在会隔一会儿再试。
- 装本地模组、导入地图的几处报错，以前带着这台电脑上的完整路径（局域网里登录的人和 AI 助手看得到），现在只写哪个文件、什么原因。
- 解压便携 Java 时要排队等磁盘（同一个盘上正有大文件在写），以前排着的时候取消不了，现在可以取消，任务日志里会说在等什么。
- 同一个 MineDeck 给同一台服务器连续备份，两次落在同一个时间点、标签又一样时，后一份会盖掉前一份，现在会避开已有的文件名。两个 MineDeck 同时往同一个备份文件夹里写，照旧可能互相盖掉。

## 给 AI 助手、MCP 和自己调接口的人

- **保存启动参数**（`instance.settings.set` 带 `extraJvm`）：MineDeck 照旧按版本补上该有的 log4shell 防护参数；服务端 jar 自带的 log4j 看得出是修过的，Mojang 日志配置的那一条不补。
- **接管**（`POST /api/adopt`）：服务端 jar 自带的 log4j 看得出是修过的，不下载 Mojang 的日志配置、不新增引用。重新接管 MineDeck 管过的文件夹时，原来的参数会带过来，里面已有的引用要等下次从 MineDeck 里开服时才摘掉。
- **工具箱导出整合包的预览**（`POST /api/toolbox/mrpack/preview`，在界面上和人直接调 HTTP 接口都能用，AI 助手和 MCP 调不了）：选「自己挑模组」（`source: "draft"`）时，待装清单文件在、却读不出来，回 503 和一句修文件的提示，以前当成空清单。从已有服务器导出的不看这份清单，不受影响。

接口的详细说明见 [`docs/设计与参考/API.md`](https://github.com/Trasperioooooon/MineDeck/blob/v3.2.3/docs/设计与参考/API.md)。

## 下载哪个文件

| 文件 | 给谁 |
|---|---|
| `MineDeck.exe` | 开服的人。放进一个单独的空文件夹，双击运行；已经在用旧版本的，换掉原来的那个。 |
| `minedeck-companion-neoforge-1.21.1-0.2.1.jar` | 用了 AI 伙伴的 NeoForge 1.21.1 服上的好友：放进客户端的 `mods` 文件夹 |
| `minedeck-companion-forge-1.20.1-0.2.1.jar` | 同上，Forge 1.20.1 的服 |
| `SHA256SUMS` | 校验和，自动更新会用到，一般不用管 |

伙伴模组还是 0.2.1，和 v3.2.2 的是同一份，已经装过的好友不用换。

## 这一版实际试过的

- **自动测试**：在最终代码上，Go 测试 43 个包全部通过，代码检查（go vet）没有提醒；界面交互测试 265 条、界面原型自检 162 个场景全部走通。会删文件、会自动改服务器设置的那几处，逐条反着试过：把对应的代码改回去，相关的用例都会失败。
- **认服务端的 log4j**：拿官方的 Paper 构建核对过：1.8.8 build 445、1.11.2 build 1106、1.12.2 build 1620、1.16.5 build 794 认成修过的（自带 2.17.0）；1.8.8 build 443、1.11.2 build 1104、1.12.2 build 1618 和 Spigot 1.8.8、1.12.2、1.16.5，以及原版、Forge 1.7.10 都认成没修过或看不出来，照旧套配置。
- **log4shell 实测**：用发版的那条命令编出这一版的程序，用 Java 8 和官方服务端，照 v3.2.0 到 v3.2.2 的写法摆了五台旧服：两台 Paper 1.8.8 build 445（一台套着 v3.2.2 给的配置，一台套着 v3.2.0 给的），只带 noLookups 的 1.8.9 原版、1.12.2 原版和 Paper 1.11.2 build 1104。在本机起一个只监听 127.0.0.1 的端口，逐台开服，在控制台发 `say ${jndi:ldap://127.0.0.1:<端口>/x}`，看那个端口有没有被连。
  - 没联网时：两台 Paper 1.8.8 在 MineDeck 打开后就摘掉了引用（这一步不用下载），开服以后控制台照常输出，「启动完成」认出来了，一次都没被连。两台原版下载不成，什么都没改，照常开，控制台说了没下载成；这时它们和 v3.2.2 一样没防住，各被连了 3 次。Paper 1.11.2 build 1104 没补，照常开，控制台有提醒，被连了 2 次。
  - 联网以后：1.8.9 补上了 1.7 到 1.11.2 的那份、1.12.2 补上了 1.12 到 1.16.5 的那份，`instance.json` 和 `run.bat` 都跟着改了，开服以后「启动完成」照常认出来，都没被连。两台 Paper 1.8.8 照常，没被连。Paper 1.11.2 build 1104 照旧没补、照常开，被连了 2 次，和 v3.2.2 一样，这就是已知情况里的第二条。
- **复审**：log4shell 和 frpc 收尾、五个小问题是 Claude 写的，Codex（GPT-6.2-Astra，max 档，只读）看了两遍。第一遍指出的里面，最要紧的是给 Spigot 和老构建的 Paper 补配置会让它们一直显示启动中、定时任务跟着不做，这一版改成了不补；另外收窄了几处会删文件、会覆盖文件的地方（frpc 只删两个标准名、链接和目录联接里的不删不清、同名配置文件不覆盖）。第二遍又提了几处同类的边角，照同样的做法改了；改完的那一小段没再请它看。工具箱导出和待装清单界面那两条是 Gemini 写的，由 Claude 读过一遍。这份发布说明请 Codex（GPT-6.2-Astra，max 档，只读）对着代码核对过，它指出的说得不准的地方（主要是哪些 Paper 补不补配置按的是控制台的写法、不是按构建日期，以及几处说满了的话）都改了。

## 还没实测过的

- **log4shell**：接管、导入时按新判断办，只有自动测试，没在界面上走过；Paper 1.9.4、1.10.2 和 Mohist 这类混合端没看；修过的版本里实测过的只有 2.17.0。Spigot 的三个 jar 来自第三方下载站，不是自己编的。
- **frpc**：没拿真的 OpenFrp、樱花、frp 的 frpc 试过「是不是完整的程序」这一步，用的是别的 Windows 程序和故意截短的副本；没从 OpenFrp 真的下载一次。
- **清临时文件**：只拿 `mklink /J` 建的目录联接试过「不进联接」，OneDrive 同步的文件夹没试。
- **保存时的重试**：没在真的杀毒软件、同步盘底下试过，用的是在测试里占着这个文件的办法。
- v3.2.2、v3.2.1、v3.2.0 发布说明里写的那些照旧没实测，见 [v3.2.2 的发布说明](https://github.com/Trasperioooooon/MineDeck/blob/v3.2.2/docs/releases/v3.2.2.md)。

## 已知情况

- **Spigot（1.8 到 1.16.5）和 1.11.2 及以前的 Paper，套着 Mojang 的日志配置时控制台没有输出**，MineDeck 一直显示启动中，热备份、定时命令和定时重启都不做；服务器其实起来了，它自己的 `logs\latest.log` 里有 Done。新建、接管、导入这两类服务器时，自带的 log4j 看不出修过的照旧会套上这份配置。Paper 换成这个版本最新的构建就好了；Spigot 还没定怎么改。
- **1.11.2 及以前、2021 年 12 月以前的 Paper 构建，当初又没套上配置的**，这一版不补，log4shell 防护仍然没加上（启动时控制台会提醒）。开这类服务器、又开了内网穿透让外人进来的，请换成最新的 Paper 构建，或者只让信得过的人进。
- **还需要官方配置的服务器**：接管时文件夹里已有同名、内容和官方不一样的日志配置，照旧会被换成官方那份（和 v3.2.2 一样）；保存启动参数时，文件夹里有这份文件就会强加它的引用。打开 MineDeck 以后和从 MineDeck 里开服前的整理不覆盖。
- **待装清单读不出来的那段时间删掉一台服务器**，读出来以后清单里还留着那台服务器的记录，之后再建一台同名的会看到它。
- v3.2.2 和 v3.2.1 已知情况里的另外几条照旧，见 [v3.2.2 的发布说明](https://github.com/Trasperioooooon/MineDeck/blob/v3.2.2/docs/releases/v3.2.2.md)。
