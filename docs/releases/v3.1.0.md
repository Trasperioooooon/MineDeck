这是 MineDeck v3.1.0 正式版。

和 v3.0.0 比，这一版加了几样大功能：把一台服务器整个打包交给别人、自己挑模组一次装好、接管电脑上已有的服务器、直接导入整合包作者给的现成服务端。界面和界面上的文字也整个改了一遍。这些在 v3.1.0-beta.1 到 beta.4 里陆续发过测试版，下面合在一起说，每一项更细的说明见 [beta.1](https://github.com/Trasperioooooon/MineDeck/releases/tag/v3.1.0-beta.1)、[beta.2](https://github.com/Trasperioooooon/MineDeck/releases/tag/v3.1.0-beta.2)、[beta.3](https://github.com/Trasperioooooon/MineDeck/releases/tag/v3.1.0-beta.3)、[beta.4](https://github.com/Trasperioooooon/MineDeck/releases/tag/v3.1.0-beta.4) 的发布说明。发正式版之前又从头检查了一遍，修了几处问题，见「正式版前修的」。

## 怎么升级

用着 v3.0.0 或者 3.1.0 测试版（beta.1 到 beta.4）的，打开「设置 → 更新与关于」，点「检查更新」就能直接升到 3.1.0。服务器、Java、设置和 AI Key 都会接着用。更新前先停掉正在运行的服务器；保险起见，可以先把整个 MineDeck 文件夹备份一份。要手动替换 `MineDeck.exe` 的，先完全退出 MineDeck（在托盘图标上右键退出），再替换。

用 beta.1、beta.2 接管过服务器的：那两版接管时记下的是上一层文件夹，同一层里别的服务器也会出现在列表里。升到 3.1.0 不会自动清掉这条记录，处理办法见 [v3.1.0-beta.3 的发布说明](https://github.com/Trasperioooooon/MineDeck/releases/tag/v3.1.0-beta.3)。

## 把服务器打包交给别人

自己开的服不想开了，可以整台交给朋友接着开；也可以打一份发给朋友，让他照着在自己电脑上开一台。

- **打包**：停掉服务器，在服务器卡片的「···」菜单里点「交接给其他电脑…」，选这个包给谁、存到哪个文件夹，会生成一个 `.mdpack` 文件。存档、`server.properties`、核心自己的配置、`mods`、`plugins`、`config`、白名单和管理员名单都在里面；服务端核心默认不带，导入时重新下载，勾上「完整模式」就连核心一起带。
- **导入**：在「新建服务器」页选「导入交接包」，选这个文件，填名称和端口。Java 和核心按收包那台电脑的情况重新准备。给收包的人准备了一份[上手指南](https://github.com/Trasperioooooon/MineDeck/blob/v3.1.0/docs/接收者上手指南.md)。
- **要知道的**：
  - 包里的模组和插件会在收包的电脑上运行，只导入信得过的人给的包。
  - 配置文件是原样进包的，里面写着的密码（RCON 密码、插件里的数据库密码、机器人令牌）会一起交出去。
  - 原来的 JVM 参数、定时任务和崩溃自动重启不会带过来，游戏内 AI、AI 伙伴和音乐共享要在收包的电脑上重新打开。

## 自己挑模组，一次装好

新建服务器的向导里有可选的一步「选模组」，每台模组服、插件服的详情页有「待装清单」标签。左边一打开就是当前核心和版本下的热门模组，可以按类别筛、往下翻，也能搜；挑中的放进右边的待装清单，点「安装」一次装好。缺的必装前置会自动一起装上。自己下载的 jar 可以「从电脑添加」。模组都从 Modrinth 下载，按核心和 Minecraft 版本挑兼容的版本，下载下来要对得上 Modrinth 给的校验值。AI 助手也能帮你挑，但真正往服务器里装之前，要你在卡片上确认。

## 导入整合包和现成服务端

- **下载不了的文件逐个处理**：以前整合包里只要有一个文件下载不了，整个整合包都导不进来。现在照常导入，下载不了的文件列在任务页的「待决文件」里，每个自己选「跳过」「用本地文件代替」或「信任站点并下载」。导入时可以填一个「本地来源文件夹」（比如以前那台服务器的文件夹），下载不了的文件那里有的，会自动拿过来。
- **CurseForge 整合包**：资源包、光影、数据包按类别分别放进 `resourcepacks`、`shaderpacks`、`datapacks`，不再全塞进 `mods`。下载不了的文件会写出文件名、项目名和下载页。
- **清单套了一层文件夹也能认**，比如 `整合包名/manifest.json`。
- **作者给的现成服务端压缩包可以直接导入**，解压成一台新服务器，不重新下载核心，所以核心得已经在包里：Forge、NeoForge 要带着装好以后的 `libraries` 文件夹，Fabric、Paper、原版等要带着服务端 jar。包里已经有 `server.properties` 的，只改端口，正版验证和允许飞行沿用包里的。
  - **只带启动脚本的 Server Pack 不能直接导入。** 不少整合包作者给的 Server Pack（Forge、NeoForge 的尤其多）只带模组、配置和一个启动脚本，第一次运行脚本时才装加载器。导入这种包会提示「看着像现成服务端，但没认出核心和版本」。可以先解压，运行包里的启动脚本或安装器把加载器装好（一般要用电脑上装好的 Java），再用「接管已有服务器」选中那个文件夹。
- 模组声明要用的 Java 比这台服务器现在用的新时，会提醒你去「内存 / 启动」换 Java。

## 接管已有服务器，换 Java

- **接管已有服务器**：在「新建服务器」页选一个以前自己开的服务器文件夹，MineDeck 认出核心、版本和启动文件后就地登记进来。文件不搬，存档和配置不动。
- **移出列表**：删除服务器时不勾「同时删除服务器文件夹」，就只是从列表里拿掉，以后还能接管回来。
- **换 Java**：每台服务器的「内存 / 启动」页可以选 MineDeck 下载的、电脑上装的 Java，或者现下一个。

## 界面和报错

- 选文件夹用的是 Windows 自带的窗口，挂在 MineDeck 的窗口上，不再闪出命令行窗口。窗口最小 1024×576。
- 「新建服务器」的四种方式排成两组一样大的卡片。内网穿透页的添加表单挪到了列表上面。
- 界面上的文字重写了一遍，统一说「服务器」「文件夹」。
- 报错先说没做成什么，后端给的原因是一句看得懂的中文时接在后面；带着文件路径、英文系统报错的完整原文，点「详情」能看到、能复制。
- 部署做到一半切到别的页面或者刷新，回来还能找到进度。任务日志太长时，开头的说明会留着。超过上限的整合包和交接包，选了文件就提示，不用等传完。

## 内网穿透

- OpenFrp 的 frpc 下载修好了：以前拼出来的下载地址不对，几个下载源都是 404。
- frpc 常被杀毒软件当成风险软件拦下或删掉。现在隧道卡片上会直接说「frpc 被杀毒软件拦下了」或者「frpc 不见了」，并告诉你到 Windows 安全中心的「保护历史记录」里允许或还原它。

## 正式版前修的

发正式版之前，在一台 Windows 11 上从头做了一次检查：自动测试、真机测试和安全审查，过程和结论见[检查报告](https://github.com/Trasperioooooon/MineDeck/blob/v3.1.0/docs/测试报告-v3.1.0-正式版前检查.md)。修了这些：

- **ServerPackCreator 打的服务端包**：很多整合包作者的 Server Pack 是用这个工具打的，以前导入时报一句 JSON 内部错误。现在会提示「看着像现成服务端，但没认出核心和版本」，详情里说明先运行包里的启动脚本或安装器装好加载器，再接管。
- **局域网访问的登录**：请求的大小有了上限，同时校验密码的个数也有了上限，有人不停猜密码时不会再把电脑拖慢。
- **`run.bat`**：服务器名字里的换行、JVM 参数里的双引号，以前能让手动双击 `run.bat` 时多执行命令，现在不能了。JVM 参数结尾带反斜杠时（比如 `-Ddir=C:\My Server\`），双击 `run.bat` 启动，Java 收到的参数会串位，也修了。
- **整合包的覆盖文件**：解压有了上限，和现成服务端压缩包一样，恶意的整合包不能再把磁盘写满。
- **自定义 frps 的地址**：以前地址里写特定的模板写法，能把这条隧道的令牌带到别处去。现在地址只认域名或 IP。
- 编译用的 Go 换成还在维护的 1.27，拿得到标准库的安全补丁。

## 升级以后要留意的

- **新加的 JVM 参数里不能有双引号。** 在「内存 / 启动」里新加或改过的参数带双引号，保存时会被拒绝，去掉引号就行。已经存下的参数不受影响。
- **自定义 frps 的地址只能填域名或 IP**，不能带 `http://`，也不能带端口（端口填在旁边那一栏）。改了自定义 frps 的地址或端口，或者把服务商的隧道改成自定义 frps，要重新填一次凭据。
- **局域网登录**：同一台设备同时发好几个登录请求，后到的会提示「请求太频繁，稍等几秒再试」，正常在网页上登录碰不到。
- **整合包的覆盖文件**超过 20 万个或 8 GiB 的会被拒绝，正常的整合包到不了。

## 局域网访问

打开局域网访问以后，用访问密码登录的人能新建服务器、给服务器装模组和插件、改 JVM 参数和更新源，这些都等于能在这台电脑上运行程序。**访问密码只给信得过的人。**

## 下载哪个文件

| 文件 | 给谁 |
|---|---|
| `MineDeck.exe` | 开服的人。放进一个单独的文件夹，双击运行。 |
| `minedeck-companion-neoforge-1.21.1-0.2.1.jar` | 用了 AI 伙伴的 NeoForge 1.21.1 服上的好友：放进客户端的 `mods` 文件夹 |
| `minedeck-companion-forge-1.20.1-0.2.1.jar` | 同上，Forge 1.20.1 的服 |
| `SHA256SUMS` | 校验和，自动更新会用到，一般不用管 |

伙伴模组和 v3.0.0、各个测试版的是同一份，已经装过的不用换。

## 这一版实际试过的

- 自动测试：Go 测试在 Windows 上用 Go 1.27 全部通过；界面交互测试 126 条、界面原型 107 个场景在仿真后端上全部走通。
- 真机：在一台 Windows 11 上用编出来的程序，新建并开起了 Paper、Fabric、Forge、NeoForge、原版共 8 台服务器；整合包、现成服务端压缩包、交接包三类导入，接管、换 Java、待装清单、备份还原、报错诊断、局域网访问、AI 测试连接和 MCP 都走过一遍；从 v3.0.0 和 beta.4 换成新程序以后，原来的服务器和设置都还在。
- 原生窗口（选文件夹的窗口、最小窗口、标题栏、托盘、启动画面、浅深色、125% 和 150% 缩放）在真窗口里看过。
- 安全审查查了 14 条线索，要紧的几处修了，修复又请别家模型（Gemini）做了两轮复审。
- 还没测到的：用游戏客户端进 Forge、NeoForge 的服；带着装好的加载器的第三方 Server Pack；真实的 AI Key、MCP 客户端和第二台电脑。

## 已知情况

- **外部链接不是在你的浏览器里打开的**：界面上的外部链接（EULA、申请 CurseForge Key、openfrp.net 这些），在 MineDeck 弹出的简易窗口里打开，用不了自己浏览器里的密码管理器和登录状态，可以把地址复制到自己的浏览器里打开。下个版本改。
- **交接包不能超过 8 GiB，整合包上传不能超过 4 GiB**：开了很久的服务器，存档有可能超过。超过的话，把整个服务器文件夹拷到另一台电脑上，用「接管已有服务器」收进来。
- **CurseForge 上的整合包多数是给客户端用的**：里面常有只能装在客户端的模组，照着清单装出来的服务器会开不起来，MineDeck 目前不会提前提醒。大型整合包的作者一般另外提供 Server Pack。
- **整合包和现成服务端压缩包**：包装文件夹只认一层，整包里只能有一处整合包清单；Quilt 仍不支持；服务端的版本只写在日志里的认不出来，用「接管已有服务器」自己填。
- **待决文件要在这次运行里处理完**：关掉 MineDeck 再打开，任务页上的待决文件就没有了，只剩服务器文件夹里的清单文件，要照着自己把文件放进去。信任过的站点目前要手动改 `config.json` 里的 `trustedHosts` 才能取消。
- **导入交接包被打断**（关程序、断电）时，建到一半的文件夹会留在存放位置里，不会出现在列表中，可以直接删掉。
- **向导里挑的模组**不记是给哪种核心挑的，回头换了核心，有的可能装不上，到新服务器的「待装清单」里重新挑。
- **常用设置里 1.21.9 以上的几个游戏规则开关**（命令方块、PVP、下界、刷怪）：初始状态按 `server.properties` 里的旧值显示，不看服务器当前的游戏规则。
- **没有数字签名**：第一次运行时，Windows 可能提示「Windows 已保护你的电脑」，点「更多信息 → 仍要运行」。
- 和 v3.0.0 相同的几条（国内网络下载慢、Windows 10 上的音乐共享会录进整机声音）见 [v3.0.0 的发布说明](https://github.com/Trasperioooooon/MineDeck/releases/tag/v3.0.0)。
