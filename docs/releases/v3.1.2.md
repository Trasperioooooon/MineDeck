这是 MineDeck v3.1.2，一个小版本：修了 OpenFrp 隧道第一次启动时下不了 frpc 的问题，下载失败时的提示也写得更明白。没有新功能，界面没有变化。

## 怎么升级

用着 v3.1.1 的，打开「设置 → 更新与关于」，点「检查更新」就能升到 3.1.2。服务器、Java、设置和 AI Key 都会接着用。更新前先停掉正在运行的服务器。

从 v3.1.0、v3.0.0 或者 3.1.0 测试版也可以直接升到 3.1.2。只是这时换程序的是旧版本自己带的更新脚本，它有两种情况换不了程序，处理办法和升到 3.1.1 时一样，见 [v3.1.1 的发布说明](https://github.com/Trasperioooooon/MineDeck/releases/tag/v3.1.1) 最后的「已知情况」。

## 修了什么

- **OpenFrp 隧道第一次启动时下不了 frpc**：OpenFrp 的下载源前面有一层机器人防护，它把 MineDeck 的下载请求当成了机器人，回的是 HTTP 567。于是还没下过 frpc 的电脑上，第一次启动 OpenFrp 隧道会停在「下载 OpenFrp frpc 失败」。现在这一处下载换了一种握手方式（只用 TLS 1.3），写这处修复时对着线上试过，这样能下回来。以前已经下好 frpc 的电脑不受影响，本来就不会再下一次。
- **下载失败时说清是哪一种**：不管下的是什么，几个下载源都试过还是不行的时候，报错里每个源的状态码后面会带一句原因。567 写「被源站 CDN 的机器人防护拦截」，403 写「源站拒绝访问：可能是机器人防护、链接失效或没有权限」，520 到 524 写「源站故障或超时」，404 写「该源没有这个文件」。别的状态码照旧只写数字。
- **OpenFrp 的 frpc 实在下不来时，告诉你怎么手动放**：报错里会写上自己去 OpenFrp 下载 `frpc_windows_amd64.zip`，把压缩包里的 `frpc_windows_amd64.exe` 放进哪个文件夹（MineDeck 旁边的 `runtimes\frpc\openfrp`，程序会先把它建好），放好以后再点一次启动就行。

另外清掉了程序里两条一直挂着的代码检查提醒（窗口去标题栏和最小窗口那两处），只是换了一种写法，窗口的表现没有变。

## 下载哪个文件

| 文件 | 给谁 |
|---|---|
| `MineDeck.exe` | 开服的人。放进一个单独的文件夹，双击运行。 |
| `minedeck-companion-neoforge-1.21.1-0.2.1.jar` | 用了 AI 伙伴的 NeoForge 1.21.1 服上的好友：放进客户端的 `mods` 文件夹 |
| `minedeck-companion-forge-1.20.1-0.2.1.jar` | 同上，Forge 1.20.1 的服 |
| `SHA256SUMS` | 校验和，自动更新会用到，一般不用管 |

伙伴模组和 v3.1.0、v3.1.1 的是同一份，已经装过的不用换。

## 这一版实际试过的

- 自动测试：Go 测试在 Windows 上全部通过，代码检查（go vet）没有任何提醒，以后每次提交 CI 都会跑这项检查。这一版加的测试逐条反着试过，把对应的代码改坏它们会失败：frpc 的下载没走新的握手方式、握手不止报 TLS 1.3、失败时没建好文件夹、窗口那两处把系统给的地址取错。窗口那两处换写法前后程序的行为是一样的，测试分不出新旧写法，守着写法的是代码检查。
- OpenFrp 下载：自动测试用假的下载源验了被 567 拦下时报错里有原因和手动的办法，也验了这一处下载确实只用 TLS 1.3 握手。这些都不连 OpenFrp。真的去 OpenFrp 的下载源下一次 frpc，是写这处修复的时候试的，能下回来；发版前的这一轮检查没有再联网下一次。
- 窗口：用发版那条命令编出来的程序打开真窗口，和正式版 3.1.1 逐项对照着量了一遍，两边的数字完全一样。量的是三件事：没有系统自带的标题栏，窗口内容从窗口顶边开始；最大化以后内容正好铺满屏幕的工作区，不露出系统标题栏，也不裁掉 MineDeck 自己的顶栏；把窗口缩到 400×300，它停在 1024×576 不再变小。窗口是脚本摆弄的，不是人手拖的；只在一块 100% 缩放的屏幕上试过。
- 从 v3.1.1 在程序里点更新到 3.1.2，是 3.1.1 修好的那份更新脚本第一次真的换程序，要等发版以后才能实测。
- 复审：两处改动由另一个 Claude 会话做了只读复审，没有查出必须改的问题。它提的建议里改了四条：403 的说法留了余地，下载失败时先建好放 frpc 的文件夹，给下载走哪种握手补了测试，CI 加了代码检查。握手失败时退回原来的方式再试一次，这条没有做。

## 已知情况

- **OpenFrp 的下载以后可能又被拦**：这次的修复靠的是下载源的机器人防护眼下认哪种握手，对方哪天换了规则，下载会重新失败。那时照报错里写的办法手动放一次 frpc 就能接着用，也欢迎来提 Issue。
- **网络出口不支持 TLS 1.3 时，OpenFrp 的 frpc 下不了**：少数公司网络、代理或者杀毒软件的「HTTPS 扫描」只支持到 TLS 1.2，经过它们时这一处下载会握手失败。办法同上，手动放一次。别的下载不受影响。
- 从 3.1.0 及以前的版本升级时可能换不了程序，以及和 v3.1.0 相同的几条，见 [v3.1.1 的发布说明](https://github.com/Trasperioooooon/MineDeck/releases/tag/v3.1.1) 和 [v3.1.0 的发布说明](https://github.com/Trasperioooooon/MineDeck/releases/tag/v3.1.0)。

遇到问题，欢迎在 GitHub 上提 Issue，写清楚做了什么、看到了什么。**不要贴出 API Key 和各种令牌。**
