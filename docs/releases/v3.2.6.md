这是 MineDeck v3.2.6，接着 v3.2.5 往下修问题的小版本。这一版处理的是又一批积攒下来的毛病：删除服务器删到一半碰上被占着的文件，不会再卡成「删不掉」；待装清单点「全部安装」之前会先查前置，新建向导里挑了没装上的东西不再悄悄留着；卸载便携 Java 和给服务器换 Java 不会撞在一起，连不上 Adoptium 时更快改用 Mojang 运行时；上次没建完的文件夹，建在新位置里的也找得到，删的时候不会删错；换地图的进度在别的设备上也接得上，取消不了时写明原因。

## 怎么升级

用着 v3.2.5、v3.2.4、v3.2.3、v3.2.2、v3.2.1 或 v3.2.0 的，打开「设置 → 更新与关于」，点「检查更新」，查到新版本以后点更新就能升到 3.2.6。服务器、Java、设置、隧道和 AI Key 都会接着用。更新前先停掉正在运行的服务器。

用着 v3.1.1、v3.1.2 或者 3.2.0 测试版的，也能在程序里直接升到 3.2.6：3.2.0 的 beta.3 到 beta.5 不管更新渠道选的是哪个都查得到，beta.1、beta.2 和 3.1.x 只看正式版，3.2.6 就是正式版，也查得到。

从 v3.1.0 及更早的版本升级时，换程序的是旧版本自己带的更新脚本，它有两种情况换不成，新版本这时已经下载好、放在旁边。处理办法见 [v3.2.0 的发布说明](https://github.com/Trasperioooooon/MineDeck/blob/v3.2.0/docs/releases/v3.2.0.md)「已知情况 → 升级和更新」的第一条。

从 v2.6.1 及更早的版本升级（那时的程序叫 `AutoMCHUB.exe`），自动更新找不到改名后的文件，请手动下载 `MineDeck.exe` 放进原来的文件夹。旧的开机自启项会被删掉，需要的话在「设置 → 启动与托盘」里重新打开。

从 v3.2.4 及更早的版本直接升上来的，v3.2.5 的几处变化也一起生效：同一个文件夹里的 MineDeck 只能开一份；两台服务器重名、其中一台是接管进来的，列表里显示的可能换成另一台（两台的文件都在）；许可证从 v3.2.5 起改成 GNU AGPL-3.0。细节见 [v3.2.5 的发布说明](https://github.com/Trasperioooooon/MineDeck/blob/v3.2.5/docs/releases/v3.2.5.md)。

## 改了什么

### 删除服务器

这是 v3.2.5「已知情况」里记着的那一条，这一版修了。

- **删到一半碰上被占着的文件，还能再删。** 以前「删除服务器和文件夹」删到一半，碰上一个正被别的程序占着的文件（杀毒软件正在扫、别的程序开着它），会报删除失败；这时服务器的 `instance.json` 可能已经先被删掉了，这台还留在列表里，再点删除只会报「找不到 instance.json，已拒绝删除」。现在先删别的文件，最后才删 `instance.json`：中途失败的话，它还在，关掉占着文件的程序以后再点一次删除就行。
- **只是被短暂占一下的文件，会等一小会儿再试。** 杀毒软件、索引这类程序常常只占一瞬间，这种情况不再当场报失败。
- **文件都删完了、只剩空文件夹删不掉时，照常算删掉。** 比如有个命令行窗口正停在这个文件夹里。这台服务器会从列表里消失，留下一个空文件夹，过后自己删掉就行。

### 待装清单

- **点「全部安装」之前先查一遍前置。** 以前没点过「检查前置」就点「全部安装」，自动补上的必装前置不会先列出来，直接一起装了。现在没查过、或者查过以后清单又变了的，会先查一遍，再弹出「另外会自动装上 N 项必装前置」让你确认；查的这一会儿你又往清单里加了东西，会自动再查。前置没查出来（比如断网）就不开始安装，并提示「检查前置失败，没有开始安装」。
- **新建向导里挑的东西，会记着是给哪种核心、哪个版本挑的。** 在「选模组」（或「选插件」）这一步挑好以后，回头换了核心或游戏版本，这一步会提示清单里有几项是给原来的核心挑的、换了以后可能装不上，可以点「清空草稿清单」，也可以点「留着」（插件不卡游戏版本，插件服只换版本不提示）。以前不提示，要等建服以后在任务页看到「找不到能装的版本」才知道。
- **建服时切到了别的页面，挑好的东西不再悄悄留着。** 向导里挑好的模组是等服务器建好以后才装的，这期间要是切走了，以前它们就留在草稿清单里，那台服务器的页面上什么也看不到。现在那台服务器的「插件」或「模组」页里，待装清单上面会有一条「新建时挑的 N 项还没装」，核心对不上的、装不上的会标出来，可以点「一起装上」，也可以点「不要了」（只清掉这些，这台自己清单里的不动）。「一起装上」和「全部安装」一样，会先查前置、先确认。
- **检查前置快了一些。** 检查前置、AI 助手提出安装时，要给服务器里已经装的每个 jar 算一遍校验值，再联网去认。以前每次都从头算；现在文件没变过的不重算，模组多的服务器第二次检查起会快一些。联网那一步照旧每次都做。MineDeck 关掉以后要重新算一次。

### 整合包里没装上的文件

一次处理的文件超过 500 个时，界面会分几批提交。

- **现在看得到做到第几批了。**「应用所选的处理」旁边会写「正在处理第 2 批，共 3 批」。以前整个过程只有一个变灰的按钮。
- **还没提交完就要离开，会先问一句。** 切到别的页面，或者关掉详情页上那个处理窗口时，会提示「还有 N 项还没提交，离开后不会继续；正在处理的这一批会照常做完」，点「留在这里」就接着提交。以前直接走掉，剩下的批次不再提交，也不提示。关掉整个 MineDeck 窗口或刷新页面时不问。

### 删掉服务器时，它的待装清单跟着清

删除一台服务器（包括只移出列表）时，这台待装清单里的东西本来就会一起清掉，免得以后同名新建的那台看到上一台留下的。

- **清单的存档文件正好读不出来时，也会补清。** 这个文件被杀毒软件、同步盘占着，或者内容坏了的那段时间里删服务器，以前清不掉、也不说，以后再建一台同名的，就会看到上一台挑的模组。现在这种时候先记一笔，等清单读得出来了（下次启动，或者不用重启、下一次用到清单时）先补清。只清删服务器之前加进去的；同名新建的那台后来加的不动。
- **实在清不掉时会告诉你。** 清不掉、也记不下来的时候，服务器照样删，另外弹一条提示：「待装清单里的东西没清掉，以后再建同名的服务器时看一眼它的待装清单」，点「详情」能看到原因。

### Java

- **卸载一套便携 Java 和把服务器换成这套，不会再撞在一起。** 以前卸载是先查有没有服务器用着这套、再删，查完到删完的这一会儿，另一个页面能把某台服务器换成它，那台下次开服就找不到 Java。现在两边互相看得见：这套 Java 正在卸载时，换成它会被拦下，提示「这套 Java 正在卸载，没有换上。等卸载完再换，或者换成别的 Java」；有服务器正在换成这套时点卸载，会提示稍后再试，什么都不删。
- **卸到一半没卸完的那一套，不让换上。** 卸载中途失败留下半截的，或者已经卸掉的，再换成它会提示「这套 Java 已经卸载了或者没装完整，没有换上」。接管已有服务器时指定的是 MineDeck 下载的便携 Java、它却正在卸载或者已经卸了，接管不会做，报错里说明原因。
- **下载 Java 期间再保存一次，不会多出一个任务。** 给服务器换一个要现下载的 Java，下载还没完时重新进页再保存，以前会再建一个下载任务（文件不会重复下，任务列表里多一条）。现在回到已有的那个任务。
- **连不上 Adoptium 时，更快改用 Mojang 运行时。** v3.2.4 起，连不上 Adoptium 官方接口就直接改用 Mojang 官方运行时（经 BMCLAPI 镜像），但有两种情况还在等：下载源选了「官方」，或者清华镜像也连不上，这时 Adoptium 官方源那一步仍按默认时限等。现在这一步向 Adoptium 接口问的每一问最多等 10 秒，头一问就连不上的（连接被拒、域名解析不了、超时这类），后面的不再问，任务日志里会写「Adoptium 的接口连不上，直接改用 Mojang 官方运行时」。
- 顺带改了一处判断：以前向 Adoptium 要校验值时只要没要到，就当成连不上、跳过 Adoptium 官方源。现在只有真的连不上才跳过；接口回了话、只是没给出要的东西（比如回 404）时，Adoptium 官方源照常试一次。

### 上次没建完的服务器文件夹

v3.2.4 起，新建、导入中途停下留下的文件夹会列在「服务器」页上方，可以删掉。这一版修了它的几处毛病。

- **建在新位置里的也找得到。** 第一次往一个新的存放位置里建服务器，建到一半 MineDeck 被关掉、崩溃或断电，以前这个位置还没被记住，留在那里的文件夹不会列出来。现在放下记号之前先把这个位置记一笔，下次启动找得到。只是记下来找没建完的文件夹用：服务器没建成的话，这个位置里别的服务器文件夹不会因此出现在列表里。
- **不会删到别处的同名文件夹。** 两个存放位置里各有一个同名的没建完的文件夹时，以前有一种情形会删错：列表停在页面上的这段时间里，存放位置的先后变了（比如改了默认存放位置），再点其中一行，删掉的可能是另一个位置里的那个。现在每一行认的是它自己所在的位置，位置对不上就不删，并重新读一次列表。确认框里也写上了它在哪个位置：「将删除位于「…」的「…」」。
- **删除没成功时，列表会重新读一次**，不会让你接着点一行已经变了的。
- **登记到最后一步时程序没了，下次启动能接上。** 服务器已经建好、正要记进列表的那一刻程序被关掉，以前在新位置里建的这台重开以后既不在服务器列表里、也不算没建完的。现在下次启动会认出来，照常列进服务器列表。

### 接管已有服务器

- **Paper 旁边多放了一个原版 `server.jar`，不再提示「不止一种服务端」。** Paper、Purpur、Folia、Leaves 的文件夹里只多一个原版 jar 时，识别页的「识别时注意到」里改成说一句「旁边的 server.jar 是原版，没有用它。」原版 jar 不止一个，或者和别的核心放在一起的，照旧提示请你在「启动文件」里确认。
- **已经照提示加过日志配置引用的，接管时不再重复提醒。** v3.2.5 起，老版本服务器的文件夹里有一份自己改过的日志配置时，接管会提醒这台没有套上 Mojang 的日志配置。把服务器移出列表再接管回来时，如果原来的启动参数里已经加了对这个文件的引用，现在不再提醒一遍。

### 换地图和备份来源

- **导入地图没成、自动退回以后，「当前世界从哪份备份还原」的说明还在。** 备份页页顶会写现在的世界是从哪份备份还原来的。以前导入地图走到停服、准备换图那一步以后，哪怕最后没换成、自动退回了原来的世界，这句说明也会被清掉。现在世界确实没换的（临换之前放弃了，或者出错以后自动退回成功了），这句留着。「恢复导入前的地图」没换成、自动退回的也一样。退回也失败、要人处理的那种，照旧清掉。
- **交接包会带上这句来源。** 打包的那台服务器，世界是从某份备份还原来的，接手的人导入以后，备份页页顶会写「原来那台电脑上从 … 的备份还原来的，随交接包带过来（那份备份不在这台电脑上）」。包里没带世界的不沿用。
- **别的设备上发起的换地图，这边也接得上进度。** 以前只有发起的那台设备看得到进度，别的设备打开同一台服务器的「换地图」页，只看到一句正在换地图。现在会直接接到进度页。
- **取消不了时，写明为什么。**「取消导入」取消不了的时候按钮是灰的，旁边写原因：已经开始停服、正在替换世界文件夹，或者这次导入是在别的设备上发起的（只有发起的那台设备能取消）。以前是按钮直接收掉，写一句固定的话。
- **任务页的「完成」回到这台服务器。** 换地图做完以后，按钮是「完成，回到这台服务器」，点了回到它的「换地图」页；以前回的是服务器列表。结果那句话里也写上了服务器的名字。
- **用极限模式的地图新建服务器，会自动打开极限模式。** 服务器开不开极限模式，看的是 `server.properties` 里的 `hardcore`，不看地图自己的标记；以前用极限模式的地图新建，开出来的不是极限模式。现在向导的预览里会说明这是一张极限模式的地图，新服务器会打开极限模式（难度固定为困难，玩家死了只能旁观）。替换已有服务器的地图时照旧不自动改，要改的话在「可以一起改的设置」里勾。
- 「换地图」页的恢复点大小不再每次刷新都重数一遍，页面刷新得比以前勤。

## 给 AI 助手、MCP 和自己调接口的人

- **待装清单**：`modcart.add`（`POST /api/modcart`）往草稿清单里加时可以带 `core` 和 `mc`，记下是给哪种核心、哪个版本挑的（核心认不出来就都不记，不报错）；`modcart.list`（`GET /api/modcart`）看草稿清单时，项目里多了 `pickedCore`、`pickedMc`，记过目标服务器时最外层多一个 `draftInst`。新加操作 `modcart.draft.target`（`POST /api/modcart/draft/target`，body `{"inst":"…"}`）：记下草稿清单是给哪台新服务器挑的，仅人工，AI 助手和 MCP 调不了。`GET /api/modcart/deps` 认查询串里的 `includeDraft=true`，把草稿清单并进来一起查。
- **删除服务器**（`DELETE /api/instances/{name}`，操作 `instance.delete`）：正常还是回 `"ok"`；这台的待装清单没清掉、也记不下来时，服务器照样删，`data` 换成 `{note}`，是一句说明。
- **卸载便携 Java**（`java.remove`，`POST /api/javas/remove`）：有服务器正在换成这套时也回 409。**换 Java**（`instance.java.set`，`PUT /api/instances/{name}/java`）：要换上的便携 Java 正在卸载时回 409，已经卸了或没装完整的回 400；这台服务器同一个版本的下载还在跑时，返回那个任务的 `taskId`，不另建。**接管**（`POST /api/adopt`）：`javaPath` 指的是 MineDeck 的便携 Java、而那一套正在卸载、已经卸了或没装完整时，接管任务失败。
- **没建完的文件夹**（`GET /api/creating-leftovers`、`POST /api/creating-leftovers/discard`）：`id` 的样子变了，现在是「所在存放位置的短哈希/文件夹名」，照旧只能用列表里给的，对不上现在任何一个位置的回「没有这一项」。`GET` 现在只读，不再顺手去掉已登记服务器里残留的记号（改在启动时去掉）。`GET /api/config` 多一个只读的 `creatingRoots`：正在建服务器、还没记成存放位置的地方。
- **世界状态**（`world.status`，`GET /api/instances/{name}/world`）：正在导入地图或换回旧地图时多一个 `task`：`{id, kind, canCancel, cancelWhy?}`，`kind` 是 `import` 或 `restore`，`canCancel` 按问的人算。**取消导入**（`world.import.cancel`，`POST /api/world/cancel`）被拒时，报错里是具体原因。
- **任务**（`task.list`、`task.get`，`GET /api/tasks`、`GET /api/tasks/{id}`）：多了可选的 `inst`，是任务操作的服务器，目前只有换地图的任务带。换地图任务的 `result` 里现在带着服务器名。
- **实例列表里的 `worldFrom`**：多了可选的 `carried`，为 true 表示这条记录是随交接包带来的，那份备份不在这台电脑上。导入交接包（`POST /api/transfer/import`）时，包里的世界确实带过来了才沿用这条记录，并且逐项核对。
- **导入计划**（`POST /api/world/plan`）：给新建服务器做的计划里，地图是极限模式时 `issues` 多一条 `info` 级的 `hardcore`；照这份计划新建的服务器，`server.properties` 里会写上 `hardcore=true`。

接口的详细说明见 [`docs/设计与参考/API.md`](https://github.com/Trasperioooooon/MineDeck/blob/v3.2.6/docs/设计与参考/API.md)。

## 这一版实际试过的

- **自动测试**：这一版的改动大多带着新加的自动测试（Go 用例和界面交互用例）。发版前跑了一遍全量（跑的那个提交和发出去的代码只差文档）：代码格式、编译和代码检查（go vet）都没有提醒；Go 的 44 个有测试的包全部通过，界面交互用例 304 条全部通过，界面原型自检 162 个场景走通。
- **反着试**：会删文件、会清掉已有数据的，和牵涉先后顺序的这几处，逐条反着试过，把程序改回去，对应的测试都会失败：删除服务器最后才删 `instance.json`；删服务器时补清待装清单的几条规矩（读出来的那一刻补清、只清删服之前加的、清单存不进去时什么都不删）；装之前核对前置；卸载 Java 和换 Java 两边的先后；没建完的文件夹怎么找、怎么编号、登记到最后一步的先后；导入地图退回以后留住备份来源。
- **frpc**：这一版没有改内网穿透，但顺手补了以前的发布说明里记着没试过的一件事：拿真的 OpenFrp frpc（`OF_0.68.0`）和 frp 0.61.1 的官方压缩包，用这一版的代码过了一遍「是不是完整的程序」的检查和解压，都判成能用，解压挑对了文件。

## 还没实测过的

- **真窗口**：这一版新加的提示和按钮（「新建时挑的 N 项还没装」那一条和上面的「一起装上」「不要了」，向导里的「清空草稿清单」「留着」，分批的进度和离开前的确认，换地图变灰的取消键和原因，「完成，回到这台服务器」）都是在测试用的浏览器里点的，没在 MineDeck 的窗口里逐个点过。
- **删除服务器**：被占着的文件是测试里自己占住的，没拿真的杀毒软件去占。放在 OneDrive 这类云同步文件夹里的服务器，没在真的云同步文件夹上删过。
- **待装清单的补清**：没拿真的杀毒软件或同步盘去占着清单的存档文件，用的是在测试里独占这个文件的办法。
- **Java**：连不上 Adoptium 改用 Mojang 运行时这一步，是在测试里造出连不上的样子试的，国内的网络没人实测过。卸载和换 Java 互相避让，只有自动测试。
- **没建完的文件夹**：没在真程序里走一遍「新建到一半结束程序、重开以后看列表」，测试里是直接摆出建到一半的样子再重新启动管理服务器的那部分程序；导入现成服务端走的是真的流水线。符号链接那一条在我们自己的电脑上建不了符号链接，要到 GitHub 的 Windows 测试机上才跑。
- **换地图**：没用两台设备真的试过接上进度和取消键变灰；极限模式的地图没在真的服务端上开服看过；交接包带来源没拿两台电脑真的走一遍。
- v3.2.5 发布说明里写的那些照旧没实测，见 [v3.2.5 的发布说明](https://github.com/Trasperioooooon/MineDeck/blob/v3.2.5/docs/releases/v3.2.5.md)。往前几版记着的 frpc 那几条里，「拿真的 frpc 试完整性检查」和「拿真的 frp 发行包解压」这两件这次试过了（见上一节）；樱花的 frpc 没试。

## 已知情况

- **用「自定义 frps」时，下载 frp 客户端那一步可能被杀毒软件拦下。** frp 这类内网穿透程序常被杀毒软件当成风险软件。发版前在我们自己的电脑上，Windows 安全中心把 frp 0.61.1 的官方压缩包报成木马隔离了；这是 frp 常碰到的误报，MineDeck 下载下来的包也会和官方的校验值核对。被拦以后隧道启动不了，卡片上有时能认出来、直接说是被杀毒软件拦下了，有时只是一句下载失败或找不到文件的报错。被拦的可能是还在下载的压缩包（在 MineDeck 的缓存文件夹里，名字里不带 frpc），也可能是解压出来的 `frpc.exe`。碰上了，到 Windows 安全中心的「保护历史记录」里找到被拦的那一项，点允许，再启动隧道，MineDeck 会重新下载；别的杀毒软件，到它的隔离区里恢复、允许这一项，再启动隧道。也可以自己从 frp 的 GitHub 发布页下载 `frp_0.61.1_windows_amd64.zip`，把里面的 `frpc.exe` 放进 MineDeck 旁边的 `runtimes\frpc\custom` 文件夹；放进去又不见了的，同样到「保护历史记录」或隔离区里允许、还原它。
- **程序的配置文件写不进盘时，在新位置里新建的服务器重开以后可能不见。** 很少见：MineDeck 的 `config.json` 正好写不进去（磁盘满、被占着），这时第一次往一个新的存放位置里建服务器，建好以后当时在列表里，重开 MineDeck 就不在了，也不在「没建完的文件夹」里。文件都在，用「接管已有服务器」把它加回来就行。
- **删服务器时待装清单的补清，有时要等到下次启动。** 清单的存档文件读得出来的那一刻如果补清没做成（那份记录正好也被占着），要等下次启动才清，这期间同名新建的那台的清单里还看得到上一台留下的东西；这期间又把同一个模组加了一遍的，下次启动时会被当成旧的清掉，再加一次就行。清掉的只是 MineDeck 里的清单和暂存的副本，你电脑上的原文件不动。
- **Adoptium 的接口连得上、却回得很慢时**，还是要等：最多四问，每问最多 10 秒，最坏接近 40 秒才改用 Mojang 运行时。清华镜像本身一直不回话时，那一问照旧按默认时限等。
- **同一台服务器下载 Java 的途中又改选另一个版本**，会有两个下载任务，后做完的那个说了算。
- **换地图卡住以后点「重试恢复」**，就算恢复成功，备份页页顶「从哪份备份还原」的那句说明也已经没有了。
- **在这台电脑上导入地图，仍然没有选 ZIP 文件的对话框。** 可以在路径框里直接填 ZIP 的完整路径，或者用「上传 ZIP」。
- **单实例检查只管当前登录的这个 Windows 用户会话。** 切换到另一个 Windows 用户，或者计划任务在别的会话里启动同一个文件夹里的 MineDeck，拦不住。检查本身出错时（比如没有权限打开那把锁），MineDeck 照常启动。
- **同名服务器，接管的那台优先，有一种情形会让人意外。** 接管进来的服务器放在移动硬盘里，硬盘没插上的时候，你用同一个名字新建了一台；硬盘插回来、重开 MineDeck 以后，列表里显示的会换成硬盘里那台，你正在用的那台只出现在页面顶部的提示里。从 v3.2.4 及更早的版本升上来、以前就有两台重名的，列表里显示的那台也可能换掉。文件都还在，照提示里的办法给其中一台改个名字，两台就都出来了。
- **少见的日志格式可能认不出「启动完成」。** v3.2.5 起只认服务端自己打的那一整行，1.7 以前没有方括号开头的老日志格式认不出；Taiyitist（原 Banner），还有 Sponge 这类靠接管进来的服务端，日志格式没有逐个核对过。认不出的话，服务器明明开好了，状态却一直停在「启动中」。碰到了请告诉我们，附上控制台里启动完成的那一行。
- **导入交接包的表单**提交时不做端口复查，它查端口时也不认系统保留的范围；端口不能用的话，要到开服才报。
- **netsh 里带 `*` 的「管理的端口排除」不算系统保留。** 这种端口在 Windows 上实际能用，MineDeck 不拦。
- **提交时查端口有一种会放过去的情形**：别的程序占着某个端口，而你另一台没停着的服务器的设置里写的也是这个端口。这时表单不拦，开服前的检查会拦。
- **名字正好像临时文件的会被清掉。** 你自己放的文件，如果名字正好是 `.minedeck-backup-20261122.tmp` 这种样子（MineDeck 的固定开头、中间是不超过 10 位的纯数字、固定的结尾），放在服务器文件夹或备份文件夹里一个小时以上没动，启动时会被当成临时文件清掉。
- **这一版仍然只有 Windows 的程序。**
- v3.2.4 已知情况里的几条，有三条这一版变了：「卸载一套便携 Java 的同时把服务器换成这套」修了；「一次处理几百个没装上的文件」现在有批次进度和离开前的确认；「连不上 Adoptium 时官方源那一步仍按默认时限等」改成了上面说的样子。其余照旧，见 [v3.2.4 的发布说明](https://github.com/Trasperioooooon/MineDeck/blob/v3.2.4/docs/releases/v3.2.4.md)。
