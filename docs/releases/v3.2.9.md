这是 MineDeck v3.2.9，接着 v3.2.8 往下修问题的小版本。这一版收拾的多是平常看不见的地方。一块是往服务器文件夹里写文件：碰上和外面的文件是同一份的「硬链接」，不再顺着改到外面去；还原备份之前先看落点，服务器文件夹里有指向别处的链接就不还原；OneDrive 这类云同步的文件夹不再被当成链接（只改了文件夹，也没在真的 OneDrive 上验证过）。另一块是窗口：页面要跳去别的网站时，主窗口留在原地，交给默认浏览器打开；选文件夹的系统对话框改在窗口自己的线程上弹。另外给以后的 Mac 版铺了些路，官网的文档补齐了英文。平常用起来和 v3.2.8 差不多。

## 怎么升级

用着 v3.2.8、v3.2.7、v3.2.6、v3.2.5、v3.2.4、v3.2.3、v3.2.2、v3.2.1 或 v3.2.0 的，打开「设置 → 更新与关于」，点「检查更新」，查到新版本以后点更新就能升到 3.2.9。服务器、Java、设置、隧道和 AI Key 都会接着用。更新前先停掉正在运行的服务器。

用着 v3.1.1、v3.1.2 或者 3.2.0 测试版的，也能在程序里直接升到 3.2.9：3.2.0 的 beta.3 到 beta.5 不管更新渠道选的是哪个都查得到，beta.1、beta.2 和 3.1.x 只看正式版，3.2.9 就是正式版，也查得到。

从 v3.1.0 及更早的版本升级时，换程序的是旧版本自己带的更新脚本，它有两种情况换不成，新版本这时已经下载好、放在旁边。处理办法见 [v3.2.0 的发布说明](https://github.com/Trasperioooooon/MineDeck/blob/v3.2.0/docs/releases/v3.2.0.md)「已知情况 → 升级和更新」的第一条。

从 v2.6.1 及更早的版本升级（那时的程序叫 `AutoMCHUB.exe`），自动更新找不到改名后的文件，请手动下载 `MineDeck.exe` 放进原来的文件夹。旧的开机自启项会被删掉，需要的话在「设置 → 启动与托盘」里重新打开。

从 v3.2.4 及更早的版本直接升上来的，v3.2.5 的几处变化也一起生效：同一个文件夹里的 MineDeck 只能开一份；两台服务器重名、其中一台是接管进来的，列表里显示的可能换成另一台（两台的文件都在）；许可证从 v3.2.5 起改成 GNU AGPL-3.0。细节见 [v3.2.5 的发布说明](https://github.com/Trasperioooooon/MineDeck/blob/v3.2.5/docs/releases/v3.2.5.md)。

从 v3.2.6 及更早的版本直接升上来的，v3.2.7 的两处隧道变化也一起生效：以前手改 `tunnels.json` 撞了号的隧道会被分开，靠后的那条以后会真的跟着服务器启动；新加隧道时「跟随服务器启动」默认不再勾上。细节见 [v3.2.7 的发布说明](https://github.com/Trasperioooooon/MineDeck/blob/v3.2.7/docs/releases/v3.2.7.md)「怎么升级」。

从 v3.2.7 及更早的版本直接升上来的，v3.2.8 的两处变化也一起生效：AI 的每日额度只算输入和输出，用到提示缓存的人额度会显得「松」了，「今天已用」「本月」的 token 数也按新算法重算、变小；服务器文件夹里的 `instance.json` 读不出来的，列表里会多一张「无法读取」的只读卡片。细节见 [v3.2.8 的发布说明](https://github.com/Trasperioooooon/MineDeck/blob/v3.2.8/docs/releases/v3.2.8.md)「怎么升级」。

升级以后有一件事可能和以前不一样，先说在前面：

- **用硬链接让几台服务器共用白名单这类文件的，在 MineDeck 里改它会报错。** 硬链接是让磁盘上同一份文件有两个名字（比如用 `mklink /H` 建的）。以前服务器停着时在 MineDeck 里改白名单、OP、封禁名单，是直接写进这份文件，别的服务器跟着变；现在查出这个文件还有别的名字就不写，报「这个文件和服务器文件夹外的文件是同一份（硬链接），为了不改到外面，没有写入：whitelist.json」。用符号链接共用的不受影响，照旧改的是链接指着的那一份。见下面「往服务器文件夹里写文件时，不会改到外面」。

## 改了什么

### 往服务器文件夹里写文件时，不会改到外面

硬链接是磁盘上同一份文件有两个名字，一个可以在服务器文件夹里，另一个在外面。顺着里面那个名字把内容原样写进去，外面那个也跟着变了。MineDeck 以前查落点时认得出符号链接和目录联接，认不出硬链接。

- **原样写进去的那些，先查这个文件还有没有别的名字，有就不写。** 服务器停着时在 MineDeck 里改白名单、OP、封禁名单（开着的时候是发命令给服务端，由服务端自己写）；新建、接管、导入现成服务端时写的 `eula.txt`；存 `instance.json` 时先写的那份临时文件；新建 Fabric 服务器时的 `fabric-server-launcher.properties`；导入整合包、现成服务端时解出来的文件；还原备份时解出来的世界文件；接管失败时放回去的原文件，等等，一共十几处。查是在打开文件以后、清空它之前做的，查出来就关掉，外面那份一个字节不动。报错是「这个文件和服务器文件夹外的文件是同一份（硬链接），为了不改到外面，没有写入」，后面接文件名。
- **另外几处改成先写一个新文件再换上去，换完和外面那份就分开了。** MineDeck 改语音聊天的 `voice_host` 之前留的 `voicechat-server.properties.bak`，修改模组配置文件之前在 `.minedeck/config-backups` 里留的备份，游戏内 AI 的 `gameai.json` 和 `gameai-state.json`，以前都是原样写进固定名字的文件，现在先写新文件再换上去。前两份备份的名字上原来就有一个只读文件的，照旧报错、不盖掉它，报错里写明是哪个文件。换地图时的事务记录碰上硬链接，就把服务器文件夹里这个名字去掉、另建一个新的，外面那份不动。`server.properties`、`run.bat` 这些以前就是这么写的。
- **符号链接的文件照旧跟过去写。** 这一版只管硬链接。几台服务器用符号链接共用一份 `whitelist.json` 的，改的还是链接指着的那一份，和以前一样。

### 还原备份之前先看落点

- **服务器文件夹里有指向别处的链接，就不还原。** 还原之前，备份里每个要写的文件，先看它在服务器文件夹里要经过的那几层文件夹：有一层是目录联接或符号链接，就不还原，报比如「服务器文件夹里的「world/region」是指向别处的链接，没有还原」；那几层都不是链接、要写的那个东西本身却指到了服务器文件夹外面（或者查不清它实际在哪里）的，报「服务器文件夹里的「…」指到了服务器文件夹外面，或者查不清实际在哪里，没有还原」。以前只按路径的写法查，碰上这样的链接，有可能顺着它写到外面去。
- **备份压缩包里自己带着符号链接的，也不还原**，报「备份内含符号链接」。
- 这一查放在删旧世界之前，被拦下时世界文件一个都没动。

### OneDrive 这类云同步的文件夹

MineDeck 有二十来处要先确认「这是一个普通文件夹，不是指向别处的链接」，才往里走、往里写或者删它：列出和删除没建完的文件夹、建服失败以后的清理、记下「上次没能启动」、启动时清临时文件、卸载便携 Java、换地图等。OneDrive「按需下载」这类云同步的文件夹，按程序读到的文件类型，在这些检查里可能被当成链接，服务器放在 OneDrive 管着的「桌面」「文档」底下时，可能出现没建完的文件夹列不出来、删不掉，建服失败以后没清理，「上次没能启动」记不下来这类毛病。现在这些地方把云同步的文件夹当普通文件夹，真的符号链接、目录联接照旧拦下。

这一条没在真的 OneDrive 上验证过，只改了文件夹；云同步的**文件**在几处检查里可能仍被当成链接，见「已知情况」。

### 窗口

- **页面要跳去别的网站时，主窗口不跟着走。** 点外部链接本来就交给系统默认浏览器打开；可页面要是绕开了这一层、直接让主窗口换地址（比如脚本改了地址），主窗口会真的跳过去。现在主窗口自己再把一道关：去的是 MineDeck 自己的地址，照常；是别的 http、https 网址，主窗口留在原处，交给默认浏览器打开；别的（`file:` 这类）直接拦下。MineDeck 自己的地址里带了用户名的，也拦下。这一道挡的是换页、不挡请求，见「已知情况」。
- **选文件夹的系统对话框改在窗口的界面线程上弹。** 各处「浏览…」和「设置 → 存储位置」里「更改…」弹出的选文件夹对话框，以前是在处理请求的后台线程上弹、再挂到主窗口上，跨线程挂窗口有卡住、焦点乱跳的隐患。现在交给主窗口自己的界面线程去弹。用起来和以前一样：开着时主窗口点不动，选好或者取消以后回到原处；对话框开着时 MineDeck 被关掉或退出，也能干净退出。

### 给 Mac 版铺路

Mac 版还没有发布，这一版发的仍然只有 Windows 程序。这一版在 Windows 上先做了 Mac 版能先做的一部分：几处只在 Mac 上用到的代码（打开文件之前先确认是普通文件、检查端口时补查本机回环地址、比较路径时在 Mac 上区分大小写等），以及 GitHub 上的 macOS 测试机从这一版起把 Go 的自动测试真跑一遍，不再只是编译。Windows 上用起来没有变化。

### 官网文档的英文版

官网文档中心缺的 27 篇英文补齐了，中英文现在各 33 篇。这是官网的内容，官网部署以后才看得到，和程序本身无关。

### 代码整理

还有一批代码上的整理（拆短过长的函数、合并几份重复的实现、按功能给测试文件改名），用起来没有变化。

## 给 AI 助手、MCP 和自己调接口的人

- **玩家名单**（`instance.whitelist.*`、`instance.players.op`、`deop`、`ban`、`pardon`，`POST /api/instances/{name}/players`）：服务器停着、要改的名单文件还有别的硬链接时失败，`error` 是「这个文件和服务器文件夹外的文件是同一份（硬链接），为了不改到外面，没有写入：文件名」。别的原地写（新建、接管、导入时写 `eula.txt` 这些）碰上硬链接也报这一句。
- **还原备份**（`instance.backup.restore`，`POST /api/instances/{name}/backups/restore`）：多三种报错，「服务器文件夹里的「…」是指向别处的链接，没有还原」「服务器文件夹里的「…」指到了服务器文件夹外面，或者查不清实际在哪里，没有还原」「备份内含符号链接: …」，都在删旧世界之前报。
- **启动参数预览**（`POST /api/instances/{name}/settings/preview`）改成经操作层的 `instance.settings.preview`，仅人工、不记操作记录，AI 助手和 MCP 看不到它（以前它不是操作层的一项，也调不到）。请求和返回照旧。

接口的详细说明见 [`docs/设计与参考/API.md`](https://github.com/Trasperioooooon/MineDeck/blob/v3.2.9/docs/设计与参考/API.md)。

## 这一版实际试过的

- **自动测试**：这一版的改动大多带着新加的自动测试。发版前跑了一遍全量：（全量结果待填）。几处改动合到一起以后，在开发分支上先跑过一遍全量：Go 的 46 个有测试的包全部通过，界面交互用例 325 条全部通过，界面原型自检 162 个场景走通；GitHub 上的自动测试在那个提交上也通过了（Windows 上跑 Go 测试；macOS 上这一版起也跑 Go 测试，不只是编译）。
- **反着试**：错了不容易发现的几处，逐条反着试过，把程序改回去，对应的测试都会失败：原地写碰上硬链接要拒绝（白名单、接管时的 `eula.txt`、`instance.json` 的临时文件、还原备份）；语音聊天配置的备份、模组配置的备份、换地图的事务记录、游戏内 AI 的两个文件碰上硬链接不改到外面，两份备份的名字上有只读文件时照旧报错；还原时从上一级文件夹查链接、目标本身指到外面也拦下；云同步的文件夹当普通文件夹、目录联接和符号链接照旧拦下；主窗口导航里 MineDeck 自己的地址（查询或 `#` 后面带反斜杠、零散的 `%`）留在窗口里、不交给浏览器；判断导航时出了错按取消处理；选文件夹对话框的唤醒丢了会补发、对话框关掉以后被压住的回应会执行。
- **窗口的两处在真的 MineDeck 窗口里走过一遍**，先在 v3.2.8 上走同样的步骤对照：接管页的「浏览…」弹得出选文件夹对话框，开着时主窗口不可用、关掉以后恢复，对话框确实在主窗口的线程上了（v3.2.8 不是）；取消、选定都正常；开着时再要一次选文件夹不会弹第二个；对话框开着时给窗口发关闭、或者发「退出 MineDeck」，程序都在一秒内干净退出，不留进程。F5 刷新照常重载、留在界面里；控制台的「导出为 txt」照常下载，主窗口不动。页面里跳到 MineDeck 自己的地址（包括带反斜杠、零散 `%` 的）留在窗口里；「设置 → 更新与关于」里「源码在 GitHub」的链接点一次，只在默认浏览器里开一次。
- **伙伴模组和语音桥接模组**：这一版没有改这两个模组，GitHub 上用源码重编、和打进程序的 jar 对比那一项照常通过。

## 还没实测过的

- **云同步的文件夹**：没在真的 OneDrive 上试过。用例里代替它的，是在测试里造出来的文件夹类型和目录联接，不是真的云同步文件夹和文件。
- **硬链接**：都是在测试里自己建的。十几处原地写里，有单独用例的是白名单、还原备份、接管时的 `eula.txt`、`instance.json` 的临时文件这四处，别的靠它们走的是同一段检查。
- **还原时目标本身是指到外面的符号链接**：发版用的电脑上没有建符号链接的权限，这条用例在那里跳过，只在 GitHub 的测试机上跑过。
- **选文件夹对话框**：真窗口里只走了接管页的「浏览…」，别处的「浏览…」和「更改…」没有逐个点。对话框开着时窗口正在被拖动、或者托盘菜单正开着的情形没试，补发唤醒只在仿照窗口线程写的测试里试过；对话框开着时从托盘退出也没试。主窗口不可用是看窗口状态确认的，没拿真鼠标去点。
- **导航拦截**：在真的 MineDeck 窗口里，`file:` 地址留在原页，可那是浏览器自己先拦下了，拦截那一道有没有单独起作用没看到；往外跳的那一次拿的是浏览器本来也不让去的端口，默认浏览器确实被拉起来了，主窗口留在原页却不能全算拦截的功劳。拦下换页这件事，是在自动测试里用真的 WebView2 隐藏窗口试的。拖进窗口的文件归不归它管，没验证。
- **Mac**：Mac 版的程序没在真的 Mac 上跑过，只有 GitHub 上 macOS 测试机跑的自动测试。
- **官网的英文文档**：只抽看了几篇，没有逐句对过译文。
- v3.2.8 发布说明里写的那些照旧没实测，见 [v3.2.8 的发布说明](https://github.com/Trasperioooooon/MineDeck/blob/v3.2.8/docs/releases/v3.2.8.md)。

## 已知情况

- **云同步的文件夹那一条只改了文件夹，也没在真的 OneDrive 上验证过。** 云同步的**文件**（不是文件夹）在几处检查里可能仍被当成链接，比如删没建完的文件夹、卸载便携 Java、换地图时查来源和暂存区。服务器放在 OneDrive 这类文件夹里、换地图又退回时，暂存区可能留着不删，不会让换地图失败，也不会删错。放在 OneDrive 里的服务器碰上说某个东西是链接、不处理的报错，欢迎告诉我们。
- **选文件夹的对话框开着时，窗口对页面的其他回应要等对话框关掉才回来。** 关掉以后马上就回来；以前是立刻回应。对话框开着时主窗口本来就点不动，一般感觉不到。
- **主窗口的导航拦截挡的是换页，不挡请求。** 被拦下的那一次，页面要去的地址仍会收到一次请求；交给默认浏览器打开的外部地址会被请求两次，一次在窗口里，一次在浏览器里。页面里嵌着的网页（iframe）和另开的小窗不归它管。
- **还原被拦下时，「还原前自动」的那份备份已经做好了。** 还原之前会先把当前的世界备份一份，再查落点；查出链接不还原时，这份备份留着，算在保留份数里。
- **以前强退留下的 `gameai.json.tmp`、`gameai-state.json.tmp` 不会被自动清掉。** 3.2.8 及以前的游戏内 AI 用固定名字的临时文件，程序被直接关掉时可能留下来。它们没有害处，可以手动删掉。
- **用硬链接共用的名单文件，在 MineDeck 里改不了。** 见上面「怎么升级」。要改的话，到文件夹里直接改那一份。
- **这一版仍然只有 Windows 的程序。**
- 往前几版已知情况里的各条照旧，见 [v3.2.8 的发布说明](https://github.com/Trasperioooooon/MineDeck/blob/v3.2.8/docs/releases/v3.2.8.md)。
