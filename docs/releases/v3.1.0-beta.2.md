这一版没有新功能，是把 beta.1 实际测出来的问题修掉。beta.1 新加的三个功能（把服务器打包交给别人、模组购物车、整合包里下载不了的文件逐个处理）见 [v3.1.0-beta.1 的发布说明](https://github.com/Trasperioooooon/MineDeck/releases/tag/v3.1.0-beta.1)。

beta.1 发出去的时候，有三块没有实际试过：Forge 和 NeoForge 的服务器交接、几个 GB 的大交接包、CurseForge 的整合包。这次在一台 Windows 11 上把它们都跑了一遍，一共 22 条，下面的修复都是这一轮测出来的。

## 修了什么

**导入交接包**

- **导入完看不到开头的说明**：不带核心的交接包导入时要跑官方安装器，安装器一口气打几百上万行，把日志开头「包里有什么、哪些没带过来」那几行挤没了，而最后一行偏偏写着「没带过来的东西见上面几行」。现在日志太长时，开头的几十行会留着，中间省略了多少行会标出来。新建 Forge 服务器、导入整合包的日志同样如此。
- **超过 8 GB 的包**：以前要等整个文件传完，才冒出一句 `上传解析失败: http: request body too large`。现在选了文件就告诉你超过了上限，不用白等。上限本身没有变，见下面的「已知情况」。
- **旧版 Forge 装了一半被当成装好**：Forge 1.16.5 这类老版本的官方安装器，在它自己的联网检查失败时（网络一抖就会），什么都不装就报告「成功」。如果正好发生在 MineDeck 重试的那一次，上一次留下的半截安装会被当成装好的，导入显示成功，服务器一开就崩。现在这种情况算作这一次失败，会接着重试。新建旧版 Forge 服务器时同样受益。
- **两句说错的话**：导入旧版本的服务器时，日志里把 MineDeck 自己加的两个安全参数列成「原来的 JVM 参数没有带过来，需要的话自己加」，其实已经加上了，照做就加重了。导出时，空文件夹（比如 Forge 一装好就有的空 `defaultconfigs`）被提醒成「没有进包」。这两句都去掉了。

**导入 CurseForge 整合包**

- **资源包、光影、数据包不再全塞进 `mods`**：整合包的清单不区分这些，以前一律放进 `mods`，在那里什么用都没有。现在按它们在 CurseForge 上的类别分开放：资源包进 `resourcepacks`，光影进 `shaderpacks`，数据包进 `datapacks`。实测的一个整合包里，有 203 个文件原来放错了地方。
- **下载不了的文件看得出是哪个了**：作者不允许第三方工具下载的那些，以前「待处理」里只有一串项目编号。现在有文件名、项目的名字、具体是什么原因，还有这个文件在 CurseForge 网站上的下载页，点过去就能手动下载。
- **用本地来源目录能自动补上**：因为现在知道文件名了，导入时在「本地来源目录」填上自己电脑里那个整合包的文件夹（比如 CurseForge 客户端里的那一份），下载不了的文件凡是那里有同名的，会自动拿过来。
- **超过 4 GB 的整合包**同样在上传前就提示。

**其他**

- 导入交接包的页面上，先选好一个包、再换成另一个文件时，上一个包的摘要会立刻清掉。以前换成一个有问题的文件，页面上还留着上一个包的信息，点「导入」导的是上一个。
- CurseForge 接口返回的文件名现在只认单独一个文件名，带路径的一律不用，免得文件落到不该去的地方。

## 这一轮实际试过的

- **Forge 1.20.1、NeoForge 1.21.1、旧版 Forge 1.16.5 的交接**：带核心和不带核心的各一遍，外加一个带中文和空格的名字。模组、配置和存档逐个文件比对，一个不缺、内容相同，导入出来的服务器都能开起来。不带核心的包导入要重新跑安装器，花一到三分钟；带核心的三秒。
- **大交接包**：5 GB 的包和里面有单个 4.5 GB 文件的包都走通了，导入后和原来逐字节相同。导出 6 到 9 秒，传给另一份 MineDeck 半分钟出头，导入 9 到 15 秒。MineDeck 占的内存一直在 300 MB 以内，和包的大小无关。
- **CurseForge 整合包**：四个真实的整合包（All the Mods 10、BMC4、Fabulously Optimized、Prominence II），填了 API Key 和没填各导了一遍，清单里的每一项要么下载到了，要么列在「待处理」里，数目都对得上。

上面这些是在 beta.1 上跑的。修好以后，用改过的程序重跑了其中三条（旧版 Forge 的交接、一个 CurseForge 整合包、一个超过上限的包），结果和上面「修了什么」里写的一致。完整的记录在[补测报告](https://github.com/Trasperioooooon/MineDeck/blob/v3.1.0-beta.2/docs/测试报告-v3.1.0-beta.1-补测.md)里。

## 请重点帮忙试这些

下面这些还没有人试过，最想知道结果：

- **真的换一台电脑**：上面的交接都是在同一台电脑的两份 MineDeck 之间做的。把包拿到另一台电脑、另一个 Windows 用户下导入，是不是一样顺。
- **进游戏看一眼**：导入出来的服务器只确认了文件一致、能开起来。用游戏客户端进去，地形、箱子、玩家数据是不是都在。
- **带很多模组或插件的真实服务器**交接过去以后，是不是和原来一样能进、能玩。
- **CurseForge 整合包里下载不了的文件**：照着下载页手动下载以后，用「用本地的文件」补上；或者用「本地来源目录」让它自动认。
- **购物车**：Forge、NeoForge 的模组和 Paper 的插件；让 AI 助手帮着挑、帮着装；新建向导里「选模组」那一步。
- **带自建站点下载地址的真实整合包**。

发现问题请在 GitHub 上提 Issue，或者直接告诉作者。**不要贴出 API Key 和各种令牌。**

## 已知情况

- **交接包不能超过 8 GB**：开了很久的服务器，存档有可能超过这个数。超过的话，把整个服务器文件夹拷到另一台电脑上，在「新建服务器」页用「接管已有服务器」把它收进来。
- **CurseForge 上的整合包多数是给客户端用的**：里面常有只能装在客户端的模组（比如渲染优化类的），照着清单装出来的服务器会开不起来。这次试的四个整合包里有三个是这样。MineDeck 目前不会提醒这一点，看到的是导入成功、启动后崩溃。大型整合包的作者一般另外提供 Server Pack：下载那个，解压以后用「接管已有服务器」。
- **整合包清单里的数据包放在 `datapacks` 文件夹里，不会自己生效**：带数据包的整合包通常自己带着加载它们的模组和一份放好位置的拷贝，MineDeck 不去动存档里的数据包设置。
- **待处理的文件要在这次运行里处理完**：关掉 MineDeck 再打开，任务页上的待处理清单就没有了，只剩服务器文件夹里的「导入待决清单.txt」和「未解析模组清单.txt」，要自己照着把文件放进去。
- **信任过的站点没有地方取消**：目前要手动改 `config.json` 里的 `trustedHosts`。
- **导入交接包被打断**（关程序、断电）时，建到一半的文件夹会留在存放位置里，不会出现在服务器列表中，可以直接删掉。
- **向导里挑的模组放在一辆「草稿」购物车里**，它不记是给哪种核心挑的。挑了模组以后回头换了核心，或者上次挑完没建成服，下次建服时这些模组可能装不上，任务页会写「找不到能装的版本」。遇到了就到新服务器的「购物车」标签里重新挑。
- **购物车一次能带出多少前置没有上限**：前置很多的模组，检查依赖和安装会慢一些。
- **没有数字签名**：第一次运行时，Windows 可能提示「Windows 已保护你的电脑」，点「更多信息 → 仍要运行」。
