这一版只修了一件事，和「接管已有服务器」有关。别的功能和 beta.2 一样，见 [v3.1.0-beta.2](https://github.com/Trasperioooooon/MineDeck/releases/tag/v3.1.0-beta.2) 和 [v3.1.0-beta.1](https://github.com/Trasperioooooon/MineDeck/releases/tag/v3.1.0-beta.1) 的发布说明。

## 修了什么

**接管一台服务器以后，旁边的服务器不再自己出现在列表里。**

以前接管一个文件夹时，MineDeck 记下的是它的上一层目录，下次启动会把那一层里的文件夹都看一遍。结果是：上一层里别的被 MineDeck 管过的服务器（文件夹里有 `instance.json` 的），没点过接管，重启以后也出现在了列表里。最容易碰到的情形是老版本 MineDeck 的 `servers` 目录：接管其中一台，重启后其余几台都回来了，它们记的 Java 路径还可能指向已经不在的地方。

现在接管只记被接管的那一个文件夹，旁边的不会跟着出现。服务器文件夹暂时不在（比如放在没插上的移动硬盘里）时，这台服务器这次不显示，下次文件夹回来了照样在。把服务器移出列表或者删除以后，这条记录也一起去掉。

新建服务器、导入整合包、导入交接包不受影响，和以前一样。

## 用 beta.1、beta.2 接管过服务器的，请看这里

这次的修复只管以后的接管，管不到已经接管过的：那两版记下的上一层目录还在配置里，升级以后你接管的服务器照样在，但那一层里别的服务器也照样会出现。程序没法替你清，因为它分不出哪一条是接管时记的、哪一条是你自己设过的存放目录。

不想看到那些多出来的服务器，有两个办法。

简单的办法：在列表里把多出来的那几台逐个「移出列表」（删除时不要勾「同时删除服务器文件夹」）。文件都留着，以后不会再出现。要注意，这会把那个文件夹里的 `instance.json` 改名成 `instance.json.bak`；如果那几台正被另一份 MineDeck 管着，那一份里它们也会消失，这种情况用下面的办法。

彻底的办法：先把你接管的那台「移出列表」，然后完全退出 MineDeck，用记事本打开 `MineDeck.exe` 旁边的 `config.json`，在 `roots` 里删掉那一层目录所在的那一行，保存。再打开 MineDeck，重新接管那台服务器，原来的内存、定时任务这些设置会带回来。

## 这一版实际试过的

在一台 Windows 11 上，用一份全新的 MineDeck 接管了一台真实的 NeoForge 1.21.1 服务器，它旁边放着另一台带 `instance.json` 的 Forge 1.20.1 服务器。重启以后列表里只有接管的那一台；把它移出列表再重启，列表是空的；再接管回来，重启后还在。

修之前的那一轮真机实测（识别、接管、启动真实的服务器、换 Java、移出列表再接管，一共 31 步）记在[实测报告](https://github.com/Trasperioooooon/MineDeck/blob/v3.1.0-beta.3/docs/测试报告-接管已有服务器-真机实测.md)里，这个问题就是那一轮发现的。

还没有人试过的：在真实窗口里点「浏览」选文件夹来接管（上面是直接调接口做的）；Paper、Fabric 和老版本 Forge 的真实服务器。

## 下载哪个文件

| 文件 | 给谁 |
|---|---|
| `MineDeck.exe` | 开服的人。放进一个单独的文件夹，双击运行。 |
| `minedeck-companion-neoforge-1.21.1-0.2.1.jar` | 用了 AI 伙伴的 NeoForge 1.21.1 服上的好友：放进客户端的 `mods` 目录 |
| `minedeck-companion-forge-1.20.1-0.2.1.jar` | 同上，Forge 1.20.1 的服 |
| `SHA256SUMS` | 校验和，自动更新会用到，一般不用管 |

伙伴模组和 v3.0.0、beta.1、beta.2 的是同一份，已经装过的不用换。

## 已知情况

和 beta.2 相同，见 [v3.1.0-beta.2 的发布说明](https://github.com/Trasperioooooon/MineDeck/releases/tag/v3.1.0-beta.2)里的「已知情况」。另外补一条和接管有关的：

- **接管进来的服务器和存放目录里的服务器重名时**，列表里只显示存放目录里的那一台。接管的时候会查重名，所以一般碰不到；碰到了，给其中一台换个名字（移出列表后重新接管时可以改名）。
