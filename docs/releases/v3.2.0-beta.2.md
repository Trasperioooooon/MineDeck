和 v3.2.0-beta.1 比，这一版修了内网穿透的三个问题，还有保存文件时偶尔报错的一个问题。

## 内网穿透

- **公网地址显示成 `ext.go:37`**。OpenFrp、樱花的隧道启动以后，卡片上的公网地址有时不是能连的地址，而是 `ext.go:37` 这样的一串。那是 frpc 日志里标注程序位置的一小段，被 MineDeck 当成了地址，v3.1.2 也有这个问题。现在会跳过这类内容，取这一行里真正的地址。域名和 IP 都出现时照旧优先用域名。
- **隧道配置读不出来时，不会再把原来的隧道盖掉**。以前 MineDeck 启动时，`tunnels.json` 要是刚好被别的程序占着（杀毒软件、同步盘），或者文件坏了，隧道页会显示成一条隧道都没有；这时再添加一条，原来的隧道和保存的凭据就全没了。现在读不出来时，隧道页会直接说明原因，读出来之前不能添加、修改、删除或启动隧道，原文件不动。占用放开或者文件修好以后会自动恢复，不用重启。
- **隧道配置写不进磁盘时会告诉你**。以前磁盘满了、文件被设成只读的时候，添加隧道、从平台导入或创建隧道都显示成功，重启以后却不见了。现在会提示这次没有保存。在平台上已经建好、只是本机没存上的那一条，会提醒你去「导入」，不要再创建一次。

## 保存设置和配置文件

- **偶尔报「替换文件失败：Access is denied」**。几处同时保存同一个文件（比如 `server.properties`），或者文件正好被别的程序读着，保存有很小的概率失败，再点一次才成功。这是 v3.2.0-beta.1 换保存方式时带进来的。现在碰上这种情况会隔一会儿再试，最多约半秒，还不行才报错。

## 这一版实际试过的

- 自动测试：Go 测试在 Windows 上全部通过（41 个包），带竞态检测再跑一遍也全部通过；界面交互测试 183 条、界面原型 119 个场景在仿真后端上走通。
- 保存文件：几路同时保存同一个文件的测试连跑 150 遍，保存这部分的全部测试连跑 100 遍，没有再出现「Access is denied」。
- 隧道配置读不出来：用编出来的程序实际试了三种情况，文件坏了一半、文件被别的程序占着、没有这个文件。前两种，隧道列表都报出了原因，添加隧道被拒绝，原文件没有被动过；把文件修好或者把占用放开以后，不用重启，原来的隧道回来了，再加一条，新旧两条都在。
- 公网地址：用三十来种照着 frpc 的写法造出来的日志行测过，包括带程序位置的、域名和 IP 同在一行的、IPv6 的。
- 这一版的改动请别家模型（Codex）做过只读复审，三处修复的结论都是可以发。
- 发版前在一台 Windows 11 上用编出来的程序做了基本核对：程序报的版本号对，不开窗口启动以后首页能打开；端口被别的程序占着时点启动会马上提示，放开以后真的开起一台 Paper 1.20.1 服务器，再停掉。

## 还没测到的，请帮忙留意

- **公网地址的修复没有用真实的 OpenFrp、樱花账户验证过**。手头没有真实的隧道日志，修复是按 frpc 的日志写法做的，测试用的是照着写的日志行。如果卡片上的公网地址还是不对，请把隧道日志里带地址的那几行发给我们，凭据记得遮掉。
- **真的被杀毒软件、同步盘占着 `tunnels.json` 的情况没有制造过**，测试里是程序自己把文件占住，系统报的是同一种错。
- **保存时文件被别的程序占着**，同样是程序自己占住来测的。半秒够不够等过真实的杀毒扫描，没有实测数据。
- v3.2.0-beta.1 发布说明里「还没测到的」那几条（地图导入在真窗口里完整走一遍、导入以后用游戏客户端进服、真实的 AI Key 等）仍然没有测。

## 已知情况

- **隧道配置读不出来的时候，音乐共享页仍然显示「没有语音隧道」**。只是说法不准，不会改动任何配置；隧道页上的说明是对的。
- **文件一直被别的程序占着时，报错会比以前晚约半秒**。比如服务器开着的时候替换一个正在用的模组文件。
- v3.2.0-beta.1 发布说明里「已知情况」的各条仍然适用。
