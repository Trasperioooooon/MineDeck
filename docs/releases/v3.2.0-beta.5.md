> - **用着 v3.2.0-beta.3 或 beta.4 的**，「设置 → 更新与关于」里没选过更新渠道、或者选的是「最新版」，检查更新就能直接换到这一版。选了「稳定版」的看不到它。

这一版只修问题，没有新功能，界面没有变化。前几次发版时自动测试常常要重跑几遍才通过，这次把历次失败逐一查清了：多数是测试自己的毛病，也有几处是程序里真的问题。顺着这次排查，又把 beta.1 里一次大改动重新逐行读了一遍，找出两处会影响到你的问题，一起修了，见「修复」。

## 修复

- **定时备份碰上服务器正在启动、停止或重启，这一天就没有备份**（beta.1 起）。beta.1 给备份加了两道保护：服务器正在启动或停止时不备份；备份途中服务器停止或重启过，这一份作废。手动备份碰上了会提示你重试，定时备份却只在控制台留一行字，不再试。于是把定时备份和定时重启排在同一分钟、世界又大到一分钟压不完的，或者把备份排在重启后一两分钟、服务器还没启动完的（带模组的服常常要几分钟），每天都做不成备份，自己还不一定看得见。现在定时备份因为这个原因没做成时，会等服务器启动完或停稳（最多等 15 分钟）再备份，最多再试两次，控制台里写明这一次为什么没做成、正在等。别的原因失败的不重试。
  - 手动备份不变。只有一处变化：服务器开着时备份，压缩途中有人点了停止的，这一份现在也作废，提示重新备份（以前会照样保存一份）。
- **便携 Java 装到一半中断的，下次会重新装**（beta.1 起）。以前只要 `bin\java.exe` 在，就算这套 Java 装好了。beta.1 给解压加了磁盘余量检查，盘上只剩两三百兆时，可能解到一半因为空间不够停下，留下一个有 `java.exe`、别的却不全的半截。腾出空间以后，这半截会被直接拿去开服，报的是 Java 自己的错误，看不出是没装完，也不会重新下载，只能手动删掉 `runtimes\java-N` 文件夹。现在开始装之前会先放一个「还没装完」的记号（`runtimes\java-N.incomplete`），整套装完才拿掉，记号还在的下次会重装；解压失败时把解出来的一半删掉；一开始就按解开以后的总大小查磁盘空间，放不下就不动原来的文件夹。以前装好的 Java 照旧能用。
  - 如果你碰到过开服时 Java 报一串看不懂的错、怎么重试都一样，可以看看 MineDeck 文件夹里的 `runtimes`，把那个版本的 `java-N` 文件夹删掉，下次开服会重新下载。
- 几处极短的先后顺序问题，人手几乎点不出来，一起改了：AI 伙伴刚连上的一瞬间，伙伴页显示已连上、却还没有模组版本；导入交接包失败以后，用同一个名字马上重试，偶尔被回「正在创建中」；换地图时刚读完压缩包的内容就取消，上传的文件偶尔删不掉。

## 已知情况

这次重读 beta.1 的那次大改动，还找出几处没有在这一版改的，先写在这里：

- **同一个盘上正在做很久的备份、还原或换地图时**，新建服务器（要解压 Java）、第一次启动隧道（要解压 frpc）、添加本地模组，会停下来排队等前面的做完，期间取消不了，界面上也没有「在排队」的提示。
- 程序被强行结束或断电时，正在下载、复制、保存的临时文件（名字以 `.minedeck-` 开头）会留下，不会自动清理。反复强退的话，下载到一半的 Java 包、服务端文件会占着空间，可以手动删掉。
- **C 盘（系统临时文件夹所在的盘）只剩一两百兆时**，上传很小的文件（比如一个几兆的模组）也会被拒收，报错里没说是哪个盘不够。
- 导入现成服务端压缩包（文件直接放在最外层的那种）时，任务标题显示成一串数字，比如「导入服务端 3045782611」。
- AI 的回复长到超过上限时，如果已经开始输出，界面上可能说成「回复中途断开了」，真正的原因在「复制原文」里。

下面这些是 beta.4 就写过的，照旧：

- **新建时预查端口查不出 Windows 保留的端口段**。Hyper-V、WSL、Docker 这类会成段保留端口，被保留的端口预查时看着是空的，开服时照旧报「用不了」，页头照旧给「改端口」。
- 新建的表单打开时查过的默认端口（包括自动换成的那一个），表单开着期间被别的程序占上的话，不会再提示，开服时才会报。
- 备份页页顶「现在的世界从哪来」靠的是「换地图」里的记录，记录删掉以后只能说没有记录。新建向导和「换地图」页里，地图仍显示存档里的名字（多半是 world）。
- **报错提示的位置**：窗口比较窄（800 像素宽上下）时打开报错的「详情」，提示会盖住弹窗右边一截；窗口很矮、提示退回标题栏下方时，会盖住页头右边的启动这几个按钮；提示落在提示区下面时，会挡住标签栏右端的一两个标签；好几条提示叠在一起、比整个窗口还高时，下面的几条会出屏幕。提示 20 秒后自己走，鼠标停在上面时不走。
- 一个以前就有、要别的程序配合才碰得上的竞态：MineDeck 核对完服务器里的文件夹在哪、真正去读写之前的那一瞬间，要是别的程序正好把这个文件夹换成了指到服务器外面的目录联接，读写配置、补没装上的文件时有可能动到服务器外面。以后的版本把这几处改成按已经核对过的文件夹来操作。
- 在 MineDeck 里保存设置以后，设成只读的 `server.properties` 这类文件不再是只读的；还想让服务端改不了它，要再设一次只读。
- **存放位置的「撤销」不是完全撤销**：选错了文件夹再撤销，那个文件夹仍会留在扫描列表里。
- **原版服务器上**，导入整合包时跳过的文件在界面上找不回来（原版没有插件 / 模组页）。
- **接管已有服务器时，如果它的端口和别的服务器撞了**，MineDeck 会改它 `server.properties` 里的 `server-port`（只改这一项，界面上会说明）。
- 启动时后台检查更新，日志里不写用的是哪个渠道。选了更新渠道以后，要程序启动时自己去查，还得打开同一页上的「启动时静默检查更新」。
- **26.1 及以后的服务器，如果以前在游戏里用命令改过难度**，第一次用 beta.3 及以后的版本开服时，难度会改回「设置」里写的那个。想保留游戏里的难度，先到这台服务器的「设置 → 常用」里把难度改成一样的。
- 给服务器换一个要现下的 Java 时，下载还没完就重新打开这台服务器的「设置 → 启动与内存」再保存一次，会再建一个下载任务（不会重复下载文件）。
- 检查更新比较版本号时，预发布那一段（beta、rc 这些）不分大小写。MineDeck 自己的版本号都是小写，碰不到。
- beta.1、beta.2 发布说明里「已知情况」的其余各条仍然适用。
