这是 MineDeck v3.2.7，接着 v3.2.6 往下修问题的小版本。这一版处理的是导入和内网穿透两块积攒下来的毛病：整合包和现成服务端压缩包套了好几层文件夹、核心改了名字、版本号只写在日志里的，现在也认得出，启动脚本里的 JVM 参数挑安全的带过来，跳过了哪些文件、哪些文件只差大小写会列在导入结果里；导入失败以后只清理这次自己建的东西，清不干净时照实说；导入交接包也能「返回修改」了。内网穿透这边，以前撞了号的隧道会分开，OpenFrp 的 frpc 下载握不上手时有了一次退路，坏掉的 frpc 不会再反复重下，在平台上建隧道出了错不会让人再点一次、多建一条。

## 怎么升级

用着 v3.2.6、v3.2.5、v3.2.4、v3.2.3、v3.2.2、v3.2.1 或 v3.2.0 的，打开「设置 → 更新与关于」，点「检查更新」，查到新版本以后点更新就能升到 3.2.7。服务器、Java、设置、隧道和 AI Key 都会接着用。更新前先停掉正在运行的服务器。

用着 v3.1.1、v3.1.2 或者 3.2.0 测试版的，也能在程序里直接升到 3.2.7：3.2.0 的 beta.3 到 beta.5 不管更新渠道选的是哪个都查得到，beta.1、beta.2 和 3.1.x 只看正式版，3.2.7 就是正式版，也查得到。

从 v3.1.0 及更早的版本升级时，换程序的是旧版本自己带的更新脚本，它有两种情况换不成，新版本这时已经下载好、放在旁边。处理办法见 [v3.2.0 的发布说明](https://github.com/Trasperioooooon/MineDeck/blob/v3.2.0/docs/releases/v3.2.0.md)「已知情况 → 升级和更新」的第一条。

从 v2.6.1 及更早的版本升级（那时的程序叫 `AutoMCHUB.exe`），自动更新找不到改名后的文件，请手动下载 `MineDeck.exe` 放进原来的文件夹。旧的开机自启项会被删掉，需要的话在「设置 → 启动与托盘」里重新打开。

从 v3.2.4 及更早的版本直接升上来的，v3.2.5 的几处变化也一起生效：同一个文件夹里的 MineDeck 只能开一份；两台服务器重名、其中一台是接管进来的，列表里显示的可能换成另一台（两台的文件都在）；许可证从 v3.2.5 起改成 GNU AGPL-3.0。细节见 [v3.2.5 的发布说明](https://github.com/Trasperioooooon/MineDeck/blob/v3.2.5/docs/releases/v3.2.5.md)。

升级以后有两件和隧道有关的事可能和以前不一样，先说在前面：

- **以前撞了号的隧道会被分开，靠后的那条以后会真的跟着服务器启动。** 只有手改过 `tunnels.json` 的人可能碰上，见下面「撞了号的隧道」。程序文件夹里可能因此多出一个 `tunnels.json.bak-年月日-时分秒` 备份文件。
- **新加隧道时，「跟随服务器启动」默认不再勾上。** 已经有的隧道不受影响，原来勾着的照旧勾着。

## 改了什么

### 导入整合包和现成服务端

- **套了好几层文件夹的包也认得出。** 以前包装文件夹只认一层，整合包清单或服务端文件再往里套一层就认不出来。现在只有一个文件夹一层层套着的，最多往里认三层。Mac 上打的压缩包夹带的 `__MACOSX` 文件夹、`.DS_Store` 和 `._` 开头的文件不算数，不会因为它们认不出。导入页上的说明和认不出时的报错跟着改了。
- **不会再把不是整合包、不是服务端的东西认错。** 文件夹里放着一份 `manifest.json` 的，要读得出来、写着游戏版本（或者明写是整合包清单）才当成 CurseForge 整合包；最外层单独一个名字和内容都认不出的 jar，不再当成服务端。反过来，服务端 jar 改了名字、包里只有它加一个启动脚本的，会打开 jar 按内容认出核心。
- **解压现成服务端之前先查一遍盘上的空间。** 按解开以后的大小算，不够就在写第一个文件之前停下，不会写到一半才把盘塞满。查不到剩余空间的盘照常解压，任务日志里说一句。
- **启动脚本里的 JVM 参数挑安全的带过来。** 以前只写在 `run.bat`、`start.bat`、`run.sh`、`start.sh` 或 `user_jvm_args.txt` 里的 JVM 参数一个都不带。现在调性能的几类会带到「设置 → 启动与内存」的自定义 JVM 参数里：`-XX:` 的开关和数值、`-Xss` 这几样、`-D` 里不是 Java 自己的设置的。内存照旧按导入页上填的。能让 Java 另外加载程序、执行命令、往服务器文件夹外面写文件、改代理的，还有日志配置和编码，一律不带。带了哪些、没带哪些，导入结果里会列一条「启动脚本里的 JVM 参数带过来 N 个，没带 N 个」。脚本里的变量展开以后长得离谱的（一个变量或一行超过 32 KB，或者整份超过 1 MB），整份按认不出办，什么都不带，免得一份坏脚本把 MineDeck 的内存吃光。
- **版本号只写在日志里的服务端也认得出。** 服务端 jar 里没写 Minecraft 版本时，最后会看压缩包里的 `logs/latest.log`，从开服时打的那一行认版本。这样认出来的，导入页的提示会说「版本号是从压缩包里的日志认出来的」，导入结果里也有一条「版本号是从日志里认出来的」：它是这台服务器上一次开服时的版本，后来换过服务端的话就不对了。
- **导入时跳过了哪些文件，导入结果里列得出来。** 以前只在任务日志里提一句，有的（Modrinth 清单里写明只给客户端用的）连日志里都没有。现在导入结果里有一条「N 个文件没有装进来」，每一项后面写着原因：只给客户端用的、MineDeck 自己的文件、名字在 Windows 上写不出来的。
- **只差大小写的文件，导入结果里也列出来。** Windows 上 `Config.yml` 和 `config.yml` 是同一个文件，只能留一份。以前留哪个的规矩不变，但只写在任务日志里；现在导入结果里有一条「N 组文件名只差大小写」，每组写明留下的内容是哪一个。整合包清单里的下载、覆盖文件夹里的文件、现成服务端压缩包里的都算。
- **整合包导入留下了没装上的文件时，任务页上多一个「打开服务器文件夹」。** 里面的「导入待决清单.txt」列着这些文件，处理时点了「跳过」的也在。原版服务器没有插件 / 模组页，以前导入完了就找不回来，现在至少在任务页上能打开文件夹看；只在这台电脑上打开 MineDeck 时有这个按钮。

### 导入失败以后的清理

新建服务器、导入整合包、导入现成服务端和导入交接包，失败或取消以后都会清掉建了一半的文件夹。这一版把这一步收紧了。

- **只整个删这次自己建的文件夹。** 以前清理时不看文件夹是不是这次建的，有一种很少见的情形会误删：选好名字以后、MineDeck 真正建文件夹之前，同一个位置上正好冒出了一个同名文件夹（比如你刚拷进去的），之后任务又失败了，这个文件夹会被当成半成品删掉。现在建服务器文件夹时，这个位置上已经有同名文件夹就直接失败，报「这个位置已经有一个同名文件夹（可能是刚放进来的），没有动它」，什么都不删。
- **清理没成时照实说。** 文件被别的程序占着、删不干净时，导入交接包和导入现成服务端的任务页以前还说「半成品的文件夹已经清理干净，可以重试」，导入交接包时清理出的错甚至直接丢掉。现在四种任务都一样：失败原因后面接上「清理半成品失败」和原因，任务页上原来那句提示换成「文件夹没删干净：这次建了一半的会列在服务器页上方「没建完的文件夹」里，到那里处理。」
- **接管一个没建完的文件夹时，先去掉它「没建完」的记号再动手。** 去不掉就不接管，报错里写明原因；接管失败时记号和别的文件一起放回去。

### 导入交接包可以「返回修改」

和导入整合包一样，导入交接包失败或取消以后，任务页上有「返回修改」，回到刚才的表单，名字、端口、内存、Java、存放位置和 EULA 都还在。上传的那份交接包在导入结束时已经删掉了，所以回来以后会把你选的包自动再上传一遍；浏览器没留住这个文件的话，会提示「上次选的是「…」，请再选一次」。

### log4shell 防护

v3.2.3 起，MineDeck 会看服务端 jar 自带的 log4j 是哪一版，修过的就不套 Mojang 的日志配置。

- **jar 里记版本的那几份文件靠不住时，照旧套上防护。** 以前这几份文件有同名的两份、大得离谱（超过 64 KB），或者 `pom.properties` 里版本写了两次又不一样时，有可能被判成「已经修过」，等于把防护摘掉了。现在这几种都按「看不出来」处理，照旧套上 Mojang 的配置。
- **带签名的大清单不连累整个 jar。** 原版 1.21.11 这类服务端 jar 的 `MANIFEST.MF` 后面逐个文件列着签名摘要，有一两 MB。这里只用开头那一段找启动类，所以超过 64 KB 时只读开头，开头那一段完整的照常认。
- **开服时要补上或换上日志配置的引用，设置文件却写不进去时，照实说。** 官方的那份配置已经在服务器文件夹里、只差启动参数里的引用时，MineDeck 会在开服前当场补上。这时 `instance.json` 写不进去（只读、被别的程序占着），以前控制台里说「后台正在下载，补上了下次启动生效」，其实不需要下载，后台那一遍也只会再写不进去一次；现在照实说这台服务器的设置文件写不进去、原因，这次照旧启动，并提醒在补上之前先别让不认识的人进服。

### 撞了号的隧道

v3.2.2 修过「手改 `tunnels.json` 把 `seq` 改小以后，新加的隧道会和已有的撞号」，但那以前已经撞了号的两条隧道没有分开。按编号改、删、启动时，MineDeck 只认得靠前的那一条，靠后的那条改不了、删不掉、启动的其实是前一条；两条都是自定义 frps 的，还会写同一份 frpc 配置。

- **现在读 `tunnels.json` 时会把它们分开。** 靠前的那条留着原来的编号，后面的换一个新编号；隧道名、凭据和别的设置都不动。
- **靠后的那条以后会真的跟着服务器启动。** 它以前勾着「跟随服务器启动」，却从来没有真的起来过（拉起的是靠前那条）。换了号以后，它绑定的服务器一开，它就会被拉起来，把服务器映射到公网。不想这样的，到「内网穿透」页把它的「跟随服务器启动」关掉。自定义 frps 的隧道换了号以后，在 frps 上的代理名（`minedeck-编号`）也跟着变。
- **改写之前先在同一个文件夹里留一份备份。** 程序文件夹（`MineDeck.exe` 所在的文件夹）里会多出一个 `tunnels.json.bak-年月日-时分秒`，留不下备份就不改写。这个备份不会自动清理，确认隧道都正常以后可以自己删掉。原来的 `tunnels.json` 里还有很老的版本存下的明文凭据时，备份里的凭据是加密过的，不是原文件一字不差的样子，明文不会留在程序文件夹里。
- 换了哪几条、备份叫什么，写在程序日志和操作记录里（操作记录里是一条 `tunnel.renumber`，做的人写的是「读取隧道配置」）。界面上不另外弹提示。`tunnels.json` 是只读的、写不回去时，这次运行照新编号用，之后哪次保存写进去了再补记一条。

### 添加隧道和跟随启动

- **「跟随服务器启动」默认不勾了。** 手动添加隧道、导入平台上的隧道、在平台上新建隧道，三处都是。勾上以后每次开服都会自动把服务器映射到公网，这件事由你自己决定。已经有的隧道不变。
- **手动「添加隧道」连点两下不会加出两条。** 请求途中按钮是灰的。
- **开服时隧道配置读不出来，有记录可查。** 服务器启动时 `tunnels.json` 还是读不出来（被别的程序占着、内容坏了），跟着它启动的隧道一条也拉不起来。以前只在程序日志里记一行；现在操作记录里也有一条失败的「跟随服务器」记录，服务器控制台里会说「隧道配置读不出来，有隧道跟随这台服务器启动的话，这次没有拉起」，后面接原因，以及处理好以后到「内网穿透」页手动启动隧道。
- **OpenFrp、樱花的隧道 ID 只收数字。** 手动添加隧道时填的不是数字，会提示「隧道 ID 只能是数字（在服务商官网的隧道列表里看）」，和导入平台隧道时的规矩一样；经接口修改隧道 ID 时也这样查。自定义 frps 不管。以前存下的不是数字的 ID，只要不去改它，照常改名、改跟随、照常启动。

### 在平台上新建隧道

- **出错的原因写在对话框里。** 以前只弹一下提示就没了。对话框里的报错旁边有复制键，复制出来的是原文；后面的平台概览会重新拉一次。
- **平台上多半已经建好时，不再让你再点一次。** 平台的创建请求已经回了成功、之后才出错的（本机写不进磁盘、认不出新建的是哪一条、途中账户被断开、平台回的内容看不懂这类），平台上多半已经有这条隧道了。以前「创建并导入」恢复可点，再点一次平台上就多一条。现在这个按钮收起来，换成「关闭，去导入」，点了关掉对话框，概览里同名的隧道只有一条时会滚到它的「导入到 MineDeck」上。报错说的是「平台上的隧道已建好，但没能导入 MineDeck。在平台隧道列表里导入它，不要再创建」，拿不准有没有建好时说「平台回了成功，但没能确认隧道建好。请到平台隧道列表里看一下，有就导入它，不要再创建」。平台明说没建成的（比如 OpenFrp 回了失败），照旧可以改了再试。
- **樱花账户没有 frpc 用的访问密钥时，不会先白建一条。** 以前要等在樱花上建完才报；现在建之前就报「SakuraFrp 账户没有可用于 frpc 的访问密钥，没有创建隧道」。
- 请求途中和平台上已经建好以后，樱花的「这是公开服务器」开关也锁住，切它不会把按钮重新放开、发出第二次创建。

### OpenFrp 的 frpc

- **下载时 TLS 1.3 握不上手，有了一次退路。** 这是 v3.2.0 起「已知情况」里记着的那一条。OpenFrp 的下载站前面有机器人防护，3.1.2 起这一处下载只用 TLS 1.3 握手来过这一关；网络出口只支持到 TLS 1.2 的（少数公司网络、代理，或者杀毒软件的「HTTPS 扫描」），以前就直接下载失败。现在握不上手时，换一种兼容的连接方式把整次下载再来一遍，只再来这一次，隧道日志里会写「TLS 1.3 连不上，改用兼容的连接方式重试」。退回的这一次证书照样验，跳转照样只跟 https，下回来的文件照样检查。超时、取消、证书对不上，或者第一次下载写盘时已经被杀毒软件拦下的，不退回。
- **但退回的那一次多半还是会被挡下。** 它直连的还是 OpenFrp 的下载站，那里的机器人防护多半会回 HTTP 567，这一处当初只用 TLS 1.3 就是为了过这一关。所以这条退路能不能下成要看情况。两次都没下成时，报错先写手动放 frpc 的办法，再写「两种连接方式都试过了」和两次各自为什么没成：照报错里的办法，自己下载 `frpc_windows_amd64.zip`，把里面的 exe 放进 MineDeck 旁边的 `runtimes\frpc\openfrp` 文件夹。
- **坏掉的 frpc 不会再反复重下。** 缓存里的压缩包解压得开、里面的 frpc 却是坏的时，以前每次启动隧道都是删掉 frpc、再从同一个压缩包解出同样坏的一份，一直这样转。现在解压出来的 frpc 先查一遍，坏了连缓存的压缩包一起删掉，重新下载一次；还是坏的就停下，报「下载到的 frpc 是坏的」，后面写手动放 frpc 的办法。缓存的压缩包被别的程序占着删不掉时，照实说删不掉，请关掉占用它的程序或手动删掉，不再说「重新下载了一次」。
- **删坏 frpc 之前再确认一次。** 查出 frpc 坏了、到真的删掉它之间，你正好放进来一份好的，不会被删掉。查的时候文件一直在变（多半有程序正在写它），不删，照常用它启动，隧道日志里说一句「检查 frpc（…）的时候文件一直在变，可能有程序正在写它」。
- **判成坏的、又因为不是标准名字没删的 frpc，重新解压以后不会又被挑中。** 以前解压出来的那份被杀毒软件删了时，会挑中这个坏的，启动时报一句看不懂的错；现在照实报 frpc 不见了，多半是被杀毒软件删掉了。

## 给 AI 助手、MCP 和自己调接口的人

- **在平台上创建隧道**（`POST /api/tunnel-accounts/{provider}/tunnels`）：失败的响应里可能多一个 `created: true`，意思是平台上已经建好或多半已经建好（平台的创建请求回了成功、之后才出错），这时别再发一次创建，去平台隧道列表里导入。这个字段是全站共用的报错写法里加的，目前只有这个接口会带。樱花账户没有 frpc 访问密钥时，在建之前就报错。
- **隧道新增和修改**（`tunnel.add`，`POST /api/tunnels`；`tunnel.update`，`PUT /api/tunnels/{id}`）：OpenFrp、樱花的 `proxyId` 只收数字，按十进制存，不是数字回 400。修改时只在改了 `proxyId` 或换了服务商时查，没改的旧数据照常保存。
- **操作记录**：新加一种 `tunnel.renumber`，`src` 为 `schedule`，`actor` 为「读取隧道配置」，`args` 里 `renamed` 是换了号的几条（`[{tunnel, from, to}]`），`backup` 是备份的文件名，`backupSealed` 为 true 表示备份里原来的明文凭据已经加密，`backupSealFailed`（有才写）是其中加密失败、备份里还是明文的条数；写不回去的记为失败，之后保存写进去时再补一条成功的。跟随启动时隧道配置读不出来，记一条失败的 `tunnel.start`，`args` 里只有实例名 `inst`。
- **导入整合包**（`POST /api/import/modpack`）：返回的 `pack` 里多一个 `mcFromLog`，为 true 表示版本号是从压缩包里的 `logs/latest.log` 认出来的。
- **任务**（`task.get`，`GET /api/tasks/{id}`）：建服、导入失败以后半成品没清干净时，快照里多一个 `cleanupFailed: true`，只在单个任务的快照里有，列表摘要不带。任务结果的告警（`warnings[]`）新加四种：`import-skipped`（没装进来的文件）、`import-case`（只差大小写的文件），这两种整合包和现成服务端都有；`script-jvm`（启动脚本里的 JVM 参数带了哪些、没带哪些）、`mc-from-log`（版本号从日志认的），这两种只有现成服务端有。
- **更正 v3.2.6 发布说明的一句**：换 Java（`instance.java.set`，`PUT /api/instances/{name}/java`）时，只有带着 `path`、指着已经卸了或没装完整的那套便携 Java，才回 400；不带 `path` 的照平常自动选，本机另有这个大版本就用，没有就重新下载。
- 接口说明里跟随启停那条操作记录的 `actor` 改成和程序一致的「跟随服务器」，以前的记录里是「跟随实例」。

接口的详细说明见 [`docs/设计与参考/API.md`](https://github.com/Trasperioooooon/MineDeck/blob/v3.2.7/docs/设计与参考/API.md)。

## 这一版实际试过的

- **自动测试**：这一版的改动大多带着新加的自动测试（Go 用例和界面交互用例）。【待填：发版前全量的结果——跑的是哪个提交，代码格式、编译和 go vet，Go 有测试的包数，界面交互用例条数，界面原型自检场景数】
- **反着试**：会删文件、会改写已有数据的，和牵涉先后顺序、关系到防护的这几处，逐条反着试过，把程序改回去，对应的测试都会失败：导入失败时只整个删这次建的文件夹、同名文件夹已在就不动它、交接包清理出错不再丢掉；启动脚本变量展开的上限；log4j 版本记录同名、超长时按看不出处理；删坏 frpc 之前的确认、坏了只重下一次、判坏的不再挑中、frpc 文件夹是目录联接时不删；平台上已建好时锁住按钮；撞号的换号、改写前留备份、没撞号的文件一个字节不改、明文凭据不进备份；frpc 下载退路的几条规矩（退回以后跳到 http 照样拒绝、会 TLS 1.3 的下载站回 404 不退回、被杀毒软件拦下和被取消的不退回、退回的那次真的能用 TLS 1.2）。
- **log4j 的判断**：改到一半的时候（「带签名的大清单只读开头」那一处还没改），拿我们手头 48 个真的服务端 jar，新旧两版逐个判断自带的 log4j 修没修过，结果一样。只读开头那一处是用造出来的 1 MB 签名清单测的。
- **frpc 的检查**：判断 frpc 是不是完整程序的那段检查这一版没改，上一版已经拿真的 OpenFrp frpc（`OF_0.68.0`）和 frp 0.61.1 的官方压缩包过过一遍，都判成能用。

## 还没实测过的

- **真窗口**：这一版新加的界面和提示（平台建隧道对话框里的报错和「关闭，去导入」、锁住的「这是公开服务器」，导入交接包的「返回修改」和自动再上传，任务页的「打开服务器文件夹」和清理没成时那句话，导入页上从日志认版本的提示，导入结果里新加的几条）都是在测试用的浏览器里点的，没在 MineDeck 的窗口里逐个点过。
- **在平台上新建隧道**：没用真的 OpenFrp、樱花账号试过，用的都是照着平台接口写的仿真。「平台回了成功、之后出错」那几种情形，真的平台上到底建没建好，也没法验证。
- **frpc 下载的退路**：没在真的只支持 TLS 1.2 的网络、代理，或者开着杀毒软件「HTTPS 扫描」的电脑上试过，也没有真的去 OpenFrp 的下载站下过；退回的那一次会不会被回 567，没有证据。杀毒软件的 HTTPS 扫描会替我们和下载站重新握手，那种情况下退回以后怎样，说不准。
- **坏掉的 frpc 重下和删前确认**：「查完到删之间文件被换掉」「文件一直在变」只在测试里造过，没有真的让人在那一刻放文件；frpc 是坏的、要重下的那一路，也没拿真的下载站走过。
- **导入的改动**：没用真用户的整合包和服务端压缩包试过，只用测试数据：几十种包的形状（套几层、Mac 打的、改了名的 jar 等）是在测试里造的，启动脚本也是照常见写法造的。只差大小写的那条，在区分大小写的文件夹里各列各的那一半，要在区分大小写的盘上才跑，没真跑过。删不干净的情形是在测试里自己占着文件造的。
- **log4shell 防护**：带签名大清单的真服务端 jar（比如原版 1.21.11、Forge 1.7.10 的 universal 包）没有拿最终的代码再判断一遍。
- **撞了号的隧道**：没拿真用户的 `tunnels.json` 试过，都是测试里造的文件；`tunnels.json` 本身是一个符号链接的情况没有专门处理。备份时「只认普通文件」那一查，在我们的电脑上造不出能单独抓住它的情形（建不了指向文件的符号链接）。
- 新加的用例大多只在 Windows 上跑过。
- v3.2.6 发布说明里写的那些照旧没实测，见 [v3.2.6 的发布说明](https://github.com/Trasperioooooon/MineDeck/blob/v3.2.6/docs/releases/v3.2.6.md)。

## 已知情况

- **用「自定义 frps」时，下载 frp 客户端那一步可能被杀毒软件拦下。** 这一条 v3.2.6 就记着，这一版没改。frp 这类内网穿透程序常被杀毒软件当成风险软件。发 v3.2.6 前在我们自己的电脑上，Windows 安全中心把 frp 0.61.1 的官方压缩包报成木马隔离了；这是 frp 常碰到的误报，MineDeck 下载下来的包也会和官方的校验值核对。被拦以后隧道启动不了，卡片上有时能认出来、直接说是被杀毒软件拦下了，有时只是一句下载失败或找不到文件的报错。被拦的可能是还在下载的压缩包（在 MineDeck 的缓存文件夹里，名字里不带 frpc），也可能是解压出来的 `frpc.exe`。碰上了，到 Windows 安全中心的「保护历史记录」里找到被拦的那一项，点允许，再启动隧道，MineDeck 会重新下载；别的杀毒软件，到它的隔离区里恢复、允许这一项，再启动隧道。也可以自己从 frp 的 GitHub 发布页下载 `frp_0.61.1_windows_amd64.zip`，把里面的 `frpc.exe` 放进 MineDeck 旁边的 `runtimes\frpc\custom` 文件夹；放进去又不见了的，同样到「保护历史记录」或隔离区里允许、还原它。
- **OpenFrp 的 frpc 下载，退路不一定救得回来。** 上面说了，退回的那一次多半仍会被下载站的机器人防护挡下（HTTP 567），下不成照旧手动放 frpc。握手一直不回话、等到超时的那种网络，不算握不上手，不退回。解压出来的 frpc 是坏的、要重下一次时，那一次又从 TLS 1.3 开始，隧道日志里换连接方式那句可能出现两次；某个下载源握不上手、另一个源因为别的原因失败时也会退回，这时那句「TLS 1.3 连不上」只说对了一半。
- **在平台上新建隧道时，请求发出去以后一直没回音的**（超时、断网），仍按没建成处理，「创建并导入」会恢复可点。平台那边其实可能已经建好了，再点之前先到平台的隧道列表里看一眼。
- **「关闭，去导入」只在概览里同名的隧道只有一条时才滚过去。** 同名的有好几条时只关掉对话框，到平台隧道列表里自己找。
- **建服务器文件夹撞上已经有的同名文件夹而失败时**，任务页的提示没跟上：导入交接包、导入现成服务端仍说「半成品的文件夹已经清理干净，可以重试」，新建服务器和导入整合包说的是「已下载的文件有缓存，再试一次很快」，可重试照样会失败。看失败原因里的那句，换个名字，或者先把那个同名文件夹挪走。
- **删到一半、只剩一个 `instance.json.tmp` 的半成品文件夹**，「没建完的文件夹」里列不出、也删不了，要自己到文件夹里删。
- **现成服务端压缩包的两处误认**：文件直接放在最外层的包里有名字带 quilt 的 jar（不一定是核心）时，会报「暂不支持 Quilt」；启动类名字里带 banner 字样的工具 jar，可能被认成 Banner 核心。碰上了可以先解压，用「新建服务器 → 接管已有服务器」自己选核心。
- **带过来的 JVM 参数是给原来那个 Java 写的。** 换了 Java 大版本以后有的可能不认（比如老的 `-XX:+UseConcMarkSweepGC` 在 Java 14 以后开不了服），导入结果里那一条写了：开不了服就到「设置 → 启动与内存」里删掉它。
- **原版服务器上，整合包里没装上的文件在处理时点了「跳过」以后**，详情页上没有入口再找回来。这一版只做了一半：导入完成时任务页上能打开服务器文件夹，看里面的「导入待决清单.txt」；离开任务页以后，到服务器文件夹里找这份清单。
- **这一版仍然只有 Windows 的程序。**
- 往前几版已知情况里的几条，这一版变了：v3.2.0 的「OpenFrp 的 frpc 握不上手就下不了」有了上面说的退路；v3.2.0 的「包装文件夹只认一层」「服务端的版本只写在日志里的认不出来」都改了；v3.2.0 的「原版服务器上导入时跳过的文件找不回来」改了一半；v3.2.2 的「以前已经撞了号的不会自动分开」现在会分开。其余照旧，见 [v3.2.6 的发布说明](https://github.com/Trasperioooooon/MineDeck/blob/v3.2.6/docs/releases/v3.2.6.md)。
