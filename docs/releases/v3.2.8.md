这是 MineDeck v3.2.8，接着 v3.2.7 往下修问题的小版本。这一版收拾的是几处用起来别扭的地方：启动时查到新版本，设置入口上会亮一个小圆点，不再只写进日志；更新渠道能选回「跟随当前版本」，稳定渠道不会被误标成 Latest 的测试版带偏；报错能认出是磁盘满、文件被占、没有权限、压缩包坏了、连不上这几类时，会接一句该怎么办；点了保存、还没存完时接着输入的内容不再被冲掉；服务器的设置文件读不出来时，列表里会有一张卡片说明，不再一声不响地少一台。另外，AI 的每日额度改成只算输入和输出。

## 怎么升级

用着 v3.2.7、v3.2.6、v3.2.5、v3.2.4、v3.2.3、v3.2.2、v3.2.1 或 v3.2.0 的，打开「设置 → 更新与关于」，点「检查更新」，查到新版本以后点更新就能升到 3.2.8。服务器、Java、设置、隧道和 AI Key 都会接着用。更新前先停掉正在运行的服务器。

用着 v3.1.1、v3.1.2 或者 3.2.0 测试版的，也能在程序里直接升到 3.2.8：3.2.0 的 beta.3 到 beta.5 不管更新渠道选的是哪个都查得到，beta.1、beta.2 和 3.1.x 只看正式版，3.2.8 就是正式版，也查得到。

从 v3.1.0 及更早的版本升级时，换程序的是旧版本自己带的更新脚本，它有两种情况换不成，新版本这时已经下载好、放在旁边。处理办法见 [v3.2.0 的发布说明](https://github.com/Trasperioooooon/MineDeck/blob/v3.2.0/docs/releases/v3.2.0.md)「已知情况 → 升级和更新」的第一条。

从 v2.6.1 及更早的版本升级（那时的程序叫 `AutoMCHUB.exe`），自动更新找不到改名后的文件，请手动下载 `MineDeck.exe` 放进原来的文件夹。旧的开机自启项会被删掉，需要的话在「设置 → 启动与托盘」里重新打开。

从 v3.2.4 及更早的版本直接升上来的，v3.2.5 的几处变化也一起生效：同一个文件夹里的 MineDeck 只能开一份；两台服务器重名、其中一台是接管进来的，列表里显示的可能换成另一台（两台的文件都在）；许可证从 v3.2.5 起改成 GNU AGPL-3.0。细节见 [v3.2.5 的发布说明](https://github.com/Trasperioooooon/MineDeck/blob/v3.2.5/docs/releases/v3.2.5.md)。

从 v3.2.6 及更早的版本直接升上来的，v3.2.7 的两处隧道变化也一起生效：以前手改 `tunnels.json` 撞了号的隧道会被分开，靠后的那条以后会真的跟着服务器启动；新加隧道时「跟随服务器启动」默认不再勾上。细节见 [v3.2.7 的发布说明](https://github.com/Trasperioooooon/MineDeck/blob/v3.2.7/docs/releases/v3.2.7.md)「怎么升级」。

升级以后有两件事可能和以前不一样，先说在前面：

- **AI 的每日额度会显得「松」了。** 以前额度把输入、输出和提示缓存（缓存命中、缓存写入）都算进去，现在只算输入和输出。用到提示缓存的人，同样的对话扣的额度比以前少；「设置 → AI（可选）」里「今天已用」「本月」的 token 数，升级以后也按新算法重算，会变小。费用估算不变。见下面「AI 每日额度」。
- **服务器列表里可能多出一张「无法读取」的卡片。** 服务器文件夹里的 `instance.json` 读不出来、内容坏了或者缺了名字的，以前这台服务器直接不在列表里；现在列表上给它一张只读的卡片，告诉你是哪个文件夹、为什么读不出来。见下面「设置文件读不出来的服务器」。

## 改了什么

### 检查更新

- **启动时查到新版本，设置上亮一个小圆点。** 打开了「设置 → 更新与关于」里的「启动时静默检查更新」（默认关着）的，以前启动时查到新版本只写进程序日志，界面上什么也不说。现在侧栏的「设置」和设置页里的「更新与关于」旁边会亮一个小圆点，「更新与关于」页上多一行「启动时查到新版本 v…」，点「查看」，显示查到的是哪个版本、按哪个渠道查的，以及「立即更新并重启」。不弹窗，不打断手上的事。后台检查要联网，界面打开时它常常还没查完；查完以后（最多半分钟）圆点会自己亮起来，不用先进设置。点「检查更新」、换了更新渠道或者改了更新仓库以后，这条提示就清掉。
- **程序日志里写明按哪个渠道查的、查的结果。** 比如「稳定版渠道：已是最新 v3.2.8」「稳定版渠道：有新版本 …（当前 …），可在设置中更新」，没查成也写一句原因。
- **更新渠道可以选回「跟随当前版本」。** 以前「更新渠道」只有「稳定版」「最新版」两项：没选过时按正在用的版本定，可一旦点过其中一项，就回不到「按正在用的版本定」了。现在第一项是「跟随当前版本（默认）」：用着正式版时只收正式版，用着测试版时连测试版一起收，以后装回正式版也跟着回到只收正式版。
- **稳定渠道不会被误标成 Latest 的测试版带偏。** GitHub 上可以把一个测试版手动标成「Latest」。稳定渠道以前直接看这个标记，碰上这种情况会提示更新到这个测试版。现在发现标着 Latest 的是测试版，就改从发布列表里挑最新的正式版；一个正式版也找不到时，写「还没有正式发布的版本，暂不更新」。这一条从 3.2.8 起查更新时才管用，旧版本查到什么照旧。
- **版本号比较照语义化版本的规范来。** 预发布那一段（beta、rc 这些）以前不分大小写，现在照规范区分。MineDeck 自己的版本号都是小写，平常碰不到。

### 报错时告诉你下一步怎么办

- **认得出原因的报错，接一句该怎么办。** 磁盘满了、文件正被别的程序占着、没有读写权限、压缩包坏了或者没下载完整、连不上远端服务器、网络超时、安全连接握手失败（证书、TLS），这几类按系统给的错误认出来，报错提示里换成一句对应的办法，比如「磁盘剩余空间不足，请清理磁盘空间或更换存放位置后再试」；MineDeck 自己查出磁盘不够时，还写明是哪个盘。以前原文是英文、带着路径的报错，提示里只有一句「无法……」；现在接上这句办法，原文照旧在「详情」和「复制报错信息」里，一个字不少。自己点了取消的，不加这句。
- **有些地方写了具体的下一步。** 比如 Forge、NeoForge 安装器出错时，提示可以在「设置 → 下载与网络」切换下载源重试，或者看安装日志；整合包、交接包、备份、地图压缩包打不开时，说可能坏了、没写完整；平台账户登录失效时，请重新连接这个平台账户；frpc 起不来时，提醒可能被安全软件拦了；价格数据取不到时，可以直接填写自填单价。
- **后台任务失败时，任务页上也有这句。** 新建、导入、安装这类在任务页上跑的，失败原因下面多一行修复提示。
- **几处说法改成界面上现在的叫法。** 处理整合包里没装上的文件时撞上上一批还没做完，报错改说「上一批没装上的文件还在处理」（以前说「待处理的文件」）；日志配置的提示里把「启动与内存」写全成「设置 → 启动与内存」；AI 助手改内存和启动参数时，确认卡片和操作记录里这项操作的名字改成「修改启动与内存」。

### 报错横幅「端口被占」

服务器起不来，是因为查询（query）端口或远程控制（RCON）端口被占着时，修复说明以前也叫人改 `server-port`、让好友换新端口连。这两个端口和玩家进服没关系，现在改说在 `server.properties` 里把 `query.port` 或 `rcon.port` 改成别的空闲端口，好友连的地址不用换。游戏端口被占时的说法不变。

### 保存途中接着输入的内容不再丢

点了保存、请求还没回来的那一两秒里接着在框里改的内容，以前保存完页面一重画，就被换回刚才保存的样子。下面五处现在会留住接着改的内容和光标位置，保存按钮恢复可点，有的提示里会说一句「输入框里还有未保存的新改动」：

- 「设置 → 手机远程管理」里的访问密码；
- 「设置 → AI（可选）」里添加自填单价；
- 「内网穿透」里编辑隧道的窗口；
- 「扩展 → AI 伙伴」里添加、编辑禁挖区域的窗口；
- 「扩展 → 游戏内 AI」里按名字授权。

编辑隧道和禁挖区域这两个窗口，碰上这种情况时先不关，前一次照样存下，留着让你把新改的再保存一次。

### 工具箱的整合包草稿

工具箱「导出 Modrinth 整合包」里「自己挑模组」时，名称、版本这几格会自动存成草稿。两个窗口同时开着它时，以前有几处边角会把新改的改回旧的：先发的那次保存比后发的晚到；离开页面时补发的那次，盖掉另一个窗口随后存的；刷新页面时排着的那次没存上。现在每次保存都带着编号，晚到的旧值不会再盖掉新值；离开或刷新页面时，只把还没发出去的改动补发出去。

### AI 每日额度

- **每日额度只算输入和输出。** 推理（思考）的 token 本来就算在输出里，照旧算；提示缓存的命中和写入不再算。「设置 → AI（可选）」里「每日额度」那一节的说明改成「只算输入和输出，缓存不计入额度」。游戏内 AI 的「全服每天的 token」也按同样的算法记。
- **用到提示缓存的，额度会显得「松」了。** 同样的对话，扣的额度比以前少，以前刚好够用的额度现在能多用一些。升级以后，「今天已用」和「本月」的 token 数也按新算法重算，看起来会变小。
- **费用估算不变。** 花多少钱照旧按输入、输出、缓存命中、缓存写入各自的单价算。
- **存着的用量记录不改写。** 用量文件原样留着，读的时候按新算法算；只有总数、分不出输入输出和缓存的那部分，照旧整个算进额度。

### 设置文件读不出来的服务器

- **列表上给它一张卡片。** 服务器文件夹里有 `instance.json`，MineDeck 启动时却读不出来（比如没有权限）、内容坏了（括号、引号、逗号没写对），或者里面缺了服务器名称（`name`）的，以前这台服务器不在列表里，只在程序日志里记一行，看上去就是「服务器不见了」。现在「服务器」页的列表里多一张卡片：标题是文件夹名，下面写「设置文件无法读取」，标着「无法读取」，再写一句原因，比如「设置文件 JSON 格式有误（可能是括号、引号或逗号没写对）」。列表上方的合计里也会写「配置无法读取 N 个」。
- **卡片是只读的。** 点它不会进详情，也不能启动。在这台电脑上打开 MineDeck 时，卡片上有「打开文件夹」，打开那台服务器的文件夹，去修 `instance.json`；用手机或局域网里别的设备打开时没有这个按钮，写的是「请到主机上打开这个文件夹，检查或修复 instance.json」。
- 修好或者删掉以后，卡片会消失；这台服务器要重开 MineDeck 才回到列表里，见「已知情况」。

## 给 AI 助手、MCP 和自己调接口的人

- **报错的 `hint`**：HTTP 接口失败时的 `{"ok": false, "error": …}`，以前只有少数几处（AI 服务商的报错、导入整合包的解析报错等）另带 `hint`。现在能从错误里认出原因的（磁盘满、文件被占、没有权限、压缩包坏、连不上远端、超时、证书和 TLS），以及后端写了具体下一步的，都带一句 `hint`；`error` 原文不变。取消的不带。
- **任务**（`task.get`，`GET /api/tasks/{id}`）：失败的任务，快照里可能多一个 `errHint`，是一句修复提示，有才写。
- **程序信息**（`app.info`，`GET /api/app`）：启动时的后台检查查到新版本时，多一个 `startupUpdate`：`{tag, notes?, sizeBytes?, prerelease?, channel}`。它只在内存里，重开程序就没了；`app.update.check` 查过一次、或者 `app.config.set` 改了 `updateChannel`、`updateRepo` 以后清掉。
- **全局设置**（`app.config.set`，`PUT /api/config`）：`updateChannel` 收空串，意思是「跟随当前版本」，回到没选过的状态，生效的渠道照旧看 `GET /api/app` 的 `updateChannel`。
- **检查更新**（`app.update.check`，`POST /api/update/check`）：稳定渠道拿到的 `releases/latest` 是草稿、预发布或者标签带预发布后缀时，改看发布列表第一页（最多 30 个）里最新的正式版；一个都没有时 `hasUpdate` 为 false，`latest` 里没有 `tag`。版本比较的预发布段区分大小写。
- **服务器列表**（`GET /api/instances`）：顶层多两项。`broken` 是 `[{id, folder, reason}]`，启动时 `instance.json` 读不出来、坏了或缺 `name` 的文件夹，只有文件夹名，不带完整路径，修好或删掉以后不再列；`local` 是这次请求是不是本机。这两项是 HTTP 接口加的，`instance.list` 操作本身（AI 助手、MCP 看到的）不带。
- **打开文件夹**（`instance.opendir`，`POST /api/instances/{name}/opendir`）：`{name}` 可以传 `broken[]` 里的 `id`（`__broken__:` 开头），这时不能带 `sub`，只打开那个文件夹本身；照旧只接受本机请求。
- **AI 用量**（`ai.settings.get`，`GET /api/ai/settings`）：`today`、`month` 里的 `tokens` 改成只算输入和输出，`input`、`output`、`cacheRead`、`cacheWrite` 照旧分开给。游戏内 AI 每台服务器当天的 `tokens` 也只累计输入和输出。`ai.quota.set` 的说明跟着改了。
- **工具箱草稿**（`toolbox.mrpack.draft.save`，`PUT /api/toolbox/mrpack/draft`）：可以带请求头 `X-Draft-Client`、`X-Draft-Seq`（或者请求体里的 `clientId`、`seq`），同一个发送端晚到的旧序号按字段丢掉；不带的照旧直接合并。
- **排错**（`GET /api/instances/{name}/diag`）：`port-in-use` 碰上查询或 RCON 端口被占时，`fixes` 的第二条改成改 `query.port` 或 `rcon.port`，好友不用换地址。
- `instance.settings.set` 的标题改成「修改启动与内存」，确认卡片和操作记录里显示的是这个名字。

接口的详细说明见 [`docs/设计与参考/API.md`](https://github.com/Trasperioooooon/MineDeck/blob/v3.2.8/docs/设计与参考/API.md)。

## 这一版实际试过的

- **自动测试**：这一版的改动大多带着新加的自动测试（Go 用例和界面交互用例）。发版前跑了一遍全量（跑的那个提交和发出去的代码只差这一句）：代码格式、编译和代码检查（go vet）都没有提醒；Go 的 45 个有测试的包全部通过，界面交互用例 325 条全部通过，界面原型自检 162 个场景走通。几处改动合到一起以后，在开发分支上先跑过一遍全量：Go 的 45 个有测试的包全部通过，界面交互用例 324 条全部通过，界面原型自检 162 个场景走通；GitHub 上的自动测试在那个提交上也通过了（Windows 上跑 Go 测试，macOS 上做代码检查和编译）。
- **反着试**：错了不容易发现的几处，逐条反着试过，把程序改回去，对应的测试都会失败：版本号的预发布段区分大小写；稳定渠道跳过标着 Latest 的测试版；整合包草稿按编号丢掉晚到的旧值；每日额度只算输入和输出；修复提示的两条规矩（自己取消的不加提示；只有往外连、没连上才说「连不上远端服务器」，本机端口被占、连本机地址出错都不算）。
- **启动时查到新版本的小圆点**：起草这份说明时发现，界面只在打开和进「设置」时看一眼，后台检查比界面打开晚查完（多数时候如此）圆点就不亮；发版前补上了界面打开后再问几次，加了一条界面用例，去掉这一处改动用例会失败。
- **保存途中接着输入的那几条界面用例**，不靠固定的等待时间，改成先把保存请求扣住、等用例改完输入框再放行，筛出来连跑三遍都过。
- **伙伴模组和语音桥接模组**：GitHub 上的自动测试新加了一项，用源码重新编一遍，和打进程序的 jar 对比；合进来之前和合进来以后各跑过一次，两个模组都对得上。这一版没有改这两个模组。

## 还没实测过的

- **真窗口**：这一版新加的界面（侧栏和「更新与关于」上的小圆点、「启动时查到新版本」和「查看」、更新渠道的「跟随当前版本」、设置文件读不出来的那张卡片和「打开文件夹」、任务页上的修复提示，保存途中留住输入的五处）都是在测试用的浏览器里点的，没在 MineDeck 的窗口里逐个看过。
- **启动时的检查**：没拿真的 GitHub 发布页走过一遍「启动时查到新版本 → 亮圆点 → 查看 → 更新」。测试版被误标成 Latest 的情形，只在测试里用假的发布页试过。
- **修复提示**：都是在测试里造出来的错误（磁盘满、文件被占、证书不对、连不上这些）验证的，没在真的满了的磁盘、真的被杀毒软件占着的文件、真的会拦 HTTPS 的网络上看过。
- **AI 额度**：在测试里拿造好的用量和老记录算过，没拿真的服务商、真的带缓存的对话核对额度扣得对不对。
- **设置文件读不出来的服务器**：卡片没在真程序里看过。测试里造过的是内容坏了、缺名字、字段类型不对，以及接管进来的服务器读不出来的；没有权限读的那种没造过。
- **保存途中接着输入、两个窗口同时改**：五处表单是在测试浏览器里把保存请求扣住、趁这时改输入框造的；整合包草稿的乱序和补发，是在测试浏览器里开两个页面造的。没拿 MineDeck 窗口和手机真的同时改过。离开页面时补发草稿，也只在测试用的浏览器里试过；程序被直接关掉时，正在存的不一定存得上，和以前一样。
- **报错横幅「端口被占」**：用照着服务端日志写的测试文本试的，没让真的服务端撞上查询、RCON 端口被占。
- 新加的用例大多只在 Windows 上跑过。
- v3.2.7 发布说明里写的那些照旧没实测，见 [v3.2.7 的发布说明](https://github.com/Trasperioooooon/MineDeck/blob/v3.2.7/docs/releases/v3.2.7.md)。

## 已知情况

- **设置文件读不出来的服务器，修好以后要重开 MineDeck 才回到列表。** MineDeck 只在启动时找这样的文件夹：修好 `instance.json` 以后，卡片会消失，但这台服务器要等下次启动才列出来。反过来，MineDeck 开着的时候才弄坏的，也要到下次启动才出卡片。
- **点「查看」只在当前这一页收起小圆点。** 刷新界面，或者在手机上打开，圆点还会出来；点一次「检查更新」才算清掉。
- **程序日志里，「最新版」渠道写成了「测试版渠道」。** 日志里的「测试版渠道」就是界面上的「最新版（包括测试版）」。
- **稳定渠道改挑正式版时，只看发布列表的第一页（最近 30 个）。** 再早的正式版不看。
- **修复提示是按系统给的错误类型推的。** 只认得上面说的那几类，认不出的照旧只写「无法……」；推出来的那句和实际情况对不上时，以「详情」里的原文为准，也欢迎告诉我们。
- **有几处设置是整段保存的，两个窗口同时改时，以后存的为准**：AI 伙伴的「攻击时不许打的生物」、游戏内 AI 的「别名」、音乐共享的「我在游戏里的名字」，还有第一次打开时的引导。
- **用量记录里只有总数、分不出明细的那部分**，照旧整个算进每日额度，不会因为升级变少。
- **这一版仍然只有 Windows 的程序。**
- 往前几版已知情况里的几条，这一版变了：v3.2.0 的「启动时的后台检查只写进日志」现在有小圆点和「更新与关于」里的提示，日志里也写了渠道；v3.2.1 的「点了保存、还没存完的那一两秒里接着输入的内容，可能被清掉」修了，「工具箱的整合包草稿，保存还没完成时马上刷新或关掉页面」那一条也修了（程序被直接关掉的情形除外）；3.2.0 测试版里记着的「预发布那一段不分大小写」现在区分了。其余照旧，见 [v3.2.7 的发布说明](https://github.com/Trasperioooooon/MineDeck/blob/v3.2.7/docs/releases/v3.2.7.md)。
