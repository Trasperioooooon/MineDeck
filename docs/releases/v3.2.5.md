这是 MineDeck v3.2.5，一个以修问题为主的小版本。这一版集中处理了一批积攒下来的毛病：同一个文件夹里不会再同时开出两份 MineDeck；新建、导入时能查出被别的程序占着、或者被 Windows 留作他用的端口；1.21.9 起改成游戏规则的四个开关，显示的状态和发出去的命令都对了；上次启动失败的原因，重开程序以后还看得到；备份、保存文件和启动时清理临时文件更稳；同名的服务器、自带日志配置的老服务器，处理得更清楚。

**许可证从这一版起改成 GNU AGPL-3.0。** 只限第 3 版（`AGPL-3.0-only`）。只是下载来开服的人不受影响，照旧免费用。要留意的是改代码的人：把改过的版本发布出去，或者把改过的版本放到网络上给别人用，都要按同样的协议公开源码。v3.2.4 及以前的版本照旧按 MIT，那份许可原文留在仓库的 [`docs/许可/`](https://github.com/Trasperioooooon/MineDeck/tree/v3.2.5/docs/许可) 里。伙伴模组和语音桥接模组暂时仍按 MIT。

## 怎么升级

用着 v3.2.4、v3.2.3、v3.2.2、v3.2.1 或 v3.2.0 的，打开「设置 → 更新与关于」，点「检查更新」，查到新版本以后点更新就能升到 3.2.5。服务器、Java、设置、隧道和 AI Key 都会接着用。更新前先停掉正在运行的服务器。

用着 v3.1.1、v3.1.2 或者 3.2.0 测试版的，也能在程序里直接升到 3.2.5：3.2.0 的 beta.3 到 beta.5 不管更新渠道选的是哪个都查得到，beta.1、beta.2 和 3.1.x 只看正式版，3.2.5 就是正式版，也查得到。

从 v3.1.0 及更早的版本升级时，换程序的是旧版本自己带的更新脚本，它有两种情况换不成，新版本这时已经下载好、放在旁边。处理办法见 [v3.2.0 的发布说明](https://github.com/Trasperioooooon/MineDeck/blob/v3.2.0/docs/releases/v3.2.0.md)「已知情况 → 升级和更新」的第一条。

从 v2.6.1 及更早的版本升级（那时的程序叫 `AutoMCHUB.exe`），自动更新找不到改名后的文件，请手动下载 `MineDeck.exe` 放进原来的文件夹。旧的开机自启项会被删掉，需要的话在「设置 → 启动与托盘」里重新打开。

升级以后有两件事可能和以前不一样，先说在前面：

- 同一个文件夹里的 MineDeck 只能开一份了，见下面第一小节。
- 以前就有两台服务器重名、其中一台是接管进来的，升级以后列表里显示的可能换成另一台，见下面「同名的服务器」。两台的文件都在，没有删。

## 改了什么

### 同一个文件夹里只能开一份 MineDeck

以前同一个文件夹里的 `MineDeck.exe` 可以双击开出两份，两份各读各写同一批设置和数据，会互相盖掉。

- **现在第二份不会开起来。** 它先等最多 3 秒（刚退出马上又打开时，上一份可能还在收尾），上一份还在，就弹出一句「这个文件夹里的 MineDeck 已经开着了。如果刚关掉它，等几秒再打开。」然后退出，不碰任何数据。
- **窗口收在托盘里时再双击一次，看到的就是这句话。** 要回到窗口，在托盘图标的菜单里点「打开 MineDeck」。
- **不同的文件夹里各放一份，照样能同时开。**
- **带 `-nogui` 或 `-minimized` 启动时不弹框**（开机自启用的就是 `-minimized`），只把这句话写到标准错误，以退出码 1 退出。用脚本、计划任务启动 MineDeck 的，可以按退出码判断。
- 给 MCP 工具用的 `MineDeck.exe -mcp` 不受影响，它本来就要和开着的 MineDeck 一起用。

### 开服和端口

- **新建、导入时，被占着的端口会被拦下。** 「新建服务器」（包括用已有地图开服）和「导入整合包」（包括现成服务端压缩包）点下去的时候，MineDeck 再查一次端口：这时正被别的程序占着的，或者落在 Windows 系统保留的端口范围里的（开了 Hyper-V、WSL 这类功能的电脑上会有），不建服务器，在端口那一栏说明原因，旁边给一个「改成 N」的按钮。以前只在填表单的时候查，不认系统保留的范围，点下去时也不再查一次；端口在保留范围里，或者填完以后才被占上，都要到开服才报错。
- **被你自己的另一台服务器用着的端口，只提示、不拦。** 两台不同时开的服务器可以共用一个端口，不管那一台现在开着还是停着，都照样能建。
- **默认端口会避开系统保留的范围。** 比如 25565 正好在保留范围里，表单会换一个，并写明「25565 在系统保留的端口范围里，已改为 …」。自动换出来的端口，你改过再填回去，也照常查。
- **开服前照旧真的试一下端口能不能用。** 试不上、又查得出是系统保留时，报错会直接写明「端口 N 在系统保留的端口范围里（Hyper-V、WSL 等保留），换个端口试试」；以前这种情况说的是「被别的程序独占着，或者在 Windows 保留的端口范围里」，分不清是哪一种。
- **崩溃自动重启碰上端口还没放开，会接着等。** 以前等大约 5 秒，还占着就放弃。现在按崩溃重启本来的间隔（10 秒、30 秒、60 秒）再试，控制台里会写「仍在等待端口 N 放开」；这几次算在连续 3 次的上限里，3 次都不行才停。定时重启和手动「重启」照旧。
- **`server-ip` 填了解析很慢的域名，开服时界面不再跟着卡住。**

### 判断「启动完成」更准

以前控制台里只要出现类似 `Done (…)!` 的字样，MineDeck 就当服务器启动好了。有的模组加载到一半会打出差不多的话，MineDeck 就会提前当成启动完成，定时命令也可能发早。现在只认服务端自己打的那一整行（`Done (3.5s)! For help, type "help"` 这种），聊天里、命令回显里、模组日志里出现类似的话都不算。

### 上次没能启动的原因，重开以后还在

服务器没启动起来时，卡片和详情页头会留一条「上次没能启动」和原因。以前它只记在内存里，MineDeck 一关就没了。现在记在这台服务器自己的文件夹里（`.minedeck/start-fail.json`），重开 MineDeck 还看得到；下次启动成功就消失，也可以点新加的「关闭提示」自己关掉。

### 1.21.9 起的四个游戏规则开关

Minecraft 1.21.9 起，PVP、允许下界、命令方块、生成怪物这四项从 `server.properties` 搬进了游戏规则，在「设置 → 常用」里是服务器开着才能拨的开关。

- **开关的初始状态按世界存档里的游戏规则显示。** 以前显示的是 `server.properties` 里留下的旧值，和服务器里实际的规则可能对不上。世界还没生成、或者存档读不出来时，照旧按 `server.properties`。
- **服务器开着时拨开关，按游戏版本发对的规则名。** 1.21.11 起，允许下界、命令方块、生成怪物这三项的规则换了名字，以前发的还是旧名字，服务端不认，界面却提示「已应用」。1.21.9 和 1.21.10 上命令方块那一项发的名字也不对。现在都按版本发。
- 刚拨过的开关，切到别的标签再回来不会跳回旧状态。

### 备份、保存文件和临时文件

- **两份 MineDeck 同时往同一个备份文件夹里备份同一台服务器，不会互相盖掉。** 压好的备份改成正式名字时不再覆盖已有的文件。备份文件名里的时间仍是开始备份的时间；真撞了名，后完成的那份换一个时间另存。
- **备份压到一半留下的临时文件会被清掉。** 备份时的临时文件改了名字（`.minedeck-backup-<数字>.tmp`）。以前的版本压到一半被关掉、断电时留下的 `.backup-<数字>.tmp`，这一版启动时也会清：只看每台服务器的备份文件夹这一层，名字要完全是这个样子，而且一个小时以上没动过。
- **启动时清理没写完的临时文件，范围扩大到服务器文件夹里更深的子文件夹**（比如 `config/某个模组/` 下面），导入整合包、补装文件时被打断留下的也能清到。不进世界文件夹，不跟着链接和目录联接走，最多往下 6 层。
- **只清 MineDeck 自己起的那种名字。** 也就是固定的开头（比如 `.minedeck-download-`、`.minedeck-write-`）、中间一串纯数字、固定的结尾（`.part`、`.tmp` 等），并且一个小时以上没动过。你自己起的 `.minedeck-我的备份.zip`、`.minedeck-notes.txt` 这类名字不会动。
- **`run.bat` 改成先写到临时文件、写完再替换。** 写到一半断电不会留下半截脚本；几台服务器经链接共用一份 `run.bat` 时，改一台不会连带改到别的。
- **保存只读文件更稳。** 只读的文件被杀毒软件之类短暂占着时，会重试几次，不再当场失败。
- **取消下载时不再多等。** 下载完往目标位置放的那一步如果在等别的程序放开文件，点取消会马上停。
- 另外修了几处少见的边角：上一级文件夹的名字以点或空格结尾时保存文件的排队，开了「区分大小写」的文件夹里保存只读文件后的核对。

### 同名的服务器

两个不同的文件夹里，服务器起了同一个名字时（一般是接管进来的一台，和服务器存放位置里的一台），列表里只能显示一台。

- **现在接管进来的那台优先。** 以前是先读到哪台算哪台，实际上显示的是存放位置里的那台。
- **没列出来的那台不再悄悄不见。** 「服务器」页顶部会有一条提示，写明哪个文件夹里的服务器因为和哪一台重名没有列出来。两台的文件都原样留着。
- **想让两台都显示，有两种办法**，提示里也写着：打开没列出来的那个文件夹里的 `instance.json`，把 `"name"` 改成别的名字，重开 MineDeck；或者把列表里的这台移出列表，再用别的名字接管回来，然后重开 MineDeck。

### 老版本服务器的日志配置（log4shell 防护）

1.7 到 1.16.5 的服务器，大多要靠一份 Mojang 官方的日志配置文件防 log4shell 漏洞（服务端自带的 log4j 已经修过的不用），MineDeck 会把它下载到服务器文件夹里，并在启动参数里引用它。服务器文件夹里已经有一份同名、但内容不是官方那份的文件时（多半是你自己改过的），这一版统一成一条规矩：不覆盖它，也不替它加引用，并且说清楚后果。

- **接管已有服务器时不再换掉它。** 接管完成页、任务日志和控制台里会写明：这台服务器没有套上 Mojang 的日志配置，等于没防。也写了两种办法：要用官方的，把这个文件改名或挪走，再重开 MineDeck；要用自己的，在「设置 → 启动与内存」里加上 `-Dlog4j.configurationFile=文件名`。
- **在「启动与内存」里保存参数时，不再给它强加引用。** 以前只看文件在不在，在就加上引用。现在内容不是官方那份的不加，保存后的提示里会说明。
- **程序启动后给老服务器补下载官方配置的那一小段时间里，你放进去的同名文件不会被换掉。**
- **「启动与内存」里新加了「实际启动参数预览」。** 一边改一边能看到保存以后真正用来开服的完整参数，包括 MineDeck 自动补上的 log4shell 防护参数。AI 助手提出改启动参数时，确认卡片上列的也是补上以后的实际参数。

### 别的

- **游戏内 AI 页上的白名单提醒更准。** Minecraft 26.3 起，`server.properties` 里没写 `white-list` 这一项时，服务端默认是开着白名单的。以前 MineDeck 把没写当成「关」，会在「扩展 → 游戏内 AI」里误提醒「没有开启白名单」。现在按版本算。
- **关于页和用户协议里的许可证说明**跟着改成了 GNU AGPL-3.0。

## 给 AI 助手、MCP 和自己调接口的人

- **服务器列表**（`GET /api/instances`）：响应最外层除了 `data`，多了 `duplicates`：`[{name, dir, keptDir}]`，是因为重名没列出来的文件夹（`dir`）和留在列表里的那一台的文件夹（`keptDir`）。只有这个 HTTP 接口带，操作 `instance.list` 的结果没变。
- **上次没能启动**：列表每一项里的 `lastStartError`、`startPortBusy` 现在重开程序以后还在。新加 `DELETE /api/instances/{name}/start-error`（操作 `instance.starterr.clear`，仅人工，不记进操作记录），把这条提示连同存下来的记录一起清掉。
- **新建和导入整合包提交时查端口**（`POST /api/instances`、`POST /api/import/modpack`）：端口正被别的程序监听着，或者落在系统保留的范围里时，回 409，响应里除了 `error` 还有 `portBusy`：`{port, process?, reserved?, suggest?}`（占着它的程序名、是不是系统保留、建议改成哪个）。被 MineDeck 自己的服务器用着的端口不拦。代理端不查；AI 助手和 MCP 提出的新建不做这一步，开服前照旧会查。
- **端口默认值**（`GET /api/ports/suggest`）：给出的 `port` 现在也避开系统保留的端口范围；`from` 落在保留范围里时，`fromBusy` 为 true，并多一个 `fromReserved: true`。
- **读设置**（`GET /api/instances/{name}/properties`）：1.21.9 起的服务器、世界存档读得出来时，多一个 `gamerules`，里面是 `pvp`、`allow-nether`、`enable-command-block`、`spawn-monsters` 现在的值（`"true"` 或 `"false"`）。只有这个 HTTP 接口带，操作 `instance.props.get` 的结果没变。
- **改运行参数**（`PUT /api/instances/{name}/settings`，操作 `instance.settings.set`）：成功时不再只回一句 `ok`，改回 `{xmxMb, xmsMb, extraJvm, launchArgs, note?}`：保存下来的内存和参数、完整的启动参数，以及因为同名日志配置不是官方那份而没加引用时的说明。AI 发起时，确认卡片上「JVM 参数」一行是补上 log4shell 参数以后的值，有这种说明时写在卡片的提醒里。
- **新加预览运行参数**（`POST /api/instances/{name}/settings/preview`）：请求体和返回同上，只算不存，不记进操作记录。
- **接管任务的告警**：任务快照的 `warnings[]` 里新加一种 `custom-log4j`，就是上面说的「同名日志配置不是官方那份，没有替换」。
- **游戏内 AI**（`GET /api/instances/{name}/gameai`）：`whitelistOn` 在 `server.properties` 没写 `white-list` 时按游戏版本取服务端的默认值（26.3 起为 true）。
- **启动 MineDeck 的脚本**：同一个文件夹里已经开着一份时，新起的那份以退出码 1 退出，带 `-nogui` 或 `-minimized` 时只写标准错误。`-mcp` 不受影响。

接口的详细说明见 [`docs/设计与参考/API.md`](https://github.com/Trasperioooooon/MineDeck/blob/v3.2.5/docs/设计与参考/API.md)。

## 这一版实际试过的

- **自动测试**：这一版的改动大多是先写出一条会失败的测试、再改程序。发版前在最终代码上跑了一遍全量：Go 的 44 个有测试的包全部通过，界面交互用例 275 条全部通过，界面原型自检 162 个场景走通，代码格式和代码检查（go vet）都没有提醒。Mac 版照旧只做了编译和代码检查。
- **反着试**：会删文件的（清临时文件的每一条规则）、牵涉锁和先后顺序的（单实例检查、备份不互相覆盖、保存文件的排队和重试、开服时查端口、预览参数）、关系到防护的（下载期间不覆盖你的日志配置）这几处，逐条反着试过：把程序改回去，对应的测试都会失败。

## 还没实测过的

- **真窗口**：这一版新加的提示和按钮（重名提示、「关闭提示」、端口旁边的「改成 N」、启动参数预览）都是在测试用的浏览器里点的，没在 MineDeck 的窗口里逐个点过。
- **单实例检查**：用发版参数编出来的程序真跑过：同一个文件夹里再开一份（`-nogui`、`-minimized` 各试一次），3 秒左右被拦下、以退出码 1 退出、不弹框；另一个文件夹里的一份照常起来；3.2.5 开着的时候，照应用内更新的换程序脚本把 exe 换掉，旧进程退出、新程序自己打开，并接着把住这个文件夹。没开两份带窗口的程序去看那个提示框。
- **系统保留的端口**：没在真的带着 Hyper-V、WSL 保留端口的电脑上，把新建、开服整条路走一遍；自动测试里用的是造出来的保留范围。
- **游戏规则**：没在真的 1.21.10、1.21.11 和 26.x 服务端上逐个拨过开关；读存档用的是造出来的存档文件。
- **启动完成的那一行**：各种核心的样子是照它们的日志格式写进测试的，没有把每种核心都真的开一遍。
- **经符号链接共用 `run.bat`**：在我们自己的电脑上建不了符号链接，这一条是在 GitHub 的 Windows 测试机上跑的；硬链接的两边都试过。
- v3.2.4 发布说明里写的那些照旧没实测，见 [v3.2.4 的发布说明](https://github.com/Trasperioooooon/MineDeck/blob/v3.2.4/docs/releases/v3.2.4.md)。

## 已知情况

- **单实例检查只管当前登录的这个 Windows 用户会话。** 切换到另一个 Windows 用户，或者计划任务在别的会话里启动同一个文件夹里的 MineDeck，拦不住。检查本身出错时（比如没有权限打开那把锁），MineDeck 照常启动。
- **同名服务器，接管的那台优先，有一种情形会让人意外。** 接管进来的服务器放在移动硬盘里，硬盘没插上的时候，你用同一个名字新建了一台；硬盘插回来、重开 MineDeck 以后，列表里显示的会换成硬盘里那台，你正在用的那台只出现在页面顶部的提示里。升级前就有两台重名的，升级以后列表里显示的那台也可能换掉。文件都还在，照提示里的办法给其中一台改个名字，两台就都出来了。
- **少见的日志格式可能认不出「启动完成」。** 改成只认整行以后，1.7 以前没有方括号开头的老日志格式认不出；Taiyitist（原 Banner），还有 Sponge 这类靠接管进来的服务端，日志格式没有逐个核对过。认不出的话，服务器明明开好了，状态却一直停在「启动中」。碰到了请告诉我们，附上控制台里启动完成的那一行。
- **导入交接包的表单**提交时不做上面说的端口复查，它查端口时也不认系统保留的范围；端口不能用的话，要到开服才报。
- **netsh 里带 `*` 的「管理的端口排除」不算系统保留。** 这种端口在 Windows 上实际能用，MineDeck 不拦。
- **提交时查端口有一种会放过去的情形**：别的程序占着某个端口，而你另一台没停着的服务器的设置里写的也是这个端口。这时表单不拦，开服前的检查会拦。
- **名字正好像临时文件的会被清掉。** 你自己放的文件，如果名字正好是 `.minedeck-backup-20261122.tmp` 这种样子（MineDeck 的固定开头、中间是不超过 10 位的纯数字、固定的结尾），放在服务器文件夹或备份文件夹里一个小时以上没动，启动时会被当成临时文件清掉。
- **删除服务器时有一个文件正被别的程序占着，可能删不干净、还删不掉。** 这是以前的版本就有的：「删除服务器和文件夹」删到一半碰上被占着的文件（杀毒软件正在扫、别的程序开着它），会报删除失败；这时服务器的 `instance.json` 可能已经先被删掉了，这台还留在列表里，再点删除会报「找不到 instance.json，已拒绝删除」。碰上了，先关掉占着文件的程序，把这台「移出列表」，再到文件夹里手动删掉剩下的文件。下一版改成最后才删 `instance.json`。
- **这一版仍然只有 Windows 的程序。**
- v3.2.4 已知情况里的几条照旧，见 [v3.2.4 的发布说明](https://github.com/Trasperioooooon/MineDeck/blob/v3.2.4/docs/releases/v3.2.4.md)。
