> **这是测试版**，给自己和好友试用、找问题的，可能还有毛病。
> - **用着 v3.2.0-beta.3 的**，「设置 → 更新与关于」里没选过更新渠道、或者选的是「最新版」，检查更新就能直接换到这一版。选了「稳定版」的看不到它。
> - **从 v3.2.0-beta.2 或更早的版本换过来，要手动换一次程序。** 那些版本检查更新时只看正式版，看不到测试版。请先关掉 MineDeck，下载下面的 `MineDeck.exe`，换掉原来文件夹里的那一个。服务器、设置和隧道都存在那个文件夹里，不用动。

和 v3.2.0-beta.3 比，这一版修了一个 beta.1 起就有的问题：服务器里的文件设成只读时，保存设置会报成功，其实没存上，见「修复」。另外把 beta.3 那次走查记下、当时没来得及改的几处改了：备份页说清现在的世界从哪来，改过备份存放位置以后不再让人以为备份丢了，新建服务器时预先避开被别的程序占着的端口，报错提示不再盖住修复按钮。

## 修复

- **服务器里的文件设成只读时，保存报成功却没存上**（beta.1、beta.2、beta.3 都有，正式版 v3.1.2 没有）。比如有人把 `server.properties` 设成了只读、不想让服务端改它，在 MineDeck 里改设置保存，会提示保存成功，文件其实没变；同一个文件夹里还会多出一个名字带乱码的文件，里面是这次想存的内容。偶尔会直接报「文件名语法不对」。原因是替换只读文件时传给系统的新名字少了结尾的空字符，系统把名字后面碰巧不是零的内存也当成了名字。现在名字后面补上了结尾，替换只读文件以后还会核对一次新文件确实换到了原来的位置，对不上就报错，不再报成功。和 beta.1 起一样，在 MineDeck 里保存以后，换上的文件不再是只读的；还想让服务端改不了它，要再设一次只读。
  - **请留意**：用过 beta.1 到 beta.3、又把服务器里的文件设成过只读的，请看一眼那个只读文件所在的文件夹（多半是服务器文件夹，`server.properties` 就在那一层），有没有名字是原来的文件名后面跟着一串乱码的文件。那是当时没存上的内容。先到这台服务器的「设置」里看看设置是不是你想要的，没问题就可以把那个文件删掉。没设过只读的不会碰上这个问题。

## 改进

- **备份页页顶说清现在的世界从哪来**。用已有地图新建的、换过地图的服务器，「世界与备份 → 备份」页顶以前一律写「服务器自己的世界」。现在写导入时的来源（文件夹或压缩包的名字）和导入时间；换过地图又换回来的，写换回了；旁边有到「换地图」的链接。从备份还原过的照旧写是哪一份备份。换地图的记录删掉以后就查不出导入过，这时写「没有从备份还原过，「换地图」里也没有导入记录」。
- **改过备份存放位置以后，说清旧备份在哪**。以前的备份留在原来的文件夹里，照常列出来、能还原能删，以前页面上不说，点「打开」看到新文件夹是空的，容易以为备份丢了。现在「备份放在」改叫「新的备份放在」，下面写明另有几份是改存放位置以前做的、还在原来的哪个文件夹，在这台电脑上可以直接打开那个文件夹；列表里那几份标着「在原来的文件夹」。
- **新建服务器时预先避开被别的程序占着的端口**。新建、导入整合包、用已有地图开服时，默认端口（一般是 25565）被这台电脑上别的程序占着的话，换成下一个空着的，端口框下面写明换了、被哪个程序占着。手填的端口，停手以后查一次，被占着就提示一句，不拦着你。查的办法是读系统里正在监听的端口，不去试着占一下端口，所以不会让防火墙弹窗。接管已有服务器时只提示、不换：多半是原来那台服务器还开着，提示里会让你先把它停掉。
- **报错提示不再盖住修复按钮**。服务器详情页上，右上角的报错提示改落在页头提示区的下面，不再挡住「改端口」「去换 Java」这些按钮；窗口太矮放不下时，退回页头下面或标题栏下方，保证整条看得见。开服、重启没成功、原因是找不到 Java 或者端口被占时，提示上和「详情」弹窗里都直接给「去换 Java」或「改端口」。
- **工具箱「导出整合包」读不出存好的草稿时有提示**。以前这种时候不自动保存（免得盖掉存好的），但页面上什么都不说。现在页面上常驻一条说明，带「重新读取」：读出来以后表单换成存好的那份，读失败期间改的不保留。

## 这一版实际试过的

- 发版前在最终代码上跑了一遍全部测试：后端的测试全过；界面的交互用例 244 条全过（beta.3 是 241 条，这一版加了 3 条）；界面原型的 162 个场景都能走通。
- 只读文件的问题：这个问题平时很难碰上，要程序里分配过不少内存以后才会出现，原来那条保存用例只在 CI 上偶尔挂过一次。查的时候在替换后面加了核对，把整组测试连着跑，立刻大量报错、报出新文件被改成了带乱码的名字。现在另加了一条每次都能稳定复现的用例，专门检查名字后面的结尾空字符，去掉它这条用例就挂；原来那条保存用例也加了一项：只读文件换完以后，文件夹里只能有原来那一个文件。另外用这一版编出来的程序实际开起来，对一台服务器里设成只读的 `server.properties` 连着保存三次，每次内容都换上了，文件夹里没有多出别的文件。
- 改动都经过另一方复审：Claude 写的修改交给 Codex 看过。只读文件那处看了两遍，第二遍没有发现要改的问题。走查的这几处看了两遍，找出的问题都改了；最后一次修改改完以后，发版前又请它单独看了一遍，没有要挡发版的问题，记下的小问题写在「已知情况」里。
- 界面上的这几处改动，是在仿真的后端上用不同大小的窗口看过、跑过用例的，没有编出程序在真窗口里走一遍。界面用到的几项数据（端口被别的程序占着、备份在哪个文件夹、换地图的记录），和真后端的字段逐一对过。

## 已知情况

- **新建时预查端口查不出 Windows 保留的端口段**。Hyper-V、WSL、Docker 这类会成段保留端口，被保留的端口预查时看着是空的，开服时照旧报「用不了」，页头照旧给「改端口」。
- 新建的表单打开时查过的默认端口（包括自动换成的那一个），表单开着期间被别的程序占上的话，不会再提示，开服时才会报。
- 备份页页顶「现在的世界从哪来」靠的是「换地图」里的记录，记录删掉以后只能说没有记录。新建向导和「换地图」页里，地图仍显示存档里的名字（多半是 world）。
- **报错提示的位置**：窗口比较窄（800 像素宽上下）时打开报错的「详情」，提示会盖住弹窗右边一截；窗口很矮、提示退回标题栏下方时，会盖住页头右边的启动这几个按钮；提示落在提示区下面时，会挡住标签栏右端的一两个标签；好几条提示叠在一起、比整个窗口还高时，下面的几条会出屏幕。提示 20 秒后自己走，鼠标停在上面时不走。
- 一个以前就有、要别的程序配合才碰得上的竞态：MineDeck 核对完服务器里的文件夹在哪、真正去读写之前的那一瞬间，要是别的程序正好把这个文件夹换成了指到服务器外面的目录联接，读写配置、补没装上的文件时有可能动到服务器外面。这一版不改，以后的版本把这几处改成按已经核对过的文件夹来操作。
- **存放位置的「撤销」不是完全撤销**：选错了文件夹再撤销，那个文件夹仍会留在扫描列表里。
- **原版服务器上**，导入整合包时跳过的文件在界面上找不回来（原版没有插件 / 模组页）。
- **接管已有服务器时，如果它的端口和别的服务器撞了**，MineDeck 会改它 `server.properties` 里的 `server-port`（只改这一项，界面上会说明）。
- 启动时后台检查更新，日志里不写用的是哪个渠道。选了更新渠道以后，要程序启动时自己去查，还得打开同一页上的「启动时静默检查更新」。
- **26.1 及以后的服务器，如果以前在游戏里用命令改过难度**，第一次用 beta.3 或这一版开服时，难度会改回「设置」里写的那个。想保留游戏里的难度，先到这台服务器的「设置 → 常用」里把难度改成一样的。
- 给服务器换一个要现下的 Java 时，下载还没完就重新打开这台服务器的「设置 → 启动与内存」再保存一次，会再建一个下载任务（不会重复下载文件）。
- 检查更新比较版本号时，预发布那一段（beta、rc 这些）不分大小写。MineDeck 自己的版本号都是小写，碰不到。
- beta.3「已知情况」里的这四条这一版改掉了：用存档新建或换过地图的服务器备份页页顶的说法、改了备份存放文件夹以后不提醒、工具箱读草稿失败没有提示、新建时不预先检查端口。其余各条都抄在上面。beta.1、beta.2 发布说明里「已知情况」的其余各条仍然适用。
