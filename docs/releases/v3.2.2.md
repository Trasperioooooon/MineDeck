这是 MineDeck v3.2.2，一个小版本。v3.2.1 的发布说明末尾有一节「已经查到、下一版修的」，写了三个问题，这一版都修了，另外修了七个小问题。没有新功能。

**开 1.7 到 1.11.2 服务器的，请尽快升级。** v3.2.1 说明里写的是「推断 log4shell 防护可能没起作用」，这次实测证实了：照 v3.2.1 给这段版本的设置起 1.8.9 原版和 Forge 1.7.10 的服务器，在控制台发一句带 `${jndi:...}` 的话，服务器都会去连那句话里写的地址，也就是防护没有起作用。升到 3.2.2 以后，已经建好、启动参数里引用着旧配置的这些服务器，会自动换上 Mojang 给这段版本的配置，下次从 MineDeck 里启动时生效。

## 怎么升级

用着 v3.2.1 或 v3.2.0 的，打开「设置 → 更新与关于」，点「检查更新」，查到新版本以后点更新就能升到 3.2.2。服务器、Java、设置、隧道和 AI Key 都会接着用。更新前先停掉正在运行的服务器。

用着 v3.1.1、v3.1.2 或者 3.2.0 测试版的，也能在程序里直接升到 3.2.2：3.2.0 的 beta.3 到 beta.5 不管更新渠道选的是哪个都查得到，beta.1、beta.2 和 3.1.x 只看正式版，3.2.2 就是正式版，也查得到。

从 v3.1.0 及更早的版本升级时，换程序的是旧版本自己带的更新脚本，它有两种情况换不成，新版本这时已经下载好、放在旁边。处理办法见 [v3.2.0 的发布说明](https://github.com/Trasperioooooon/MineDeck/blob/v3.2.0/docs/releases/v3.2.0.md)「已知情况 → 升级和更新」的第一条。

从 v2.6.1 及更早的版本升级（那时的程序叫 `AutoMCHUB.exe`），自动更新找不到改名后的文件，请手动下载 `MineDeck.exe` 放进原来的文件夹。旧的开机自启项会被删掉，需要的话在「设置 → 启动与托盘」里重新打开。

## 修了什么

### v3.2.1 里「已经查到、下一版修的」三条

- **1.7 到 1.11.2 的服务器，log4shell 防护换成了 Mojang 给这段版本的那份配置**（`log4j2_17-111.xml`）。以前这段版本用的是 Mojang 给 1.12 到 1.16.5 的那份，这段版本自带的 log4j 太老，认不得它。
  - 以后接管、导入这段版本的服务器，直接用新配置。
  - 已经建好的，只要启动参数里引用着旧配置、MineDeck 认得出它的版本，打开 MineDeck 以后就会在后台下载新配置，核对过 Mojang 给的校验值，再把引用旧配置的那一条换掉，别的参数一条不动，`run.bat` 也跟着重写（重写不成时控制台里会说），下次从 MineDeck 里启动时生效。服务器正开着时也照样换，这一次运行还是旧的，重启以后生效。
  - 没联网、下载不成时什么都不改，服务器照旧用原来的配置开，和以前一样，控制台里会说一声。之后每次启动这台服务器，都会在后台再试一次。
  - 新配置会把带 `${` 的消息整条丢掉，所以这段版本的服务器上，聊天或命令里带这种写法的那一句，不会出现在控制台和日志里。这是 Mojang 这份配置本来的做法。
  - 换下来的旧配置文件 `log4j2_112-116.xml` 留在服务器文件夹里，不删：你自己的启动脚本可能还在用它。服务器文件夹里原来就有一份 `log4j2_17-111.xml`、内容和官方的不一样的，会被换成官方那份。
  - 1.7 以前的正式版还没用 log4j，不再给它们加这两条参数。1.12 以后的版本照旧。
- **待装清单的文件读不出来时，不再当成空清单。** 清单存在 MineDeck 文件夹的 `data\modcart\cart.json` 里。MineDeck 打开时它在、却读不出来（比如正被杀毒软件或同步盘占着），或者内容坏了，清单和暂存在 MineDeck 里的本地模组都原样留着；这段时间不能往清单里加、移除或安装，清单的位置会说明原因，带一个「重试」。读出来以后不用重启就恢复正常。
  - 有一处做法变了：内容坏了的清单文件，以前会被改名成 `cart.json.bad`，然后从空清单开始；现在会一直挡着，等你修好。报错里会写坏在哪儿（能定位的写大概第几行），可以用记事本修，记事本存出来的格式也认。不想修的话，把这个文件改名挪走，就会从空清单开始；这时暂存在 MineDeck 里的本地模组，下次打开 MineDeck 时会被清掉，电脑上原来那份不受影响。
- **frpc 解压到一半出错，不再留下半截的程序。** 解压时先写成临时文件，全部写完、核对过再换成正式的名字，中途出错时，这次写出来的会删掉；文件夹里原有的同名文件不再被覆盖。OpenFrp 的下载缓存按版本存，解压失败时连缓存的压缩包一起删掉，下次重新下载。OpenFrp 给的下载地址只认 https 的（不是 https 的那几个跳过，一个都不剩才报错），下载时的跳转也只跟 https 的。
  - 以前的版本解压失败留下的半截 frpc，这一版还会照用。隧道一直启动失败的，删掉 MineDeck 旁边 `runtimes\frpc\openfrp` 文件夹里的 frpc exe（自定义 frps 的在 `runtimes\frpc\custom`），再启动隧道，会重新下载（有同一版本的缓存时直接重新解压）。

### 七个小问题

- 手改 `tunnels.json`、把里面的 `seq` 改小以后，新加的隧道会和已有的撞号。现在读隧道列表时会接着已有的最大编号往下排；以前已经撞了号的不会自动分开。
- 导入不带外层文件夹的现成服务端压缩包时，任务标题和返回的包名是一串随机数字，现在用上传时的文件名。服务器的名字照旧是你填的那个。
- AI 助手的回复太长、已经开始输出以后被截断时，以前说「回复中途断开了」，现在说回复内容过多，请缩小问题范围。
- 整个上传请求在 64 MiB 以内的，以前也会因为系统临时文件夹所在的盘空间不够被拒收，其实这么小的不往那个盘上写，现在不再查它。更大的被这个盘拒收时，报错里写明是系统临时文件夹所在的盘，能取到盘符的带上盘符。
- 导入整合包在最后一步失败或者被取消以后，任务页上不再挂着「几个文件待处理」和相关的提醒。
- 装 AI 伙伴的模组和它的前置、写进服务器的 `mods` 文件夹失败时，报错会提示「可能正被服务器占用，停服后再试」；盘满、内容核对不上、取消时照旧报原来的原因。
- 两处说明写错了：接口说明漏了换地图记录里的 `stagedBytes`；地图导入的使用说明里取消的入口说得不对，换地图要在「换地图」那一页取消。

## 给 AI 助手、MCP 和自己调接口的人

- **待装清单的操作**：清单文件在、却读不出来时，查看、加入和移除、清空、添加和移除本地文件、检查前置、安装的预览和执行都会被拒绝。直接调 HTTP 接口的回 503 和一句提示，MCP 里是这次工具调用出错（`isError`）；以前会返回一张空清单。在 Modrinth 搜索（`modcart.search`）不受影响。
- **保存启动参数**（`instance.settings.set` 带 `extraJvm`）：和以前一样，MineDeck 会按版本补上该有的 log4shell 防护参数；1.7 到 1.11.2 补的是新配置那一条（服务器文件夹里有这份文件时）。

接口的详细说明见 [`docs/设计与参考/API.md`](https://github.com/Trasperioooooon/MineDeck/blob/v3.2.2/docs/设计与参考/API.md)。

## 下载哪个文件

| 文件 | 给谁 |
|---|---|
| `MineDeck.exe` | 开服的人。放进一个单独的空文件夹，双击运行；已经在用旧版本的，换掉原来的那个。 |
| `minedeck-companion-neoforge-1.21.1-0.2.1.jar` | 用了 AI 伙伴的 NeoForge 1.21.1 服上的好友：放进客户端的 `mods` 文件夹 |
| `minedeck-companion-forge-1.20.1-0.2.1.jar` | 同上，Forge 1.20.1 的服 |
| `SHA256SUMS` | 校验和，自动更新会用到，一般不用管 |

伙伴模组还是 0.2.1，和 v3.2.1 的是同一份，已经装过的好友不用换。

## 这一版实际试过的

- **自动测试**：在最终代码上，Go 测试 42 个包全部通过，代码检查（go vet）没有提醒；界面交互测试 264 条、界面原型自检 162 个场景全部走通。删文件和清单读不出来时的那几处保护，写代码的一方逐条反着试过，合并时又抽了几处再试：把对应的代码改回去，相关的用例都会失败。
- **log4shell 实测**：用 Java 8 和官方服务端，在本机起了一个只监听 127.0.0.1 的端口，在服务器控制台发 `say ${jndi:ldap://127.0.0.1:<端口>/x}`，看那个端口有没有被连。1.8.9 原版和 Forge 1.7.10 用旧配置时各被连了 2 次，换成新配置以后 0 次，控制台照常输出，「启动完成」照常认出来；1.12.2 原版和 Paper 1.16.5 照旧用原来的配置，没被连。最后用发版的那条命令编出来的程序，在两台摆成旧版样子的服务器（1.8.9 和 1.12.2）上又走了一遍：没联网时什么都不改，服务器照旧能开，旧配置下照样被连了 2 次；联网以后，1.8.9 那台在 MineDeck 打开后自动换上了新配置，旧文件留着，起服以后「启动完成」照常认出来，一次都没被连；1.12.2 那台没被动，也没被连。
- **复审**：最要紧的三条，Codex（GPT-6-Astra，max 档，只读）看了两遍。第一遍看整支改动，指出三处，都改了：换下来的旧配置文件会被删掉，可它可能还在被你自己的启动脚本用着；启动脚本读不出来时也照删；MineDeck 所在文件夹的名字里带方括号时，清理 frpc 解压残留会删到旁边别的文件夹里的东西。第二遍只看这次修改，结论是可以合。另外七个小问题是 Gemini 写的，由 Claude 读过一遍。这份发布说明请 Codex（GPT-6.2-Astra，max 档，只读）对着代码核对过，指出的说得不准和漏写的地方都改了。

## 还没实测过的

- **log4shell**：Spigot、别的 Paper 1.8.8 构建和别的 1.7 到 1.11.2 的 Bukkit 系服务器没试过；换配置只在摆成旧版样子的服务器上试过，没走接管和导入。
- **待装清单**：没拿真的杀毒软件或同步盘去占着清单文件，用的是在测试里独占这个文件的办法；没有读取权限的那种没单独测过。
- **frpc**：没从 OpenFrp 真的下载一次（下载地址只认 https 以后）；自定义 frps 没拿真的 frp 发行包解压过。
- **七个小问题**只有自动测试，没在真窗口里试；伙伴模组写进 `mods` 时盘满的那种没单独测过。
- v3.2.1、v3.2.0 发布说明里写的那些照旧没实测，见 [v3.2.1 的发布说明](https://github.com/Trasperioooooon/MineDeck/blob/v3.2.1/docs/releases/v3.2.1.md)和 [v3.2.0 的发布说明](https://github.com/Trasperioooooon/MineDeck/blob/v3.2.0/docs/releases/v3.2.0.md)。

## 已知情况

- **Paper 1.8.8**（试的是 build 445）：套上 Mojang 的日志配置以后（v3.2.1 用的那份和这一版换上的这份都一样），控制台在「Loading libraries」之后就没有输出了，MineDeck 认不出启动完成，服务器其实已经起来了（它自己的日志里有 Done）。v3.2.0 起就是这样，还没定怎么改。这个构建自己修过 log4shell，不加 Mojang 的配置也没被连。别的 1.7 到 1.11.2 的 Bukkit 系构建没试过，可能也这样。
- **当初防护配置没下载成的 1.7 到 1.16.5 服务器**（建的时候没联网），这一版不会自动补上，MineDeck 的这层防护还是没加上。开这类服务器、又开了内网穿透让外人进来的，请只让信得过的人进。
- **待装清单读不出来的那段时间**：删掉一台服务器，读出来以后清单里还留着那台服务器的记录，之后再建一台同名的会看到它；工具箱「导出 Modrinth 整合包」选「自己挑模组」时会说清单是空的，文件修好以后，先打开一次待装清单，导出才恢复。
- **从电脑添加模组时，查不到那个盘还剩多少空间**（少数网络盘、特殊的挂载方式），待装清单的位置也会显示「无法显示待装清单」，其实清单没事：点「重试」就恢复，那个文件为什么没加进去，看它旁边的提示。
- **OpenFrp 查版本的那一步和自定义 frps 的下载**，跳转还不限 https。自定义 frps 下载下来的文件会核对官方的校验值。
- v3.2.1 已知情况里的几条照旧，见 [v3.2.1 的发布说明](https://github.com/Trasperioooooon/MineDeck/blob/v3.2.1/docs/releases/v3.2.1.md)。它末尾「已经查到、下一版修的」三条，以及 v3.2.0 已知情况里小文件被临时盘拒收、导入任务标题是一串数字、AI 回复太长说成断开这三条，这一版都修了。
