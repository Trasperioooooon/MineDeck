# 服务器详情：资源

## 一、这一屏是做什么的

按当前核心和 Minecraft 版本去 Modrinth 搜模组或插件，搜到就装进 `mods` 或 `plugins` 文件夹。搜索框留空直接点「搜索」也能出结果（热门）。每个结果一行：图标、名字、Modrinth 上的一句话简介、下载量、右边一个「安装」。装完按钮变成「已安装」，提示里写出落地的文件名，并说明要重启服务器才生效。

原版没有这个标签（没有加载器，装了也没用）。这一屏只处理 Modrinth 上能按核心和版本匹配到的资源；挑多个再一起装的那条路是「待装清单」。

## 三、不改的条目及原因

- 搜索框占位「搜索 Modrinth 模组/插件（英文名效果更好）」：括号里那条是实话，Modrinth 的中文搜索确实弱。
- 空列表「输入关键词搜索，或直接点搜索看热门资源」：一句说明加一个动作，而且动作就是旁边的按钮。
- 「安装」「安装中…」「已安装」三个状态与它们的 `aria-label`（「安装 JEI」「安装中… JEI」「已安装 JEI」）：`tests.js` 里断言了「安装 + 资源名」和装好后跟着变，这套写法保留。
- 下载量用「1.2M / 34k」这种缩写：一列数字，位置窄，缩写合理。
- 资源简介、名字、图标全部来自 Modrinth，属于外部内容，不改。
- 出错时的错误框：按 `00-报错信息.md` 统一处理。

## 四、没弄清、需要作者定的

1. 搜索框占位写「模组/插件」，但这个标签在插件服上只装插件。要不要按核心改成「搜索 Modrinth 插件」/「搜索 Modrinth 模组」，跟「选模组 / 选插件」的做法一致？涉及一个小改动（占位按 `coreKind` 拼）。
2. 装好后的提示里带完整相对路径（`mods/xxx.jar`），对排查有用；如果作者觉得太长，可以只留文件名。
3. 「清空搜索看热门资源」这个说法我按代码里的行为写的（空关键词会返回热门），但没有核对后端在空关键词时是否有条数上限。
