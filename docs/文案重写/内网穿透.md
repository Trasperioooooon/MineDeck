# 内网穿透

## 一、这一页是做什么的

把本机的服务器端口映射到公网，让不在同一网络的人能连。一条隧道对应一个 frpc 进程，服务商支持三种：OpenFrp、樱花穿透（SakuraFrp）、自定义 frps。选服务商后表单会换：OpenFrp 和樱花要「用户密钥（访问密钥）+ 隧道 ID」，自定义 frps 要地址、端口、token 和三个端口号。都可以绑定一台服务器，并选择是否跟着它启停。

列表每条一行：状态胶囊、名称、服务商徽标、绑定关系（带「· 跟随」）、当前状态、启动 / 停止、日志、删除。状态位会显示凭据解不开、上次出错、连接出错、连接中…、尚未启动，或者拿到公网地址后给一个「复制」键。日志按需展开，走 SSE。

没有隧道时表单常开，页头的「添加隧道」收起来；有隧道时由页头按钮展开 / 收起。列表 4 秒刷一次，启动或停止后改成每秒一次，直到这条隧道稳定（最多 30 秒）。刷新偶尔失败时，列表和展开的日志都留着，只在摘要那里提示一句。

## 三、不改的条目及原因

- 三种服务商的名字与「自定义 frps」：跟服务商自己的叫法一致。
- 三段 `tn-help`（OpenFrp / 樱花 / 自定义各一段）：都是「先去哪、填什么」的两步说明，句子长但每句都在办事。
- 状态位的五种说法（「凭据无法解开，请删除后重新添加」「连接出错」「上次出错」「连接中…」「尚未启动」）：区分得出是凭据问题、这次失败还是上次失败。其中「凭据无法解开」被 `tests.js:719` 断言、「上次出错」被 `tests.js:1932` 断言。
- 摘要行的「刷新失败：…」：被 `tests.js:1977` 断言；偶尔失败时不打断列表和日志，这个提示就是全部交代。
- 「启动」「停止」「日志」「删除」与它们的 `aria-label`（「启动 家里的隧道」这套）：符合「可见文字 + 对象」。
- 删除确认框（「删除隧道？」+「仅删除本机配置，服务商侧隧道不受影响。」）：把最容易误会的一点写在正文里。
- 「隧道启动中，公网地址稍后显示在列表」「已复制公网地址：xxx」「隧道已添加」：都在说这一下的结果。
- 「· 跟随」这个后缀：跟在服务器名后面，两个字说明它会跟着启停。

## 四、没弄清、需要作者定的

1. 摘要行的「刷新失败：原文」是这一页唯一把原始报错直接摆出来的地方。要不要也按 `00-报错信息.md` 加成「复制报错信息」，我倾向加（这一行很小，按钮可以只放图标），但会让摘要行变高，等作者定。（2026-11-12 文案收尾时主会话定了加：「无法刷新隧道列表」后面跟一个只有图标的复制键。作者可以否决，见 `01-补完口径.md`。）
2. 表单里「隧道名称」默认值「我的隧道」：两条以上隧道时会出现两个同名项，是否改成空、或用服务商名做前缀，属于产品判断。
3. 音乐共享会在这一页追加「用途（游戏 / 语音）」和自定义 frps 的协议字段（`music.js` 的 `tunnelForm`）。那两处文案在音乐共享那一份里写。
