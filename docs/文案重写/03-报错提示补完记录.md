## 规则

调用的地方只给一句结论，说这一步没做成什么，比如「无法启动服务器」「保存失败」「无法把 Notch 加入白名单」。正文怎么拼，全在 `internal/web/ui/app.js` 的 `errSummary` 一个函数里。右上角的提示（`toastErr`）、页面报错框（`errBox`）、一行字里的报错（`errInline`）都调它，所以三种地方的说法永远一致。

拼法分三种情况。请求根本没发出去时，结论后面接「连不上 MineDeck」。这要同时满足两条：报错是 TypeError，原文是浏览器那几句「Failed to fetch」之类。同一个 try 里代码自己出错也会是 TypeError，但原文对不上，不会被误说成连不上。后端给的是一句看得懂的中文时，整句接在结论后面：「无法删除服务器：请先停止服务器再删除」。后端在原文之外另给了一句人话（接口里的 `hint`，目前只有 AI 服务商的报错有）时，拿这一句代替原文来判断、来接：「连接失败：Key 不对或已失效」，原文「Key 不对或已失效（HTTP 401，authentication_error）：invalid x-api-key」照旧在复制键里。后端那句自己已经带着全角冒号的，改用句号接，免得一句里出现两个冒号：「发送失败。AI 未启用：先在「设置 → AI」里选择服务商，填好 Key 和模型」。其余情况只写结论。不管哪种情况，「详情」和「复制报错信息」里都是完整原文，一个字不少，连回车换行都原样保留。

「看得懂的中文」有三个条件：含中文，不超过 60 个字，没有技术痕迹。技术痕迹是一张清单，写在 `ERR_TRACES` 里，每条都有注释。清单包括文件路径（盘符开头的、反斜杠隔开的、斜杠开头的、带扩展名的相对路径），`fork/exec`、`exit status`、`i/o` 这类外部程序和读写的报错，带着真实地址的网址（只提到「http://」这几个字的不算），以及 Go 拼报错时用的半角冒号加空格。连着两个以上的小写英文单词也算，那就是英文报错句；`EOF`、HTTP 状态码、十六进制的系统错误码、换了行的原文，同样算。Codex 复审时构造了几种边界情况，规则跟着修了：单独列出来的反斜杠字符、「1.20/1.21」这种版本号、带书名号的「https://」不再被当成痕迹；冒号后面的绝对路径、中文文件夹名的相对路径不再漏进正文；Bad Gateway、ACCESS DENIED 这类大写的常见英文报错按一张短语表认，不对所有英文词放宽大小写，免得误伤 Simple Voice Chat 这类名字。这些例子都加进了规则测试。判断只看文字，不看 HTTP 状态码，因为同一个 400 既可能是「服务器名称需为 1~40 个字符」，也可能带着系统给的英文原文。后端的话要么整句接上，要么不接，从不截短。

60 字是量出来的：提示框正文一行放十五个汉字上下，结论加 60 个汉字正好五行。拿后端代码里含中文的报错格式串数了一遍（占位符按两个字算），没有技术痕迹的有 535 条，其中 40 字以内 485 条，60 字以内 528 条，80 字以内 533 条。

前端自己编的兜底词不接，只写结论。这些词是后端没给原因时才用得上的「未知错误」「导入失败」「上传失败」「添加失败」「登录失败」，放在 `ERR_FALLBACKS` 里，只认整句相等，不做「X失败」那种模糊匹配，不然会拼出「无法导入整合包：导入失败」这种话。「需要登录」不在里面：后端 401 自己说的也是这句，它是有用的原因。

这套规则的代价，主会话看过试点以后决定接受，作者可以否决。带路径的有用话会只剩结论，比如樱花 frpc 的首次放置说明；这两条长说明在隧道卡片上照样整句显示，提示里只写结论，而找不到 Java 那句后端已经改成不带路径。名字是两个小写英文词的服务器（比如 my server）会被当成英文报错句，只剩结论。Windows 函数名这类驼峰写法的英文会漏过去，比如「无法开始广播。WaitForMultipleObjects 失败：句柄无效。」，不为它加规则，免得误伤模组名。

## 三种呈现

右上角的提示用 `toastErr(结论, e)`。`toast` 多了第三个参数 `detail`，「详情」对话框里显示它，不给就沿用正文。

页面报错框用 `errBox(结论, e, { hint, actions, id, label })`，返回 HTML，调用处直接拼进 `innerHTML`。样子照服务器列表那处原来的写法：一句结论，下面一个带复制图标的「复制报错信息」。`hint` 是「正在自动重试」「可在「设置 → 下载与网络」换一个下载源后重试。」这类下一步，单独占一行，这样结论后面才接得上后端的原句。`actions` 是放在复制键前面的按钮，比如待装清单的「重试」。`id` 给测试和样式用。`label` 用在同一页可能同时有几个报错框的地方，给复制键的名字带上是哪一块（「复制报错信息 前置检查」），读屏和无障碍测试才分得开。复制键不各自绑点击：原文转义以后放在按钮的 `data-err-raw` 上，document 上一个委托统一处理，所以服务器列表这类每隔几秒重画一次的地方也不用重新绑。

一行字里的报错用 `errInline(结论, e, { label })`：警告图标、正文，后面一个只有图标的复制键，名字和悬停提示都是「复制报错信息」。AI 设置页上，AI 测试连接的行内报错和 MCP 设置的报错框可能同时出现，两个复制键分别带上「AI 测试连接」「MCP 设置」（Codex 复审发现）。

## 后端原文里读起来不像给人看的

下面这些句子在提示里只会剩下结论。要让用户直接看到原因，得在后端改写法，这一轮前端不动后端字符串（AI 服务商那条后来在后端补了，见下文）。

最多的是 Go 拼接的报错：用半角冒号把系统原文接在后面，比如「启动失败: %w」「存放文件夹不可用: %s」「无法打开整合包（需为 .mrpack 或 zip）: %w」「获取 Fabric 版本列表失败: %w」，格式串里有七十多条。

影响最大的是 AI 服务商的报错。`internal/ai/ai.go` 的 `APIError.Error` 一律写成「Key 不对或已失效（HTTP 401，authentication_error）：invalid x-api-key」这种形状，前半句本来很有用，但带着 HTTP 状态码，整句都会进「详情」。这一处后来在后端补上了：`APIError` 和 `NetError` 多了 `Hint()`，给出不带状态码的那一句（「Key 不对或已失效」「连不上服务商，检查网络、代理和接口地址」），`writeErr` 把它放进响应的 `hint`，测试连接的结果也带着它，前端的正文优先接这一句。原文一个字没改。

还有几句超过了 60 个字：伙伴模组协议对不上、没法按版本自动选 Java、不能选 MineDeck 自己的程序文件夹、文件夹里没找到服务端、安装器多次运行失败。前面一句话就能说清原因的，可以拆成一句原因加一句做法。最后是带着英文状态词或函数名的，比如服务器当前状态那句（后端已经改成中文状态），以及音乐共享采集声音时的 Windows 函数名报错。
