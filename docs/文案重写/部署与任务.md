# 部署与任务页

## 一、这一页是做什么的

所有后台任务共用这一页：部署服务器、接管、换 Java、导出交接包、导入交接包、安装待装清单。地址是 `#/task/<任务编号>`，任务结束后仍可回看。

页头按任务类型换说法（部署、接管、换 Java、导出、导入、装清单各一套标题和说明）。下面是步骤条（步骤名由后端给）、一条 30 格的进度条（换下载项就清空重来，完成时填满并闪一下）、可选的「下载慢或在重试」提示卡、告警卡、待决文件面板、日志和底部操作区。

任务失败时错误框里是后端给的失败原因加一句下一步；成功时底栏出现「完成，进入控制台」，失败时是「返回重试」，进行中写「…中，请勿关闭程序…」。进度和日志每 800 ms 刷新一次；拿不到任务时顶部错误框自动重试。

待决文件面板只在整合包导入出现：列着没法自动下载的文件，每条给一个下载地址和三种处理方式（跳过、用本地文件代替、信任站点并下载），选完点「应用所选的处理」。

另外，服务器列表页和新建服务器页顶部那条「部署与下载任务」是这一页的摘要列表，文案在那两份里已经写过，这里不重复。

## 三、不改的条目及原因

- 六套任务说法（部署、接管、换 Java、导出、导入、装清单）的标题、说明、完成语、失败语和「下一步」：每套都对得上各自会做什么，且失败语都给了出路（返回重试、去「内存 / 启动」换 Java、去待装清单再装）。
- 「部署中，请勿关闭程序…」这类进行中的提示：关掉程序确实会中断任务，属于必须说的后果。
- 「待决清单已全部处理完」收尾卡：被 `tests.js:2663` 断言，且说法准确。
- 三种处理方式的名字（跳过 / 用本地文件代替 / 信任站点并下载）：都是动词短语，长度也够排在一行。
- 「应用所选的处理」按钮、「先给至少一个文件选处理方式」「XXX 选了「用本地文件代替」但没给路径」这两条提示：说的是用户下一步要做什么，没有责备。
- 步骤条和进度条的文字（步骤名来自后端，标签来自后端最近一条进度）：不改前端。
- 页头眉标「第 2 步/共 6 步」「已完成 · 共 6 步」：与向导的步骤条同一套写法。

## 四、没弄清、需要作者定的

1. 任务不存在（后端 404）时现在直接显示后端原文，例如「任务不存在」。要不要也改成「找不到这个任务」+ 复制原文，取决于作者对「后端中文串是否直接当正文」的态度。
2. 告警卡里的 `w.note`、`w.items` 的文字全由后端拼（`internal/inst/import.go` 一带），这一页只负责排版。我准备在「弹窗、提示与报错」那一份里集中处理这些后端串，不在这里逐条列。
3. 「去「内存 / 启动」换 Java」这个按钮的文字是前端写死的，而后端 Java 提示卡的标题里写的是「这台实例现在是 Java 17」——术语按方案 A 应改成「这台服务器」。它属于后端串，记在待定清单里，等后端那批一起改。
