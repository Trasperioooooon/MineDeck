# 服务器详情：待装清单

## 一、这一屏是做什么的

装模组的地方，两个形态共用一套界面：详情页的「待装清单」标签（给已经建好的服务器装），和新建向导里的「选模组 / 选插件」那一步（先攒成草稿，服务器建好后自动装）。

左栏是 Modrinth 的列表，按当前核心和版本过滤：一进来是热门（按下载量，一页 20 个，最多翻到第 100 个），可以搜关键词、按类别筛、点「加载更多」。每张卡的按钮在「加入清单」和「已在清单」之间变。右栏是清单本体：项数、拖放区、「从电脑添加…」、每项可以移除，「检查前置」列出还缺的必装前置，最后「全部安装」提交一个后台任务（任务页那种），装进 `mods` 或 `plugins`。

本地文件是先在界面上传到暂存目录、安装时再拷进服务器；服务器里已有同名但内容不同的文件时不会覆盖，任务页会说明。清单里的模组/插件合计最多 50 项，单个文件最大 256 MB。

## 三、不改的条目及原因

- 搜索占位（按核心拼成「搜索模组（英文名效果更好）」或「搜索插件（…）」）与它的 `aria-label`：`tests.js:3034` 按名字找控件。
- 「加入清单 / 已在清单」两种按钮字与「加入清单 JEI」这套 `aria-label`：`tests.js:2885` 断言过。
- 「全部安装」「全部安装（12）」「检查前置」「还缺的前置（必装）」「不缺前置，清单里的可以直接装。」：每个都是动词短语或一句结论，位置窄。
- 安装前的确认框（「另外会自动装上 3 项必装前置」+「一起安装」「先不装」）：把「你不只装了清单里这些」说在了最前面。
- 「共 12 项」「已开始安装清单里的 6 项。服务器正在运行，装完要重启才生效」：一个数字，一个结果加生效时机。
- 「有 3 个文件没有加进清单：」+ 文件名与原因：这是失败清单的标题，越短越好。
- 状态标签（已在清单、加载中…、重试、已装的模组里缺 N 项前置）：都是两三个字。

## 四、没弄清、需要作者定的

1. 第 5 条里「这一步可以先跳过」在详情页不该出现（那里没有「建服务器」这回事），要按调用位置分两套字。这是行为差异，改起来是加一个参数，涉及改代码，等作者同意。
2. 清单里本地文件的名字、大小、状态文字来自上传接口，我没逐条核过它们在文件很小时显示成什么样。
3. 「待装清单」这个词已经定死；但列表页那边「加入清单」用的是「清单」两个字，标题却是「待装清单」，要不要统一成「加入待装清单」会变长，作者挑。
