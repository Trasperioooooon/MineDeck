# 新建服务器：导入整合包

## 一、这一页是做什么的

把 Modrinth（.mrpack）或 CurseForge（zip）的整合包变成一个 MineDeck 服务器。选文件、填名称、端口、内存、存放位置，勾 EULA，点「导入并部署」：文件先上传，后端识别出核心、版本和加载器，然后跳部署任务页。上传上限 4 GiB，超过就在上传前拦下。

「本地来源目录」是可选的：包里那些没法自动下载的文件（自定义直链、缺校验值），如果这个文件夹里已有同名文件，按原样放进服务器，不做线上校验。没填的话，这些文件会列进任务页的「待决文件」逐个处理。

「正版验证」默认关，「允许飞行」默认开。CurseForge 的包要下载模组得有 API Key，没填也能导入，只是那些文件进待决清单。

## 三、不改的条目及原因

- 「整合包文件」「端口」「存放位置」「正版验证」「允许飞行」：名词与名词短语，2–6 字。
- 「正版验证」的说明「默认关闭」：一句话交代状态，与向导里的写法不同（那里写「默认关闭：离线账户可直接进服」），两者都不错，不强求一致。
- 三句校验：「请先选择整合包文件（.mrpack 或 .zip）」「导入前需要同意 Minecraft EULA」「这个整合包有 X GB，超过了 4 GB 的上限，导不进来。」——最后一句的后半句被测试断言，且上限数字必须留。
- 「导入并部署」「上传中…」按钮文字：说到做到，上传和部署确实是两步。
- 「已选择：路径」这类 toast（`app.js:1343`、`1347`）：短，且带上了具体路径。

## 四、没弄清、需要作者定的

1. 「这个整合包有 X GB，超过了 4 GB 的上限，导不进来。」只说了不行，没说怎么办。我拿不准 4 GB 以上的整合包有没有可行的替代路径（交接包页那种「复制文件夹 + 接管」在这里未必成立：整合包解压出来不等于一个能启动的服务器文件夹），所以没写。作者若知道可行做法，这句要补半句。
2. 整合包「只能装在客户端的模组」问题：`docs/功能清单.md` 说导入时不提醒，崩了以后靠报错横幅认出来。这里要不要在导入前给一句「包里可能含只给客户端用的模组」，属于产品判断，没加。
3. 「已识别 …（123 个文件）」里的「文件」数来自后端 `pack.files`，我没有核它算的是包内条目还是将要写入的文件数。
