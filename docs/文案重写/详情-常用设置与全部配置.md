# 服务器详情：常用设置、全部配置

## 一、这两屏是做什么的

「常用设置」把 `server.properties` 里常见的几十项按七个分组摊开（基础与玩法、世界生成、玩家与权限、性能、网络与远程管理、资源包、安全与杂项），每项一行：中文名、说明、键名、控件。项和说明都来自 `internal/web/ui/props-catalog.js`，按实例的 Minecraft 版本取舍（未引入的隐藏、已移除的隐藏、已迁移成游戏规则的改成开关）。

顶部有搜索（中文名和键名都能搜），还有七个分组芯片，点一下滚到那一组。多字段表单，底部吸底保存条：干净时写「所有修改已保存」，有改动时显示未保存项数。服务器运行时保存，要重启才生效；游戏规则的开关例外——运行时拨一下就直接发 `/gamerule`，即时生效，行上带「游戏规则」标签。

「全部配置」是同一份文件的原始视图：左边键名、中间中文名（已知项才有）、右边值，一行一项，全都能改，保存提交全部键值。搜索只藏行不删数据。文件还没生成时两屏各自给一句说明。

代理端这两屏都不可用（代理端没有 `server.properties`，「常用设置」标签会换成一句说明）。

## 三、不改的条目及原因

- 七个分组名与分组芯片：都是名词，长度一致，能一眼看出是哪一类。
- 搜索占位（「搜索设置项（中文名 / 键名，如 视距 / rcon）」「搜索配置项（键名 / 中文名，如 rcon / 视距）」）：两种都能搜，例子给全了。
- 行上的两个标签「重启生效」「游戏规则」、以及「（服务器启动后可切换）」「注意：此版本起白名单默认开启」：都是这一项特有的状态，短。
- 「共 N 项」「找到 N 项（共 M 项）」「没有匹配的配置项：换个关键词，或者按 Esc 清空搜索。」：数字加一句出路，够用。
- 保存条的两个动词「保存设置」「保存全部」：一个存常用项，一个存全表，区分得开。
- `props-catalog.js` 里的六十来项：我按「中立、陈述、一句话」的标准抽看了一遍（如「关闭后夜晚和黑暗处不再自然刷出怪物」「改名等于换一个新世界存档」），整体是合格的，本轮不动。只有少数带版本沿革的长说明（例如命令方块那条写了「默认值从 false 翻转为 true」），信息有用但长，改动要连数据源一起，先留着。
- MOTD 那一行的色码调色板与预览：按钮只有色块和「粗体 / 斜体 / 下划线 / 删除线 / 重置」几个字，标题里给 `§x`，够了。

## 四、没弄清、需要作者定的

1. 「打开目录」这个词等第二组术语定（目录 / 文件夹），这两屏里有三处指向它。
2. `props-catalog.js` 的文件头写着「本文件为 UI 表单的唯一数据源，请勿手改单项，应回到附录 B 同步后整体重生成」。所以真要改那批说明，流程是改 `docs/UI与体验改进调研报告.md` 的附录 B 再重生成，不是直接动这个 js。这条流程我按文件头照抄，没验证过生成脚本还在不在。
3. 游戏规则的提示里要不要把规则的中文名也带上（现在只有 `keepInventory` 这种键名）。带中文名就得在 catalog 里给每条规则配一个名字，属于加数据。
