# 实例与服务器：现状统计与统一方案

这一份不针对某一页，先把两个混用的词数清楚，请作者定一个，后面各页按定的结果写。同理还有「目录 / 文件夹」，一并放在第二节。

## 一、实例 / 服务器

### 现状

界面上的「服务器」占绝大多数：页头标题、侧栏导航、空状态、删除确认框、接管页、向导的默认名字（「我的 Paper 服务器」）、详情页各标签的说明，都是「服务器」。前端源码里「服务器」出现约 250 次（含注释），后端返回给界面显示的报错和任务标题也一样，例如 `internal/inst/inst.go:209` 的「请先停止服务器再删除」、`internal/inst/install.go:153` 的任务标题「创建实例 %s（%s %s）」是少数例外。

「实例」在前端源码里出现 38 次（含注释），真正显示在界面上的只有下面 9 处：

| 位置 | 现在写的 |
| --- | --- |
| `internal/web/ui/app.js:879` | 实例目录（卡片「···」和详情页「打开目录」共用的菜单项） |
| `internal/web/ui/app.js:1312` | 实例名称（导入整合包表单的标签） |
| `internal/web/ui/app.js:1838` | 实例名称（从零创建「基本设置」的标签） |
| `internal/web/ui/app.js:2275` | 实例不存在（详情页的错误框） |
| `internal/web/ui/app.js:3012` | 绑定实例（内网穿透表单的下拉标签） |
| `internal/web/ui/app.js:3015` | 跟随实例启动（隧道的开关） |
| `internal/web/ui/music.js:312`、`321` | 跟随实例启动（音乐共享的说明文字） |
| `internal/web/ui/mcp.js:164` | 删实例（MCP 面板的说明） |

后端还会把「实例」送进 toast、错误框和任务日志，用户在界面上看得到的有：

`internal/inst/inst.go:192`（实例不存在）、`394`、`400`（实例名需为 1~40 个字符）、`internal/inst/install.go:68`、`93`、`114`（实例名已存在）、`153`（任务标题）、`375`、`446`、`591`（实例目录里的 installer 日志）、`internal/inst/import.go:398`、`715`、`718`、`internal/inst/adopt.go:245`、`internal/diag/rules.go:456`、`461`、`478`、`480`、`638`（「给这个实例换成 Java」这类修复建议）、`internal/musicshare/broadcast.go:284`（实例不见了）、`internal/transfer/import.go:229`。

### 三个方案

A. **界面一律叫「服务器」，「实例」只留在给 AI 助手、MCP、本地 API 看的描述里。** 界面要改的就是上面 9 处，后端那批字符串在出现在界面前改字（报错传给界面时换词，或者直接改字符串）。`docs/功能清单.md`、`docs/API.md` 是给开发者和 AI 看的，继续用「实例」不影响用户。
改动面最小，和现有 250 处一致；「实例」对普通用户是生词，只有写代码的人顺口。

B. 界面一律叫「实例」。要动 250 处，空状态、删除框、接管页、向导都得重写，且「我的 Paper 实例」这种默认名字要跟着改。不建议。

C. 分层：「服务器」指能启动、能进人的那个东西，「实例」专指它在磁盘上的那份目录。听起来讲得通，但删除确认框已经写「同时删除服务器文件夹」、接管页写「服务器所在的文件夹」——用户看到的还是「服务器」，分不出两套说法。不建议。

### 结论

作者选定 A：界面一律叫「服务器」。落到具体几处：

- 「实例目录」改成「服务器文件夹」，和删除确认框、接管页一致。
- 「实例名称」改成「名称」（接管页的表单标签已经只写「名称」）。
- 「实例不存在」改成「服务器不存在」。
- 「绑定实例」改成「绑定服务器」，「跟随实例启动」改成「跟随服务器启动」。
- 「删实例」改成「删服务器」。

后端那批字符串改字时不影响含义，但 `internal/inst/inst.go:394`、`400`、`install.go:68` 这类是表单校验报错，会直接显示在字段下方，建议一起换成「服务器名称需为 1~40 个字符」「已有同名的服务器」。

`docs/` 和后端代码注释里的「实例」不动：那是给开发者和 AI 看的，改了反而对不上代码里的 `Instance` 类型。

## 二、顺带发现：目录 / 文件夹

「打开文件夹」菜单里第一项叫「实例目录」，详情页的按钮叫「打开目录」，同一个按钮在说明文字里又叫「服务器目录」；删除确认框和接管页则写「文件夹」。现在两套说法交替出现，数一下可见文案：用「目录」的约 10 处（如 `app.js:899` 备份目录、`1320` 本地来源目录、`2285` 打开目录、`2921` 服务器目录），用「文件夹」的约 8 处（如 `app.js:901` 服务器文件夹、`1172`、`1174` 服务器所在的文件夹、`1414` 导出到哪个文件夹）。

Windows 11 的中文界面用「文件夹」，资源管理器里也叫文件夹。建议界面统一用「文件夹」，「目录」只留在技术描述里（`docs/`、API 说明）。这个决定会牵动详情页和设置页的几处文案，请作者一并定，定了我在后续各页按它写。
