# 新建服务器：导入交接包

## 一、这一页是做什么的

把另一台电脑上 MineDeck 导出的 `.mdpack` 交接包变成这台电脑上的服务器。先选文件并上传（上限 8 GiB），后端读出包里的清单，页面把摘要摆出来：原名称、这个包是哪种用途、核心与版本、世界大小、模组与插件数量、原来的内存、Java 版本、导出自哪个 MineDeck。然后填名称、端口、内存、Java、存放位置，勾 EULA，点「导入交接包」，跳部署任务页。

端口一改就查占用，被占了只提示不拦（可能就是要沿用包里那个）。默认包不带服务端核心，导入时重新下载；打包时勾了「完整模式」的包带核心。原来的 JVM 参数、定时任务、崩溃自动重启、游戏内 AI、AI 伙伴和音乐共享不会随包过来，日志里会写。

这一页还有一个方向：从服务器列表的卡片菜单打开「导出交接包」，那是打包这一侧的弹窗，属于「弹窗、提示」那一份。

## 三、不改的条目及原因

- 「交接包文件（.mdpack）」「存放位置」「导入交接包」「返回」：名词与动词短语，和后端、文档里的叫法一致。
- Java 下拉第一项「跟原来一样：Java 21（本机没有就下载）」：前缀被 `tests.js:2806` 断言，且「本机没有就下载」是用户要判断的信息。
- 端口占用三句（「端口 X 正被「Y」占用，启动会失败」「端口 X 正被占用」「端口 X 也是列表里某台服务器要用的」）：都说清了后果或冲突对象，且区分得出是「被别的程序占着」还是「自己列表里的另一台要用」。
- EULA 下面的「原服主在 MineDeck 里同意过 EULA 的，这步可以不勾。」：一句条件，没有多余的话。
- 「请给这台服务器起个名字」「交接包还没上传完，或上传失败了」：都已经说完发生了什么、要做什么。
- 摘要里的「模组 / 插件」值形如「36 个模组 / 2 个插件」：数字由后端给，句式没问题。

## 四、没弄清、需要作者定的

1. 摘要标签改「模组与插件」之后，值里仍是「36 个模组 / 2 个插件」，标签和值会有点重复。也可以把值改成「36 个模组、2 个插件」，作者挑一种。
2. 「世界大小」只给一个总数（`worldBytes`），没说含不含多世界插件的其他世界。`docs/功能清单.md` 说包里带这些世界，但摘要只显示一个数，我怀疑是合计。没敢在文案里写「含其他世界」。
3. 来源确认卡拆成两段之后，第二段（JVM 参数、定时任务不随包过来）严格说不算风险，摆在警告卡里合适吗？也可以挪到表单下方的普通说明。
