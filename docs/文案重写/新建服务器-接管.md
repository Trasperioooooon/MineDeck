# 新建服务器：接管已有服务器

## 一、这一页是做什么的

把已经在这台电脑上跑着的服务器文件夹登记进 MineDeck，文件不搬家。填文件夹（或点「浏览」选，选完自动识别），点「识别」后后端只读地认一遍：核心、版本、构建、能启动的文件、原启动脚本里分的内存、EULA 有没有同意过。识别结果填进表单，可以逐项改；识别时发现的问题（没认出核心、有多个启动文件、JVM 参数带不过来等）列在「识别时注意到」那张卡里。

确认后点「接管这台服务器」，跳部署任务页。改动只在文件夹里写 `instance.json` 和启动脚本，原有的 `run.bat` 先另存为 `run.before-minedeck.bat`。原来没同意 EULA 的要在表单里勾。代理端不显示端口和 EULA，版本标签写成「代理端版本」。

## 三、不改的条目及原因

- 「服务器所在的文件夹」「识别」「识别中…」「接管这台服务器」：动词短语，说明这一下会发生什么。
- 「识别时注意到」这张卡的标题：是提醒不是错误，措辞准确。
- 写文件那段说明（「接管时 MineDeck 只在这个文件夹里写自己的 `instance.json` 和启动脚本 `run.bat`。原来就有 `run.bat` 的，先另存为 `run.before-minedeck.bat`。别的文件都不动。」）：这是用户最担心的事，写成三条事实，一个字都不多，保留。
- 「这个文件夹里没看到存档（world），启动后会生成一个新世界。存档放在别处的话，先确认选对了文件夹。」：条件加后果，没劝。
- 三句表单校验（起名字、选一个最接近的类型、填版本）与 EULA 那句：都说清了怎么改，且「插件服选 Paper，模组服按加载器选」是这一页最需要的一句话。
- 后端送来的识别提醒（`internal/inst/adopt_scan.go:235`–`251`）：都是「发现什么 + 怎么办」，没有多余的话，本轮不动。
- 「名称」「服务端类型」「Minecraft 版本 / 代理端版本」「启动文件」「Java」「存放位置」这些字段名：名词，够短。

## 四、没弄清、需要作者定的

1. 「启动文件」下拉里每一项的文字（`AdoptTarget.label`）由后端拼，我没核过它在多启动文件时的可读性（比如都写成「server.jar（Paper 1.20.1）」还是带路径）。如果要统一，得先定格式。
2. 代理端的「请填代理端的版本，不确定可以填 1」——「填 1」是权宜说法，代理端自己的版本号跟 Minecraft 无关，这里到底该怎么引导（留空自动选最新？），我没把握，没动。
3. 「存档放在别处的话，先确认选对了文件夹。」只提示了「有没有 world 文件夹」，但如果用户用的是自定义世界名（level-name 改过），这句会误导。是否改成「没找到默认名称的存档」，要先确认后端认不认 `level-name`。
