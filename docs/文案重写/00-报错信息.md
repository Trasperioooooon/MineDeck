# 报错信息怎么呈现（跨页共用，先立规矩再逐页改）

## 为什么会单列这一份

第 11、12 条原来是把原始报错从界面上拿掉，换成一句中文说明。作者指出这是功能回退：用户和作者排查问题都要看原文。所以改成「一句话在前，原文可达」——原文一个字都不删，只是不再占正文位置。

## 现状盘点

前端 93 处把 `e.message` 直接塞进提示（`toast(e.message, true)` 这类），31 处用 `.err-box`。后端的报错文本分两种：一种本来就是给用户看的中文（例如 `internal/inst/inst.go:209` 的「请先停止服务器再删除」），另一种是浏览器的原始报错（取不到数据时是 `Failed to fetch`）、HTTP 状态码、或者 Go 的错误串（`实例名已存在: xxx`）。同一个 toast 里现在两种混着出。

## 建议的做法

**正文一行，原文一键。** 错误提示的正文只写两件事：发生了什么（拿不到什么、做不成什么）、用户下一步能做什么（重试、去哪改、不用管会自动重试）。原始报错收进一个次要按钮「复制报错信息」，点一下进剪贴板，再给一句「已复制报错信息」。这样正文可读，原文也没丢。

**分三种承载方式：**

页面级错误框（`.err-box`，占一块地方）——一句话 + 「复制报错信息」按钮。示例已经按这个做法在改稿拷贝里实现了，场景 `l-error` 可以点：一行「无法获取服务器列表，正在自动重试」，下面一个带复制图标的次要按钮。2026-11-12 文案收尾时改成了两行：「无法获取服务器列表」，下一行「正在自动重试」，这样结论后面才接得上后端的原句（主会话定的，作者可以否决，见 `01-补完口径.md`）。按钮的 `aria-label` 与可见文字一致。

限时的提示（toast，3.5 秒 / 出错 6.5 秒）——放不下多行，原文塞进去也看不完。建议正文只留一句中文结论，后面跟一个「详情」按钮，点了弹一个小对话框：对话框里是可选中、可直接复制的原文，加「复制报错信息」。多出来的这个「详情」是新增交互，作者 2026-11-11 定了加，见下文「已经定下的」第 1 条。

字段错误（表单里的 `.field-err`）——后端回的校验串本来就是中文（「服务器名称需为 1~40 个字符」），直接显示在字段下方就够，不加复制按钮。

**后端那些英文/内部串不翻译。** 它们出现在复制出来的文本里，改了反而对不上日志和代码。要改的是它们旁边的中文说明。

## 已经按这个做法改的地方

服务器列表页第 11、12 条。原始实现分别是 `<div class="err-box">${esc(e.message)}</div>` 和 `slot.textContent = "暂时无法获取后台任务，稍后自动重试：" + e.message`；改后是中文一句 + 复制按钮。

## 已经定下的

作者 2026-11-11 定：

1. toast 里的错误加「详情」按钮：正文一句中文结论，后面跟「详情」，点开一个小对话框，里面是可选中、可直接复制的原始报错，并有「复制报错信息」。对话框沿用现有 `confirmModal` 的样式，只留一个关闭键。
2. 错误 toast 的停留时间从 6.5 秒延长到 8 秒（普通提示仍是 3.5 秒）。实现位置在 `app.js:136` 的 `setTimeout(kill, isErr ? 6500 : 3500)`。
3. 「复制报错信息」用这个词，所有页面统一。
