# 拿到一个 .mdpack 之后怎么办

你收到了一个 `.mdpack` 文件。它是别人用 MineDeck 把一台 Minecraft 服务器打成的包：世界存档、每个人的进度、模组或插件、配置、白名单都在里面。把它导入自己的 MineDeck，就能在你的电脑上把这台服务器接着开起来，人物、家、装备都还在。

这份指南写给收包的人。打包的人怎么操作，见发布说明里「把服务器交给别人续服」一节。

## 先确认一件事：这个包是谁给的

包里的模组和插件是对方电脑上带过来的程序，服务器一启动，它们就会在你的电脑上运行。所以只导入你信得过的人给的包，来路不明的不要导。

MineDeck 在导入时会替你挡掉一些东西：包里夹带的启动配置不采用，原来的 JVM 参数、定时任务和崩溃自动重启不带过来，原来开着的 RCON（远程控制台）会先关掉。这些在导入完成后的日志里都会列出来，需要的话你自己再加回去。

## 第一步：准备好 MineDeck

还没有 MineDeck 的话，到[发布页](https://github.com/Trasperioooooon/MineDeck/releases)下载 `MineDeck.exe`，新建一个空文件夹（比如 `D:\MineDeck`）把它放进去，双击运行。Windows 弹出「已保护你的电脑」时，点「更多信息 → 仍要运行」，这是因为程序没有数字签名。第一次打开按引导走完就行，什么都不用改。

要能导入 `.mdpack`，MineDeck 要是 3.1.0 或更新的版本，3.1.0 的测试版也行。

## 第二步：导入

在左侧点「新建服务器」，选「导入交接包」这张卡片，然后选对方发给你的 `.mdpack`。文件不要解压，也不用改名。选完会自动上传，包大的话要等一会儿。

上传完，页面上会列出这个包里是什么，先核对一下：原来叫什么、是什么核心和版本、世界有多大、有多少个模组或插件、什么时候导出的。和对方说的对得上再往下走；对不上的包先别导。

接着填几项：

- 名称：这台服务器在你这边叫什么，默认和原来一样。
- 端口：默认沿用包里的。换了端口，旁边会提示这个端口现在有没有被占用。
- 内存：按原来分的填好了，可以调整。
- Java：一般不用改，默认和原来那台用的一样，电脑上没有会自动下载。
- 存放位置：默认放在 MineDeck 的服务器文件夹里。
- Minecraft EULA：包里原服主同意过的可以不勾，没同意过的要勾上才能导入。

点「导入交接包」，会转到任务页。不带核心的包这时要联网重新下载服务端核心，Forge 和 NeoForge 还要跑一遍官方安装器，可能要几分钟；带核心的包直接解开就行。进度走完，点页面下方的按钮就进入这台服务器。

## 第三步：开服，让大家进来

在服务器列表里点「启动」，控制台出现 `Done` 就是开好了。第一次启动可能要等一两分钟。

你自己进服，地址填 `127.0.0.1`；端口不是 25565 的话写成 `127.0.0.1:端口`。

朋友怎么进，分两种情况。和你在同一个网络里的（一个宿舍、一个家），用你这台电脑的局域网地址加端口进；Windows 防火墙第一次弹窗时选「允许访问」。不在同一个网络的，到左侧「内网穿透」加一条隧道，那里有一步一步的说明，拿到公网地址后发给大家。

白名单、正版验证这些设置和原来一样，照旧生效。

## 导入之后要知道的

导入是复制了一份。对方那边的服务器不受影响，他之后再怎么玩，也不会影响你这一份；你拿到的是他打包那一刻的进度。

下面这些不会跟着包过来，用得到的话要自己重新弄：

- 原来的 JVM 参数。比如原来用外置登录（authlib-injector），对应的 jar 和启动参数都要另外向对方要，在「内存 / 启动」里加回去。
- 定时任务和崩溃自动重启。
- 游戏内 AI、AI 伙伴和音乐共享，要在你这边重新打开。
- 服务器文件夹里交接范围之外的东西，比如地图插件在根目录生成的地图文件、对方自己放的文件。导入日志里会列出有哪些，需要的话让对方另外拷给你。

## 遇到问题

导入失败时，任务页会写原因，建到一半的文件夹会自动清理掉，可以直接重试。常见的几种：

- 说磁盘空间不够：换一个存放位置，或者腾出空间再试。
- 说交接包被改过或者坏了：让对方重新导出一份再发。传文件时用网盘或者压缩包，别让聊天软件「压缩图片」之类的功能碰它。
- 下载核心很慢或者失败：检查网络后重试；也可以让对方导出时勾上「完整模式」，把核心一起带上。
- 启动后报错：把控制台里报错的那一段和报错横幅截图发给对方。多半是 Java 版本或者某个模组的问题，可以先到「内存 / 启动」里换一个 Java 试试。

反馈问题时，说清楚这几样最有用：你做了什么、看到了什么、本来以为会怎样，再附上截图。
