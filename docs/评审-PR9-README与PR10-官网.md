## 一、PR #10 官网：界面与体验

### 怎么看的

把 `origin/website-a` 的 `website/` 放进一份 `origin/main` 的快照里，装上 fonttools 和 brotli 以后离线构建（字体子集化生效：像素字体 23 KB，Noto 188 KB），用自带的 `serve.mjs` 起本地服务，在浏览器里逐页看了中文和英文的首页、下载、功能、更新日志、单版本详情、帮助、反馈、关于和 404。宽度看了 1440、1200、1024 和 375，另外用脚本把 18 个页面在 375、560、768、900 四个宽度下各量了一遍有没有横向溢出。

有一件事没法在预览里判断：动效的节奏。预览面板每秒只渲染两三帧，首页那张「方块落下、终端打出 Done」的小卡片和各处热力图在截图里经常停在动画的第一帧（一片空白）。查过以后确认是预览面板掉帧，不是网站的问题，但动效实际的手感要在正常浏览器里再看一眼。真机、真实网络下的字体加载、关掉 JavaScript 的样子也都没有试。

### 总的印象

底子是好的。暖沙色底、草绿色、像素标题、粗边框加硬阴影，这套「方块工作台」的样子从头到尾是统一的，和程序本身的默认配色也对得上。响应式做得扎实：18 个页面在四个宽度下都没有横向溢出，表格到手机上会折成一条一条的卡片，版本详情页左边的版本列表到手机上变成下拉框。无障碍的基本功也在：有「跳到正文」，键盘焦点有 3 像素的绿色外框，图片都有替代文字，系统开了「减少动态效果」时动效全关。首页首屏加起来大约 430 KB，浏览器运行时不请求 GitHub。「最近一次发布：今天」这种相对时间是浏览器里现算的，不会过期。

问题主要在两处：页面上讲什么、先讲什么；还有一批上线前必须收掉的占位和细节。

### 上线前值得改的

**1. 首页没有讲出 MineDeck 和别的开服工具不一样的地方。**
首页「核心功能」的四张卡是一键开服、Java 与国内镜像、整合包导入、内网穿透，这四样别的开服工具也有。真正只有 MineDeck 有的东西（报错横幅、AI 助手、游戏内 AI、AI 伙伴、音乐共享、交接包）在首页一个字都没有，它们的截图只在功能页里以 237 像素宽的缩略图出现。与此同时，首页拿出一整屏放提交热力图、贡献者头像和「版本总数 13」「GitHub Star 16」。这些是给开发者看的，想给朋友开个服的人不关心。建议在四张卡后面加两三段「大截图加一句话」，把报错横幅和 AI 助手、游戏内 AI 和伙伴、音乐共享或交接包摆出来；热力图和贡献者往后挪，或者只留在关于页。Star 只有 16 的时候不如先不显示（`site.config.json` 里的 `stats.showStars`）。

**2. 首屏文案重复，而且没有给出理由。**
第一屏里「Windows」出现了四次（小标签、大标题、导语、按钮下面的小字）。导语「下载 Java 与服务端，在窗口里创建、导入并管理服务器」是在描述程序，不是在说为什么用它。main 上现在那份 README 的第一段反而写得更像样：一个文件、13 MB、不在同一个网络的朋友也能连进来。

**3. 功能页是 README 的搬运。**
16 节、81 条，写的是实现层面的事：「按工件上的 SHA-1、SHA-256 或 MD5 校验后原子写入」「Key 用 Windows DPAPI 加密保存」「优先读版本元数据里的 javaVersion」。导语里还写着「整理自仓库 README」（帮助页的导语也有这句，都该删）。来访的人是在这一页决定要不要下载的。建议每一节先用一句大白话说「能拿它做什么」，技术细节收进折叠块或者指回 README。截图现在是 237 像素的缩略图，点了以后整页跳到原图、没有返回入口，正文栏有将近 800 像素宽，直接放大图更好。左侧「本页目录」没有当前位置的高亮，功能页、帮助页、关于页都是这样。

**4. 下载页上测试版和稳定版一样显眼。**
两张卡并排，一样大，都是同样的绿色主按钮，测试版那张因为多了说明还更高一些。不留神的人会顺手下到测试版。测试版的按钮应该降成次要样式。下面「最近的版本」表格里又是五个带粗边框和阴影的「国内镜像下载」按钮，太重了，用文字链接就够。

**5. 下载主按钮指向的是占位地址，而且页面上有一句话说得不对。**
全站的主下载按钮（首页、下载页、每个版本页）都指向 `https://dl.minedeck.cn/releases/{tag}/{file}`，这个地址现在是占位。PR 描述里已经写明了这一点，这里要补的是两件事。一是下载页写着「镜像缺某个文件时，按钮会改指 GitHub」，代码里没有这回事：`website/lib/data.mjs` 第 44 行只在整个镜像关掉时才不生成镜像地址，没有逐个文件的判断，镜像上缺一个文件，那个主按钮就是死链。要么在构建时拿一份「镜像上实际有哪些文件」的清单来决定，要么把这句话改掉。二是「镜像地址目前是占位，上线前会替换」和页脚的「ICP 备案号：待填写　公安备案号：待填写」现在是直接显示给访客的。占位应该让正式构建失败，备案号没填就整行不显示。

**6. 手机上的主按钮是下载一个 Windows 程序。**
375 宽度下，首屏最大的按钮仍然是「下载 v3.0.0」，页头里还有一个。从 QQ、微信、B 站点进来的人多半在用手机，把 exe 下到手机上没有用，这些应用的内置浏览器通常也下不了。窄屏上更合适的是「请在电脑上打开 minedeck.cn」加一个复制链接，下载降为次要入口。

**7. 反馈页说「不需要 GitHub 账号」，实际上没有账号就交不出去。**
默认配置下只开了三个通道：复制报告、下载为 .md、去 GitHub 提 Issue。没有 GitHub 账号的人复制完报告无处可发。上线前至少要打开 QQ 群、邮箱、直接发送三者之一，否则这句导语要改。表单本身有两处可以顺手改：两栏并排的那几行，左边有提示小字、右边没有，右边的输入框因此低了大约 15 像素（「MineDeck 版本」对「Windows 版本」，「版本号」对「内存」）；一共十五个栏位偏长，可选的那些可以收进一个「更多信息」。日志自动脱敏、草稿存本地、右侧「日志在哪」这几样做得好，保留。

### 小一些的细节

- **小号主按钮的对比度不够。** 白字压在 `#5a9e36` 上是 3.29:1，14 像素的字需要 4.5:1。按钮底色换成 token 里现成的 `grass-700`（`#3f7a22`）是 5.2:1。首页那个大按钮字够大，不受影响。
- **等宽字体里的中文掉到了系统字体上。** `--font-mono` 是 `"MD Geist Mono", ui-monospace, Consolas, monospace`，里面没有中文字体，于是版本卡片上的「北京时间」、帮助页代码样式里的「这台电脑的局域网 IP:端口」会用系统的等宽中文字体，和旁边的字明显不是一套。在通用字体族前面加上 `"MD Noto Sans SC"` 和微软雅黑就好。
- **大标题的折行。** 英文首页的标题在 1024 到 1200 宽时折成三行（Run a Minecraft / server / on Windows），两个下载按钮也跟着上下叠放。中文标题在 1024 宽时会剩一个「台」字单独一行。给标题加 `text-wrap: balance`，或者中等宽度下把字号降一级。同一宽度下「v3.1.0-beta.3」在统计小卡里从中间断开。
- **手机上的排版。** 四张功能卡在 375 宽度下仍是两列，一行只有七八个字，560 以下改成单列更好读。可点区域偏小的有：菜单按钮 72×34、菜单里的链接高 38、语言切换 32×24，建议都到 44。
- **关于页的 52 周热力图**在桌面宽度下装不下，卡片里出了一条横向滚动条。格子缩小一点，或者少显示几周。
- **更新日志页的发布日历**没有月份标注；点了「测试版」筛选以后，日历上的点不跟着变。
- **截图都是 v2.9.0-beta.1 时拍的**（窗口角上有版本号），首页大图也是。上线前重拍，顺便补上交接包、购物车、待处理文件这几个新界面。
- **没有深色模式。** 系统是深色时网站仍然是浅色。程序本身七套配色都有深色，网站可以以后再补，不急。
- 「版本总数 13」「Star 16」这种很小的数字做从 0 数上来的动画意义不大，直接显示就行。

## 二、PR #9 README

### 怎么核对的

### 措辞和写法

**开头三段是写给审 PR 的人看的。** 第 18 行讲徽标指向哪个版本、`internal/app/app.go` 里写的是哪个版本号、和哪个标签是同一次提交；第 20 行还交代了一个远程分支上没有 `main` 尚未包含的提交。读 README 的人不需要这些，而且它已经不对了（见下一节）。这两段可以整段删掉，换成一句话：标了「测试版」的功能目前只在 3.1.0 测试版里。

**相对日期。** 第 307 行「今天发布的 v3.1.0-beta.1 和 v3.1.0-beta.2」，第 361 行的小标题「稳定版和今天的两个测试版怎么选？」。「今天」第二天就不对了。

**功能介绍里夹着源码路径和函数名。** 「注册表在 `internal/mcsrc/registry.go`」（第 28 行，「注册表」还和第 61 行说的 Windows 注册表撞了词）、`FloorVersion`（45）、`staticJavaFor`（49）、「`internal/web/ui/app.js` 里对应复选框的初始状态」（69）、「代码里没有给它们配 BMCLAPI」（73）、「代码里的服务商 ID 是 `natfrp`」（168），第 146、211、223、237、285 行也各有一处。这些是作者给自己留的出处，应该从正文里拿掉。

**丢了原来那段像样的开场。** main 上现在的 README 第一段用几句话说清了这是什么、为什么省事（一个文件、大约 13 MB、整合包直接导入、不在一个网络的朋友也能连），紧接着就是主界面截图。新版把它换成了一句干巴巴的定义加上面那三段，截图被压到第 289 行以后，前面是 265 行条目。标题里的「我的世界一键开服工具」也没了，这是别人搜得到这个仓库的关键词。

**整体是清点，不是介绍。** 功能一节把实现细节和用户关心的事摆在同一层：下载后「原子写入」、启动时从环境里去掉哪六个变量、Java 与 frpc 放进同一个 Job、音频「48 kHz、16 位、单声道，每 20 毫秒一帧」。这些没有错，但用户不靠它们决定用不用。建议 README 保留旧版那种粒度的功能概览（一项功能一两句大白话），把这份完整清单另存成 `docs/功能清单.md` 之类的文件，README 里链过去。这样两头都不丢。

**Beta 标注太碎。** 现在正文里散着 15 处「（Beta，v3.1.0-beta.N）」，其中有几处标的是修复而不是功能（比如「换了一个交接包文件时，上一份的摘要会清掉」），这种不该出现在 README 里。等 3.1.0 正式发布，这 15 处要一处一处删。更省事的写法是单独一小节「3.1.0 测试版里新增的」，列出交接包、购物车、整合包待处理文件、接管已有服务器、界面换 Java 这五样，正文里不再逐条打标。

**截图说明里的内部备注。** 「窗口角落的版本号是拍摄时的 v2.9.0-beta.1，画面不包括……」和后面那条 HTML 的 TODO 注释，是给维护的人看的。

### 缺了什么

**beta.3 的全部内容。** 接管现在只登记被接管的那一个文件夹；用 beta.1、beta.2 接管过的人，配置里还留着上一层目录，旁边的服务器会继续出现，要照发布说明里的两个办法手动清；接管来的服务器和存放目录里的服务器重名时只显示一台。

**交接包对收包人的安全提醒。** 第 118 行提醒了打包的人「密码会在包里」，没有提醒收包的人：包里的模组和插件是对方电脑上带来的程序，会在你的电脑上运行，只导入信得过的人给的包。界面上和 beta.1 的发布说明里都有这句。另外包里还会带上封禁名单（含 IP 地址）和代理端的转发密钥，隐私提醒里没列。

**测试版可以直接升到正式版。** README 三处都只说了「稳定版收不到测试版」「测试版之间不互升」，没说装了测试版的人到时能在设置里直接更新到 v3.1.0。代码和发布说明都是这样。

**发布说明里的几条已知情况。** 存档超过 8 GB 的服务器走不了交接包，要拷文件夹再用「接管」；CurseForge 上的整合包多数是给客户端的，导入成功、一开就崩，应该下作者的 Server Pack 再接管；待处理的文件要在这次运行里处理完，重启后只剩两个文本清单；信任过的站点在界面上取消不了，只能改 `config.json`；清单里的数据包不会自己生效；向导里的草稿购物车不记是给哪种核心挑的。

**备份的范围。** 备份只包含世界目录，不含 mods、config 和插件数据。还原前会自动再备份一份，这一份也算进保留份数。

**几条和隐私、费用有关的行为。** 每次开服后第一次有人向游戏内 AI 提问时，会向全服广播一句「向 AI 提的问题会发给某某处理」；局域网里的设备默认可以用应用内助手，花的是房主的额度；用自定义地址走中转时，中转方看得到全部对话和 Key。

**接管时带不过来的启动参数。** 原来启动脚本里的 `-javaagent`、`-D`、`-XX` 这些不会带过来（只在识别页提示），外置登录这类靠 `-javaagent` 的服务器接管以后会失效。README 只提了 `user_jvm_args.txt`。

**旧 README 里有、新版丢了的。** 除了上面说的开场和首图，还有 MCP 能接哪些工具（Claude Desktop、Cherry Studio、Cursor、VS Code）、对伙伴说话的例子（「@伙伴名 跟着我」「砍 10 个橡木原木」）、「手机上也能管服务器」这个用法。
