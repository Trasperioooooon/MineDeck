# MineDeck 功能清单

这份清单把 MineDeck 能做的事逐项写下来，给想查细节的人看。只想知道它是什么、怎么装，看仓库首页的 [README](../README.md) 就够了。

这份清单按 v3.1.2 写。每个版本具体改了什么，看 [`docs/releases/`](releases/) 里的发布说明。

界面文字是中文。程序只提供 Windows 构建。

## 服务端核心

一共 12 种：

- Vanilla：Mojang 官方服务端。
- Paper：插件服务端。版本与构建来自 PaperMC Fill v3（`fill.papermc.io`）。
- Purpur：Paper 的分支。版本与构建来自 `api.purpurmc.org`。
- Leaves：Paper 的分支，面向原版特性。版本与构建来自 Leaves 自己的 API。
- Folia：Paper 的多线程分支。与 Paper 一样走 Fill v3。
- Fabric：模组加载器。版本、Loader 和安装器来自 Fabric Meta；有 BMCLAPI 镜像。
- NeoForge：1.20.2 及以后的模组加载器。安装走官方安装器，镜像用 BMCLAPI。
- Forge：模组加载器。安装走官方安装器，镜像用 BMCLAPI。
- Mohist：Forge 与 Bukkit 插件同服。版本与构建来自 MohistMC API。
- Banner：Fabric 与 Bukkit 插件同服，同一套 MohistMC API。
- Velocity：群组代理。Java 固定为 21。版本号是 Velocity 自己的，不是 Minecraft 版本号。走 Fill v3。
- Waterfall：BungeeCord 分支的群组代理。Java 固定为 17。走 Fill v3。

代理端没有 EULA，也没有 `server.properties`。新建向导把这 12 种分成五组显示：原版、插件服、模组服、混合服（模组加插件）、群组代理。

支持的 Minecraft 版本从 1.12.2 起，包括按年份编号的 26.x。各核心能选哪些版本，以该核心自己的版本清单为准。NeoForge 是例外：它列出的是 Mojang 清单里 1.20.2 及以后的正式版，某个版本还没有 NeoForge 构建时，要到选构建那一步才会提示。清单里带发布时间的，界面会带上这份时间。

Mohist 和 Banner 要求服务器所在的路径不含中文等非英文字符，新建和接管时都会检查。

## 版本与 Java

创建时用的 Java 大版本，优先读该版本元数据里的 `javaVersion`。元数据里没有这个字段时，用下面这张对照表：

| Minecraft 版本 | Java |
| --- | --- |
| 1.17 以前（含 1.12.2） | 8 |
| 1.17.x | 16 |
| 1.18 至 1.20.4 | 17 |
| 1.20.5 至 1.21.x | 21 |
| 26.1 及以后 | 25 |

Velocity 固定 Java 21，Waterfall 固定 Java 17，不按上表。

- 启动时在后台扫描本机已安装的 Java：注册表、`JAVA_HOME`、`PATH` 和常见安装目录。版本对得上就直接用。
- 本机没有合适的版本时，下载一份只给 MineDeck 用的运行时，放到程序目录的 `runtimes/java-{大版本}/`，不改系统环境变量。
- Java 的下载顺序：清华 TUNA 的 Adoptium 镜像，然后 Adoptium 官方 API，然后 Mojang 官方运行时（经 BMCLAPI 镜像，按文件下载）。前两级的地址是固定的，不受「下载源」设置影响，选了「官方」也先连清华镜像。
- 可以在「设置 → Java 运行时」里重新扫描，或指定一个本机的 `java.exe` 做版本探测后加入列表。指定路径只接受本机请求。
- 每台服务器的「内存 / 启动」里可以换 Java：MineDeck 下载的、本机已有的，或现下载一个。整合包里的模组声明了更高的 Java 时，导入完成页和服务器详情会提示，并给出换 Java 的入口。这只是提示，不阻止启动。

## 创建与安装

「新建服务器」页有四种方式，分两组：新建（从零创建、导入整合包），导入与接管（导入交接包、接管已有服务器）。还没有服务器时，首页的「从零创建」直接进向导，核心由自己选。

新建服务器的向导：选核心、选版本、选构建、内存、端口、难度、游戏模式、EULA。正版验证默认关着，允许飞行默认开着。非原版核心在「基本设置」之前多一步可选的「选模组」（插件端叫「选插件」），见下面的待装清单。

- 下载文件时按源依次尝试，整体最多 3 轮，轮与轮之间退避；某个源 90 秒收不到新数据就换下一个。下完按工件上的 SHA-1、SHA-256 或 MD5 校验，再原子写入。取版本清单和构建列表走的是另一条路径，最多 2 轮。
- Mojang 的版本清单和服务端，镜像优先（BMCLAPI），镜像不可用再走官方。下载源策略可以在「设置 → 下载与网络」里选自动、镜像或官方。
- Paper、Purpur、Leaves、Folia、Mohist、Banner、Velocity、Waterfall 的清单和文件走各自的官方地址，没有国内镜像。
- Forge、NeoForge 安装器带 `--mirror` 指向 BMCLAPI（下载源设成「官方」时不带）。NeoForge 和 1.17 以前的 Forge 会事先放好原版服务端，免得安装器自己去连 Mojang。安装器失败会再试，最多 3 次。
- 旧版 Forge 安装器在自己的联网检查失败时可能什么都没装却返回成功。这种半截安装记为这一次失败，继续重试。新建旧版 Forge 服务器和导入交接包都会走这条路径。
- 低于 1.18.1 的实例会加上 log4shell 的 `noLookups` 参数。1.12.2 至 1.16.5 另下一份官方的 log4j XML。之后在「内存 / 启动」里改 JVM 参数，这两项缺了会补回去；那份 XML 文件已经不在的话，只补前一项。代理端不加这两项。
- 启动 Java 和 frpc 时会从环境里去掉 `JAVA_HOME`、`JAVA_OPTS`、`JAVA_TOOL_OPTIONS`、`_JAVA_OPTIONS`、`JDK_JAVA_OPTIONS`、`CLASSPATH`。
- 每个实例目录里有一份与界面等效的 `run.bat`。
- 启动前按服务器真正要绑的地址（`server.properties` 里的 `server-ip` 和 `server-port`）照服务端的办法试绑一次，端口被占着就直接提示，不起服务器（代理端的端口写在它自己的配置文件里，不做这项检查；`server-port` 写 0 的也不查；JVM 参数里打开了 `java.net.preferIPv4Stack` 的只按 IPv4 查）。崩溃自动重启、定时重启和「重启」碰上端口还没放开，会先等几秒。停止时先发 `stop`，约 30 秒还没退出就强制结束。退出 MineDeck 时，正在跑的服务器和隧道会一起停。Java 与 frpc 放进同一个 Job，避免程序退出后进程留下来。
- 玩家或控制台输入的 `stop` 关服，不算崩溃，也不会触发崩溃重启。
- 部署过程中某个源超时或失败，任务快照会带上最近一次的主机名、原因和大约多久以前。进度或日志约 30 秒没有变化时，部署页会提示下载慢或正在重试。
- 任务日志过长时，开头的 40 行会留着，中间省略了多少行会标出来。新建、整合包导入和交接包导入都是这样，免得安装器的输出把开头的说明挤掉。

## 整合包导入

- Modrinth 的 `.mrpack` 可以直接导入。核心、版本和加载器从包里识别。只给客户端用的文件会跳过。
- CurseForge 的 zip 可以导入。自动下载包里的文件需要自己的 CurseForge API Key；没填 Key 时照常导入，那些文件要自己补：它们列进下面说的「待决文件」，也写进服务器文件夹里的「未解析模组清单.txt」。Key 用 Windows DPAPI 加密存在程序目录的 `secrets.json`，界面和 API 都不把明文发回去。
- 上传上限 4 GiB。选中的文件超过上限时，在上传前说明，并给出上限。
- CurseForge 清单里的文件按站点上的类别放置：模组进 `mods`，资源包进 `resourcepacks`，光影进 `shaderpacks`，数据包进 `datapacks`。文件名只认单独一个文件名，带路径的不用。数据包放进 `datapacks` 以后不会自己生效，程序不去动存档里的数据包设置。
- 下载地址不在允许的站点里、缺少校验值、不是 https、校验对不上，或 CurseForge 没能解析的文件，不会让整个导入失败。这些文件列在任务页的「待决文件」里，可以逐个：
  - 跳过；
  - 用本地文件或文件夹原样复制进去，不校验内容；
  - 对 https 的公网地址，看过风险说明并确认后下载。内容必须对上包里的校验值。确认过的主机名记在配置的 `trustedHosts` 里，范围是 `modpack`，之后同一主机不再逐次确认。界面上没有取消信任的地方，要取消得手动改 `config.json`。
- 待处理的文件要在这次运行里处理完。关掉 MineDeck 再打开，任务页上的清单就没有了，只剩服务器文件夹里的「导入待决清单.txt」和「未解析模组清单.txt」，要自己照着把文件放进去。因为网络问题下载不下来的文件不在此列：那种情况整次导入仍然失败，重试一次即可，已经下好的有缓存。
- 导入表单可以填「本地来源文件夹」。待处理文件若在这个文件夹里已有对应文件，按原样保留。CurseForge 的待处理项带有文件名、项目名和它在 CurseForge 网站上的下载页，同名文件也能从这个文件夹自动补上。
- 下载走受控客户端：直连时每个解析出的 IP 在连接前要是公网地址；环境里配了代理时按主机名检查，本机和内网名字不连。跳转只跟 https，最多 10 次。
- 整合包覆盖目录或本地来源文件夹里按原样留下的文件，会在任务告警里列出来，并标明未校验。
- 清单可以在压缩包最外层，也可以只套一层文件夹（`整合包名/manifest.json`）。两处都有清单、或者同一层里两种清单都在时不猜，报错说明。
- 作者给的现成服务端压缩包也能在这里导入：没有整合包清单，但有 mods、plugins、server.properties 或服务端 jar（同样可以套一层文件夹）。直接解压成一台新服务器，不重新下载核心，所以核心要已经在包里：Forge、NeoForge 带着装好以后的 libraries 文件夹，Fabric、Paper、原版等带着服务端 jar。核心和版本按「接管已有服务器」的办法识别，认不出时说明缺什么。只带启动脚本（或者再加一个加载器安装器）、第一次运行脚本才装加载器的 Server Pack 认不出来，接管也认不出，要先解压、运行包里的脚本把加载器装好再接管。压缩包里已有 server.properties 时只改端口，正版验证和允许飞行沿用包里的；1.12 到 1.16.5 的和新建一样加 log4shell 防护。包里的 `instance.json`、`run.bat` 不采用，只写在原来启动脚本或 `user_jvm_args.txt` 里的 JVM 参数不会带过来。解压出来的服务器算新建的，删除时文件夹一起删。暂不支持 Quilt。
- 包里名字在 Windows 上不能原样用的文件不收：`CON.txt`、`COM1.log` 这类设备名（带不带扩展名都算），结尾是点或空格的，带 `< > " | ? *` 的。只差大小写的两个文件在 Windows 上是同一个：现成服务端压缩包留前一个；整合包的覆盖目录以后写的为准（`server-overrides` 本来就要盖掉 `overrides`）；清单里只差大小写的落点只下载第一个。这些都写进任务日志。
- CurseForge 上的整合包多数是给客户端用的，里面常有只能装在客户端的模组，照清单装出来的服务器会一开就崩。导入时不会提醒这一点；崩了以后，报错横幅能认出「客户端模组放进了服务端」。大型整合包的作者一般另外提供 Server Pack：下载那个，带着装好的加载器的，可以直接在「导入整合包」里导入，或者解压以后用「接管已有服务器」收进来；只带启动脚本的，先解压、运行脚本把加载器装好，再接管。

## 接管已有服务器

在「新建服务器」里选择一个已有的服务器文件夹。程序只读地识别核心、版本、构建、启动文件、原来的内存和端口，再就地登记成实例。文件留在原地。

- 会写入 `instance.json`。原来有 `run.bat` 时先另存为 `run.before-minedeck.bat`（备份已存在则不覆盖）。Forge / NeoForge 的 `user_jvm_args.txt` 同样先备份，除内存以外的 JVM 参数带到实例的额外参数里；带空格的参数带不过来，识别页会提示有几个。原来启动脚本里另外写的 JVM 参数不会自动带过来，识别页同样会提示，需要的话（比如外置登录用的 `-javaagent`），接管后在「内存 / 启动」里补上。
- 原来没同意 EULA 时，要在表单里勾选才会写 `eula.txt`。1.12.2 至 1.16.5 会放上与新建时相同的 log4shell 日志配置。
- 任务失败时，这次动过的文件恢复原样。
- 会拒绝：整个磁盘、MineDeck 程序目录及其上层、缓存和运行时目录、与备份目录重叠的文件夹、服务器总目录、已经在列表里或正在创建 / 接管的目录（含其上下层）。比较前会解开目录联接和符号链接。
- 文件夹里找不到能启动的文件时拒绝。下一层有像服务器的文件夹时，错误信息里会点名。
- 删除服务器时可以不删文件夹，只从列表移出，并把 `instance.json` 改名为 `instance.json.bak`。之后可以再次接管，原来的设置从 `.bak` 带回。
- 接管只登记被接管的这一个文件夹，同一层里别的服务器不会跟着出现在列表里。文件夹暂时不在（比如放在没插上的移动硬盘里）时，这台服务器这次不显示，文件夹回来以后照样在。
- 用 v3.1.0-beta.1 或 beta.2 接管过服务器的人要注意：那两版记下的是上一层目录，升级以后那一层里别的服务器仍会出现在列表里，程序没法替你清。处理办法见 [v3.1.0-beta.3 的发布说明](releases/v3.1.0-beta.3.md)。
- 接管进来的服务器和存放目录里的服务器重名时，列表里只显示存放目录里的那一台。接管时会查重名，一般碰不到。

## 交接包

服务器停着的时候，可以在卡片菜单里把一台服务器打成 `.mdpack`，交给另一台电脑上的 MineDeck。

- 两种用途，包里的文件相同，对方看到的说明不同：`handover`（交给下一任服主，默认）和 `distributable`（发给朋友，让他照着开一台）。
- 默认不带服务端核心，导入时重新下载。勾上完整模式则连核心一起打包。
- 包里有：存档（含多世界插件的其他世界）、`server.properties`、核心自己的配置（如 `spigot.yml`、`bukkit.yml`、`paper.yml`）、`mods`、`plugins`、`config`、`kubejs`、`scripts`、白名单、管理员名单和封禁名单、服务器图标、已经同意过的 `eula.txt`。代理端带它自己的配置，其中包括 Velocity 的转发密钥 `forwarding.secret`。
- 包里没有：日志、崩溃报告。默认也不含服务端核心。清单以外的文件（例如地图插件在根目录生成的瓦片）不带，打包日志里会列出来，最多列 30 项。
- 名字在别的 Windows 上不能原样用的文件（`CON.txt` 这类设备名，结尾是点或空格的）不进包，写进剔除清单。只差大小写、却真是两个文件的（开了「区分大小写」的文件夹里才有）只带先找到的那个，另一个也写进剔除清单。导入时包里有这类名字，或者有两个只差大小写、内容又不一样的文件，整个包不收；内容一样的只取一个。
- 原来的 JVM 参数、定时任务、崩溃自动重启、游戏内 AI、AI 伙伴和音乐共享不会带过去。原来开着的 RCON 会先关掉。导入日志里会列出原来的 JVM 参数，并说明定时任务和崩溃自动重启没有带过来；游戏内 AI、AI 伙伴和音乐共享要在收包的电脑上重新打开。
- 给打包的人：配置文件原样进入包，其中的密码（RCON、数据库、机器人令牌等）也会在里面，在别处也用着的先改掉再交。包里有玩家存档、白名单、管理员名单和封禁名单（封禁名单里有 IP 地址），交之前先和服里的人说一声。
- 给收包的人：包里的模组和插件（完整模式下还有核心）是从对方电脑上带来的程序，启动服务器时会在你的电脑上运行。只导入信得过的人给的包。
- 导入在「新建服务器 → 导入交接包」。填写名称和端口。不带核心的包，核心在收包这台电脑上重新下载、重新安装；完整模式的包直接用包里的核心和依赖库。Java 在这台电脑上重新准备，默认沿用原来那台的大版本，可以改。包里已经同意过 EULA 的，可以不再勾。
- 上传上限 8 GiB，超过时在上传前说明。存档超过这个数的服务器，把整个文件夹拷到另一台电脑上，用「接管已有服务器」收进来。
- 打包或导入进行中，这台服务器不能启动，也不能删除。导入被打断（关程序、断电）时，建到一半的文件夹会留在存放位置里，不在服务器列表中，可以直接删掉。
- 给收包的人有一份说明：[接收者上手指南](接收者上手指南.md)。

## 模组、插件与待装清单

非原版实例有「资源」标签：按当前核心在 Modrinth 上搜索，安装到 `mods` 或 `plugins`。模组还会按 Minecraft 版本过滤，插件不卡版本。

查看实例里的模组清单、按文件启用或禁用（禁用是改扩展名）、读取和修改模组的配置文件，这几样在界面上没有单独的入口，是给应用内助手、MCP 工具和本地 API 用的。助手和 MCP 发起的修改要先在 MineDeck 里确认。配置文件的真实落点（解开目录联接、符号链接以后）必须还在服务器文件夹里，查不清的不读也不改；用目录联接把 config 挪到别的盘的，那些配置要直接去文件夹里改。

另有待装清单（以前叫「购物车」），和「资源」页是两条路径：

- 新建向导里，非原版核心多一步「选模组」（Paper 一系和代理端叫「选插件」），可以留空跳过。原版以外的服务器（包括代理端）详情里都有「待装清单」标签。原版没有这一步，也没有这个标签。
- 一打开就列出当前核心（模组还按版本）下最热门的，按下载量排，一页 20 个，最多翻到第 100 个；可以按类别筛，也可以搜关键词。数据来自 Modrinth，插件不卡版本，和资源页一样。只在客户端用的模组不会列出来。热门清单加载慢或者加载失败，不影响向导往下走。
- 挑中的放进待装清单。服务器里已经有的不重复装。下载后对 Modrinth 给出的校验值。
- 自己下载好的 jar 可以「从电脑添加」（也可以拖进清单区），和 Modrinth 上挑的列在同一张清单里，两样合计最多 50 项，单个文件最大 256 MB。文件先暂存在程序目录的 `data/modcart/local` 下，安装时拷进服务器的 `mods` 或 `plugins`。服务器里已经有同名但内容不同的文件时不覆盖，任务页会说明。添加本地文件只有人在界面上能做（局域网里用手机打开界面也可以），应用内助手和 MCP 客户端做不了，它们只看得到文件名。
- 本地文件加进来以后自动查一次前置。在 Modrinth 上认得出的文件（按文件内容的哈希认），它缺的必装前置会和别的一起补上；认不出的（别处下载的、改过的），只能按 jar 自己写的依赖报出还缺哪些模组，这些要自己去找。加载器对不上的文件会有提醒，不拦。
- 可以检查前置。必装前置会列出来；不检查也会在安装时一并装上。一次能带出多少前置没有上限，前置很多的模组，检查前置和安装会慢一些。
- 向导里挑的内容放在一张「草稿」清单里，它不记是给哪种核心挑的。挑完以后回头换了核心，或者上次挑完没建成服，下次建服时这些模组可能装不上，任务页会写「找不到能装的版本」，到新服务器的「待装清单」标签里重新挑就行。
- 向导里挑好的内容，在服务器建好以后安装。安装前如果草稿清单和当时看到的不一致（例如助手又加了项目，或者里面有上次没装完留下的本地文件），安装会被拦住，先看当前清单。
- 应用内助手可以搜索并加入待装清单。真正安装时只生成确认卡片，列出要下载的文件和要拷进去的本地文件，确认后才写进服务器。

## 运行、控制台与配置

实例详情的标签，按核心显示：控制台；非代理端还有玩家、备份；定时任务；非原版有资源；符合条件时有待装清单、音乐共享、游戏内 AI、伙伴；非代理端有常用设置和全部配置；最后是内存 / 启动。

- 控制台经 SSE 推送，先回放再实时。可以在 GBK 和 UTF-8 之间切换。警告和错误着色。日志可过滤。命令有历史。常用命令和在线玩家名可以用 Tab 补全。
- 服务器控制台输出默认使用 UTF-8。手动选了 GBK 的实例保持 GBK。
- MOTD 可以选颜色并预览。中文和表情符号按游戏要求的格式写入。
- 「常用设置」把 `server.properties` 里的 78 项分成 7 组：基础与玩法、世界生成、玩家与权限、性能、网络与远程管理、资源包、安全与杂项。每项有中文名、说明和是否要重启。当前游戏版本用不到的项会隐藏。
- 「全部配置」把 `server.properties` 里现有的键值逐行列出来，认识的键附中文名，可以按中文名或键名搜索。
- Minecraft 1.21.9 及以后，「常用设置」里已经改成游戏规则的项（例如 PVP、命令方块、生成怪物）是开关：服务器开着的时候切换，立即生效，不必重启；服务器停着时不能切。
- `level-name` 写成指向服务器文件夹以外的路径时，备份和还原按默认的 `world` 处理。v3.0.0 会跟着这个路径走，还原时可能删到别的文件夹。
- 「内存 / 启动」里内存用滑块和数字框，下限 1024 MB，并对照本机物理内存（新建向导里的下限是 512 MB）。可以另加一行一条的 JVM 参数。
- 打开目录时可以进实例根目录，或 `mods`、`plugins`、`world`、`logs`、`crash-reports`。这几项只接受本机请求。

## 玩家

- 查看在线玩家，以及白名单、管理员、封禁三份名单。
- 加入或移出白名单；设为 OP 或取消；踢出；封禁或解除封禁。
- 服务器开着时走控制台命令。关着时直接改名单文件。踢人要求服务器正在运行。

## 备份、崩溃重启与定时任务

- 可以立即备份、还原、删除。服务器开着时也能备份。备份的只是世界目录，不包括模组、插件和配置。还原要先停服，还原之前会自动把当前的世界再备份一份。
- 默认每台服务器保留 10 份，可在 1 到 1000 之间改。这个份数是全局设置，改了所有服务器一起变。新备份写当前备份根。列表、还原和删除也查找内置根和改目录之前用过的旧根。同名文件视为同一份。只接受 `.zip` 文件名。
- 崩溃自动重启默认关着。打开以后按 10 秒、30 秒、60 秒退避，连续 3 次仍起不来就停止。这次运行若已超过 10 分钟，计数先清零再计这一次。期间如果有人手动启动或停止，这次自动重启取消。
- 定时任务每天在一个 `HH:MM` 执行：重启、一条控制台命令，或备份。没补零的时间会规整成 `HH:MM`。

## 内网穿透

- 三种：OpenFrp、樱花穿透、自己的 frps。
- OpenFrp 和自定义 frps 用的 frpc 会自动下载到 `runtimes/frpc/`。OpenFrp 的下载源会把一般程序的下载请求当成机器人拦掉（HTTP 567），3.1.2 起这一处下载只用 TLS 1.3 握手来过这一关；哪天又被拦了，报错里会写手动的办法：自己下载 `frpc_windows_amd64.zip`，把里面的 exe 放进 `runtimes/frpc/openfrp/`。樱花穿透的 frpc 要自己下：第一次用时程序会提示去樱花的管理面板下载 Windows 版 frpc，放进它指给你的目录，只需要做一次。凭据用 DPAPI 加密写在 `tunnels.json`，响应里不带回明文。自定义 frps 的 token 经环境变量交给 frpc，不写进配置文件。OpenFrp 和樱花的 frpc 仍从命令行参数接收凭据。
- 用途分游戏和语音。语音隧道的公网地址会写入所绑定实例的 `voice_host`。自定义 frps 可选 TCP 或 UDP；樱花和 OpenFrp 的协议在服务商后台决定。
- 可以绑定到某台服务器，并设成跟随该服务器启动。服务器崩溃后自动再启动时，跟随的隧道会再起来；服务器停下约 5 秒还没再开，隧道才停。
- 页面上可以复制公网地址。有域名时优先显示域名。启动失败的原因写在隧道卡片上，包括凭据解不开（换过电脑或 Windows 用户时需要重填）。
- 存过 token 的自定义 frps 隧道，卡片上有「清除凭据」，清掉以后启动不带 token。OpenFrp 和樱花的隧道启动时必须带凭据，不能清。界面上没有修改隧道的地方，要改别的就删掉重建。
- frpc 的日志经 SSE 查看。
- 平台账户：OpenFrp 用浏览器远程授权连接，不收账号密码；樱花粘贴访问密钥连接。连上以后能看账户、流量和平台上的隧道（概览缓存 30 秒），能在平台上新建 TCP / UDP 隧道并导入，也能导入已有的隧道。OpenFrp 的隧道名只能用英文字母、数字、下划线和连字符。樱花建隧道时可以勾「这是公开服务器」，勾了只列公开服专用节点（名称含「多线」或带公开游戏标记），这是樱花的规定，用错节点会被封号。签到和购买只打开官网，不代签、不代下单。平台凭据用 DPAPI 加密存在 `secrets.json`，界面上拿不到明文；连接、断开、概览、创建和导入只能在本机做，局域网里打开时账户区只读。断开账户只清 `secrets.json` 里的凭据，已导入的隧道不动。OpenFrp 部分使用 OpenFrp OPENAPI，界面和 README 上注明了社区开发声明。

## 窗口、托盘与外观

- 界面是内嵌网页，放在 WebView2 窗口里。没有 WebView2 时，用系统默认浏览器打开本机地址。
- 窗口版里点外部链接（EULA、申请 CurseForge Key、openfrp.net、AI 回答里的链接等），左键、Ctrl / Shift 点、中键和回车都交给系统默认浏览器打开，用得上自己浏览器里的密码管理器和登录状态。MineDeck 自己的页面照旧在窗口里开。
- 窗口版里把文件或链接拖到没地方接的位置，页面一律不让放，松手没有反应，WebView2 不会另开小窗把那个文件或网页打开。待装清单的「从电脑添加」照旧能把 jar 拖进去，输入框照旧能拖进文字。
- 默认端口 27333。被占用时改用随机端口。窗口标题是「MineDeck · MC 一键开服」。
- 7 套配色：方块（默认）、Fluent、GitHub、石墨、Nord、Catppuccin、Solarized。每套可以浅色、深色或跟随系统。强调色 8 种（蓝、靛蓝、紫、青、绿、橙、玫红、石墨），或跟随方案。外观存在本机 `localStorage`，局域网另一台设备可以各自记忆。
- 字体打进程序：Geist、Geist Mono、Noto Sans SC 的子集。子集以外的字由系统字体补。
- 12 种核心各有像素头像。
- 冷启动时窗口底色取标题栏色，并有启动画面。原生窗口会把当前标题栏色存进配置，下次启动在页面画出来之前使用。
- 高 DPI 下声明 DPI 感知，窗口尺寸按系统缩放。窗口最小 1024×576（按缩放比例放大，屏幕放不下时以屏幕为准），不能再拖得更小；宽高比不锁。
- 可以关掉窗口时缩到托盘，服务器继续运行。托盘菜单有「打开 MineDeck」，以及「全部停止并退出」。有服务器在跑、又没开「最小化到托盘」时，关窗口会先询问。
- 可以开机自启（当前用户的 `HKCU\...\Run`，不需要管理员）。自启时带 `-minimized`，进托盘且不激活前台窗口。从旧名 AutoMCHUB 留下的自启项会删掉。
- 第一次打开有引导，并要同意用户协议与免责声明。
- 把图片放进程序旁边的 `bg` 文件夹，可以作为界面背景。
- 服务器和备份的存放根可以改到别的盘，用系统的选择文件夹窗口（资源管理器那种带地址栏的新式窗口）。改根时旧根仍会被扫描。多个根都会认到。
- 实例显示名里的空格和点会变成连字符，只保留 ASCII 字母、数字、连字符和下划线。没有这些字符时，目录名是 `server-` 加上创建时间。
- 后台任务在切页或刷新后仍能从任务列表回到进度。列表只给摘要；步骤和日志要再查单个任务。程序重启后，这次运行的任务记录清空。
- WebView2 窗口不显示左下角的链接状态栏。
- 双击标题栏可以最大化或还原。
- 用手机浏览器打开局域网页面时，底部避开浏览器工具栏和安全区；横持也用手机布局。

## 局域网、API、Webhook 与更新

- 「允许局域网访问」要先设访问密码。密码在服务端存成 bcrypt（旧的 SHA-256 十六进制在登录成功后升级）。监听地址只在启动时绑定：打开后要重启才从 `127.0.0.1` 改到 `0.0.0.0`；关掉立即生效。关掉或更换密码后，已有的局域网会话失效。
- 本机请求带启动 URL 里的 `token`，请求头 `X-Token`。局域网用 `POST /api/login` 换会话 Cookie。
- 选择文件夹、打开资源管理器、添加本机 Java、AI 设置的修改，只接受本机请求；接管和待处理文件也是。局域网会话不能指定实例或备份的存放路径。
- 本地 HTTP API 的路径、字段和限制写在 [docs/API.md](API.md)。控制台和 frpc 日志是 SSE。
- 可以填一个 Webhook URL。进程内事件会推出去，类型包括 `instance.start`、`instance.stop`、`instance.crash`、`player.join`、`player.leave`、`backup.done`、`tunnel.up`、`tunnel.down`。局域网登录的设备只看到地址的开头（协议和主机），后面常带着令牌的部分藏起来，要改就把整个地址重填一遍。
- 更新默认仓库是 `Trasperioooooon/MineDeck`，可以改。在「设置 → 更新与关于」里检查并应用，应用更新会下载新版本并重启。更新之前要先停掉所有服务器，有服务器在跑时程序会拒绝更新。换程序的是旧版本自己写出的更新脚本：3.1.1 起它不受中文路径、开机自启时的当前目录和 PATH 里同名程序的影响，3.1.0 及以前的会受影响，处理办法见 [v3.1.1 的发布说明](releases/v3.1.1.md)。「启动时静默检查更新」的结果目前只写进程序的日志输出，界面上不提示，想知道有没有新版本还是得到设置里点一下检查。
- 下载新版本的 exe 时先试 `ghfast.top`、`gh-proxy.com`，再直连 GitHub，下完要与发布页上的 SHA-256 一致。检查更新本身是直连 GitHub 的，连不上时检查会失败。自定义 frps 用的 frp 同样校验 SHA-256；OpenFrp 的 frpc 从 OpenFrp 自己的下载源取，不做这项校验。
- 正在使用稳定版时，不会收到预发布版的更新提示。预发布版之间也不会自动互升，需要手动替换 `MineDeck.exe`。装着测试版的人，等同一版号的正式版发布以后，可以在设置里直接更新过去。

## AI 接入

AI 是可选项。设置里没填服务商和 Key 时，程序不连接 AI 服务，也不为费用估算去下载价格数据。

- 两种协议：OpenAI 兼容的 Chat Completions，以及 Claude 的 Messages。
- 七个预设：DeepSeek、通义千问（阿里云百炼）、Kimi（月之暗面）、智谱、OpenAI、Claude、Ollama（本机，不需要 Key）。另有自定义地址；自定义地址走中转服务时，中转方看得到全部对话和 Key。
- Key 用 DPAPI 加密存在本机。除了请求发往所填的接口地址，程序不把 Key 发给别处。
- 费用按 LiteLLM 的公开价格估算。价格数据缓存超过 7 天才再下载。也可以自填单价，或手动刷新公开价格。
- 每个功能可以设每日 token 额度。
- 同一网站下只改接口路径时，已保存的 Key 保留。换成另一个网站或服务商时会先询问再清除。
- 修改 AI 设置、拉模型列表、测试连接，只接受本机请求。局域网会话可以看设置，不能改。
- 局域网里登录的设备默认也能用应用内助手，用的是房主的额度。不想这样，可以在设置里关掉「局域网可用 AI 助手」。

## 应用内助手与报错横幅

- 标题栏的「AI 助手」先读日志、配置和崩溃报告，再回答。发给模型的文本会先替换掉路径里的 Windows 用户名和程序目录、计算机名、局域网地址、Key 和令牌，玩家名保留。可以查看实际发出去的原文。
- 改配置、换 Java、重启等写操作，先给出确认卡片，确认后才执行；安装待装清单里的模组也是这样。提案生成阶段就失败时，不留一张空的确认卡。
- 外部 MCP 工具提出的写操作，也出现在助手面板顶部，同样要在 MineDeck 里确认。
- 控制台顶部的报错横幅不调用 AI，按顺序检查 13 类常见原因：缺少前置模组、客户端模组放进了服务端、装错加载器、重复模组、模组互相声明不兼容、Mixin 冲突、Java 或 JVM 参数不对、端口被占、内存不够、看门狗关服、没同意 EULA、好友进服时模组对不上、配置文件损坏。配了 AI 时可以点「让 AI 分析」。
- 界面上做的修改、确认后的执行、定时任务和崩溃重启，记在程序目录的 `logs\ops`（只读的查看不记）。记录里的密钥字段以掩码保存。

## 游戏内 AI

在服务器详情的「游戏内 AI」里打开。设置和当天用量存在该实例目录的 `gameai.json`、`gameai-state.json`，删掉服务器文件夹时一起删掉；删除时选了不删文件夹的，它们留在原处。

每次开服后第一次有人提问时，程序会在聊天里告诉所有人一次：向 AI 提的问题会发给哪家服务商处理。

- 默认前缀是 `@AI`。回复默认所有人可见。
- `/私`：回复只发给提问的人，提问本身别人仍看得到。
- `/问`：只回答，不执行命令。没有执行权限的人不会在帮助里看到这一项。
- `/额度`：今天还能问几次。
- `/帮助`：按这台服务器实际打开的选项生成说明。
- 默认限制：每人冷却 8 秒（与叫伙伴共用）；每人每天 60 次（叫伙伴另算，也是 60 次）；全服每天 300 次（提问与叫伙伴合计）；全服每天 500000 token。这些是没改过设置时的默认值。
- 同一人 1 分钟内超过 5 次算数的触发（已受理的提问，以及帮助这类不调用模型的回复），静默 3 分钟。被冷却或次数挡回的不计入这 5 次。
- 面板里勾选的玩家，可以让模型执行白名单里的命令。命令按模板分成两类：
  - 默认开：改时间、改天气、传送自己、给自己状态效果、设置自己的出生点、定位结构或生物群系、`list`。
  - 默认关：改自己的游戏模式、给自己物品、改难度、查看种子。
- `op`、`execute` 不在模板里，不会执行。每条命令的参数按该模板允许的写法核对。
- 执行后等服务器返回结果再组织回复。回复按游戏聊天宽度断行。
- 房主在「游戏内 AI」标签里能看到今天全服问了几次、用了多少 token，以及谁问了几次。
- 同一台服务器同一时间只回答一个问题，最多排队 3 个。
- 可以在面板里做识别测试，并查看最近的问答记录。

## 音乐共享

NeoForge、Forge、Mohist 的服务器有这个标签。能用要 NeoForge 1.20.5 及以后，Forge、Mohist 1.20.1 及以后；版本更早时，标签里会说明用不了。Fabric 和 Banner 没有桥接模组，不显示这个标签。

- 采集本机正在播放的声音，经 Simple Voice Chat 发给服务器里的人。玩家在语音设置里可以单独调低或静音。
- Windows 11 默认按进程环回，只录所选程序及其子进程。Windows 10 只能整机环回，会录进游戏声音和语音；第一次用之前要在界面上确认一次。
- 输出是 48 kHz、16 位、单声道，每 20 毫秒一帧，与 Simple Voice Chat 的帧格式一致。
- 音源列表来自各播放设备上的音频会话，去掉系统声音、已结束的会话、MineDeck 自己，以及游戏本身（录进去会有回声）。
- 检查清单包括：核心与版本、Simple Voice Chat、桥接模组、语音端口。缺 Simple Voice Chat 时可以按加载器和版本从 Modrinth 安装。桥接模组的 jar 随 MineDeck 自带，在音乐共享页安装进服务器。
- 没有开着的语音隧道时，页面会说明远程玩家还听不到，而不是假定连上游戏就能听到。
- 可以改 `voice_host`。语音隧道启动成功后，程序也会把公网地址写进这一项；你自己填过别的值时不覆盖。
- 开始广播只能由人在运行 MineDeck 的这台电脑上操作，助手和外部工具都不能代劳。停止广播也只能由人来点，局域网里登录的设备可以停。安装桥接模组和 Simple Voice Chat 是普通的写操作，助手可以提出来，确认后执行。退出 MineDeck 时先停止广播，再关服务器。

桥接模组的源码在 [bridge/voicechat](../bridge/voicechat/README.md)，打进程序的 jar 在 `internal/bridge/jar`。

## AI 伙伴

标签对应两套模组：NeoForge 1.21.1、Forge 1.20.1。当前打进程序的模组版本是 0.2.1。源码在 [companion](../companion/README.md)，jar 在 `internal/companion/jar`。

- 伙伴是服务端上的实体，不占玩家名额，不出现在 Tab 列表。默认最多 4 个，可在 1 到 16 之间改。随存档保存。
- 模型调用在 MineDeck 里。模组只执行本机连接发来的固定动作。
- 游戏里可以对伙伴说的动作：跟随、采集、走到坐标、攻击、把物品给玩家、停下、说话、查看状态。刷出和移除不从聊天里做，在「伙伴」标签上操作，或经助手的确认卡片。
- 可以设置禁挖区域，以及不许攻击的生物。没写攻击名单时用程序内的默认名单。
- 只有在「游戏内 AI」里授权的玩家能让伙伴执行动作。
- 服务器上的模组在「伙伴」标签安装，会从 Modrinth 取 PlayerEngine 和 Architectury API，装在服务端。好友的客户端装发布页上的伙伴模组 jar（和服务端是同一个文件），按服务器的加载器和游戏版本选；客户端不用装 PlayerEngine 和 Architectury API。
- 停住的伙伴在水里会浮起。给物品时按实际交出的数量报告结果。
- 退出 MineDeck 时向伙伴模组发结束，伙伴和任务留在游戏里。

## MCP

默认关闭。在「设置 → AI（可选）→ MCP 接口」打开。

- 只接受本机连接，要带令牌。令牌加密保存，可以重置。
- 支持 MCP 的工具通过 HTTP `/mcp`，或把 `MineDeck.exe -mcp` 当作 stdio 子进程。`-mcp` 不打开窗口，只把标准输入输出转到已经在跑的 MineDeck。
- 读状态、读日志可以直接做。改配置、重启等写操作只生成提案，在 MineDeck 里确认后执行。标记为仅人工的操作，外部工具看不到。
- 发给外部工具的文本与应用内助手一样先做脱敏。
- 面板里可以按工具复制一份配置。这里用的是那个工具自己的模型，不使用 MineDeck 里的 API Key。

## 操作记录与本机边界

界面上的操作、应用内助手和 MCP 工具发起的操作，都经过同一个操作层。每项操作有参数说明和风险等级：只读、写入、危险，或仅人工。仅人工的项不能由 AI 或定时任务调用。游戏内 AI 执行的命令和伙伴的动作不走这一层，它们受各自的白名单约束，执行后记进操作记录。

本机接口使用每次启动随机的令牌。选择文件夹和打开路径不会接受局域网会话。
