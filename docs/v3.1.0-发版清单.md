## 正式版发布说明要点（只列要点，未写成稿）

相对 v3.0.0，用户能直接感受到的变化：

- **服务器交接包。** 停服后导出 `.mdpack`，交给下一任服主或朋友另开一台；支持带核心的完整模式和导入时重新准备核心的模式，携带世界、模组／插件和指定配置。来源：`docs/releases/v3.1.0-beta.1.md:8`。
- **自选模组与待装清单。** 新建向导和服务器详情可集中挑选模组／插件、检查和补齐必装前置；beta.4 将“购物车”改名为“待装清单”，增加热门列表、分类、翻页和“从电脑添加”本地 jar。来源：beta.1 `:28`，beta.4 `:13`。
- **整合包导入更可处理。** 下载不了的文件逐个跳过、用本地文件补齐或按提示处理；可用本地来源文件夹自动补同名文件，显示更高 Java 要求；CurseForge 资源包、光影、数据包分开放置，待处理项显示名称和下载页。来源：beta.1 `:37`，beta.2 `:19`。
- **现成服务端压缩包与一层包装目录。** 整合包清单可以套一层文件夹；已经装好核心的服务端压缩包可直接导入，Forge／NeoForge 需要装好的 `libraries`，Fabric／Paper／原版等需要服务端 jar。不能笼统承诺“所有 Server Pack 都能直接导入”。来源：beta.4 `:29`。
- **接管已有服务器与界面换 Java。** 原地登记已有服务器，不搬存档；服务器可以移出列表后再接管；beta.3 修正接管后连带显示相邻服务器的行为。来源：beta.1 `:51`，beta.3 `:8`。
- **任务与安装体验。** 切页或刷新能回到后台任务；过长日志保留开头说明；超限包上传前提示；旧版 Forge 的半截安装继续重试；导入失败清理结束后再报告失败。来源：beta.1 `:56`，beta.2 `:12`，beta.4 `:40`。
- **界面、文件夹选择和提示。** 使用 Windows 选文件夹窗口；最小窗口 1024×576；新建入口重排；报错正文先说明哪步失败，详细原文可查看、复制；设置说明和“服务器／文件夹”叫法统一。来源：beta.4 `:8`、`:17`。
- **OpenFrp 下载修复。** 修复 frpc 下载地址，多个源失败时可看各自原因，卡片能显示文件被拦截或不见时的中文说明。来源：beta.4 `:24`。

升级时要说清：

- 正式版计划允许 v3.0.0 和 v3.1.0-beta.4 在“设置 → 更新与关于”更新到 3.1.0。需要等正式 Release 发布后分别实测完整流程；不能把版本比较规则成立写成实际升级已经成功。测试版之间仍不能自动互升（`docs/功能清单.md:203`）。更新前先停服、保留现有文件夹备份；手动替换时完整退出程序。
- beta.1／beta.2 接管过服务器留下的父目录记录不会自动清除。发布说明应链接 beta.3 的迁移办法，并提醒“移出列表”可能影响同一文件夹被另一份 MineDeck 管理的情况，避免只说“升级就修好了”（beta.3 `:18`、`:24`、`:26`）。
- 伙伴模组仍为 0.2.1；按当前清单发版且附件核对一致时，已装 v3.0.0 或 beta 伙伴模组的好友不必更换。发布前以最终 manifest 和实际附件为准（beta.4 `:70`）。
- 导入已有 `server.properties` 的现成服务端时，仅改端口；正版验证和允许飞行保留包内设置，导入页这两个开关不生效，需要去“常用设置”修改。原启动脚本和 `user_jvm_args.txt` 里的自定义 JVM 参数不会继承，内存按导入表单设置；解压出来的服务器按新建服务器管理，删除文件夹选项的后果要说明（beta.4 `:34`、`:36`、`:37`）。
- 交接包不继承原 JVM 参数、定时任务、崩溃自动重启；游戏内 AI、伙伴、音乐共享需要在接收电脑上重新开启，原 RCON 先关闭。普通模式不带核心；不在打包范围里的根目录自定义文件需另行复制。请勿把“交接包”和“整个程序文件夹搬家”写成同一件事（beta.1 `:14`、`:15`、`:20`）。
- 正式版前的修复收紧了几处行为，逐条见检查报告的「修好以后，升级的人会碰到的变化」：新加的 JVM 参数里不能再有双引号；自定义 frps 的地址只能填域名或 IP，改地址、端口或者从服务商改成自定义时要重填凭据；局域网登录同时发好几个请求，后到的会被请稍等；整合包的覆盖文件超过 20 万个或 8 GB 的拒绝导入。

已知功能限制应在正式版说明中继续明示：

- 交接包上传上限 **8 GiB**（8,589,934,592 字节），整合包上传上限 **4 GiB**。旧 beta 文案写“GB”，正式版建议统一为实际单位 GiB。当前依据：`internal/web/transfer.go:82`、`internal/web/ui/app.js:1624`、`docs/功能清单.md:75`。大于交接上限可整文件夹搬运后接管。
- 客户端整合包不等于服务端包，可能导入成功但因客户端专用模组启动失败；目前导入前没有对应提醒。数据包放进 `datapacks` 不会自动在世界生效（beta.2 `:66`、`:67`）。
- 只带启动脚本／加载器安装器的 Server Pack 不能直接导入或立即接管；需要先按整合包作者说明装好加载器，再接管，或在 MineDeck 新建相同核心和版本后复制模组、配置。只识别一层包装、单一清单，不支持 Quilt，版本只在日志中的包无法直接识别（beta.4 `:33`、`:76`、`:77`）。ServerPackCreator 打的这种包，以前报的是一句 JSON 解析错误，已在 `v310-fixes` 上修好：现在报「看着像现成服务端，但没认出核心和版本」，详情里说明先运行包里的启动脚本或安装器装好加载器，再接管。正式版说明照这个写，但不要写成「这种包能直接导入了」。
- 待处理文件清单和后台任务只在本次运行有效；重启后要看服务器文件夹中的清单文件补齐。强行中断交接包导入仍可能留下不会显示在列表里的半成品文件夹；正常失败后的清理改进不能表述成断电也会自动清理（beta.2 `:68`、`:70`）。
- 向导草稿清单不绑定核心；切换核心或下次新建可能出现不兼容项。前置数量没有总上限，很多时处理较慢。最小窗口下待装清单会排到结果列表下面；两台服务器同时安装同一草稿的本地文件还有已记录的限制（beta.2 `:71`、`:72`；`docs/交接说明.md:1391`）。
- 接管服务器与默认存放目录里的服务器重名时，列表只显示后者（beta.3 `:51`）。
- 1.21.9 及以上“常用设置”中命令方块、PVP、下界、刷怪四个开关的初始显示取旧配置值，不读取当前游戏规则，可能与游戏内状态不同（beta.4 `:79`）。
- 窗口版里，界面上的外部链接（EULA、申请 CurseForge Key、openfrp.net 等）是在 MineDeck 弹出的简易窗口里打开的，不是系统默认浏览器，用不了自己浏览器里的密码管理器、扩展和登录状态，可以复制地址到自己的浏览器里打开。作者测原生窗口时发现，定了下个版本修（检查报告「可以放到以后的」）。
- 长报错、路径或英文系统原文常需点“详情”查看；隧道卡片仍完整显示原因。未进行本轮验证的跨电脑、真客户端等项目应在主报告里单列，不能继续照抄 beta 历史测试人数、条数或耗时作为正式版结论。
