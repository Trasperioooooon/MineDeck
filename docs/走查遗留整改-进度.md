这份文件记 v3.2.0-beta.3 发出以后，给下一版做的那批整改做到哪了。接手的人先读它，再读 `docs/交接说明.md` 最后一节和 `docs/beta3-进度.md`。不发版，发不发由作者定。

## 从哪来

beta.3 发出以后，主会话（会话编号 `local_6f5cd2f4…`）另起了这个会话，在工作树 `.claude/worktrees/bold-khorana-2a90a4`（分支 `claude/gifted-elbakyan-436484`，基准 `721dd9d`）里做。要做的七条来自 beta.3 两轮盲测走查记下没改的问题、Codex 最后一遍记下不修的三条，都已经写进了 `docs/releases/v3.2.0-beta.3.md` 的「已知情况」：

1. 用存档新建、或换过地图的服务器，「世界与备份 → 备份」页顶仍写「服务器自己的世界，没有从备份还原过」：页顶要说清现在的世界从哪来。
2. 改了备份存放文件夹以后，备份页「备份放在」指向新文件夹，列出的却有旧文件夹里的备份，没有说明；点「打开」打开的是新的（可能是空的）文件夹。
3. 新建向导不预先检查端口有没有被别的程序占着（MineDeck 自己的会避开），开服才报。
4. 详情页右上角的报错提示会盖住页头提示区里的修复按钮；报错的「详情」弹窗没有「带我去改」。
5. 工具箱「导出整合包」页读草稿失败时，这一次不自动保存，但页面上没有提示：加常驻提示和「重新读取」。
6. `internal/ops/catalog/files_realpath_test.go` 里两条要建符号链接的用例，对任何 `os.Symlink` 错误都跳过，改成只在没权限时跳过。
7. Codex 记下的既有竞态：读写配置、补没装上的文件，在核对路径之后按字符串路径创建、替换、删除，别的程序在中间把文件夹换成联接就能动到外面。根治要把后面的操作绑在已核对的目录句柄上。

## 读代码时摸到的情况

第 1 条：`instance.json` 里的 `worldFrom` 只记「从哪份备份还原来的」，换地图（导入、换回、恢复）时清掉，所以用地图新建的、换过地图的服务器页顶一律落到「服务器自己的世界」那句。换地图页的恢复点（`worldimport` 的 `RestorePoint`）里有来源名、导入时间和状态（正在用 / 已换回），用地图新建服务器时也会留一个恢复点。

第 2 条：后端本来就把改过的旧备份根（`app.AllBackupRoots`）里的备份一起列出、能还原能删，只是 `BackupInfo` 里没有「在哪个文件夹」，界面分不出来。

第 3 条：开服前已经有照服务端绑法的试绑（`inst.checkBindPort`），「检查端口占用」操作里还有一条不用绑端口、直接读系统监听表的查法（`portOwners`）。四处表单（新建、导入整合包、接管、用地图开服）共用 `port.suggest`，只看 MineDeck 自己的服务器。接管时端口和别的服务器撞了会改它的 `server-port`，所以接管表单不能因为「别的程序占着」就挪默认值：原来那台没停的服务器自己就是「别的程序」。

第 4 条：`placeToasts` 只量 `.detail-head`，提示落在它下面；页头提示区要是在它外面，提示就会盖住提示区里的按钮。`showErrDetail` 只收一段文字，没有按钮。

第 7 条：要动的不只是 `files.go`，真正的改动面在 `atomicfile`（PR #24 加的替换重试）和三处入口。Go 1.25 起 `os.Root` 有 `WriteFile`、`Rename`、`RemoveAll`，它在 Windows 上对目录联接怎么处理要先实测。

## 做了什么

每条一个提交（第 1、2 条合成一个），都在分支 `claude/gifted-elbakyan-436484` 上，基准 `721dd9d`。

**第 6 条，`be5d186`。** `files_realpath_test.go` 里两条要建符号链接的用例改用 `symlinkOrSkip`：只有 `ERROR_PRIVILEGE_NOT_HELD`（这台机器上实际报的就是它，`-v` 看过）才跳过，别的建链失败直接判失败。判断抽成 `symlinkUnprivileged`，`TestSymlinkSkipOnlyWithoutPrivilege` 用几种假错误单测。第二条用例照 Codex 的建议补了 Lstat/Readlink，确认外面那个链接没被换成同名的普通文件。这台机器没有建符号链接的权限，两条用例本地仍是跳过；beta.3 发出后在 CI 上验证过 GitHub 的 Windows 机器建得了。

**第 5 条，`47a9c9f`。** `toolbox.js` 读草稿失败时在第一节顶上放一个 status 区的报错框，写明这一次改的不会自动保存、点「重新读取」会换成存好的那份。重新读取成功就整份填回、恢复自动保存、提示「已读回」；还失败就换上新的原因。说明和按钮只在「自己挑模组」时出现，重新读取期间来源切换锁着（Codex 第一轮指出：停在「从已有服务器导出」时重新读取、切回来一改，会把服务器名存进草稿，`30aa150` 改的）。界面用例接在原来「读草稿失败」那段后面。

**第 1、2 条，`81c6647`。** 后端 `inst.BackupInfo` 加 `dir`、`elsewhere`（不在现在的备份根里），`TestBackupListSaysWhichFolder` 覆盖新旧两个根和同名备份。`worldimport.js` 加 `MDWorldImport.origin(恢复点状态)`：从最新的恢复点往前找第一条换过世界的，已导入的给来源名和时间，换回过的说换回了，正在换或要人处理的照说，没生效的跳过，世界名对不上现在 level-name 的不算。备份页页顶先看 `worldFrom`（从备份还原的，换地图时会清掉），没有再看恢复点，有记录时带路去「换地图」。改过存放位置时「备份放在」改叫「新的备份放在」，下面按文件夹写「另有 N 份是改存放位置以前做的，还在原来的文件夹 …，照常能还原、删除」，本机上给「打开」；列表里那几份标「在原来的文件夹」。新文件夹还没建时「打开」的提示改成「在这个文件夹里还没有备份过」。仿真后端的备份列表带 `dir`。API.md 跟着改。界面用例一条，在仿真界面里也看过样子。

这批没做、走查记下的别的问题照旧没动：新建向导和「换地图」页里地图仍显示存档里的名字（多半是 world），只在页顶和来源那一行写导入时的来源名；白名单加了人但开关默认关；菜单叫「删除服务器…」其实默认只移出列表；皮肤包的 SHA-1 没解释；服务器文件夹名是编号；定时任务旁「5 分钟后」意思不清；开服后没法确认朋友能不能连上；服务器页没有通往内网穿透的入口；装完插件不提醒重启；跳过的文件在页头和卡片上没有标记；添加隧道时「跟随服务器启动」默认开。

这批自己带出来、知道但没改的：

- 端口预查只读 TCP 监听表，查不出 Windows 保留的端口段（Hyper-V、WSL、Docker 会成段保留），那种开服时照旧报「用不了」，页头照旧给「改端口」。
- 打开表单那一次后端查过是空着的默认端口不再问；表单开着期间别的程序占上了这个端口、人又没动过端口框的，开服时才报。
- 备份页的「当前世界从哪来」只读现有的恢复点：恢复点删掉以后就只能说「没有记录」。
- 第 6 条的两条符号链接用例这台机器没有权限、仍是跳过；CI 上能跑（beta.3 发出后验证过），这次的改动没有单独在 CI 上跑。
