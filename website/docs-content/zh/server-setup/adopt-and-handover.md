无论你是想把以前手动开服的文件夹收归界面管理，还是要把正在跑的周目完整打包发给下一任服主，都可以用 **「接管已有服务器」** 与 **「交接包（`.mdpack`）」** 完成。

## 一、接管已有服务器（原地收编） {#adopt}

入口：左侧栏 **「新建服务器 → 接管已有服务器」**（仅在本机电脑浏览文件夹时可用，不支持从局域网手机选择文件夹）。

1. 点击选择或粘贴那台服务器**具体的那一层目录**（包含服务端 jar、`run.bat` 或 `libraries` 的那一级）。
2. 点 **「识别」** 后，程序只读扫描目录，列出探测到的核心、Minecraft 版本、可用启动文件、`server.properties` 原端口与原内存配置，以及目标核心需要的 Java。
3. 如实填写服务器名称、核对端口与 EULA 勾选（如果目录里原已有 `eula.txt` 可不用再勾），点击接管即可完成登记。

### 接管时的保护与备份细节 {#adopt-notes}

- **文件夹留在原地**：不会把已有服务器搬走或重命名目录，只登记这**单个目标文件夹**（同级目录下的其他文件夹不会被连带收进列表）。
- **自动备份旧启动文件**：写入 `instance.json` 前，原有的 `run.bat` 会备份为 `run.before-minedeck.bat`，Forge/NeoForge 的 `user_jvm_args.txt` 也会先备份；非内存类的常见 JVM 参数会被读取进实例设置，但**带空格的参数或原 `run.bat` 内额外手写的参数（例如外置登录 `-javaagent:...`）不会自动带过来**——识别页会明确提醒，请在接管后进入该服务器的 **「设置 → 启动与内存」** 手动补填。
- **拒绝高危目录与端口冲突处理**：系统会禁止接管整个磁盘根目录、MineDeck 程序及运行目录、备份目录或已登记目录；若端口与列表里另一台服务器冲突，请在确认页改用新端口（会写回该服的 `server-port`）。
- **失败无残留**：如果接管过程失败，这次写进该文件夹的文件会自动回退清理。
- **离线文件夹容错**：如果接管进来的服务器存放在移动硬盘里，某天没插硬盘启动 MineDeck 时列表会暂时隐藏它，插回硬盘重启程序即可恢复。

## 二、移出列表与彻底删除的差别 {#remove-vs-delete}

在服务器卡片或详情页头点击 **「··· → 删除」** 时，弹窗内 **「同时删除服务器文件夹（含世界，无法恢复）」默认是关闭的**：

- **保持关闭（默认，主按钮为「移出列表」）**：只让这台服务器不再显示在 MineDeck 里，文件夹和所有文件完整保留，程序把内部的 `instance.json` 改名为 `instance.json.bak`；之后哪天想加回来，用 **「接管已有服务器」** 再选一次该文件夹就能恢复所有配置。
- **手动勾选删除开关**：需要二次确认并输入服务器名称后，才会连同服务器目录一起彻底删除（通过工具在「设置 → 存储位置」外的 `backups\` 世界备份仍保留，不会跟着误删）。

## 三、导出与导入交接包（`.mdpack`） {#handover}

想把一台服务器的**世界、人物背包进度、模组或插件、白名单和核心配置**一起交给别人接盘时，可以把整台服务器导出为一个 `.mdpack` 压缩交接包（支持最高 **8 GiB** 的包导入）。

### 导出步骤 {#export}

1. 先完全停止该台服务器（打包与导入过程中，这台服务器无法启动或删除）。
2. 在服务器卡片或详情页头点击 **「··· → 导出交接包…」**。
3. 按需选择导出用途与模式：
   - **用途选择**：**「交给下一任服主」** 或 **「发给朋友照开一台」**（包内文件相同，接收方导入界面看到的说明措辞不同）。
   - **模式选择**：**瘦身模式（默认）** 不含服务端核心，体积更小，对方导入时按需联网重下核心；**完整模式** 连同核心和 `libraries` 一起打包，适合网络不通官方源或离线环境给对方省去安装器耗时。
4. 可指定保存路径，或者在路径选择中利用 **「新建并导出」** 直接创建输出目录。

### 导入步骤（收包方） {#import}

收包方在另一台电脑打开 MineDeck（需要 **v3.1.0 或更新版本**），点击左侧栏 **「新建服务器 → 导入交接包」**，选中收到的 `.mdpack`（不要解压、不要用微信/QQ 的图片视频压缩式发送），核对核验页列出的原名、核心、版本、世界大小后填写本地服务器名称与端口，点击 **「导入交接包」** 即可。

### 打包与导入前必看清单 {#handover-rules}

| 包含在 `.mdpack` 内 | 不会跟着 `.mdpack` 迁移（需注意或重新开） |
| --- | --- |
| 世界存档（含多世界插件世界）、`eula.txt` | **日志与崩溃报告**（均不打入包内） |
| `server.properties` 及核心配置（如 `paper.yml`/`spigot.yml`） | **JVM 启动参数**（如 `-javaagent` 需自备并到「启动与内存」补写） |
| `mods/`、`plugins/`、`config/`、`kubejs/`、`scripts/`、服务器图标 | **定时任务与崩溃自动重启开关** |
| 白名单、管理员（OP）与封禁名单（含封禁 IP）、代理端转发密钥 | **RCON 会自动关闭**（出于安全考虑，导入后如需使用须重新开启） |
| — | **游戏内 AI、AI 伙伴、音乐共享开关**（须在收包机器按需重新启用） |

> [!CAUTION]
> **隐私与安全双向提醒**
> - **给打包的人**：服务器原有配置文件（含 RCON、数据库、机器人插件密钥）及封禁列表里的 IP 会原样进包——**在其他地方复用的密码，请在导出前先改掉再交**，并提前知会服内玩家。
> - **给收包的人**：完整模式下包里的核心与所有模组/插件均来自对方电脑，一旦启动就会在本机运行——**只导入信得过的人发来的 `.mdpack`**。
> - 若整服体积超过 **8 GiB**，请直接把整个服务器文件夹通过硬盘或分卷传过去，在对方电脑上使用本页第一节的 **「接管已有服务器」** 收进列表。更多接收方细节还可参考「发给朋友」流程：[打包发给朋友怎么选](../networking/share-with-friends.md)。
