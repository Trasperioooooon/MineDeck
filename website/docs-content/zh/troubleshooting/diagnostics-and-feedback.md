遇到本指南或控制台横幅一时看不懂的疑难报错时，整理好「当时做了什么 + 完整原始报错/日志」，才能最快得到朋友、AI 助手或开发者的准确定位。

## 一、从程序界面直接取原文 {#ui-copy}

- **报错弹窗 / 提示框底部按钮**：当错误通知框（Toast）出现时，停留时间足够阅读，点击后面的 **「详情」** 会弹出带完整原文的可选框；错误卡片与弹窗统一配有 **「复制报错信息」** 按钮，一键拷贝的不是缩水后的摘要，而是保留着后台原文与堆栈的信息。
- **后台任务日志**：创建服务器、整合包或交接包失败时，保留进当次任务详情页，底部可直接阅读或全选拷贝安装器与下载重试线索（长任务已特别保留开头关键 40 行，不会被滚丢）。
- **让 AI 辅助总结**：若全局配置了 AI，点报错旁的 **「让 AI 分析」**，助手会自动连同配置与崩溃摘要一并帮你想。

## 二、找到电脑上的完整日志文件 {#log-files}

在具体服务器的详情页点击顶部 **「打开目录」** 下拉入口（仅本机操作时出现），即可直接跳到对应关键位置：

| 入口 / 路径 | 里面放了什么 | 何时需要 |
| --- | --- | --- |
| **服务器根目录 `logs\latest.log`** | 当前或最近一次开服全过程完整服务端日志（非截断，包含中文不乱码原文件） | 启动报错、插件/模组异常、多人连线掉线 |
| **服务器根目录 `crash-reports\`** | Minecraft 游戏核心与模组崩溃时写出的崩溃报告（按时间命名 `.txt`） | 开服或进图途中突然异常崩溃退出 |
| **`<MineDeck 目录>\logs\ops\`** | MineDeck 界面、定时任务、AI 与 MCP 操作审计日志（已自动脱敏掩码密码与密钥） | 核对最近是谁触发过启停或配置调整 |

## 三、向社区提交反馈前的隐私保护与提单格式 {#feedback}

可以通过官网的 [反馈页](/feedback/) 按引导整理环境信息与脱敏文本（站内提供模板一键生成，即便没有 GitHub 账号也可以直接复制或下载脱敏好的报告导出，不会擅自外传数据）。

> [!CAUTION]
> **发截图、发日志前务必自我检查 3 样绝对不要公开的东西**：
> 1. 任何 **API Key**（AI 服务商 Key、CurseForge API Key）；
> 2. **内网穿透与平台凭据 / 访问密码**（OpenFrp/樱花穿透密钥、自定义 `frps` token、「手机远程管理」密码、`rcon.password`）；
> 3. 如果有截图带到了桌面用户名等不想露出的隐私路径，可先打码；同时注意不要在公共群直接转发携带 `-nogui` 本地会话 `token` 的启动链接。

按以下最小四条模板写清楚即可大大省掉来回确认的时间：
1. **做了什么**（点什么按钮、选什么核心和 Minecraft 版本）
2. **本来以为会怎样**
3. **实际发生了什么**（贴出「复制报错信息」内容或 `latest.log` / `crash-reports` 相关段落与截图）
4. **电脑系统环境**（如 Windows 11，以及当前使用的 MineDeck 版本号）
