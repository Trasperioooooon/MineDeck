想要让长期挂机的服务器省心运转，可以组合使用单台服务器的 **「定时任务」**、**「崩溃自动重启」**，以及全局的 **「通知与集成」** Webhook 推送。

## 一、每台服务器的定时任务 {#schedules}

打开服务器详情页的 **「定时任务」** 标签，可以为这台服添加每日定时执行规则：

- **执行时间**：填每天执行的 **`HH:MM`** 时间（如果写了单数字如 `4:5`，界面与后端会自动补零成 `04:05`）。
- **支持三类动作**：
  1. **定时重启服务器**：常用于夜间定时清内存与重新载入，若重启时遇到端口还没完全释放，程序会自动等待几秒再起；
  2. **发送一条控制台指令**：例如定时播报公告 `say 服务器将在 5 分钟后维护`、定时执行 `save-all` 等；
  3. **定时世界备份**：自 `v3.2.0-beta.5` 起进一步加固——如果到点刚好碰上这台服正在「启动中」或「停止中」，定时备份**不会直接报错丢掉**，而是稍等状态稳定后再延后执行并写入任务审计日志。

> [!NOTE]
> 请注意：通过 [导出交接包](../server-setup/adopt-and-handover.md) 迁移服务器到新电脑时，定时任务列表与下面的崩溃重启开关**不会跟着打包迁移**，需要在新机器按需重建。

## 二、崩溃自动重启 {#auto-restart}

同样在 **「定时任务」** 页可独立开关 **「崩溃自动重启」**（默认关闭）：

- **分级退避策略**：发现异常崩溃退出后，按 **`10 秒` → `30 秒` → `60 秒`** 逐渐拉长间隔自动拉起；如果**连续 3 次依然没能稳定拉起**，会停止继续重试，防止坏模组导致无限死循环占满 CPU。
- **稳定运行清零**：如果此次成功启动并连续运行超过 **10 分钟** 后才崩溃，失败计数会先清零再算本次。
- **以下情况不会误重启**：你自己在界面点 **「停止」**、在控制台输入 `stop` 停服、在游戏内以管理员身份输入 `/stop` 停服，或在退避倒计时等待期间手动点了启动或停止，都不会额外再触发自动重启。
- **联动穿透**：绑定了「跟随服务器启动」的 [内网穿透隧道](../networking/tunnels-and-accounts.md) 会在服务器自动拉起时一并保持或重连。

## 三、全局「通知与集成」Webhook 推送 {#webhook}

打开全局 **「设置 → 通知与集成」**，填入你的外部 HTTP 接口地址（如群聊机器人中转或自建状态看板接口），MineDeck 发生以下进程内关键事件时会自动发出 `POST` JSON 请求（若对方网络波动失败，最多重试 3 次）：

### 推送 JSON 示例

```json
{
  "type": "player.join",
  "time": "2026-07-12T03:00:00+08:00",
  "data": { "instance": "我的服务器", "player": "Steve" }
}
```

### 支持推送的 8 类事件名

| 事件 `type` | 触发时机 |
| --- | --- |
| `instance.start` | 某台服务器启动完成 |
| `instance.stop` | 某台服务器停止退出 |
| `instance.crash` | 某台服务器非正常崩溃 |
| `player.join` | 有玩家加入游戏 |
| `player.leave` | 有玩家离开游戏 |
| `backup.done` | 一份世界备份完成 |
| `tunnel.up` | 某条内网穿透隧道成功上线 |
| `tunnel.down` | 某条内网穿透隧道停止 |

> [!NOTE]
> **Webhook 令牌隐私保护**：出于防止密钥随局域网查看而外泄考虑，当使用手机或别的电脑登录局域网管理页面查看 **「设置 → 通知与集成」** 时，Webhook 地址里主机后面的路径与令牌参数会被隐藏为 `***`（如 `https://hook.example/***`）。直接保原样不会覆盖；如果要在外端设备上修改地址，需把完整带令牌 URL 重填一遍（或直接在本机桌面查看修改）。
