# 前端开发工具（tools/ui-dev）

改 `internal/web/ui/` 下的前端时用：不需要 Windows，也不需要 Go 后端，在浏览器里就能看界面、跑交互回归测试、批量截图。

| 文件 | 作用 |
|---|---|
| `server.js` | 仿真后端：直接托管 `internal/web/ui/`，`/api/*` 返回内存里的假数据（4 台服务器、2 条隧道等） |
| `tests.js` | 交互回归测试：后台任务恢复、慢响应切页、乱序搜索、切页后的轮询、未保存守卫、删除确认、新建向导、外观设置（默认方案「方块」）、远程访问二维码、局域网登录框、log4shell 参数保留、启动画面（只在冷启动播一次、可跳过）、设置分组列表、服务器状态切换的动效、「减少动态」、CurseForge Key 只写不读、隧道凭据解不开时的提示、隧道启停后卡片马上刷新和失败原因直接写在卡片上（新一次运行没连上时不拿上次的地址盖住报错、列表偶尔刷新失败不关日志）、标题栏双击最大化、关窗确认、远程访问开关即时生效（拨开关时一起保存框里的新密码）、部署卡住时的「下载慢或者在重试」、定时任务的时间输入、全部配置的搜索、音乐共享一键装 SVC、手机竖屏和横屏的底部标签栏、游戏内 AI 的用量和限流设置、无障碍（同名控件、没名字的控件、开关的可点区域）、接管已有服务器、给服务器换 Java、删除时的「移出列表」、导入的待决文件面板（逐项跳过 / 本地代替 / 信任站点要确认、同站点第二次免确认、没给路径拦下、任务列表的待决条数）、模组要求更高 Java 时实例详情的换 Java 提示和导入表的本地来源目录、交接包的导出（选这个包给谁）和导入（摘要、确认来源的提醒、选 Java、端口占用）、自选模组的向导「选模组 / 选插件」步（建服后自动装）与实例「待装清单」标签（前置检查、补齐、移除清空、搜索乱序、清单被别处改过时拦下安装）、热门清单（一打开就列出、类别筛选、加载更多到第 5 页为止、加载失败或很慢不挡向导）、从电脑添加本地文件（逐个上传或拖进来、就近说明没加上的、自动检查前置、上传时按住向导的「下一步」、只有本地文件也会装、没人看过的本地文件不装）、两栏版面（宽了并排吸顶、窄了叠成一栏）等，共 125 条 |

## 准备（只需一次）

需要 Node.js 18 或更新版本。在本目录下运行：

```powershell
npm install
npx playwright install chromium
```

第二步可以省掉：找不到 Playwright 自带的 Chromium（没装，或者装的是别的版本）时，测试和截图会自动改用本机装的 Google Chrome（见 `browser.js`）。要指定浏览器，设环境变量 `CHROME=<chrome.exe 的完整路径>` 或 `PW_CHANNEL=msedge`。

## 用法

```powershell
npm run mock                        # 启动仿真后端，然后用浏览器打开 http://127.0.0.1:27390/
npm test                            # 跑全部交互测试，全部通过时退出码为 0
npm test -- 外观                     # 只跑名字里含「外观」的测试（参数是正则）
npm run shots                       # 全部截图，存到 shots/pages 与 shots/schemes
npm run shots -- pages --only=wiz   # 只截名字匹配 wiz 的页面（新建向导各步）
npm run shots -- schemes            # 只截 7 套配色
```

`npm test` 和 `npm run shots` 会各自启动一份全新的仿真后端（随机端口），不用先开 `npm run mock`，每次都从同一份初始数据开始。`npm run mock` 默认用 27390 端口，避开 MineDeck 自己的 27333；要换端口就运行 `node server.js <端口>`。

## 界面原型

想一口气看遍各种状态（没有服务器、十二种核心各一台、向导的每一步、部署失败、隧道出错、各个设置分区……），不用真的去建那么多服务器：**双击本目录的「打开界面原型.bat」**，浏览器会打开一个场景目录页。也可以运行 `npm run proto`（或 `node proto.js [端口]`，默认 27391）。

目录页左边按页面分组列着场景，点一个，右边嵌着的界面就切到那个状态。界面是真的（`internal/web/ui/` 原样托管），数据是编的，所以可以照常点、填、切标签，只是不会真的下载和开服。右上角可以换深色 / 浅色、七套配色和窗口大小（默认、最小 1024×576、大窗口、手机）。键盘 ↑ ↓ 换场景。每次换场景，数据都回到那个场景的初始样子。

同一个地址后面加 `tour.html`，是给访客看的导览：从场景里挑了十四步，从服务器列表、新建向导、部署进度，一路看到控制台、玩家、备份、内网穿透、外观和手机上的样子，每一步配一两句给没用过的人看的说明。官网的「在线体验」用的就是这一页。

改了界面上的选择器（id、class、`data-*`）之后跑一遍 `npm run proto:check`：场景里写的选择器失效了，它会指出是哪个场景。界面有了新页面或新状态，顺手在 `proto/scenes.js` 里加一个场景。

### 静态版：不要服务器，双击就能看

上面那一套要开着 Node 才能用。**双击「生成并打开在线体验.bat」**（或者 `npm run proto:static`）会在 `proto-dist/` 里生成一个自成一体的文件夹：双击里面的 `index.html` 就是导览，`catalog.html` 是评审用的目录页。不用装任何东西，也不用开任何服务；把整个文件夹拷给别人、放到随便哪个静态托管上、放在网站的某个子目录下，都照样能用。生成只用 Node 自带的模块，不用 `npm install`。`proto-dist/` 不入库，想看新的就重新生成。

它和 Node 版是同一套东西：同一份场景清单、同一个仿真后端、同一个舞台和播放器。区别只有一处：仿真后端不再跑在 Node 里，而是打成一份脚本（`mock.js`）跑在界面那一页里，接管这一页的 `fetch` 和 `EventSource`，界面发给 `/api/…` 的请求直接交给仿真后端的处理函数，不出浏览器。`server.js` 一行没改，它用到的 Node 模块（`http`、`fs`、`path`、`vm`、`url`、`crypto`，还有 `Buffer`）在浏览器里各有一个最小的替身，都在 `proto/static-runtime.js` 里。

界面文件是原样拷进 `app/` 的，只有 `index.html` 动了两处。一是 `<head>` 里多了一行引 `mock.js` 的脚本。二是预加载字体的三行 `<link rel="preload">` 拿掉了，改由 `mock.js` 在不是 `file://` 的时候补回去：双击打开时浏览器会拦下这种请求并在控制台报跨域的错（字体本身照常能用），放在网站上则和原来一样提前下载。

演示不联网。不是发给仿真后端的 `fetch`，只放行界面自己文件夹里的文件，别的一律拒掉；仿真数据里没有外站的图片地址；`mock.js` 还给那一页加了一条内容安全策略，只许读自己文件夹里的东西，哪天界面里多了一张外站的图，浏览器会直接拦下。界面上那几个指向外站的链接（EULA、OpenFrp 控制台等）还在，要人自己点才会在新标签页里打开。上传是假的：从电脑添加 jar、上传交接包走的是仿真后端的假流程，文件只在浏览器内存里过一下（超过 32 MB 的只读开头一小段），不会发到任何地方；导入整合包会直接说演示里不能导入。

仿真后端本来是给交互测试写的，很多操作只回一句「好」，数据不跟着变。给没用过的人看，这样像是坏了，所以原型里（Node 版和静态版都一样）在它前面补了几段假流程，写在 `proto/demo.js`：点「启动」「停止」状态真的会变、控制台跟着出几行；控制台里发的命令有回显，`list`、`say` 这几条有像样的回答；走完向导建的服务器，部署进度会从第一步走到完成，能点进去；接管和导入交接包以后，列表里真的多出那一台；玩家页加白名单、设管理员、封禁、踢人以后名单真的变；备份页点「立即备份」会多出一份，能删，还原要先停服。这些只在原型里有，`npm test` 用的仿真后端不受影响。

自检有几种跑法，都是 `node proto-check.js` 后面加选项：

```powershell
npm run proto:check                         # Node 版，目录页的全部场景
npm run proto:check:static                  # 静态版，用 file:// 打开，同双击
node proto-check.js --static=http           # 静态版，放在本机的静态服务器上，而且故意放在子目录里
node proto-check.js --static --tour         # 只查导览那十四步；再加 --phone 用手机大小的窗口查
node proto-check.js --static --flows        # 查那几段假流程和上传：启动、发命令、建服、加白名单、备份、导入整合包、交接包
```

查静态版时比 Node 版多查两样：页面有没有往产物以外的任何地方发请求，浏览器控制台有没有报错。想自己在浏览器里看放到网站上的样子，运行 `node proto-static.js --serve --open`，它生成完会起一个只发文件、没有任何接口的服务器。

| 文件 | 作用 |
|---|---|
| `proto.js` | Node 版原型的服务器：起一份仿真后端，在它前面加上目录页、导览页，并在界面加载时把数据摆成地址里指定的场景。静态版里它也被打进 `mock.js`，在浏览器里跑 |
| `proto/scenes.js` | 场景清单。一个场景 = 仿真后端摆成什么样 + 界面停在哪一页 + 进页面后自动点几下。**加场景只改这一个文件**，写法见文件开头 |
| `proto/tour.js` | 导览的十四步：每一步用场景清单里的哪个场景，配什么标题和说明（中文、英文各一份） |
| `proto/fiction.js`、`proto/catalog.js` | 虚构数据：十二台服务器和每台自己的玩家、备份、控制台输出；热门清单里的模组和插件 |
| `proto/demo.js` | 上面说的那几段假流程 |
| `proto/index.html`、`proto/tour.html` | 目录页（评审用）、导览页（给访客看）。两张页面只是外面的样子不同 |
| `proto/stage.js` | 两张页面共用的「舞台」：把界面嵌进来、按窗口大小缩放、切场景 |
| `proto/player.js` | 跑在界面那一页里的「播放器」：替人点场景里写的那几下，并假装在原生窗口里（标题栏才有窗口三键）。外面的页面和它只靠发消息来往，因为双击打开时浏览器不让外面的页面直接伸手进去 |
| `proto/static-runtime.js` | 静态版的运行时：Node 模块的替身，接管 `fetch` 和 `EventSource` |
| `proto-static.js` | 生成静态版。官网的构建脚本直接调它导出的 `buildStatic()` |
| `proto-check.js` | 自检，见上面 |
| `打开界面原型.bat`、`生成并打开在线体验.bat` | 双击启动 Node 版、双击生成并打开静态版（都要装 Node.js，不用 `npm install`） |

## 注意

- 仿真后端的数据是假的，只用来看界面、测交互。后端逻辑用 `go test` 测：`internal/themes` 在任何平台都能跑，其余包需要 Windows。
- 浏览器里没有 WebView2 宿主。测试和截图脚本会模拟宿主注入的窗口函数，所以标题栏显示最小化 / 最大化 / 关闭三键；用 `npm run mock` 手动打开时不显示。启动画面只在有宿主函数、且注入了本次启动的 ID（`window.__MD_BOOT`）时播放，测试里单独模拟。
- 改了界面文字、选择器或交互，要同步改 `tests.js`；新加交互时顺手补一条测试，放在末尾「全程无页面报错」那条之前。
- 要模拟某种场景（服务器列表为空、首启引导、部署失败、开启远程访问、老版本实例），看 `server.js` 里 `/__mock/state` 的说明。
- 末尾几条「无障碍」测试读的是 Chromium 算出的无障碍树（WebView2 交给 Windows UI Automation 的就是这一份）：各主要页面不许有同名的按钮、链接、输入框，也不许有没名字的控件（同名链接指向同一处的除外）。新加的控件如果在同一页里会重复出现（每张卡片、每一行都有一个），要用 `aria-label` 带上对象，写法是「可见文字 + 对象」，如「启动 生存服」「保存触发前缀」。
- 开关的 `input` 是透明地叠在胶囊上的：测试里点开关要点 `input` 本身（如 `page.click("#gc-on")`），点 `.sw` 会被叠在上面的 `input` 挡住、一直等到超时。
