## 准备（只需一次）

需要 Node.js 18 或更新版本。在本目录下运行：

```powershell
npm install
npx playwright install chromium
```

第二步可以省掉：找不到 Playwright 自带的 Chromium（没装，或者装的是别的版本）时，测试和截图会自动改用本机装的 Google Chrome（见 `browser.js`）。要指定浏览器，设环境变量 `CHROME=<chrome.exe 的完整路径>` 或 `PW_CHANNEL=msedge`。

## 用法

```powershell
npm run mock                        # 启动仿真后端，然后用浏览器打开 http://127.0.0.1:27390/
npm test                            # 跑全部交互测试，全部通过时退出码为 0
npm test -- 外观                     # 只跑名字里含「外观」的测试（参数是正则）
npm run shots                       # 全部截图，存到 shots/pages 与 shots/schemes
npm run shots -- pages --only=wiz   # 只截名字匹配 wiz 的页面（新建向导各步）
npm run shots -- schemes            # 只截 7 套配色
```

`npm test` 和 `npm run shots` 会各自启动一份全新的仿真后端（随机端口），不用先开 `npm run mock`，每次都从同一份初始数据开始。`npm run mock` 默认用 27390 端口，避开 MineDeck 自己的 27333；要换端口就运行 `node server.js <端口>`。

## 界面原型

想一口气看遍各种状态（没有服务器、十二种核心各一台、向导的每一步、部署失败、隧道出错、各个设置分区……），不用真的去建那么多服务器：**双击本目录的「打开界面原型.bat」**，浏览器会打开一个场景目录页。也可以运行 `npm run proto`（或 `node proto.js [端口]`，默认 27391）。

目录页左边按页面分组列着场景，点一个，右边嵌着的界面就切到那个状态。界面是真的（`internal/web/ui/` 原样托管），数据是编的，所以可以照常点、填、切标签，只是不会真的下载和开服。右上角可以换深色 / 浅色、七套配色和窗口大小（默认、最小 1024×576、大窗口、手机）。键盘 ↑ ↓ 换场景。每次换场景，数据都回到那个场景的初始样子。

| 文件 | 作用 |
|---|---|
| `proto.js` | 原型的服务器：起一份仿真后端，在它前面加上目录页、场景切换的接口，并让界面以为自己在原生窗口里（标题栏才有窗口三键） |
| `proto/scenes.js` | 场景清单。一个场景 = 仿真后端摆成什么样 + 界面停在哪一页 + 进页面后自动点几下。**加场景只改这一个文件**，写法见文件开头 |
| `proto/fiction.js` | 虚构数据：十二台服务器，以及每台自己的玩家、备份、控制台输出 |
| `proto/index.html` | 目录页 |
| `proto-check.js` | 自检：把每个场景打开一遍，看自动操作有没有走完、页面有没有报错。`npm run proto:check`；加 `--shots=<目录>` 顺手每个场景截一张图 |
| `打开界面原型.bat` | 双击启动（要装 Node.js，不用 `npm install`） |

改了界面上的选择器（id、class、`data-*`）之后跑一遍 `npm run proto:check`：场景里写的选择器失效了，它会指出是哪个场景。界面有了新页面或新状态，顺手在 `proto/scenes.js` 里加一个场景。

## 注意

- 仿真后端的数据是假的，只用来看界面、测交互。后端逻辑用 `go test` 测：`internal/themes` 在任何平台都能跑，其余包需要 Windows。
- 浏览器里没有 WebView2 宿主。测试和截图脚本会模拟宿主注入的窗口函数，所以标题栏显示最小化 / 最大化 / 关闭三键；用 `npm run mock` 手动打开时不显示。启动画面只在有宿主函数、且注入了本次启动的 ID（`window.__MD_BOOT`）时播放，测试里单独模拟。
- 改了界面文字、选择器或交互，要同步改 `tests.js`；新加交互时顺手补一条测试，放在末尾「全程无页面报错」那条之前。
- 要模拟某种场景（服务器列表为空、首启引导、部署失败、开启远程访问、老版本实例），看 `server.js` 里 `/__mock/state` 的说明。
- 末尾几条「无障碍」测试读的是 Chromium 算出的无障碍树（WebView2 交给 Windows UI Automation 的就是这一份）：各主要页面不许有同名的按钮、链接、输入框，也不许有没名字的控件（同名链接指向同一处的除外）。新加的控件如果在同一页里会重复出现（每张卡片、每一行都有一个），要用 `aria-label` 带上对象，写法是「可见文字 + 对象」，如「启动 生存服」「保存触发前缀」。
- 开关的 `input` 是透明地叠在胶囊上的：测试里点开关要点 `input` 本身（如 `page.click("#gc-on")`），点 `.sw` 会被叠在上面的 `input` 挡住、一直等到超时。
