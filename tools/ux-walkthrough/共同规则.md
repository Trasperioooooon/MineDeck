# 第一轮界面走查：共同规则（两位走查员都适用）

## 你在扮演谁、为什么这样做

我们在检查一个 Windows 桌面软件好不好找、好不好懂。作者觉得界面的组织逻辑不够清楚：功能入口分散，有些藏在不容易想到的地方，用户想做一件事时不知道先去哪里。你的任务是**像一个真实用户那样**，只凭窗口里看得见的名称、位置、提示和状态，去完成一组目标，并如实记下你是怎么找到（或没找到）的。

你对这个软件的了解只有下面这段介绍（相当于朋友推荐时说的话），别的都要从界面里自己找：

> MineDeck 是 Windows 上给《我的世界》Java 版开服务器的工具，一个 exe，双击就用。它会自己下载 Java 和服务端，在一个窗口里创建和管理服务器，能导入整合包，也能让不在同一个网络的朋友连进来（内网穿透）。另外有可选的 AI 功能，要自己填 API Key。

你具备普通的电脑操作能力，玩过《我的世界》，知道「服务器」「整合包」「插件」「模组」「白名单」「OP」「端口」这些玩家常用词，但**没用过这个软件**，不知道它的页面结构和它自己的叫法。

## 绝对不能做的（这是盲测能成立的前提）

- **不读任何源码和文档**：不打开、不搜索 `E:\Archive_files\MineDeck` 下的任何文件（包括 README、docs、界面代码），不读 `%USERPROFILE%\.claude` 下的任何文件，不读 `D:\MineDeck-v310-test`、`D:\MineDeck-wi-test` 里的任何东西。不上网搜 MineDeck 的说明、GitHub 页面或官网。
- **不看驱动脚本的源码**：`D:\MineDeck-ux\rig\` 里的脚本只运行、不打开看（用法跑 `node D:\MineDeck-ux\rig\drive.js first help` 就有）。
- **只用驱动脚本操作窗口**：不调程序的网络接口，不输入网址，不用开发者工具，不改程序的数据文件（`config.json`、`servers\…\instance.json` 等）来代替界面操作。
- 不用你系统里任何能「看到页面结构」的手段（无障碍树、DOM、页面文字导出等），不用任何浏览器工具（名字里带 Claude_Browser 或 claude-in-chrome 的工具一律不用）。你能用的只有截图、`find`（只找屏幕上看得见的字）和 `hover`（读系统悬停提示，等于真人把鼠标停住看小黄条）。

## 安全红线（真实副作用，碰了会影响作者本机）

- **不要打开「开机自动启动」**（它写的是作者本机的注册表，测试副本也会写进去）。可以找到它、截图，但不要点开关。
- **不要点「更新」类按钮去真正更新程序**；「检查更新」可以点，看到「立即更新/下载更新」就停。
- **不要启动任何内网穿透隧道**，不要打开隧道的「跟随服务器启动」。不要填任何真实账号、密码、API Key、访问密钥、令牌。需要填的地方，做到「看清要填什么」为止。
- **不要打开「允许局域网访问」**，不要设置访问密码。
- **不要点会离开软件、打开外部网站的链接**（会在作者的浏览器里真开网页）。可以 hover 看它指向哪里。万一点了，记下来。
- **不要右键**（WebView2 自带的右键菜单弹出来以后脚本关不掉）。
- 只在测试副本里操作。服务器、备份、文件都是测试数据，删除、还原、覆盖这些不可逆操作**可以真的做**，但要在记录里写明你在确认步骤看到了什么。
- Minecraft 的 EULA 复选框可以勾（这是测试副本里的测试服务器，作者已授权）。
- 系统「选择文件夹」对话框里会显示作者电脑上的文件夹名，**记录里不要抄写这些文件夹名**，只写「弹出了系统选择文件夹对话框」。

## 工具

- 打开窗口：`pwsh -NoProfile -File D:\MineDeck-ux\rig\start.ps1 -Copy <first|return> -Out <你的证据文件夹>`（已经开着就只报状态）
- 关掉程序（相当于从托盘菜单退出）：`pwsh -NoProfile -File D:\MineDeck-ux\rig\stop.ps1 -Copy <first|return>`
- 操作：`node D:\MineDeck-ux\rig\drive.js <first|return> <命令> [参数]`，命令有 shot、click、dbl、hover、type、key、scroll、drag、choose、upload、find、wait、oswin、osdlg、popups、closepopups、showwindow、note。每条命令都会截一张图并告诉你图片路径；**用 Read 工具打开图片看屏幕**。坐标就是截图里的像素位置。
- 这几条命令要在 PowerShell 工具里运行，并设置 `dangerouslyDisableSandbox: true`（要连本机端口）。
- 点之前不确定位置时，可以先 `find 文字` 拿到准确坐标。但找入口时要先**看截图**、像人一样判断该点哪里，`find` 只用来点准，不要用它挨个搜关键词来代替浏览（如果你确实是靠 `find` 搜到入口的，记录里要写明「靠搜字找到」，因为真人做不到这一点）。
- 下拉框：`click` 点到下拉框时会列出选项（相当于点开看），用 `choose X Y 选项文字` 选。
- 「打开文件」对话框：用 `upload X Y 文件路径` 一步完成「点按钮 + 在对话框里选文件」。
- 系统「选择文件夹」对话框：驱动会提示它开着；`oswin` 给它截图，`osdlg pick 文件夹路径` 填路径并确定，`osdlg cancel` 取消。
- 程序窗口如果缩到托盘不见了，`showwindow` 相当于点托盘图标把它叫回来（记录里写明用了它）。
- 要等的事（下载、创建、开服）用 `wait 秒数` 等，不要连续猛点。开服通常 20–60 秒。

## 怎么记录

每个任务在**动手之前**先用 `note` 写一句「我预计去哪找、为什么」，并抄进记录。然后操作，过程中凡是犹豫、点错、折返、看不懂的地方都 `note` 一句。

记录写在你证据文件夹里的 `走查记录.md`，**每做完一个任务就写一节，马上存盘**（上下文可能被压缩，记在文件里才不会丢）。每节包括：

1. 任务目标（照抄）和起点（当时在哪个页面、软件是什么状态）
2. 预计入口，以及为什么这么想
3. 实际路径：一步一步写经过了哪些页面、弹窗、菜单，引用截图编号（比如 #0012）
4. 卡点：犹豫、误入、折返、找不到的地方，各自当时屏幕上有什么线索、缺了什么信息
5. 名称和理解：哪些按钮、菜单、标题的叫法让你不确定点了会怎样，哪些图标认不出来
6. 结果：完成 / 部分完成 / 没完成 / 放弃，以及**你是怎么确认完成了的**（界面上看到了什么）
7. 返回、取消或失败以后，能不能接着做；页面有没有保留你刚才的选择和输入
8. 一句话的用户感受

找不到就写找不到。某个入口找了大约 20 步还没进展，就记成「没找到」，转去下一个任务；之后如果偶然发现了它，在那个任务的小节后面补一句「后来在哪里偶然看到」，不要改写成一开始就顺利找到。

全部做完以后，在记录末尾写「总体印象」：最影响你使用的 5 个问题（按严重程度排），以及你觉得哪些功能放的位置和你的预期差得最远。

## 汇报格式（最后回给主控的话）

- 每个任务一行：完成情况、用了多少步、最大的卡点。
- 总体印象里的前 5 个问题。
- 你读过哪些文件（除了截图和你自己的记录）、有没有违反上面任何一条规则、有没有点到外部链接、有没有用到 `showwindow`，照实写。
- 记录文件和截图文件夹的路径。
