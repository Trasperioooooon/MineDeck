# MineDeck v3.1.0 宣传片

这个目录生成 v3.1.0 正式版的宣传片和两张封面。片子 84 秒，16:9，出 2560×1440 和 1920×1080 两个文件，都是恒定 60 帧，带一条立体声配乐，不口播，靠字幕讲。封面一张 1920×1080、一张 1080×1920。做法和 v3.0 那支（`tools/promo/video/`）一样：画面里的界面全部是在 `tools/ui-dev` 的仿真后端上拍的真实截图，数据是仿真后端里的假数据，没有真人信息，也没有用游戏本身的贴图、字体、标志或截图；交接那几段的电脑、箱子是自己画的扁平图形。

当初的方案在 `方案.md`，配乐和封面的提示词在 `配乐提示词.md`、`封面.md`。做出来的片子和方案的差别写在本文最后一节。

## 重新出片

双击 `make-video.bat`，大约 15 分钟。它按顺序做六件事：检查上屏文字，拍界面截图，逐帧渲染，编码，合配乐，出封面。需要 Node 18 以上、PATH 里的 ffmpeg、`tools/ui-dev/node_modules` 里的 Playwright、本机装好的 Google Chrome（脚本都用 `channel: "chrome"` 启动本机 Chrome），以及装了 Pillow 的 Python（只有导出封面素材时用）。

想分步跑的话，先把 `NODE_PATH` 指到 `tools/ui-dev/node_modules`，再在仓库根目录执行：

- `node tools/promo/video-v3.1/check-text.js` 检查字幕和其他上屏文字，规矩和 v3.0 一样：只用 GB2312 里的字，字幕每行不超过 18 个字符，不用「轻松」「告别」这类词，不用感叹号，「一键开服」全片只出现一次，每条字幕至少停 1.5 秒。
- `node tools/promo/video-v3.1/capture.js` 起仿真后端（端口 27410），用 Chrome 拍 32 张界面截图到 `out/shots/`，要标框、要让光标去点的元素位置记进 `out/shots/rects.json`，换 Java 那张下拉列表的选项记进 `out/shots/extra.json`。截图是 1280×800、DPR 2（推得近的几张用 DPR 3），浅色、配色「方块」。加 `--only=正则` 只重拍几组。绑本地端口，在受限的终端里跑要放开沙箱。
- `node tools/promo/video-v3.1/render.js` 逐帧渲染。先检查每个字都由内嵌字体画出来、每条字幕都在 5% 标题安全区里，再开 6 个页面并行，5040 帧大约 4 分钟。`--every=30` 每半秒一帧，`--at=12.5,40` 只渲染这几个时间点（存到 `out/samples/`）。
- `node tools/promo/video-v3.1/encode.js` 编成两个视频，用 ffprobe 核对分辨率、帧率、帧数、时长、色彩标签，出一张每秒一帧的联系表和几张样帧，最后删掉帧图（`--keep-frames` 留着）。
- `node tools/promo/video-v3.1/music.js` 把配乐合进两个视频，视频流原样拷贝，就地替换，可以反复跑。
- `node tools/promo/video-v3.1/cover.js` 出两张封面到 `out/封面-16x9.png`、`out/封面-9x16.png`。

想在浏览器里边改边看，运行 `node tools/promo/video-v3.1/serve.js`，打开 `http://127.0.0.1:27411/?t=12.5`（停在第 12.5 秒），加 `&debug` 左上角显示时间和小节，`?play=1` 按真实时间播放（没有声音）。封面是 `http://127.0.0.1:27411/cover.html?r=16x9`（或 `9x16`）。

## 文件

`captions.js` 是节拍网格、分段和全部上屏文字，改文案只改这一个文件。`scene.html`、`scene.css`、`scene.js` 是画面：`window.renderAt(t)` 只依赖时间 t，同一个 t 永远画出同一帧，页面里没有 CSS 动画和过渡。截图在画面里用「截图视图」摆放，镜头、光标、高亮框写在截图自己的坐标里；换 Java 的下拉列表、飞进待装清单的小标签、接管那段的打字效果，是叠在截图那一层上的小部件，跟着截图一起缩放。`cover.html`、`cover.js` 是封面。`analyze-music.py` 量配乐的速度、小节线和段落（`out/music-analysis.png` 是它画的谱图），`export_icon.py` 导出封面用的高清图标。`music/` 里是配乐，`cover/` 里是封面底图，`out/` 不进仓库。

## 配乐和节拍

配乐是 `music/Morning_on_the_Balcony.mp3`，作者 2026-11-12 按 `配乐提示词.md` 用 Gemini 生成的，92 秒。`analyze-music.py` 量出来是 123.99 BPM（又不是提示词里的 120，和上次一样偏快），速度很稳，每 16 拍的偏差在 8 毫秒以内。小节线从 1.372 秒起每 1.93564 秒一条。和弦在每小节第 1、3 拍换，几处段落的起点都落在这套小节线上，所以小节的第一拍是认准了的。这一点 `analyze-music.py` 起初判断错了：它只看低频起音落在哪个拍位上最强，这首曲子的低音和底鼓偏偏在第 4 拍上更重，算出来差了一拍（第一条小节线在 −0.08 秒）。后来改成先看和弦在哪两个拍位上换（第 1、3 拍得分接近，第 2、4 拍低），再看段落起点（鼓进来的 14.92 秒、主段落落下的 53.63 秒）落在其中哪一个上，现在跑出来就是第 1 小节从 1.372 秒起。换曲子时先跑它，再对着 `out/music-analysis.png` 听一遍小节线对不对；拿不准就用 `--downbeat-phase` 指定。曲子的结构是：7 小节钢琴前奏，第 5 小节低音进来；14.92 秒鼓进来，16 小节律动；45.89 秒安静下来，4 小节过渡，后两小节蓄力，落下之前有一下很短的空；53.63 秒主段落落下，16 小节；84.60 秒起收尾，89 秒前收尽。

这次画面跟着曲子走：节拍网格就用 123.99 BPM（`captions.js` 的 `BPM`），曲子不变速，只从曲子的第 3 小节（5.2431 秒，`MUSIC_START`）开始截，画面第 b 小节就是曲子第 b + 2 小节。全片 43 小节加一点尾音，84 秒。分段都落在小节线上，切镜头、点击、字幕进场落在拍上，段落之间用草绿色的方块擦除转场。

- 第 1–5 小节（0–9.7 秒），开场。先出「开服，不一定从零开始」，方块落下拼成图标，第 3 小节低音进来时落定，同时出字标、「v3.1.0 正式版」和「我的世界 Windows 一键开服工具」；然后是新建服务器页的四张卡片，第 5 小节的四拍上依次亮一下。
- 第 6–11 小节（9.7–21.3 秒），接管已有服务器。鼓进来的那一下切进来：选中以前的服务器文件夹（路径一个字一个字打出来）、认出核心和版本、就地登记、列表里多了这一台、换 Java（下拉列表选本机装的 Java 21）、删除时只移出列表。
- 第 12–17 小节（21.3–32.9 秒），自己挑模组：向导里的「选模组」、搜索、加入待装清单；然后切到建好的那台「机械动力整合包」的待装清单，清单里是 REI，检查前置列出它的两个必装前置；再回向导从电脑添加 jar；最后是那台服务器的安装任务，装 REI 和自动补上的两个前置。
- 第 18–21 小节（32.9–40.6 秒），导入整合包：本地来源文件夹、待决文件、逐个处理、现成服务端。
- 第 22–25 小节（40.6–48.4 秒），曲子安静下来。前两小节是「自己的服不想开了？或者，想让朋友也开一台」，后两小节（蓄力）是卡片菜单的「导出交接包…」和交接弹窗，第 25 小节第 3 拍点「开始打包」。
- 第 26–31 小节（48.4–60.0 秒），主段落落下：几样东西飞进箱子、箱子变成 .mdpack、从你的电脑飞到朋友的电脑、对方导入、开起来、两台电脑收束。
- 第 32–35 小节（60.0–67.7 秒），报错、frpc 被杀毒软件拦下、Java 提醒、后台任务，一小节一个。
- 第 36–40 小节（67.7–77.4 秒），正式版前的检查、检查更新、「一个文件就够了」、「接管 · 挑模组 · 导入 · 交接」回顾。
- 第 41 小节起（77.4–84 秒），片尾。图标再拼一次，字标、「免费开源 · Windows 10/11 · v3.1.0」、网址、「GitHub 搜索 MineDeck」和一行「非 Minecraft 官方产品」的小字在第 42 小节（曲子收尾）前后到位，之后静止大约 4 秒。

## 拍截图时改了的仿真数据

都是在浏览器里改仿真后端的返回或者用它的 `/__mock/state` 开关，界面代码一行没动：

- 版本号改成 3.1.0；「升级」那两张改成 3.0.0，检查更新回「发现新版本 v3.1.0」。
- 列表里那台接管进来的 `create-pack` 是脚本补进去的（仿真后端接管完不往列表里加）。
- 安装待装清单、导入交接包、导入现成服务端这三个任务页，由脚本给出任务快照，名字和日志跟片子里的故事对上；交接包上传后的摘要换成「机械动力整合包」那台。安装待装清单那个任务的四个步骤名和日志写法照真后端（`internal/ops/catalog/modcart.go` 的 `installCart`），仿真后端自己给的还是旧的三步。
- 「补前置」那一镜：仿真后端的依赖检查写死成「Architectury API 是 JEI 的前置」，现实里 JEI 没有必装前置，懂模组的人一眼能看出来。所以这一镜换成真实存在的一对：REI 在 Forge 1.20.1 上必装 Cloth Config API 和 Architectury API。项目名字、简介、许可证、版本号、文件名、大小都是 2026-11-13 在 Modrinth 上查的原样（REI 在 Forge 1.20.1 上只有 beta 版，日志里照真后端写「（beta 版）」）。仿真后端的目录里没有 REI，搜索结果、清单里那一项的名字和依赖检查的结果由 `capture.js` 给出；那台服务器挂着的「缺少前置模组 jei」示例横幅（已装模组的依赖核对）这一镜关掉了。向导里搜的仍然是 JEI，那几镜不涉及前置。
- 待决文件那两张用 `taskList` 造了一个带三个待决文件的导入任务，和界面测试的造法一样。
- frpc 被拦那张，把第二条隧道的 `lastError` 换成 `internal/tunnel/blocked.go` 里的原话。
- 「开好了」的控制台换成一段干净的 Forge 开服日志，玩家名用的是编的 Kai_07、Mochi233；那两张详情页把排错横幅关了（仿真后端给整合包服挂着一个「缺少前置模组」的示例横幅）。
- 「报错」那张让启动接口回一条带路径的英文报错，看提示只写结论、原文在「详情」里。

## 和方案的差别

- 方案按 120 BPM、45 小节、90 秒排；曲子实际是 124 BPM，前奏 7 小节，所以从曲子第 3 小节开始截，整片按曲子的段落重排，成片 84 秒。交接包仍然落在主段落上，「自己的服不想开了？」正好落在曲子安静的那 4 小节里。
- 第三章少了「CurseForge 的资源包、光影、数据包各进各的文件夹」那一小节：律动段只有 16 小节，放不下。这是方案里说的节奏太赶时先砍的三镜之一。
- 第 15 小节「补前置」照方案拍在建好的服务器的待装清单上，但清单里放的不是向导里那个 JEI，而是 REI 和它真实的两个前置，原因见上一节。
- 「选模组」那一小节的类别筛选没有单独拍：仿真后端按类别筛出来的模组名是占位的「Hot Mod 005」，放进片子不像样，改成在同一张截图上先框类别再框搜索框。
- 卡片菜单里那一项现在叫「导出交接包…」，方案（和发布说明、功能清单）写的是「交接给其他电脑…」。片子照界面拍。
- 封面的字按作者给的写法：「MineDeck 开服工具」「V3.1.0 抢先预览」，加三个新功能和「免费开源 · Windows 10/11」。片子开场的标签写的是「v3.1.0 正式版」，两边说法不一样，要统一的话改 `captions.js` 的 `TEXT.badge` 或 `cover.html` 一行就行。
- 片尾加了「非 Minecraft 官方产品，与 Mojang、微软、网易无关」，方案里列为替作者拿的主意，可以去掉（`captions.js` 的 `TEXT.endNote`）。
