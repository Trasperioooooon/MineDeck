# MineDeck v3.1.0 宣传片方案

这支片子讲 v3.1.0 正式版比 v3.0.0 多了什么。片长 90 秒左右，横版 16:9，出 2560×1440 和 1920×1080 两个文件，60 帧，不口播，靠字幕讲。样子和 v3.0 那支（`tools/promo/video/`）一脉相承：暖沙色的底，界面都是在仿真后端上拍的真实截图，段落之间用草绿色的方块擦除转场。配乐由作者照 `配乐提示词.md` 在 Gemini 里生成，封面的做法、要用的素材和提示词在 `封面.md`。

这份是开工前写的方案。片子 2026-11-13 已经做出来了，成片和这里不一样的地方（片长 84 秒、少了 CurseForge 那一小节、「补前置」那一镜的模组换成 REI 等）写在同目录 `README.md` 的「和方案的差别」，两边对不上时以 README 为准。

## 讲什么

发布说明里的大功能有四样：接管已有服务器、交接包、自己挑模组（待装清单）、导入整合包和现成服务端。片子按这四样分四章，接管放在最前面。其余的小改进，比如换 Java、报错先说结论、frpc 被杀毒软件拦下时的中文说明、部署进度切走了还找得回，放进一段快剪。最后交代正式版前做过的检查，和老用户怎么升级。

贯穿全片的是一句话：开服不一定从零开始。新建服务器页现在有四张卡片：从零创建、导入整合包、导入交接包、接管已有服务器。开场把这一页亮出来当目录，后面几章各讲一张。交接包方向反过来，是把服务器交出去，放在全片最热闹的位置。

## 节拍

先按 120 BPM 排：一拍 0.5 秒，一小节 2 秒，45 小节正好 90 秒。分段落在小节线上，切镜头、点击、字幕进场落在拍上。

配乐生成出来以后，画面跟着曲子走。先量出曲子的实际速度，把 `captions.js` 里的 BPM 改成它，再把几段的起点挪到曲子真正的段落上，不再像上次那样把曲子整首放慢去迁就画面。所以下面写的秒数都是按 120 BPM 算的，最后会跟着曲子变一点，片长会落在 85 到 95 秒之间。

## 分镜

小节从 1 数。括号里是界面原型（`tools/ui-dev/proto/scenes.js`）里对应的场景，拍的时候照它把界面摆好。字幕分眉标（小字标签）、主句、副句三层，和 v3.0 一样。

### 开场（第 1–3 小节，0–6 秒）

- 0–2 秒：沙色底上出一句「开服，不一定从零开始」。
- 2–4 秒：方块从上往下落，拼成 MineDeck 的图标。这是 v3.0 那支的开场，留着让两支片子认得出是一家的。
- 4 秒：图标落定，放出一圈小方块，同时出字标「MineDeck」和一枚「v3.1.0 正式版」的标签。全片第一个重拍。
- 4.5–6 秒：出「我的世界 Windows 一键开服工具」。「一键开服」全片只在这里出现一次。

### 四种方式（第 4–5 小节，6–10 秒）

- 新建服务器页（c-create）：四张一样大的卡片，分「新建」「导入与接管」两组。眉标「新建服务器」，主句「现在有四种方式」，副句「从零创建之外，还能导入和接管」。
- 第 5 小节的四拍上，四张卡片依次亮一下框，当作目录。最后一拍镜头推向「接管已有服务器」那张，擦除转场进第一章。

### 第一章：接管已有服务器（第 6–11 小节，10–22 秒）

- 第 6 小节：接管页（n-adopt），文件夹一栏填上 `E:\MCServers\create-pack`，第 3 拍点「识别」。眉标「接管已有服务器」，主句「以前开的服务器，选中它的文件夹」。
- 第 7 小节：识别结果（n-adopt-scan）：核心、版本、启动文件、原来的内存和端口，框出这一块。主句「核心、版本、启动文件自动认出」，副句「原来的内存和端口也带上」。
- 第 8 小节：点「接管这台服务器」，任务页的日志里写着接管完成，存档、模组、插件和配置文件都没有动。主句「就地登记，文件不搬」，副句「存档、模组和配置都不动」。
- 第 9 小节：服务器列表里多出这一台。主句「和新建的服务器一样管」。仿真后端接管完不会往列表里加，拍的时候要补一台进去。
- 第 10 小节：这台服务器的「内存 / 启动」（d-jvm），打开 Java 的选择：MineDeck 下载的、电脑上装的，或者现下一个。眉标「换 Java」，主句「每台服务器可以单独换 Java」，副句「下载的、电脑上装的，或现下一个」。
- 第 11 小节：删除确认框（o-delete），「同时删除服务器文件夹」不勾。眉标「移出列表」，主句「不想管了，只从列表移出」，副句「文件都在，以后还能接管回来」。

### 第二章：自己挑模组（第 12–17 小节，22–34 秒）

- 第 12 小节：新建向导里的「选模组」（c-wiz-mods，NeoForge）：左边一进来就是热门模组，右边是待装清单。眉标「选模组」，主句「新建向导里多了一步：选模组」，副句「按核心和版本列出热门模组」。
- 第 13 小节：点「优化」类别（c-wiz-cats），列表跟着筛。主句「按类别筛，也能直接搜」，副句「插件服这一步叫「选插件」」。
- 第 14 小节：搜「JEI」，点加入，这一项飞进右边的待装清单（n-mods-search）。主句「挑中的放进待装清单」。
- 第 15 小节：建好的服务器详情页里的「待装清单」标签，点检查前置，前置补了出来（d-cart）。主句「缺的前置，自动一起装上」，副句「建好的服务器也有待装清单」。
- 第 16 小节：「从电脑添加」几个自己下载的 jar，加载器不对的那一行带着提醒（c-wiz-local）。主句「自己下载的 jar 也能加」，副句「加载器不对的会标出来」。
- 第 17 小节：点「安装」，任务页的进度走完（t-mods）。主句「点安装，一次装好」，副句「从 Modrinth 下载并校验」。

### 第三章：导入整合包和现成服务端（第 18–22 小节，34–44 秒）

- 第 18 小节：导入整合包页（n-import），选好一个 CurseForge 整合包，框出「本地来源文件夹」。眉标「导入整合包」，主句「个别文件下载不了，也照常导入」，副句「可以填旧服务器的文件夹来补」。
- 第 19 小节：导入完成，任务页上是「待决文件（3 个）」。原型里没有现成的场景，用仿真状态的 `taskList` 造一个带待决文件的导入任务就行，界面测试（`tests.js` 2644 行附近）就是这么造的。主句「下载不了的，列进待决文件」。
- 第 20 小节：推近其中一项：「跳过」「用本地文件代替」「信任站点并下载」，光标选中「用本地文件代替」。主句「跳过、本地代替，或信任后下载」，副句「每个文件自己选」。
- 第 21 小节：一段小动画：几个文件分别落进 mods、resourcepacks、shaderpacks、datapacks 四个文件夹。眉标「CurseForge 整合包」，主句「资源包、光影、数据包各进各的文件夹」。
- 第 22 小节：一段小动画：一个服务端压缩包解开，变成服务器列表里的一张卡片。仿真后端没有这条导入路径，先用动画；要换成真界面得先给仿真后端补上。主句「核心已经在包里的服务端压缩包」，副句「直接导入成一台新服务器」。这里的说法不能再放宽：只带启动脚本的 Server Pack 导不进来，beta.4 发出去以后为这个改过一次说明。

### 转折（第 23 小节，44–46 秒）

- 沙色底的标题卡：「自己的服不想开了？」，第 3 拍补一句「或者，想让朋友也开一台」。音乐在这里蓄力，46 秒前最好有一下很短的空。

### 第四章：交接包（第 24–31 小节，46–62 秒，全片最热闹的一段）

- 第 24 小节（46 秒，第二个重拍）：服务器列表，停着的「机械动力整合包」卡片上点「···」，框出「交接给其他电脑…」（l-menu）。眉标「交接包」，主句「整台服务器，打包交给别人」。
- 第 25 小节：交接弹窗：「这个包给谁」（交给下一任服主，或者发给朋友照着开一台）、完整模式、导出到哪个文件夹。主句「交给下一任服主，或发给朋友照着开」。
- 第 26 小节：动画：存档、server.properties、mods、config、白名单、管理员名单几块小图块飞进一个包，包上写「机械动力整合包.mdpack」。主句「存档、配置、模组、名单都在包里」，副句「核心默认不带，导入时重新下载」。
- 第 27 小节：动画：这个包从左边一台电脑飞到右边一台电脑，落下那一下踩在第 3 拍。主句「一个 .mdpack，发给朋友」。
- 第 28 小节：朋友那边：新建服务器 → 导入交接包（n-transfer），选中文件以后出摘要。主句「对方在「导入交接包」里选中它」，副句「只导入信得过的人给的包」。这句副句是发布说明里的提醒，包里的模组和插件会在收包的电脑上运行，留着。
- 第 29 小节：填名称和端口，开始导入，任务页走进度。主句「Java 和核心在他电脑上重新准备」。
- 第 30 小节：朋友的服务器列表里多了这一台，点启动，控制台看到 Done。主句「接着开，存档都在」。
- 第 31 小节：收束：左右两台电脑上是同一张服务器卡片，中间一个对勾。主句「换电脑、换服主，服务器接着开」。

### 还有这些（第 32–35 小节，62–70 秒）

每小节一个点，节奏快一些。

- 第 32 小节：右上角的报错提示，点「详情」看原文（o-toast-err，接 o-err-detail）。眉标「报错」，主句「报错先说没做成什么」，副句「原文点「详情」能看、能复制」。
- 第 33 小节：内网穿透页，一条隧道卡片底下整句写着「frpc 被杀毒软件拦下了……到 Windows 安全中心的「保护历史记录」里……允许或还原它」。在 u-two 的基础上，用仿真状态的 `tunnel` 把这条隧道的 `lastError` 换成 `internal/tunnel/blocked.go` 里的原话，卡片会整句显示。眉标「内网穿透」，主句「frpc 被杀毒软件拦了，直接说」，副句「还告诉你去哪里允许或还原」。
- 第 34 小节：整合包里的模组要的 Java 比服务器现在用的新，详情页提示去换（仿真状态 `modsNeed` 打开这条提示）。眉标「Java 提醒」，主句「模组要更新的 Java，会提醒你换」。
- 第 35 小节：新建服务器页上的后台任务（n-home-tasks）。眉标「后台任务」，主句「部署切走了，回来还能找到进度」。

### 正式版和升级（第 36–37 小节，70–74 秒）

- 第 36 小节：标题卡「正式版前，从头查了一遍」，三个小标签落在第 1、2、3 拍：「自动测试」「真机测试」「安全审查」。
- 第 37 小节：设置 → 更新与关于，框出「检查更新」。仿真后端的这个接口固定回「没有更新」，拍的时候在浏览器里改成发现了 3.1.0。眉标「升级」，主句「用着 3.0 的，设置里检查更新」，副句「服务器、Java 和设置都接着用」。

### 第一次用（第 38–39 小节，74–78 秒）

- 沿用 v3.0 那张「一个文件就够了」：`MineDeck.exe` 的文件卡片写「大约 15 MB」（官网按正式版的附件写的大小），三行「不用安装，双击运行」「Java 不用自己装」「数据都在 exe 所在的文件夹」逐拍勾上。给第一次看到 MineDeck 的人。

### 回顾（第 40 小节，78–80 秒）

- 四个词落在四拍上：「接管」「挑模组」「导入」「交接」。

### 片尾（第 41–45 小节，80–90 秒）

- 第 41 小节图标再拼一次；字标、「免费开源 · Windows 10/11 · v3.1.0」、网址 `trasperioooooon.github.io/MineDeck`、「GitHub 搜索 MineDeck」在 83 秒前全部到位，之后静止大约 7 秒。v3.0 那支片尾静止了 10 秒，偏长。
- 最下面一行小字：「非 Minecraft 官方产品，与 Mojang、微软、网易无关」。程序的「关于」页有同样意思的声明（也点了这三家），v3.0 那支没加。

## 怎么做

- 工具用 v3.0 那一套：仿真后端上拍界面、`renderAt(t)` 逐帧渲染、ffmpeg 编码、合配乐。复制到这个目录再改，`tools/promo/video/` 原样留着，v3.0 那支随时还能重出。
- 拍界面要用 v3.1.0 的代码。主检出现在停在 c7e7a03，比 v3.1.0 少了 PR #15 和发版那几个提交，开工前先快进到 origin/main，或者在 v3.1.0 上开一个工作树。
- 仿真后端里写的版本号是 2.9.0-beta.2，拍的时候在浏览器里改成 3.1.0，v3.0 那次也是这么改的。上面几镜提到的仿真状态（待决文件、frpc 被拦、Java 提醒、升级、列表里多一台接管的）都是在浏览器或者 `/__mock/state` 里改数据，界面代码一行不动。
- 上屏文字照旧过 `check-text.js`：只用 GB2312 里的字（内嵌的思源黑体子集按 GB2312 做），字幕每行不超过 18 个字符，不用「轻松」「告别」这类词，不用感叹号，「一键开服」全片一次。上面写的每一句都按这几条数过。
- 不用游戏本身的贴图、字体、标志和截图。交接那段的电脑和包裹、归位那段的文件夹，都是自己画的扁平图形，配色跟界面的「方块」配色走。
- 出片和上次一样：2560×1440 和 1920×1080 两个文件，60 帧，H.264 加 AAC 立体声，响度调到 -14 LUFS。

## 替作者拿的主意（都可以改）

- 只出横版。竖版（1080×1920）每一镜都要重新构图：截图只取一部分、推得更近，字幕挪到下面，工作量大约再加一半。封面两种比例都做，要竖版视频的话说一声。
- 接管放第一章，交接包放在全片最热闹的地方。
- 片尾加一行「非 Minecraft 官方产品」的小字。
- 节奏比 v3.0 密：10 秒到 70 秒之间每 2 秒换一镜、换一句字幕，全片大约 31 条字幕，v3.0 是 22 条，而且多数带副句。做出来看着赶的话，先砍第 16 小节（从电脑添加 jar）、第 21 小节（CurseForge 归类）、第 34 小节（Java 提醒），空出来的时间分给前后几镜，每镜多停一会儿。
- 不口播，和 v3.0 一样靠字幕讲。
- 安全方面只说「安全审查」，不列修了哪几处，也不说查了多少条线索。普通观众看到数字，容易以为出过大问题。
