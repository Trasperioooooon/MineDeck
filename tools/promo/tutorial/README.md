# MineDeck 演示视频

这个目录生成五分钟左右的上手演示视频，比宣传片讲得全：从下载、新建服务器、启动，到让朋友连进来、改设置、玩家和备份、模组和整合包、AI、手机管理，走一遍真实的操作。没有口播，靠字幕讲解，配乐是四段同调同速的曲子接成的一整首。

画面不是录屏，也不是截图拼的。真实界面跑在 `tools/ui-dev` 的仿真后端上，脚本像人一样去点、去打字，每推一帧时间截一张图，出来是恒定 60 帧的 2560×1440。数据都是编的，不会露出作者的地址、隧道和账号。改一句字幕只要重录那一段。

## 重新出片

双击 `make-demo.bat` 就行，大约二十分钟。它先录十二段（四段并行），再混配乐、编码，成片在 `out/` 里：`MineDeck-demo-1440p60.mp4`、`MineDeck-demo-1080p60.mp4`，还有一份 `章节.txt`，发 B 站时贴进简介，和一张每 8 秒一帧的 `contact-sheet.png`。需要的东西和宣传片一样：Node 18 以上、PATH 里的 ffmpeg、`tools/ui-dev/node_modules` 里的 Playwright、本机装好的 Google Chrome。

想分步跑，在任意目录执行下面几条：

- `node tools/promo/tutorial/record.js --preview=30` 看片用：不编码，每 30 帧存一张半尺寸的图到 `out/preview/<段号>/`，全部十二段半分钟左右。
- `node tools/promo/tutorial/record.js --only=03,04` 只重录这几段，输出到 `out/seg/`。不加 `--only` 就是全部，`--jobs=4` 控制同时跑几段。
- `node tools/promo/tutorial/assemble.js` 把 `out/seg/` 里的各段拼起来，混配乐，编两个版本，用 ffprobe 核对分辨率、帧率、帧数和音轨。

录失败时，卡住那一刻的画面在 `out/fail/<段号>.png`，看一眼就知道停在哪。

## 文件

`scenes.js` 是全部内容：十二段的仿真数据、操作和上屏文字，改文案只改这一个文件。脚本是一串 await，写在前面的先发生，时长就是各个动作加起来的长度。没有口播，节奏靠字幕：下一条字幕要等上一条读完（按字数算，0.9 秒加每字 0.1 秒），所以改文案不用手动调时间。

`director.js` 是录制引擎，提供 `click`、`type`、`cam`（镜头）、`mark`（高亮框）、`caption`（字幕卡）、`chapter`（章节卡）、`card`（全屏示意卡）这些动作，并且在录的时候检查上屏文字：只用 GB2312 里的字（内嵌的 Noto Sans SC 子集按它做的），不超长，没有感叹号和夸张词，不符合就报错。`overlay.js` 是注入页面的部分。`record.js` 按段启动录制，`assemble.js` 负责拼接和混音，`分镜与口播稿.md` 是最早写给口播版的底稿，现在只作参考，以 `scenes.js` 为准。`out/` 和 `voice/` 不进仓库。

## 逐帧录真实界面的几个要点

这些都是试出来的，改引擎之前先看一遍。

Chrome 自己的虚拟时钟（CDP 的 `Emulation.setVirtualTimePolicy`）不能用：时钟一停，鼠标事件就卡死，因为 Chrome 要等下一帧才处理鼠标移动，帧也跟着停了。现在用 Playwright 的 `page.clock` 接管页面里的定时器、Date 和 requestAnimationFrame。CSS 动画和过渡不归它管，所以每帧把 `document.getAnimations()` 全部暂停，按出生以后过了多少虚拟毫秒拨到位，走到头的调 `finish()`，animationend 和 transitionend 照常触发，靠它们收尾的提示条、菜单都正常。

截图用另开的 CDP 会话调 `Page.captureScreenshot`，clip 里写 scale。镜头推近就是把 clip 框小、scale 放大，Chrome 会按更高的倍率重新栅格化，字不会糊。字幕卡、高亮框、光标这一层用输出画面的坐标，每帧反向缩放抵消镜头，所以大小和线宽不随镜头变。

每帧推完时间，要等到没有在途请求、并且安静 40 毫秒，接力发出的请求才算进同一帧。控制台日志流是仿真后端按真实时间推的，换成了假流，由脚本决定每行什么时候出现。平滑滚动按真实时间走，所以 `scrollIntoView` 改成立刻到位，要滚动的镜头由脚本逐帧推 `#main.scrollTop`。输入框的光标闪烁也按真实时间走，原生光标藏掉，自己画了一个。

原生下拉框的列表画不进截图，所以脚本不点开它，直接改值。AI 助手的回答是仿真后端按真实时间推的事件流，没有接进虚拟时钟：正式录的时候一帧要几十毫秒，所以把块间隔放大到 420 毫秒，看上去是一段段写出来的。这一段每次录出来的节奏会有一点差别，别的部分录两遍只差肉眼看不出的抗锯齿噪点（PSNR 67 dB 以上），比对时不要用 md5。

## 配乐

配乐是 `music/` 里的四段，作者按 `配乐提示词.md` 用 Gemini 生成的，都在 F 大调和 D 小调这一对关系调上，前三段 101.98 BPM，第四段 104 BPM。每段都比片子需要的长，所以 `assemble.js` 开头的 `TRACKS` 写明了各用哪一截，截点取在小节线上，绕开曲子里的硬停顿和安静段。交叉淡化是两小节（8 拍，4.7 秒），重叠的那段鼓点是对齐的。第三段接第四段时速度差 2%，把第四段的一个强拍对在重叠段正中，前后最多差 40 毫秒。

每段按用到的部分调到 -16 LUFS，最后整体再核一次，真峰值不超过 -1.5 dBTP。比宣传片的 -14 LUFS 低一点是有意的：这几段的真峰值都接近或超过 0 dBTP，调到 -14 会被峰值上限卡住，每段卡的量不同，响度就不一致了；看字幕时音乐轻一点也更合适。

片长变了要看一眼 `TRACKS`：音乐比片子长，多的部分被末尾的淡出截掉；短了 3 秒以上 `assemble.js` 会报错。换曲子时先量节拍网格，再定截点，不要用 `tools/promo/video/music.js` 里的数。只想换配乐时跑 `node tools/promo/tutorial/assemble.js --music-only`，视频流原样拷贝，几十秒就好。
